# 图像检测

<span style="color: rgb(15, 17, 21)">2020年5月28日发布于arXiv，ECCV 2020 (欧洲计算机视觉国际会议)</span>

### <span style="color: rgb(15, 17, 21)">DETR</span>

[End-to-End Object Detection with Transformers](https://arxiv.org/pdf/2005.12872)

<span style="color: rgb(15, 17, 21)">DETR其实就是detection transformer的缩写，网上很多人都觉得这篇论文应该是ECCV20的最佳论文。而且也就是从20年5月到今年5月2年的时间，DETR的引用就已经超过了2000。而且它的官方代码也有将近9000个star。如果我们跟去年大火的clip相比，clip的官方代码到现在也只有8000 star，所以可见DETR的受欢迎程度。</span>

<span style="color: rgb(15, 17, 21)"></span>

<span style="color: rgb(15, 17, 21)">如果对目标检测了解不多的同学来说，可能并不能体会到这个端到端的意义究竟有多大。而事实上从深度学习开始火，一直到DETR目标检测领域里，都很少有端到端的方法。</span>

<span style="color: rgb(15, 17, 21)"></span>

<span style="color: rgb(15, 17, 21)">今天我们就来精读一下DETR这篇论文，看看大家为什么喜欢它。为什么大家说它是一个目标检测里的里程碑式的工作，而且为什么说它是一个全新的架构？文章的题目非常简单明了，就是end to end object detection with transformers。这篇文章的两个关键词，一个就是n to n这种端到端的目标检测，另外一个就是使用了最近大火的transworld来做目标检测。如果对目标检测了解不多的同学来说，可能并不能体会到这个端到端的意义究竟有多大。而事实上从深度学习开始火，一直到DETR目标检测领域里，都很少有端到端的方法。</span>

> 大部分方法至少最后还需要一个后处理的操作，也就是NMS这个操作，non maxim suppression非极大值一致。不论你是proposal base的方法，还是anchor r base的方法，还是non anchor base的方法，你最后都会生成很多的预测框。那如何去除这些冗余的框，就是NMS要做的事情。而因为有了NMS的存在，这个模型在调参上就比较复杂。而且即使训练好了一个模型，部署起来也非常困难。因为NMS这个操作不是所有硬件都支持的，所以说一个简单的端到端的目标检测系统是大家一直以来梦寐以求的。

<span style="color: rgb(15, 17, 21)"></span>

<span style="color: rgb(15, 17, 21)">而DETR就解决了以上说的这些痛点。它既不需要proposal，也不需要ancor，直接利用transformer这种能全局建模的能力，而把目标检测看成了一个集合预测的问题。而且也因为有了这种全局建模的能力，所以说第一条不会输出那么多冗余的框，它最后出什么结果就是什么结果，而不需要再用AMS去做这个后处理一下，就让模型的训练和部署都简单了不少。作者其实在他们的官方代码里也写到，他们的目的就是不想让大家一直觉得目标检测是一个比图像分类难很多的任务。他们其实都可以用一种简单的优雅的框架去把它做出来，而不像之前目标检测那些框架一样，需要很多的人工干预，需要很多的先验知识，而且还需要很多复杂的甚至普通的库，或者普通的硬件不支持的一些算子。</span>

<span style="color: rgb(15, 17, 21)"></span>

<span style="color: rgb(15, 17, 21)">Alexander可能对做CV的人来说也不陌生，他就是第一个提出全景分割这个任务的那就是panoptic segment。接下来他又做了panoptic FPN，后来又和凯明一起合作了pin的这篇论文，所以在分割领域里非常有经验。这也就难怪DETR在最后做了一个全景分割的实验和拓展。</span>

<span style="color: rgb(15, 17, 21)"></span>

<span style="color: rgb(15, 17, 21)">DETR提出了两个东西，一个就是提出了一个新的目标函数，就通过这种二分图匹配的方式，能够强制模型去输出一组独一无二的预测。意思就是说没有那么多冗余的框了，每个物体理想状态下它就会生成一个框。另外一个贡献就是使用了这种transformer encoder decoder的架构。</span>

<span style="color: rgb(15, 17, 21)">具体来说，还有两个小贡献，或者说有两个小细节是在这个transform ER encoder decoder这边的。一个就是在传former解码器的时候，我们还有另外一个输入，也就本文中说的这个learned object query。这个其实也有点类似于anchor的意思，我们接下来会细讲。总之在给定了这些object query之后，第一TR就可以把这个learn的object query和这个全局的图像信息结合在一起。通过不停的去做这种注意力操作，从而能够让模型直接输出最后的一组预测框。</span>
