目前我们自己手写的RPC框架的服务消费者支持以同步、异步和单向调用的方式与服务提供者进行数据交互，我还想让服务消费者支持回调方法，这点需求不过份吧？

### **一、前言**

> 这个框架已经支持了同步、异步和单向调用，但是我就是想让它再支持回调，说吧，能不能实现？

在前面的章节中，我们实现了RPC框架的服务消费者支持以同步、异步和单向调用的方式与服务提供者进行数据交互。具体的实现方式如下：

（1）同步调用：外部服务调用服务消费者向服务提供者发送数据的方法后，需要同步等待服务消费者返回的结果数据。

（2）异步调用：外部服务调用服务消费者向服务提供者发送数据的方法后，不需要同步等待服务消费者返回的结果数据，只需要从RpcContext上下文中获取到RPCFuture对象，调用RPCFuture对象的get()方法获取数据即可。

（3）单向调用：外部服务调用服务消费者向服务提供者发送数据的方法后，不必关心返回的结果数据。

除了这三种调用方式外，我们想想如何实现服务消费者的回调方法？

### **二、目标**

> 撸起袖子加油干，服务消费者就是要支持回调方法！

说的直白点回调方法就是调用方向被调用方发起请求，或者调用方调用被调用方的方法时，传入一个回调接口，当被调用方执行完业务逻辑后，会触发回调接口中方法的执行。

还是有点绕，这么说吧，比如服务A中的方法a调用服务B中的方法b，服务B中的方法b需要传入一个回调接口作为参数，在服务A的方法a中会创建回调接口的实例对象作为参数，传递给服务B中的方法b，服务B中方法b在执行完业务逻辑后，会调用回调接口的方法。此时，就会触发服务A的方法a中的回调接口实例对象实现的方法逻辑。

那RPC框架为何要实现回调方法呢？大家可以试想一个场景，在某些场景下，当服务消费者接收到服务提供者响应的结果数据后，需要立刻主动触发外部服务的某些方法，此时，就需要回调方法的支持。在外部服务中，调用服务消费者向服务提供者发送数据的方法后，不必关心服务消费者返回的结果数据，只需要处理好回调方法即可，服务消费者会通过回调方法将返回的结果数据传递给外部服务。

本章的目标就是实现服务消费者的回调方法。

#### **3.回调接口AsyncRPCCallback的实现**

AsyncRPCCallback接口位于bhrpc-consumer-common工程下的[io.binghe.rpc.consumer.common.callback.AsyncRPCCallback](http://io.binghe.rpc.consumer.common.callback.AsyncRPCCallback)，源码如下所示。

```go
public interface AsyncRPCCallback {
    /**
* 成功后的回调方法
*/
    void onSuccess(Object result);
    /**
* 异常的回调方法
*/
    void onException(Exception e);
}
```

可以看到，在AsyncRPCCallback接口中，定义了两个方法。其中onSuccess()方法就是成功返回数据触发的方法，onException()方法就是发生异常后触发的方法。

#### **4.新增服务消费者ClientThreadPool线程池类**

ClientThreadPool类位于bhrpc-common工程下的[io.binghe.rpc.common.threadpool.ClientThreadPool](http://io.binghe.rpc.common.threadpool.ClientThreadPool)，源码如下所示。

```go
public class ClientThreadPool {
    private static ThreadPoolExecutor threadPoolExecutor;
    static{
        threadPoolExecutor = new ThreadPoolExecutor(16, 16, 600L, TimeUnit.SECONDS, new ArrayBlockingQueue<Runnable>(65536));
    }
    public static void submit(Runnable task){
        threadPoolExecutor.submit(task);
    }
    public static void shutdown() {
        threadPoolExecutor.shutdown();
    }
}
```

可以看到，ClientThreadPool类的实现还是比较简单的。

#### **5.修改自定义Future类**

RPCFuture类位于bhrpc-consumer-common工程下的[io.binghe.rpc.consumer.common.future.RPCFuture](http://io.binghe.rpc.consumer.common.future.RPCFuture)，具体的修改步骤如下所示。

**（1）新增成员变量**

在RPCFuture类中新增pendingCallbacks成员变量和lock成员变量，源码如下所示。

```go
private List<AsyncRPCCallback> pendingCallbacks = new ArrayList<AsyncRPCCallback>();
private ReentrantLock lock = new ReentrantLock();
```

pendingCallbacks成员变量主要是存放回调接口，lock锁主要是添加和执行回调方法时，进行加锁和解锁操作。

**（2）新增回调相关的方法**

1. 新增runCallback()方法

runCallback()方法主要用于异步执行回调方法，源码如下所示。

```go
private void runCallback(final AsyncRPCCallback callback) {
    final RpcResponse res = this.responseRpcProtocol.getBody();
    ClientThreadPool.submit(() -> {
        if (!res.isError()) {
            callback.onSuccess(res.getResult());
        } else {
            callback.onException(new RuntimeException("Response error", new Throwable(res.getError())));
        }
    });
}
```

1. 新增addCallback()方法

addCallback()方法主要用于外部服务添加回调接口实例对象到pendingCallbacks集合中，源码如下所示。

```go
public RPCFuture addCallback(AsyncRPCCallback callback) {
    lock.lock();
    try {
        if (isDone()) {
            runCallback(callback);
        } else {
            this.pendingCallbacks.add(callback);
        }
    } finally {
        lock.unlock();
    }
    return this;
}
```

1. 新增invokeCallbacks()方法

invokeCallbacks()方法主要用于依次执行pendingCallbacks集合中回调接口的方法，源码如下所示。

```go
private void invokeCallbacks() {
    lock.lock();
    try {
        for (final AsyncRPCCallback callback : pendingCallbacks) {
            runCallback(callback);
        }
    } finally {
        lock.unlock();
    }
}
```

**（3）修改done()方法**

修改RPCFuture类中的done()方法，当唤醒线程时，执行invokeCallbacks()方法，以便服务消费者获取到服务提供者响应的结果数据后，立刻主动执行回调方法，源码如下所示。

```go
public void done(RpcProtocol<RpcResponse> responseRpcProtocol) {
    this.responseRpcProtocol = responseRpcProtocol;
    sync.release(1);
    //新增的调用invokeCallbacks()方法
    invokeCallbacks();
    // Threshold
    long responseTime = System.currentTimeMillis() - startTime;
    if (responseTime > this.responseTimeThreshold) {
        LOGGER.warn("Service response time is too slow. Request id = " + responseRpcProtocol.getHeader().getRequestId() + ". Response Time = " + responseTime + "ms");
    }
}
```

#### **6.修改服务消费者RpcConsumer类**

RpcConsumer类位于bhrpc-consumer-common工程下的[io.binghe.rpc.consumer.common.RpcConsumer](http://io.binghe.rpc.consumer.common.RpcConsumer)，主要是修改RpcConsumer类的close()方法，当关闭服务消费者的Netty服务时，一起关闭服务消费者的线程池，源码如下所示。

```go
public void close(){
```

```go
public static void main(String[] args) throws Exception {
    RpcConsumer consumer = RpcConsumer.getInstance();
    RPCFuture rpcFuture = consumer.sendRequest(getRpcRequestProtocol());
    rpcFuture.addCallback(new AsyncRPCCallback() {
        @Override
        public void onSuccess(Object result) {
            LOGGER.info("从服务消费者获取到的数据===>>>" + result);
        }
        @Override
        public void onException(Exception e) {
            LOGGER.info("抛出了异常===>>>" + e);
        }
    });
    Thread.sleep(200);
    consumer.close();
}
```

可以看到，当调用consumer的sendRequest()方法后，返回RPCFuture对象，并没有通过RPCFuture对象来获取数据，而是通过RPCFuture对象的addCallback()方法添加了一个回调接口实例。这里，使用的是匿名内部类的形式，其中AsyncRPCCallback接口实例对象的onSuccess()方法表示RPC调用成功后会回调的方法，onException()方法表示RPC调用异常或失败时回调的方法。

为了避免服务消费者与服务提供者正在进行数据交互的过程中，服务消费者断开连接。在调用consumer的close()方法关闭服务消费者中Netty服务之前，使线程休眠200毫秒。
