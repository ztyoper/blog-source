### **一、前言**

> 服务消费者可以整合数据缓冲吗？

在前面的文章中，实现了服务提供者整合数据缓冲。那服务消费者需要整合数据缓冲吗？其实，服务消费者也是很有必要的。

### **二、目标**

> 目标很明确：服务消费者整合数据缓冲！

在我们实现的RPC框架中，服务消费者其实是可以通过@RpcReference注解与多个服务提供者进行连接，在这种情况下，服务消费者就很有可能并发收到多个服务提供者响应的结果数据。

为了保证服务消费者的稳定性，需要在服务消费者端支持数据缓冲。

由图105-1可以看出如下信息：

（1）服务提供者会通过自定义类扫描器整合注册中心，将服务注册到注册中心。

（2）服务注册到注册中心的元数据，例如服务的名称、服务的版本号、服务地址、服务端口和服务分组等信息，元数据会贯穿整个服务的注册与发现流程。

（3）服务注册与发现SPI接口对外提供服务注册与发现的方法，服务提供者通过自定义扫描器会调用服务注册与发现SPI接口的方法实现服务注册功能。

#### **3.修改RpcConsumerHandler类**

RpcConsumerHandler类的源码详见：bhrpc-consumer-common工程下的[io.binghe.rpc.consumer.common.handler.RpcConsumerHandler](http://io.binghe.rpc.consumer.common.handler.RpcConsumerHandler)，具体修改步骤如下所示。

**（1）新增成员变量**

在RpcConsumerHandler类中，新增enableBuffer和bufferCacheManager成员变量，enableBuffer表示是否开启数据缓冲，bufferCacheManager表示数据缓冲管理器，如下所示。

```go
private boolean enableBuffer;
private BufferCacheManager<RpcProtocol<RpcResponse>> bufferCacheManager;
```

**（2）修改构造方法**

在RpcConsumerHandler类的构造方法中新增enableBuffer和bufferSize参数，enableBuffer表示是否开启数据缓冲，bufferSize表示缓冲区大小，并且在构造方法中为成员变量enableBuffer赋值，当enableBuffer为true时，创建bufferCacheManager对象，并且在单独的线程池中消费缓冲区中的数据，进行处理，如下所示。

```go
public RpcConsumerHandler(boolean enableBuffer, int bufferSize, ConcurrentThreadPool concurrentThreadPool){
    this.concurrentThreadPool = concurrentThreadPool;
    this.enableBuffer = enableBuffer;
    if (enableBuffer){
        this.bufferCacheManager = BufferCacheManager.getInstance(bufferSize);
        BufferCacheThreadPool.submit(() -> {
            consumerBufferCache();
        });
    }
}
```

**（3）新增consumerBufferCache()方法**

consumerBufferCache()方法的主要作用就是不断消费缓冲区中的数据，调用handlerResponseMessage()方法进行处理，如下所示。

```go
private void consumerBufferCache() {
    //不断消息缓冲区的数据
    while (true){
        RpcProtocol<RpcResponse> protocol = this.bufferCacheManager.take();
        if (protocol != null){
            this.handlerResponseMessage(protocol);
        }
    }
}
```

**（4）新增handlerResponseMessageOrBuffer()方法**

handlerResponseMessageOrBuffer()方法的主要作用就是根据enableBuffer的值进行不同的处理逻辑，当enableBuffer的值为true时，会将数据放入缓冲区，当enableBuffer的值为false时，调用handlerResponseMessage()方法，如下所示。

```go
private void handlerResponseMessageOrBuffer(RpcProtocol<RpcResponse> protocol){
    if (enableBuffer){
        logger.info("enable buffer...");
        this.bufferCacheManager.put(protocol);
    }else {
        this.handlerResponseMessage(protocol);
    }
}
```

**（5）新增handlerMessage()方法**

handlerMessage()方法是从channelRead0()方法里抽出来的业务，如下所示。

```go
private void handlerMessage(RpcProtocol<RpcResponse> protocol, Channel channel){
    RpcHeader header = protocol.getHeader();
    //服务提供者响应的心跳消息
    if (header.getMsgType() == (byte) RpcType.HEARTBEAT_TO_CONSUMER.getType()){
        this.handlerHeartbeatMessageToConsumer(protocol, channel);
    }else if (header.getMsgType() == (byte) RpcType.HEARTBEAT_FROM_PROVIDER.getType()){
        this.handlerHeartbeatMessageFromProvider(protocol, channel);
    }else if (header.getMsgType() == (byte) RpcType.RESPONSE.getType()){ //响应消息
        this.handlerResponseMessageOrBuffer(protocol);
    }
}
```

**（6）修改channelRead0()方法**

在channelRead0()方法中使用concurrentThreadPool线程池异步执行handlerMessage()方法，如下所示。

```go
@Override
protected void channelRead0(ChannelHandlerContext ctx, RpcProtocol<RpcResponse> protocol) throws Exception {
    if (protocol == null){
        return;
    }
    concurrentThreadPool.submit(() -> {
        this.handlerMessage(protocol, ctx.channel());
    });
}
```
