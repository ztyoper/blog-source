### **一、前言**

> 服务提供者可以整合数据缓冲吗？

在高并发、大流量的业务场景下，服务提供者会并发收到大量的请求，如果同时调用的请求量过大，就会造成服务提供者卡顿，有时甚至会出现丢失请求的情况，所以，需要对在服务提供者端整合数据缓冲来缓解服务提供者的压力。

### **二、目标**

> 目标很明确：服务提供者整合数据缓冲！

服务提供者作为RPC框架最为核心的模块之一，其稳定性直接决定着整个RPC框架的可靠性。在前面的文章中，我们实现了数据缓冲的基础模型设计。本章，我们就一起实现服务提供者整合数据缓冲的功能。

（2）服务注册到注册中心的元数据，例如服务的名称、服务的版本号、服务地址、服务端口和服务分组等信息，元数据会贯穿整个服务的注册与发现流程。

#### **3.修改RpcProviderHandler类**

RpcProviderHandler类的源码详见：bhrpc-provider-common工程下的[io.binghe.rpc.provider.common.handler.RpcProviderHandler](http://io.binghe.rpc.provider.common.handler.RpcProviderHandler)，主要的修改步骤如下所示。

**（1）添加成员变量**

在RpcProviderHandler类中添加bufferCacheManager和enableBuffer成员变量，bufferCacheManager表示缓冲管理器对象，enableBuffer表示是否开启缓冲的标识，如下所示。

```go
private boolean enableBuffer;
private BufferCacheManager<BufferObject<RpcRequest>> bufferCacheManager;
```

**（2）修改构造方法**

在RpcProviderHandler类的构造方法中，新增enableBuffer和bufferSize参数，enableBuffer表示是否开启数据缓冲，bufferSize表示缓冲区大小。在RpcProviderHandler类的构造方法中为enableBuffer成员变量赋值。如果enableBuffer的值为true，则创建bufferCacheManager对象，同时使用单独的线程池消费缓冲区的数据，如下所示。

```go
public RpcProviderHandler(/**省略其他代码**/ boolean enableBuffer, int bufferSize){
    //###########省略其他代码#############
    this.enableBuffer = enableBuffer;
    //开启缓冲
    if (enableBuffer){
        logger.info("enable buffer...");
        bufferCacheManager = BufferCacheManager.getInstance(bufferSize);
        BufferCacheThreadPool.submit(() -> {
            consumerBufferCache();
        });
    }
}
```

**（3）新增consumerBufferCache()方法**

在RpcProviderHandler类中新增consumerBufferCache()方法，consumerBufferCache()方法的作用主要是在while(true)循环中消费缓冲区的数据，并调用带有缓存的调用真实方法的方法获取结果，并将结果响应给服务消费者，如下所示。

```go
private void consumerBufferCache(){
    //不断消息缓冲区的数据
    while (true){
        BufferObject<RpcRequest> bufferObject = this.bufferCacheManager.take();
        if (bufferObject != null){
            ChannelHandlerContext ctx = bufferObject.getCtx();
            RpcProtocol<RpcRequest> protocol = bufferObject.getProtocol();
            RpcHeader header = protocol.getHeader();
            RpcProtocol<RpcResponse> responseRpcProtocol = handlerRequestMessageWithCache(protocol, header);
            this.writeAndFlush(header.getRequestId(), ctx, responseRpcProtocol);
        }
    }
}
```

**（4）新增writeAndFlush()方法**

在RpcProviderHandler类中新增writeAndFlush()方法，writeAndFlush()方法的作用就是接收参数，直接向服务消费者响应结果，如下所示。

```go
private void writeAndFlush(long requestId, ChannelHandlerContext ctx,  RpcProtocol<RpcResponse> responseRpcProtocol){
    ctx.writeAndFlush(responseRpcProtocol).addListener(new ChannelFutureListener() {
        @Override
        public void operationComplete(ChannelFuture channelFuture) throws Exception {
            logger.debug("Send response for request " + requestId);
        }
    });
}
```

**（5）新增submitRequest()方法**

submitRequest()方法的主要作用就是当未开启数据缓冲时，执行submitRequest()方法的逻辑，submitRequest()方法的代码如下所示。

```go
private void submitRequest(ChannelHandlerContext ctx, RpcProtocol<RpcRequest> protocol) {
    RpcProtocol<RpcResponse> responseRpcProtocol = handlerMessage(protocol, ctx.channel());
    writeAndFlush(protocol.getHeader().getRequestId(), ctx, responseRpcProtocol);
}
```

**（6）新增bufferRequest()方法**

bufferRequest()方法的主要作用就是当开启数据缓冲时，执行bufferRequest()方法的逻辑，bufferRequest()的代码如下所示。

```go
private void bufferRequest(ChannelHandlerContext ctx, RpcProtocol<RpcRequest> protocol) {
    RpcHeader header = protocol.getHeader();
    //接收到服务消费者发送的心跳消息
    if (header.getMsgType() == (byte) RpcType.HEARTBEAT_FROM_CONSUMER.getType()){
        RpcProtocol<RpcResponse> responseRpcProtocol = handlerHeartbeatMessageFromConsumer(protocol, header);
        this.writeAndFlush(protocol.getHeader().getRequestId(), ctx, responseRpcProtocol);
    }else if (header.getMsgType() == (byte) RpcType.HEARTBEAT_TO_PROVIDER.getType()){  //接收到服务消费者响应的心跳消息
        handlerHeartbeatMessageToProvider(protocol, ctx.channel());
    }else if (header.getMsgType() == (byte) RpcType.REQUEST.getType()){ //请求消息
        this.bufferCacheManager.put(new BufferObject<>(ctx, protocol));
    }
}
```

可以看到，当开启数据缓冲时，检测到时请求类型的数据，会将请求类型的数据放入缓冲区。随后就会在consumerBufferCache()方法中消费到。

**（7）修改channelRead0()方法**

在channelRead0()方法中，首先更新连接信息，然后判断enableBuffer的值，如果enableBuffer的值为true，则调用bufferRequest()方法执行逻辑，如果enableBuffer的值为false，则调用submitRequest()方法执行逻辑，如下所示。

```go
@Override
protected void channelRead0(ChannelHandlerContext ctx, RpcProtocol<RpcRequest> protocol) throws Exception {
    concurrentThreadPool.submit(() -> {
        connectionManager.update(ctx.channel());
        if (enableBuffer){  //开启队列缓冲
            this.bufferRequest(ctx, protocol);
        }else{  //未开启队列缓冲
            this.submitRequest(ctx, protocol);
        }
    });
}
```
