### **三、目标**

> 目标很明确：当服务提供者采用asm反射机制调用真实方法时，需要支持容错处理！

在服务提供者采用asm反射机制调用真实方法时，由于某种原因，RPC框架并没有执行容错处理逻辑，本章，我们的目标就是需要RPC框架在服务提供者采用asm反射机制调用真实方法时，支持容错处理。

### **四、实现**

> 说了这么多，改怎么实现呢？

#### **1.问题定位**

根据服务提供者输出的日志信息，我们可以定位到异常是在bhrpc-reflect-asm工程下的[io.binghe.rpc.reflect.asm.AsmReflectInvoker](http://io.binghe.rpc.reflect.asm.AsmReflectInvoker)类中的getInvocationHandler()方法中抛出的。更精准的说是在getInvocationHandler()方法中的如下一行代码抛出的。

```go
Object result = method.invoke(obj, args);
```

此时，就有一个很奇怪的现象：在AsmReflectInvoker类中，是invokeMethod()方法调用了getInvocationHandler()方法中，而getInvocationHandler()方法，抛出了异常，但是invokeMethod()方法却并没有向上抛出异常。也就是说，invokeMethod()方法并没有感知到getInvocationHandler()方法的异常，这要怎么处理呢？

#### **2.问题分析**

既然invokeMethod()方法无法感知到getInvocationHandler()方法的异常，那可不可以定义一个boolean类型的全局标识，首先在invokeMethod()方法中将这个标识设置为false。接下来，在getInvocationHandler()方法中捕获抛出的异常，当捕获到异常时，说明程序抛出了异常，将这个全局标识设置为true。

当invokeMethod()方法感知到这个boolean类型的标识为true时，说明程序抛出了异常，则手动在invokeMethod()方法中向上抛出异常，使RPC框架执行容错处理。

处于线程安全的角度考虑，可以将这个boolean类型的标识存入ThreadLocal中，此时，就需要防止ThreadLocal出现内存泄露的问题。

#### **3.问题解决**

按照分析的结果对bhrpc-reflect-asm工程下的[io.binghe.rpc.reflect.asm.AsmReflectInvoker](http://io.binghe.rpc.reflect.asm.AsmReflectInvoker)类进行改造，改造后的代码如下所示。

```go
@SPIClass
public class AsmReflectInvoker implements ReflectInvoker {
​
    private final Logger logger = LoggerFactory.getLogger(AsmReflectInvoker.class);
    private final ThreadLocal<Boolean> exceptionThreadLocal = new ThreadLocal<>();
​
    @Override
    public Object invokeMethod(Object serviceBean, Class<?> serviceClass, String methodName, Class<?>[] parameterTypes, Object[] parameters) throws Throwable {
        logger.info("use asm reflect type invoke method..."  + Thread.currentThread().getName());
        exceptionThreadLocal.set(false);
        Object result = null;
        try{
            Constructor<?> constructor = serviceClass.getConstructor(new Class[]{});
            Object[] constructorParam = new Object[]{};
            Object instance = ReflectProxy.newProxyInstance(AsmReflectInvoker.class.getClassLoader(), getInvocationHandler(serviceBean), serviceClass, constructor, constructorParam);
            Method method = serviceClass.getMethod(methodName, parameterTypes);
            method.setAccessible(true);
            result = method.invoke(instance, parameters);
            if (exceptionThreadLocal.get()){
                throw new RuntimeException("rpc provider throws exception...");
            }
        }finally {
            exceptionThreadLocal.remove();
        }
        return result;
    }
​
    private InvocationHandler getInvocationHandler(Object obj){
        return (proxy, method, args) -> {
            logger.info("use proxy invoke method..." + Thread.currentThread().getName());
            method.setAccessible(true);
            Object result = null;
            try{
                result = method.invoke(obj, args);
            }catch (Exception e){
                exceptionThreadLocal.set(true);
            }
            return result;
        };
    }
}
```

整体代码逻辑比较简单，这个不再赘述。另外，需要注意的是：使用完ThreadLocal中的数据时，需要及时清除ThreadLocal中使用完毕的数据，以免ThreadLocal出现内存遗漏的问题。
