### **一、前言**

> 什么是数据缓冲呢？

数据缓冲和数据缓存其实是有一定的区别的，数据缓存更侧重于数据的读操作，当频繁读取相同的数据时，就可以将数据缓存到系统内存里，提高数据读取的性能。而数据缓冲更加侧重于数据的写操作，当存在大量写操作时，可能由于要写入的目标系统或者设备存在性能瓶颈而导致写操作性能低下，此时就可以引入数据缓冲，先将数据写入缓冲区，然后再有单独的线程从缓冲区中获取数据写入目标系统或者设备。

### **二、目标**

> 目标很明确：实现数据缓冲基础模型设计！

如果在高并发、大流量的业务场景下，服务提供者会并发收到大量的请求，如果同时调用的请求量过大，就会造成服务提供者卡顿，有时甚至会出现丢失请求的情况。服务消费者也是如此，当并发接收到大量服务提供者返回的结果数据时，也可以使用数据缓冲增强稳定性。

本章，我们就一些实现数据缓冲基础模型设计。

#### **4.新增BufferCacheManager类**

BufferCacheManager类的源码详见：[io.binghe.rpc.buffer.cache.BufferCacheManager](http://io.binghe.rpc.buffer.cache.BufferCacheManager)，BufferCacheManager类是一个单例类，主要是封装了向队列中添加和移除队列中数据的方法。也就是说，数据的缓冲操作主要是将数据放入队列，由另外的线程监听队列中是否存在数据，如果存在数据，则取出数据进行操作，如下所示。

```go
public class BufferCacheManager<T> {
    //缓冲队列
    private BlockingQueue<T> bufferQueue;
    //缓存管理器单例对象
    private static volatile BufferCacheManager instance;
    //私有构造方法
    private BufferCacheManager(int bufferSize){
        if (bufferSize <= 0){
            bufferSize = RpcConstants.DEFAULT_BUFFER_SIZE;
        }
        this.bufferQueue = new ArrayBlockingQueue<>(bufferSize);
    }
    //创建单例对象
    public static <T> BufferCacheManager<T> getInstance(int bufferSize){
        if (instance == null){
            synchronized (BufferCacheManager.class){
                if (instance == null){
                    instance = new BufferCacheManager(bufferSize);
                }
            }
        }
        return instance;
    }
    //向缓冲区添加元素
    public void put(T t){
        try {
            bufferQueue.put(t);
        } catch (InterruptedException e) {
            throw new RpcException(e);
        }
    }
    //获取缓冲区元素
    public T take(){
        try {
            return bufferQueue.take();
        } catch (InterruptedException e) {
            throw new RpcException(e);
        }
    }
}
```
