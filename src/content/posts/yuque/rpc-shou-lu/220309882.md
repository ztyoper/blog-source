#### **3.新增反射实现类CglibReflectInvoker**

CglibReflectInvoker类位于bhrpc-reflect-cglib工程下的[io.binghe.rpc.reflect.cglib.CglibReflectInvoker](http://io.binghe.rpc.reflect.cglib.CglibReflectInvoker)，主要的作用就是实现基于CGLib反射机制调用真实方法，源码如下所示。

```go
@SPIClass
public class CglibReflectInvoker implements ReflectInvoker {
    private final Logger logger = LoggerFactory.getLogger(CglibReflectInvoker.class);
    @Override
    public Object invokeMethod(Object serviceBean, Class<?> serviceClass, String methodName, Class<?>[] parameterTypes, Object[] parameters) throws Throwable {
        logger.info("use cglib reflect type invoke method...");
        FastClass serviceFastClass = FastClass.create(serviceClass);
        FastMethod serviceFastMethod = serviceFastClass.getMethod(methodName, parameterTypes);
        return serviceFastMethod.invoke(serviceBean, parameters);
    }
}
```

#### **4.添加配置文件**

在bhrpc-reflect-cglib工程下的resources目录下新建META-INF/binghe/internal 目录，在META-INF/binghe/internal 目录下新建[io.binghe.rpc.reflect.api.ReflectInvoker](http://io.binghe.rpc.reflect.api.ReflectInvoker)文件，并在[io.binghe.rpc.reflect.api.ReflectInvoker](http://io.binghe.rpc.reflect.api.ReflectInvoker)文件中添加如下代码。

```go
cglib=io.binghe.rpc.reflect.cglib.CglibReflectInvoker
```

#### **5.添加工程依赖**

### **六、总结**

> 实现了功能不总结下怎么行？

在前面的文章中，我们一起使用SPI扩展了RPC框架的序列化与反序列化功能，并且基于SPI扩展了RPC框架的动态代理功能，使其具备高度的可扩展性。如果大家觉得RPC框架目前内置的序列化与反序列化功能和动态代理功能不能满足实际需求，大家还可以根据SPI的扩展机制，自行进行扩展实现。

随后，我们基于SPI扩展实现了通过JDK反射机制调用真实方法的功能。本章，我们进一步对服务提供者调用真实方法的功能进行SPI扩展，并基于SPI扩展实现了通过CGLib反射机制调用真实方法的功能。
