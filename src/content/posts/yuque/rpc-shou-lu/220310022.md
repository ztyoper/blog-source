### **一、前言**

> 完成了结果缓存的通用模型设计，我想让服务提供者支持结果缓存！

RPC框架作为分布式系统底层通信的基础设施框架，其性能的高低直接影响着整体系统的性能水平，如果每次发起RPC调用时，都完整走一遍RPC的调用流程，会极大的影响RPC框架的性能，进而影响整个分布式系统的性能。

尤其是在大规模分布式系统场景下，RPC框架的服务提供者会承担高并发大流量的场景，如果每次接收到服务消费者发送过来的参数，尤其是频繁接收相同的参数时，都去调用真实方法来处理数据，那在一定程度上，RPC框架的性能就会受限于业务系统的方法。我们需要将RPC框架的性能尽量做到与业务方法无关.

所以，在服务提供者端，需要支持结果缓存。

### **二、目标**

> 目标很明确：服务提供者支持结果缓存！

RPC框架的性能除了在网络通信协议的设计、编解码的设计、传输数据的大小等等多个方面需要考虑外，在RPC框架中使用缓存也能在一定程度上提升RPC框架的处理性能。

上一章，我们已经实现了结果缓存的通用模型设计，本章，就一起实现服务提供者支持结果缓存的功能。

#### **3.修改消息处理器类RpcProviderHandler**

RpcProviderHandler类的源码详见：bhrpc-provider-common工程下的[io.binghe.rpc.provider.common.handler.RpcProviderHandler](http://io.binghe.rpc.provider.common.handler.RpcProviderHandler)，主要的修改步骤如下所示。

**（1）新增成员变量**

在RpcProviderHandler类中，新增是否启用结果缓存的成员变量enableResultCache和结果缓存管理器cacheResultManager，如下所示。

```go
private final boolean enableResultCache;
private final CacheResultManager<RpcProtocol<RpcResponse>> cacheResultManager;
```

可以看到，enableResultCache成员变量是boolean类型，表示是否开启结果缓存，true表示开启，false表示不开启。如果enableResultCache成员变量的值为true，则会通过cacheResultManager管理缓存数据。

**（2）修改构造方法**

在RpcProviderHandler类的构造方法中新增表示是否开启结果缓存的参数enableResultCache和表示缓存数据时长的参数resultCacheExpire，并且在构造方法中为成员变量enableResultCache和cacheResultManager赋值，如下所示。

```go
public RpcProviderHandler(String reflectType, boolean enableResultCache, int resultCacheExpire, Map<String, Object> handlerMap){
    //#############省略其他代码###############
    if (resultCacheExpire <= 0){
        resultCacheExpire = RpcConstants.RPC_SCAN_RESULT_CACHE_EXPIRE;
    }
    this.cacheResultManager = CacheResultManager.getInstance(resultCacheExpire, enableResultCache);
}
```

**（3）新增handlerRequestMessageCache()方法**

在RpcProviderHandler类中新增handlerRequestMessageCache()方法，主要的作用就是通过缓存来处理服务提供者调用真实方法获取到的结果数据。主要的逻辑就是先从缓存中获取结果数据，如果缓存中存在对应的结果数据，则直接返回结果数据。如果缓存中不存在结果数据，则服务提供者调用真实方法，将真实方法返回的结果存入缓存，并返回结果。源码如下所示。

```go
private RpcProtocol<RpcResponse> handlerRequestMessageCache(RpcProtocol<RpcRequest> protocol, RpcHeader header) {
    RpcRequest request = protocol.getBody();
    CacheResultKey cacheKey = new CacheResultKey(request.getClassName(), request.getMethodName(), request.getParameterTypes(), request.getParameters(), request.getVersion(), request.getGroup());
    RpcProtocol<RpcResponse> responseRpcProtocol = cacheResultManager.get(cacheKey);
    if (responseRpcProtocol == null){
        responseRpcProtocol = handlerRequestMessage(protocol, header);
        //设置保存的时间
        cacheKey.setCacheTimeStamp(System.currentTimeMillis());
        cacheResultManager.put(cacheKey, responseRpcProtocol);
    }
    responseRpcProtocol.setHeader(header);
    return responseRpcProtocol;
}
```

**（4）新增handlerRequestMessageWithCache()方法**

在RpcProviderHandler类中新增handlerRequestMessageCache()方法，主要的作用就是根据成员变量enableResultCache的值来处理结果数据，如果enableResultCache的值为true，则调用handlerRequestMessageCache()方法处理结果数据，如果enableResultCache的值为false，则调用handlerRequestMessage()方法处理结果数据。源码如下所示。

```go
private RpcProtocol<RpcResponse> handlerRequestMessageWithCache(RpcProtocol<RpcRequest> protocol, RpcHeader header){
    header.setMsgType((byte) RpcType.RESPONSE.getType());
    if (enableResultCache) return handlerRequestMessageCache(protocol, header);
    return handlerRequestMessage(protocol, header);
}
```

可以看到，在handlerRequestMessageWithCache()方法中，首先将Header中的msgType设置为RpcType.RESPONSE，表示响应消息。

**（5）修改handlerRequestMessage()方法**

去除handlerRequestMessage()方法中开头的如下代码。

```go
header.setMsgType((byte) RpcType.RESPONSE.getType());
```

**（6）修改handlerMessage()方法**

当handlerMessage()方法中检测到Header中的消息类型为RpcType.REQUEST时，调用handlerRequestMessageWithCache()方法来获取结果数据，源码如下所示。

```go
private RpcProtocol<RpcResponse> handlerMessage(RpcProtocol<RpcRequest> protocol, Channel channel){
    RpcProtocol<RpcResponse> responseRpcProtocol = null;
    RpcHeader header = protocol.getHeader();
    //#############省略其他代码###############
    }else if (header.getMsgType() == (byte) RpcType.REQUEST.getType()){ //请求消息
        responseRpcProtocol = handlerRequestMessageWithCache(protocol, header);
    }
    return responseRpcProtocol;
}
```
