## <span style="color: #333333">一、MyBatis简介</span>

### <span style="color: #333333">1、MyBatis历史</span>

<span style="color: #333333">MyBatis最初是Apache的一个开源项目</span>**<span style="color: #333333">iBatis</span>**<span style="color: #333333">, 2010年6月这个项目由Apache Software Foundation迁移到了Google Code。随着开发团队转投Google Code旗下， iBatis3.x正式更名为MyBatis。代码于2013年11月迁移到Github。</span>

<span style="color: #333333">iBatis一词来源于“internet”和“abatis”的组合，是一个基于Java的持久层框架。 iBatis提供的持久层框架包括SQL Maps和Data Access Objects（DAO）。</span>

### <span style="color: #333333">2、MyBatis特性</span>

1. MyBatis 是支持定制化 SQL、存储过程以及高级映射的优秀的持久层框架
2. MyBatis 避免了几乎所有的 JDBC 代码和手动设置参数以及获取结果集
3. MyBatis可以使用简单的XML或注解用于配置和原始映射，将接口和Java的POJO（Plain Old Java Objects，普通的Java对象）映射成数据库中的记录
4. MyBatis 是一个 半自动的ORM（Object Relation Mapping）框架

### <span style="color: #333333">4、和其它持久化层技术对比</span>

<span style="color: #333333">JDBC</span>

<span style="color: #333333">SQL 夹杂在Java代码中耦合度高，导致硬编码内伤</span>

<span style="color: #333333">维护不易且实际开发需求中 SQL 有变化，频繁修改的情况多见代码冗长，开发效率低</span>

<span style="color: #333333">Hibernate 和 JPA</span>

<span style="color: #333333">操作简便，开发效率高</span>

<span style="color: #333333">程序中的长难复杂 SQL 需要绕过框架</span>

<span style="color: #333333">内部自动生产的 SQL，不容易做特殊优化</span>

<span style="color: #333333">基于全映射的全自动框架，大量字段的 POJO 进行部分映射时比较困难。反射操作太多，导致数据库性能下降</span>

<span style="color: #333333">轻量级，性能出色</span>

<span style="color: #333333">MyBatis</span>

<span style="color: #333333">SQL 和 Java 编码分开，功能边界清晰。Java代码专注业务、SQL语句专注数据开发效率稍逊于HIbernate，但是完全能够接受</span>

<span style="color: #777777">核心配置文件主要用于配置连接数据库的环境以及MyBatis的全局配置信息</span>

```xml
PUBLIC "-//mybatis.org//DTD Config 3.0//EN" "http://mybatis.org/dtd/mybatis-3-config.dtd">
<configuration>
  <!--设置连接数据库的环境-->
  <environments default="development">
    <environment id="development">
      <transactionManager type="JDBC"/>
      <dataSource type="POOLED">
        <property name="driver" value="com.mysql.jdbc.Driver"/>
        <property name="url" value="jdbc:mysql://localhost:3306/MyBatis"/>
        <property name="username" value="root"/>

  </environments>
  <!--引入映射文件-->

  </mappers>

```

<span style="color: #333333">关系：关系型数据库</span>

<span style="color: #333333">映射：二者之间的对应关系</span>

<span style="color: #777777">1、映射文件的命名规则：</span>

<span style="color: #777777">表所对应的实体类的类名+Mapper.xml</span>

<span style="color: #777777">例如：表t_user，映射的实体类为User，所对应的映射文件为UserMapper.xml 因此一个映射文件对应一个实体类，对应一张表的操作</span>

<span style="color: #777777">MyBatis映射文件用于编写SQL，访问以及操作表中的数据</span>

<span style="color: #777777">MyBatis映射文件存放的位置是src/main/resources/mappers目录下</span>

<span style="color: #777777">2、MyBatis中可以面向接口操作数据，要保证两个一致：</span>

<span style="color: #777777">a&gt;mapper接口的全类名和映射文件的命名空间（namespace）保持一致</span>

<span style="color: #777777">b&gt;mapper接口中方法的方法名和映射文件中编写SQL的标签的id属性保持一致</span>

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper
PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.atguigu.mybatis.mapper.UserMapper">

<!--int insertUser();-->
<insert id="insertUser">
insert into t_user values(null,'张三','123',23,'女')
</insert>

</mapper>
```

### <span style="color: #333333">6、通过junit测试功能</span>

```java
//读取MyBatis的核心配置文件
InputStream is = Resources.getResourceAsStream("mybatis-config.xml");
//创建SqlSessionFactoryBuilder对象SqlSessionFactoryBuilder sqlSessionFactoryBuilder = new SqlSessionFactoryBuilder();
//通过核心配置文件所对应的字节输入流创建工厂类SqlSessionFactory，生产SqlSession对象
SqlSessionFactory sqlSessionFactory = sqlSessionFactoryBuilder.build(is);
//创建SqlSession对象，此时通过SqlSession对象所操作的sql都必须手动提交或回滚事务
//SqlSession sqlSession = sqlSessionFactory.openSession();
//创建SqlSession对象，此时通过SqlSession对象所操作的sql都会自动提交SqlSession sqlSession = sqlSessionFactory.openSession(true);
//通过代理模式创建UserMapper接口的代理实现类对象
/**"mybatis-config.xml"中是数据库相关信息和映射的xml文件，xml文件又关联Mapper接口类*/
UserMapper userMapper = sqlSession.getMapper(UserMapper.class);
//调用UserMapper接口中的方法，就可以根据UserMapper的全类名匹配元素文件，通过调用的方法名匹配 
    映射文件中的SQL标签，并执行标签中的SQL语句
int result = userMapper.insertUser();
//sqlSession.commit();
System.out.println("结果："+result);
```

<span style="color: #777777">SqlSession：代表Java程序和</span>**<span style="color: #777777">数据库</span>**<span style="color: #777777">之间的</span>**<span style="color: #777777">会话</span>**<span style="color: #777777">。（HttpSession是Java程序和浏览器之间的 会话）</span>

<span style="color: #777777">SqlSessionFactory：是“生产”SqlSession的“工厂”。</span>

<span style="color: #777777">工厂模式：如果创建某一个对象，使用的过程基本固定，那么我们就可以把创建这个对象的 相关代码封装到一个“工厂类”中，以后都使用这个工厂类来“生产”我们需要的对象。</span>

```xml
    <setting name="lazyLoadingEnabled" value="true"/>
  </settings>

  <typeAliases>
    <!--
    写typeAlias：设置某个具体的类型的别名属性：
    type：需要设置别名的类型的全类名
    alias：设置此类型的别名，若不设置此属性，该类型拥有默认的别名，即类名且不区分大小
    若设置此属性，此时该类型的别名只能使用alias所设置的值
    -->

    <!--<typeAlias type="com.atguigu.mybatis.bean.User"></typeAlias>-->
    <!--<typeAlias type="com.atguigu.mybatis.bean.User" alias="abc">
    
    <!--以包为单位，设置改包下所有的类型都拥有默认的别名，即类名且不区分大小写-->
    <package name="com.atguigu.mybatis.bean"/>
  </typeAliases>

  <!--
  environments：设置多个连接数据库的环境属性：
  default：设置默认使用的环境的id
  -->

  <environments default="mysql_test">
    <!--
    environment：设置具体的连接数据库的环境信息属性：
    id：设置环境的唯一标识，可通过environments标签中的default设置某一个环境的id，  表示默认使用的环境
    -->
    <environment id="mysql_test">
      <!--
      transactionManager：设置事务管理方式属性：

      type： 设 置 事 务 管 理 方 式 ，type="JDBC|MANAGED" type="JDBC"：设置当前环境的事务管理都必须手动处理;type="MANAGED"：设置事务被管理，例如spring中的AOP

      -->
      <transactionManager type="JDBC"/>
      <!--
      dataSource：设置数据源属性：
      type： 设 置 数 据 源 的 类 型 ，type="POOLED|UNPOOLED|JNDI" type="POOLED"：使用数据库连接池，即会将创建的连接进行缓存，下次使用可以从
      缓存中直接获取，不需要重新创建
      type="UNPOOLED"：不使用数据库连接池，即每次使用连接都需要重新创建;type="JNDI"：调用上下文中的数据源
      -->
      <dataSource type="POOLED">
        <!--设置驱动类的全类名-->
        <property name="driver" value="${jdbc.driver}"/>
        <!--设置连接数据库的连接地址-->
        <property name="url" value="${jdbc.url}"/>
        <!--设置连接数据库的用户名-->
        <property name="username" value="${jdbc.username}"/>
        <!--设置连接数据库的密码-->
        <property name="password" value="${jdbc.password}"/>
      </dataSource>
    </environment>
  </environments>
  <!--引入映射文件-->
  <mappers>
    <mapper resource="UserMapper.xml"/>
    <!--
    以包为单位，将包下所有的映射文件引入核心配置文件
    注意：此方式必须保证mapper接口和mapper映射文件必须在相同的包下
    -->
    <package name="com.atguigu.mybatis.mapper"/>
  </mappers>
</configuration>
```

## <span style="color: #333333">五、MyBatis获取参数值的两种方式（重点）</span>

<span style="color: #333333">My</span><span style="color: #333333">Batis获取参数值的两种方式：</span>**<span style="color: #333333">${}</span>**<span style="color: #333333">和</span>**<span style="color: #333333">#{}</span>**

<span style="color: #333333">${}的本质就是字符串拼接，#{}的本质就是占位符赋值</span>

<span style="color: #333333">${}使用字符串拼接的方式拼接sql，若为字符串类型或日期类型的字段进行赋值时，需要手动加单引 号；但是#{}使用占位符赋值的方式拼接sql，此时为字符串类型或日期类型的字段进行赋值时，可以自动添加单引号</span>

<span style="color: #333333">${}手动添加单引号传参数String: where id = ' 1 ' or 1 = 1 --&gt;sql注入</span>

**<span style="color: #333333">#{}自动添加单引号传参数int:</span>**<span style="color: #333333">' 1 ' or 1 = 1这样写会报错，只能填数字--&gt;没有sql注入</span>

### <span style="color: #333333">1、单个字面量类型的参数</span>

<span style="color: #333333">若mapper接口中的方法参数为单个的字面量类型</span>

<span style="color: #333333">此时可以使用${}和#{}以</span><span style="color: #DF2A3F">任意的名称</span><span style="color: #333333">获取参数的值，注意${}需要手动加单引号</span>

### <span style="color: #333333">2、多个字面量类型的参数</span>

<span style="color: #333333">若mapper接口中的方法参数为多个时</span>

<span style="color: #333333">此时MyBatis会自动将这些参数放在一个map集合中，以arg0,arg1...为键，以参数为值；以</span>

<span style="color: #333333">param1,param2...为键，以参数为值；因此只需要通过${}和#{}访问map集合的键就可以获取相对应的 值，注意${}需要手动加单引号</span>

<span style="color: #333333"></span>

**<span style="color: #333333">3、map集合类型的参数</span>**

<span style="color: #333333">若mapper接口中的方法需要的参数为多个时，此时可以手动创建map集合，将这些数据放在map中只需要通过${}和#{}访问map集合的键就可以获取相对应的值，注意${}需要手动加单引号</span>

### <span style="color: #333333">4、实体类类型的参数</span>

<span style="color: #333333">若mapper接口中的方法参数为实体类对象时</span>

<span style="color: #333333">此时可以使用${}和#{}，通过访问实体类对象中的属性名获取属性值，注意${}需要手动加单引号</span>

### <span style="color: #333333">5、使用@Param标识参数</span>

<span style="color: #333333">可以通过@Param注解标识mapper接口中的方法参数</span>

<span style="color: #333333">此时，会将这些参数放在map集合中，以@Param注解的value属性值为键，以参数为值；以</span>

<span style="color: #333333">param1,param2...为键，以参数为值；只需要通过${}和#{}访问map集合的键就可以获取相对应的值， 注意${}需要手动加单引号</span>

## <span style="color: #333333">八、自定义映射resultMap</span>

### <span style="color: #333333">1、resultMap处理字段和属性的映射关系</span>

<span style="color: #333333">若字段名和实体类中的属性名不一致，则可以通过resultMap设置自定义映射</span>

<span style="color: #777777">若字段名和实体类中的属性名不一致，但是字段名符合数据库的规则（使用_），实体类中的属性 名符合Java的规则（使用驼峰）</span>

```xml
<!--
resultMap：设置自定义映射属性：
id：表示自定义映射的唯一标识
type：查询的数据要映射的实体类的类型子标签：
id：设置主键的映射关系result：设置普通字段的映射关系
association：设置多对一的映射关系；collection：设置一对多的映射关系属性：
property：设置映射关系中实体类中的属性名column：设置映射关系中表中的字段名
-->
<resultMap id="userMap" type="User">
  <id property="id" column="id"></id>
  <result property="userName" column="user_name"></result>
  <result property="password" column="password"></result>
  <result property="age" column="age"></result>
  <result property="sex" column="sex"></result>
</resultMap>
<!--List<User> testMohu(@Param("mohu") String mohu);-->
<select id="testMohu" resultMap="userMap">
  <!--select * from t_user where username like '%${mohu}%'-->

</select>
```

## <span style="color: #333333">九、动态SQL</span>

<span style="color: #333333">Mybatis框架的动态SQL技术是一种根据特定条件动态拼装SQL语句的功能，它存在的意义是为了解决 拼接SQL语句字符串时的痛点问题。</span>

### <span style="color: #333333">1、if</span>

<span style="color: #333333">if标签可通过test属性的表达式进行判断，若表达式的结果为true，则标签中的内容会执行；反之标签中的内容不会执行</span>

```xml

<!--List<Emp> getEmpListByMoreTJ(Emp emp);-->
<select id="getEmpListByMoreTJ" resultType="Emp"> select * from t_emp where 1=1
  <if test="ename != '' and ename != null"> and ename = #{ename}
  </if>
  <if test="age != '' and age != null"> and age = #{age}
  </if>
  <if test="sex != '' and sex != null"> and sex = #{sex}
  </if>
</select>
```

### <span style="color: #333333">2、where</span>

```xml
<select id="getEmpListByMoreTJ2" resultType="Emp"> select * from t_emp
  <where>
    <if test="ename != '' and ename != null"> ename = #{ename}
    </if>
    <if test="age != '' and age != null"> and age = #{age}
    </if>
    <if test="sex != '' and sex != null"> and sex = #{sex}
    </if>
  </where>
</select>
```

<span style="color: #777777">where和if一般结合使用：</span>

<span style="color: #777777">a&gt;若where标签中的if条件都不满足，则where标签没有任何功能，即不会添加where关键字</span>

<span style="color: #777777">b&gt;若where标签中的if条件满足，则where标签会自动添加where关键字，并将条件最前方多余的and去掉</span>

<span style="color: #777777">注意：where标签不能去掉条件最后多余的and</span>

### <span style="color: #333333">3、trim</span>

```xml
<select id="getEmpListByMoreTJ" resultType="Emp"> select * from t_emp
  <trim prefix="where" suffixOverrides="and">
    <if test="ename != '' and ename != null"> ename = #{ename} and
    </if>
    <if test="age != '' and age != null"> age = #{age} and
    </if>
    <if test="sex != '' and sex != null">
      trim用于去掉或添加标签中的内容常用属性：
      sex = #{sex}
    </if>
  </trim>
</select>
```

<span style="color: #777777">prefix：在trim标签中的内容的前面添加某些内容</span>

<span style="color: #777777">prefixOverrides：在trim标签中的内容的前面去掉某些内容</span>

<span style="color: #777777">suffix：在trim标签中的内容的后面添加某些内容</span>

<span style="color: #777777">suffixOverrides：在trim标签中的内容的后面去掉某些内容</span>

<span style="color: #777777">trim是调整整个拼接好的sql语句的前后缀的。</span>

### <span style="color: #333333">4、choose、when、otherwise</span>

<span style="color: #333333">choose、when、otherwise相当于if......else if.....else</span>

```xml
<!--List<Emp> getEmpListByChoose(Emp emp);-->

  select <include refid="empColumns"></include> from t_emp
  <where>
    <choose>
      <when test="ename != '' and ename != null"> ename = #{ename}
```

## <span style="color: #333333">十、MyBatis的缓存</span>

### <span style="color: #333333">1、MyBatis的一级缓存</span>

<span style="color: #333333">一级缓存是SqlSession级别的，通过同一个SqlSession查询的数据会被缓存，下次查询相同的数据，就 会从缓存中直接获取，不会从数据库重新访问</span>

<span style="color: #333333">使一级缓存失效的四种情况：</span>

1. 不同的SqlSession对应不同的一级缓存
2. 同一个SqlSession但是查询条件不同
3. 同一个SqlSession两次查询期间执行了任何一次增删改操作
4. 同一个SqlSession两次查询期间手动清空了缓存

### <span style="color: #333333">2、MyBatis的二级缓存</span>

<span style="color: #333333">二级缓存是SqlSessionFactory级别，通过同一个SqlSessionFactory创建的SqlSession查询的结果会被 缓存；此后若再次执行相同的查询语句，结果就会从缓存中获取</span>

<span style="color: #333333">二级缓存开启的条件：</span>

<span style="color: #333333">a&gt;在核心配置文件中，设置全局配置属性cacheEnabled="true"，默认为true，不需要设置</span>

<span style="color: #333333">b&gt;在映射文件中设置标签&lt;cache /&gt;</span>

<span style="color: #333333">c&gt;二级缓存必须在SqlSession关闭或提交之后有效</span>

<span style="color: #333333">d&gt;查询的数据所转换的实体类类型必须实现序列化的接口使二级缓存失效的情况：</span>

<span style="color: #333333">两次查询之间执行了任意的增删改，会使一级和二级缓存同时失效</span>

### <span style="color: #333333">3、二级缓存的相关配置</span>

<span style="color: #333333">在mapper配置文件中添加的cache标签可以设置一些属性：</span>

<span style="color: #333333">eviction属性：缓存回收策略</span>

<span style="color: #333333">LRU（Least Recently Used） – 最近最少使用的：移除最长时间不被使用的对象。FIFO（First in First out） – 先进先出：按对象进入缓存的顺序来移除它们。SOFT – 软引用：移除基于垃圾回收器状态和软引用规则的对象。</span>

<span style="color: #333333">WEAK – 弱引用：更积极地移除基于垃圾收集器状态和弱引用规则的对象。默认的是 LRU。</span>

<span style="color: #333333">flushInterval属性：刷新间隔，单位毫秒</span>

<span style="color: #333333">默认情况是不设置，也就是没有刷新间隔，缓存仅仅调用语句时刷新</span>

<span style="color: #333333">size属性：引用数目，正整数</span>

<span style="color: #333333">代表缓存最多可以存储多少个对象，太大容易导致内存溢出</span>

<span style="color: #333333">readOnly属性：只读，true/false</span>

<span style="color: #333333">true：只读缓存；会给所有调用者返回缓存对象的相同实例。因此这些对象不能被修改。这提供了很重要的性能优势。</span>

<span style="color: #333333">false：读写缓存；会返回缓存对象的拷贝（通过序列化）。这会慢一些，但是安全，因此默认是false。</span>

### <span style="color: #333333">4、MyBatis缓存查询的顺序</span>

<span style="color: #333333">先查询二级缓存，因为二级缓存中可能会有其他程序已经查出来的数据，可以拿来直接使用。 如果二级缓存没有命中，再查询一级缓存</span>

<span style="color: #333333">如果一级缓存也没有命中，则查询数据库</span>

<span style="color: #333333">SqlSession关闭之后，一级缓存中的数据会写入二级缓存</span>
