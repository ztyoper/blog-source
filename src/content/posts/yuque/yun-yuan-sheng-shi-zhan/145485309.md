# Docker-基本概念

## 1、解决的问题

### 1、统一标准

- 应用构建

- Java、C++、JavaScript写好的程序
- 应用构建就是打成软件包（java 打包成jar包，还有直接源代码编译，压缩包运行，乱七八糟 ）
- .exe就很好（参照windows 直接使用.exe就成）
- docker build .... 镜像（把软件包打成镜像）

- 应用分享

- 所有软件的镜像放到一个指定地方 docker hub
- 就像安卓中的应用市场

- 应用运行

- 统一标准的 **镜像**
- docker run （gcc 运行c代码，java -jar ,前端 start 就乱七八糟，docker直接run）

- .......

### 2、隔离对比

> 一个服务器不可能只运行一个应用。势必会运行多个应用。第一，每个应用有不同的运行环境。第二，使用隔离的方法防止一个应用出现问题，例如内存泄露，8G内存将整个服务器的内存的挤占掉，让其他应用无法正常运行。因此就需要隔离。

![tmp1C39.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/209847386d94ee4eba4499065c7bc05168114ff9396593444c48e34fa79a06b0.png)

> 在服务器中构建多个虚拟机，在多个虚拟机中运行多个应用。
> 缺点：
> 1. 每一个虚拟机：操作系统+配套环境应用们+应用打成镜像后，镜像很大，GB级别
> 2. 虚拟机不方便，创建较为麻烦
> 3. 启动速度慢
> 4. 镜像移植与分享不方便
> 优点：
> 1. 隔离性强

![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/3b2a397e76fe3e11be98312ad63ae8e79a6d741424c59139dcd2f798fce54fa9.png)

> 在服务器中构建多个容器，在多个虚拟机中运行多个应用。
> 优点：
> 1. 每一个容器：机器与机器之间差异的部分+镜像，MB级别
> 2. 创建简单
> 3. 启动速度快
> 4. 移植与分享方便
> 5. 隔离性强
> 6. 将公共操作系统抽取出来： `Host Operating System`

### 3、资源隔离

> cpu、memory?资源隔离与限制
> - 访问设备隔离与限制
> - 网络隔离与限制
> - 用户、用户组隔限制
> 总之隔离性强，黑客一次入侵获得root权限，也只能黑一个容器

### 4、自己的理解

> 1. 在电脑（服务器）上，不能同时运行 `jdk19的java项目` 和 `jdk17的java项目`
> 2. 不能同时启动两个 `mysql` ，因为要占用端口 `3306` 。
> 3. 把项目给别人，别人还要配置 `jdk` 环境。
> 因此，虚拟机隔离是一个解决办法，但是`docker`更好。
> docker:
> 1. 别人机器只要 `docker` 软件管理发过来的镜像即可运行项目，不需要配置环境。
> 2. `docker` 的容器可以配置多个 `mysql` 容器。端口不冲突。

## 2、架构

![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/776307f91a476eed12be87ea5f78b35dce03c5144fd9e180196b6f0308f6f74a.png)

- Docker_Host：

- 安装Docker的主机

- Docker Daemon：

- 运行在Docker主机上的Docker后台进程

- Client：

- 操作Docker主机的客户端（命令行、UI等）

- Registry：

- 镜像仓库
- Docker Hub

- Images：

- 镜像，带环境打包好的程序，可以直接启动运行
- 每一个容器都可以使用本地镜像仓库中的镜像。

- Containers：

- 容器，由镜像启动起来正在运行中的程序

使用逻辑

> 装好**Docker**，然后去**软件市场**寻找**镜像**，下载并运行，查看**容器**状态日志等排错

### 2.安装方式

#### 1.[使用 apt 存储库安装](https://docs.docker.com/engine/install/ubuntu/#install-using-the-repository)

<span style="color: rgb(0, 0, 0)">在新主机上首次安装 Docker 引擎之前，需要 需要设置 Docker 存储库。之后，您可以安装和更新 存储库中的 Docker。</span>

```xml
# Add Docker's official GPG key:
sudo apt-get update
sudo apt-get install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Add the repository to Apt sources:
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
```

> <span style="color: rgb(36, 41, 47)">这些命令用于在 Ubuntu 系统中添加 Docker 官方的 GPG 密钥，并</span>**<span style="color: rgb(36, 41, 47)">将 Docker 软件源添加到 Apt 源列表中(不然找不到安装包)</span>**<span style="color: rgb(36, 41, 47)">。下面是每个命令的作用：</span>
> 1. sudo apt-get update ：
>    - 这个命令用于更新本地的软件包列表，确保系统拥有最新的可用软件包信息。
> 2. sudo apt-get install ca-certificates curl ：
>    - 这个命令用于安装 ca-certificates 和 curl 这两个工具。
>    - ca-certificates 用于管理和维护 SSL 证书。
>    - curl 是一个用于在命令行下传输数据的工具，这里将用它来下载 Docker 的 GPG 密钥。
> 3. sudo install -m 0755 -d /etc/apt/keyrings ：
>    - 这个命令创建一个目录 /etc/apt/keyrings ，用于存放 GPG 密钥文件。
> 4. sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc ：
>    - 这个命令使用 curl 工具从 Docker 的官方网站下载他们的 GPG 密钥，并将其保存为 /etc/apt/keyrings/docker.asc 文件。
> 5. sudo chmod a+r /etc/apt/keyrings/docker.asc ：
>    - 这个命令修改 /etc/apt/keyrings/docker.asc 文件的权限，使其对所有用户可读。
> 6. echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list &gt; /dev/null ：
>    - 这个命令将 Docker 软件库的地址添加到 /etc/apt/sources.list.d/docker.list 文件中。
>    - 它会根据系统的架构和版本名称构建相应的地址，并将该地址写入文件中。
> 7. sudo apt-get update ：
>    - 最后一个命令再次运行 apt-get update ，以确保新加入的 Docker 软件源已被添加到系统中。
> <span style="color: rgb(36, 41, 47)">这些操作的目的是为了添加 Docker 的官方 GPG 密钥，并将 Docker 软件源添加到系统中，以便后续可以使用 APT 包管理工具安装 Docker 相关的软件包。</span>

#### 2.<span style="color: rgb(0, 0, 0)">安装 Docker 包</span>

> <span style="color: rgb(0, 0, 0)">安装最新版本，请运行：</span>

```xml
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

> `docker-ce`：`docker`社区版
> `docker-ce-cli`：`docker`命令行客户端
> `containerd.io`：`docker`容器化运行环境

### 3.<span style="color: rgb(0, 0, 0)">验证安装是否成功</span>

> <span style="color: rgb(0, 0, 0)">通过运行映像来验证 Docker 引擎安装是否成功。</span><span style="color: rgb(0, 0, 0)">hello-world</span>

```xml
sudo docker run hello-world
```

> <span style="color: rgb(0, 0, 0)">此命令下载测试映像并在容器中运行它。当 容器运行，它会打印一条确认消息并退出。现在，您已成功安装并</span><span style="color: rgb(0, 0, 0)">`启动`</span><span style="color: rgb(0, 0, 0)">了 Docker 引擎。</span>

### 4.卸载 Docker 引擎

1. 卸载 Docker 引擎、CLI、containerd 和 Docker Compose 包：

```xml
sudo apt-get purge docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin docker-ce-rootless-extras
```

2. 主机上的映像、容器、卷或自定义配置文件 不会自动删除。要删除所有映像、容器和卷，请执行以下操作：

```xml
sudo rm -rf /var/lib/docker
sudo rm -rf /var/lib/containerd
```

<span style="color: rgb(0, 0, 0)">您必须手动删除任何已编辑的配置文件。</span>

### 8、YUM 安装 docker

#### 1.移除老版本

```java
sudo yum remove docker docker-client docker-client-latest docker-common docker-latest docker-latest-logrotate docker-logrotate docker-engine
```

#### 2.配置 yum 源

> 配置 yum 并指导它去哪里下载 docker

```java
sudo yum install -y yum-utils  
// sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
sudo yum-config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
```

#### 3.安装 docker

```java
sudo yum install -y docker-ce docker-ce-cli containerd.io
```

#### 4.启动

```java
systemctl enable docker --now
```

#### 5.配置加速

> 这里额外添加了docker的生产环境核心配置cgroup

```java
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<-'EOF'
{
    "registry-mirrors": ["https://2wkh4qk7.mirror.aliyuncs.com"],
    "exec-opts": ["native.cgroupdriver=systemd"],
    "log-driver": "json-file",
    "log-opts": {
        "max-size": "100m"
    },
   "storage-driver": "overlay2"
}
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
```
