## 基础实战

### 1、找镜像

> 去[docker hub](http://hub.docker.com)，找到nginx镜像

```bash
docker pull nginx  #这样写，默认下载最新版，因为nginx===nginx:latest

镜像名:版本名（版本名也叫标签Tag）

docker pull nginx:1.20.1 #下载指定版本的镜像


docker pull redis  #下载最新
docker pull redis:6.2.4

## 下载来的镜像都在本地
docker images  #查看已下载的所有镜像
redis = redis:latest

#卸载镜像
docker rmi redis === docker rmi redis:latest 
docker rmi 镜像名:版本号
docker rmi 镜像id
```

> 镜像放在：`/var/lib/docker/image/overlay2/imagedb/content/sha256`，简称`/var/lib/docker`

### 2、启动容器

> 启动nginx应用容器，并映射88端口，测试的访问

```bash
docker run --help 找到用法如下：
docker run [OPTIONS] IMAGE [COMMAND] [ARG...]
 -m, --memory bytes                     Memory limit
      --mount mount                      Attach a filesystem mount to the container
      --name string                      Assign a name to the container
      
-m 2 === -mount=2 ，定义了两种设置项的写法。
但
--name=xxx 没有-n的写法，因为没有定义这种写法

【docker run  设置项   镜像名  】 镜像启动运行的命令（镜像里面默认有的，一般不会写）
# 这样运行后，终端会阻塞
docker run --name=mynginx
# 解除阻塞：ctrl+c强制停止 ctrl+alt+p正常退出

# -d：后台运行
# --restart=always: 应用开机自启，表示容器在运行期间，如果关机，那开机后自启动该容器。
docker run --name=mynginx   -d  --restart=always nginx
#如果docker run --name=mynginx -d 忘记添加--restart=always了：
docker update 容器id/名字 --restart=always
# 重启终端 
reboot



# 查看正在运行的容器
docker ps
# 查看所有(包括启动失败的容器)
docker ps -a
# 删除停止的容器
docker rm  容器id/名字
docker rm -f mynginx   #强制删除正在运行中的

#Docker 1.13版本以后，可以使用 docker containers prune 命令，删除孤立的容器。
sudo docker container prune

#停止容器
docker stop 容器id/名字
#再次启动
docker start 容器id/名字
```

```shell
要每隔 5 秒查询一次 Docker 容器的执行情况，你可以结合 watch 命令来实现。watch 命令会周期性地执行指定的命令，并且可以设置时间间隔。

在你的情况下，你可以使用以下命令：

watch -n 5 docker ps -a
这条命令的含义是：

watch: 命令会周期性地执行后面跟着的命令。
-n 5: 每 5 秒执行一次后面的命令。
docker ps -a: 查看所有容器的状态。
这样，你每 5 秒钟就会看到一次容器的执行情况。

-n 选项的全称是 --interval，它用来指定 watch 命令执行的时间间隔，单位是秒。

因此，命令 watch -n 5 docker ps -a 等价于：

bash
复制代码
watch --interval 5 docker ps -a
这表示每 5 秒执行一次 docker ps -a 命令。
```

> 1. 主机是 `wsl` 的 `Ubuntu` 系统， `IP` 也是！！只不过在 `WSL 2` 的命令行下访问 `127.0.0.1` 时，实际上是在访问运行 `WSL 2` 的 `Windows` 宿主机本身,也是 `wsl2` 本身。这样设计是为了方便在 `WSL 2` 中开发和调试网络服务，同时也确保了与 `Windows` 主机的良好集成。

> 4. 当 `App2` 也启动运行后，主机就不能设置端口 `88` 了，要重新设置一个端口对应容器的随便一个端口，比如 `80:80` ，相当于宏观上主机的 `两个端口` 对应 `两个应用` 。而两个应用在两个容器中，两个容器的端口不冲突。

> 1. 当我们启动第二个 `nginx` 后，我们不想使用第一种方法金进行修改 `html` 页面，我们就通过 `-v /data/html:/usr/share/nginx/html:ro` ,进行目录的映射。当然也可以是 `文件` 的映射。 指定了将主机的 /data/html 目录挂载到容器的 /usr/share/nginx/html 目录
> 2. 当 `/data/html` 为 `空目录` 时，挂载启动该容器后，将会 `覆盖` 原有的 `被映射的目录` ，也就变为了 `空目录` 。因此在挂载启动前，需要保证 `Docker` 服务器中的 `目录不为空` 或者 `文件为空` ，尤其是映射容器的 `配置文件` 时。

```bash

docker run --name=nginx2   \
-d  --restart=always \
-p  81:80 
-v /data/html:/usr/share/nginx/html:ro  \ 
#-v可以多次调用，也就是可以挂在多个文件。
#不可以结合docker update来添加忘记加的文件挂载，因为没有这个选项。
#ro = read only ； rw = read write 或者不指定也行
nginx

# 修改页面只需要去 主机的 /data/html
# -v 后面必须是/ 或者./ 如果直接是data/html， 它会去创建Volume 数据卷，具体看黑马教程，其实也不用看，知道该规则就好。
```

> 1. 我们使用的不是 `公网IP` ，而且局域IP `192.168.2.24` 访问不了。将 `Spring Boot应用` 打成 `jar` 包，再使用 `Dockerfile` 打成镜像，如果你的 `springboot` 配置文件中 `mysql` 和 `redis` 访问 `IP` 写的是 `127.0.0.1` 或 `localhost` 是不行的。因为 `docker` 容器中的 `127.0.0.1` 和 `localhost` 是它 `容器本地的` ，是 `映射不到宿主机` 的。必须将 `127.0.0.1` 或 `localhost` 修改为 `host.docker.internal` ，容器内部会通过 `host.docker.internal` 来访问宿主机上的服务。需要注意的是 `host.docker.internal` 只在 `Windows` 和 `Mac` 环境中可用，在 `Linux` 环境中并不支持。我们 `wsl2` 是 `linux` 环境，我们是在 `Linux` 中配置的 `docker` 容器。因此 `host.docker.internal` 没有定义。

> 3. 您在 `WSL 2` 的命令行下访问 `127.0.0.1` 时，实际上是在访问运行 `WSL 2` 的 `Windows` 宿主机本身,也是 `wsl2` 本身。这样设计是为了方便在 `WSL 2` 中开发和调试网络服务，同时也确保了与 `Windows` 主机的良好集成。而虚拟机的命令行下访问 `127.0.0.1` 时，实际上是访问了虚拟机的本地回环接口，即 `虚拟机本身` 。

#### 3、怎么打包-Dockerfile

```dockerfile
FROM openjdk:8-jdk-slim
LABEL maintainer=ztyoper

# 设定时区（东八区）,不然容器的日志时间不对是中八区
ENV TZ=Asia/Shanghai
RUN ln -snf /usr/share/zoneinfo/$TZ /etc/localtime && echo $TZ > /etc/timezone

COPY target/*.jar   /app.jar

ENTRYPOINT ["java","-jar","/app.jar"]
```

> ENTRYPOINT ["java","-jar","/app.jar"]：启动镜像就表示该容器对应的小linux系统会自动执行["java","-jar","/app.jar"]

> 1. `FROM openjdk:8-jdk-slim` ：该项目需要该基础运行环境的镜像。如果是 `python` 项目，那这里就是 `python` 的镜像。
> 2. `LABEL maintainer=ztyoper` ：项目的作者是谁。
> 3. `COPY target/*.jar   /app.jar` ：将 `.jar` 包复制到容器（小linux中）的 `/app.jar` 文件
> 4. `ENTRYPOINT ["java","-jar","/app.jar"]` ：镜像启动运行的命令，也可以是 `CMD` , 区别如下：
>    1. `CMD` 命令启动时， `run` 填入的命令会顶替 `CMD`
>    2. `ENTRYPOINT` 启动时， `run` 后跟的命令，作为 `ENTRYPOINT` 命令的参数
> 我也不知道两者的区别，照着写就是了。

#### 1、kafka等等所有镜像配置

> 配置kafka等等所有镜像配置

```yaml
version: '3.9'

services:
  redis:
    image: redis:latest
    container_name: redis
    restart: always
    ports:
      - "6379:6379"
    volumes:
      - /data/redis/redis.conf:/etc/redis/redis.conf
      - /data/redis/data:/data
    command: redis-server /etc/redis/redis.conf
    networks:
      - backend

  zookeeper:
    image: bitnami/zookeeper:latest
    container_name: zookeeper
    restart: always
    environment:
      ZOOKEEPER_CLIENT_PORT: 2181
      ZOOKEEPER_TICK_TIME: 2000
    networks:
      - backend

  kafka:
    image: bitnami/kafka:3.4.0
    container_name: kafka
    restart: always
    depends_on:
      - zookeeper
    ports:
      - "9092:9092"
    environment:
      ALLOW_PLAINTEXT_LISTENER: yes
      KAFKA_CFG_ZOOKEEPER_CONNECT: zookeeper:2181
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
    networks:
      - backend
  
  kafka-ui:
    image: provectuslabs/kafka-ui:latest
    container_name:  kafka-ui
    restart: always
    depends_on:
      - kafka
    ports:
      - "8080:8080"
    environment:
      KAFKA_CLUSTERS_0_NAME: dev
      KAFKA_CLUSTERS_0_BOOTSTRAPSERVERS: kafka:9092
    networks:
      - backend

  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    restart: always
    volumes:
      - /data/prometheus:/etc/prometheus
      - /data/prometheus/prometheus.yml:/etc/prometheus/prometheus.yml
    ports:
      - "9090:9090"
    networks:
      - backend
#安装grafana；默认账号密码 admin:admin
  grafana:
    image: grafana/grafana:latest
    container_name: grafana
    restart: always
    depends_on:
      - prometheus
    ports:
      - "3000:3000"
    networks:
      - backend

networks:
  backend:
    name: backend
```

```yaml
services:
  mysql:
    image: mysql
    container_name: mysql
    ports:
      - "3306:3306"
    environment:
      TZ: Asia/Shanghai
      MYSQL_ROOT_PASSWORD: abc123 # 在这里设置mysql的密码

      - "./data/mysql/init:/docker-entrypoint-initdb.d"

      - sky-net #设置sky-net网关, 容器会加载到该网关下，同网关下的容器可以通过容器名相互访问
  redis:
    image: redis:latest
    container_name: redis
    restart: always
    ports:
      - "6379:6379"
    volumes:
      - ./data/redis/redis.conf:/etc/redis/redis.conf
      - ./data/redis/data:/data
    command: redis-server /etc/redis/redis.conf
    networks:
      - sky-net
  sky-take-out:
    image: sky-take-out:v1.0
    build: 
      context: ./data/
      dockerfile: ./data/Dockerfile
    container_name: sky-take-out
    ports:
      - "8080:8080"
    volumes:
    # 有了下面这条 -v ,这样就不用每次切换.jar文件后又要重新创建项目镜像了<--失败了，就算不失败也有两个原因不这样写：
    # 1.需要重新启动容器，因为更新jar包时，jar包可能还在运行
    # 2.如果新的jar包需要新的依赖，没有使用dockerfile进行创建镜像，那么这些依赖就会不存在。新jar运行就会报错。
      # - /data/target/sky-server-1.0-SNAPSHOT.jar:/app.jar
      #使用config下的-dev profile替换掉app.jar中的application-dev.yml, 首个目录名字必须是config
      - ./data/target/config/application-dev.yml:/config/application-dev.yml
    networks:
      - sky-net
    # 依赖mysql容器，因此mysql容器会先创建并启动，项目容器会在之后创建并启动
    depends_on:
      - mysql
  nginx:
    image: nginx
    container_name: nginx
    ports:
      - "80:80"
    volumes:
      - "./data/nginx/nginx.conf:/etc/nginx/nginx.conf"
      - "./data/nginx/html:/usr/share/nginx/html"
    depends_on:
      - sky-take-out
    networks:
      - sky-net
# 创建网络，然后执行services
networks:
  sky-net:
    # name: sky-take-out 解除注释不会影响前面的，避免弄混，我们不指定sky-take-out作为该网络的名字
    name: sky-net #不指定name,默认为data_sky-net
```
