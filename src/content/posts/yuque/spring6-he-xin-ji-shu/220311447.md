### **一、学习指引**

> Spring调用通知方法的流程，你真的彻底了解过吗？

在前面的文章中，深度解析了Spring构建AOP拦截器的执行流程，通过创建Bean构建增强器链和初始化Bean之后执行后置处理器构建拦截器链两个流程的分析，构建的拦截器链最终会存入AdvisedSupport类中的ArrayList类型的成员变量advisors中。后续在调用方法执行AOP切面通知方法时，就会执行拦截器链中的拦截器，按照一定的顺序执行AOP通知方法。

### **二、通知顺序**

> 通知方法的执行顺序，你了解过吗？

不同的Spring版本的通知顺序是不同的，这里，主要给出Spring4与Spring5和Spring6之间的差异。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/43fe4e27687c32ff2a838dcc2abe85d502b0534e003c52b482bab7ce838a1a47.png)

可以看到，Spring4与Spring5和Spring6的执行顺序是不同的。

（1）Spring4中@After在@AfterReturning/@AfterThrowing的前面，并且@Around会将@Before包裹起来。

（2）Spring5和Spring6中@After在@AfterReturning/@AfterThrowing的后面，并且@Around会将@Before、@AfterReturning/@AfterThrowing和@After包裹起来。

```go
@Override
public MethodInterceptor[] getInterceptors(Advisor advisor) throws UnknownAdviceTypeException {
    List<MethodInterceptor> interceptors = new ArrayList<>(3);
    Advice advice = advisor.getAdvice();
    if (advice instanceof MethodInterceptor) {
        interceptors.add((MethodInterceptor) advice);
    }
    for (AdvisorAdapter adapter : this.adapters) {
        if (adapter.supportsAdvice(advice)) {
            interceptors.add(adapter.getInterceptor(advisor));
        }
    }

        throw new UnknownAdviceTypeException(advisor.getAdvice());
    }
    return interceptors.toArray(new MethodInterceptor[0]);
}
```

可以看到，在DefaultAdvisorAdapterRegistry类的getInterceptors()方法中，判断如果增强器是MethodInterceptor类型的，就将增强器强转为MethodInterceptor类型后添加到interceptors集合中，否则，使用adapter对象的getInterceptor()方法将增强器封装成MethodInterceptor对象后添加到interceptors集合中。最后将interceptors集合转化成数组并返回。

（10）解析ReflectiveMethodInvocation类的proceed()方法

源码详见：[org.springframework.aop.framework.ReflectiveMethodInvocation#proceed](http://org.springframework.aop.framework.ReflectiveMethodInvocation#proceed)()。

```go
@Override
@Nullable
public Object proceed() throws Throwable {
    if (this.currentInterceptorIndex == this.interceptorsAndDynamicMethodMatchers.size() - 1) {
        return invokeJoinpoint();
    }
    Object interceptorOrInterceptionAdvice =
        this.interceptorsAndDynamicMethodMatchers.get(++this.currentInterceptorIndex);
    if (interceptorOrInterceptionAdvice instanceof InterceptorAndDynamicMethodMatcher dm) {
        Class<?> targetClass = (this.targetClass != null ? this.targetClass : this.method.getDeclaringClass());
        if (dm.methodMatcher.matches(this.method, targetClass, this.arguments)) {
            return dm.interceptor.invoke(this);
        }
        else {
            return proceed();
        }
    }
    else {
        return ((MethodInterceptor) interceptorOrInterceptionAdvice).invoke(this);
    }
}
```

可以看到，在ReflectiveMethodInvocation类的proceed()方法中，首先会判断如果currentInterceptorIndex的值指向interceptorsAndDynamicMethodMatchers集合的最后一个位置，也就是当前执行的是interceptorsAndDynamicMethodMatchers集合中的最后一个拦截器，则直接执行invokeJoinpoint()方法。

这里，有个特殊情况，就是interceptorsAndDynamicMethodMatchers集合中没有元素，由于currentInterceptorIndex的初始值为-1，也会满足条件，直接执行invokeJoinpoint()方法。

接下来，在ReflectiveMethodInvocation类的proceed()方法中，会挨个获取interceptorsAndDynamicMethodMatchers集合中的拦截器，判断是否是InterceptorAndDynamicMethodMatcher类型，由于此时interceptorsAndDynamicMethodMatchers集合中的拦截器都不是InterceptorAndDynamicMethodMatcher类型的拦截器，所以会直接执行else条件分支的逻辑。也就是执行如下代码片段。

```go
return ((MethodInterceptor) interceptorOrInterceptionAdvice).invoke(this);
```

此时会执行ExposeInvocationInterceptor类的invoke()方法。
