### **一、学习指引**

> Spring中的@RequestAttribute注解，你真的彻底了解过吗？

在基于SpringMVC或者SpringBoot开发Web应用程序时，如果不想通过HttpServletRequest的getAttribute()方法从请求域中获取数据，以此来达到与Servlet API进行解耦的目的，那我们又该如何实现呢？

### **二、注解说明**

> 关于@RequestAttribute注解的一点点说明~~

@RequestAttribute注解指定属性名称就可以直接从当前请求的作用域中获取指定属性名称的值，接下来，看看@RequestAttribute注解的源码和使用场景。

#### **2.1 注解源码**

@RequestAttribute注解的源码详见：[org.springframework.web.bind.annotation.RequestAttribute](http://org.springframework.web.bind.annotation.RequestAttribute)。

```go
/**
* @author Rossen Stoyanchev
* @since 4.3
* @see RequestMapping
* @see SessionAttribute
*/
@Target(ElementType.PARAMETER)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface RequestAttribute {
    @AliasFor("name")
    String value() default "";
​
    @AliasFor("value")
    String name() default "";
​
    boolean required() default true;
}
```

从源码可以看出，@RequestAttribute注解是从Spring4.3版本开始提供的注解，只能标注到方法中的参数上，并且在@RequestAttribute注解中提供了如下属性。

1. value：String类型的属性，主要用于指定请求作用域中的属性名称。

2. name：String类型的属性，作用与value属性相同。

3. required：boolean类型的属性，表示请求作用域中的属性是否必需。true：必需；false：非必需。如果为true，则当前请求域中没有对应的属性，就会抛出异常。默认取值为true。

#### **2.2 使用场景**

在基于SpringMVC或者SpringBoot开发Web应用程序时，如果不想通过HttpServletRequest的getAttribute()方法从请求域中获取数据，从而实现与Servlet API进行解耦的目的，就可以使用@RequestAttribute注解实现。

### **三、使用案例**

> 一起实现@RequestAttribute注解的案例吧~~

本节，就基于@RequestAttribute注解实现一个从请求作用域中，获取指定属性值的小案例。具体场景就是：提供两个API，一个是/request/test1，另一个是/request/test2，访问/request/test1时，会将name属性和对应的值存入HttpServletRequest的属性中，也就是存入了当前的请求域中，随后将请求转发到/request/test2。并且在/request/test2对应的方法中使用@RequestAttribute注解指定属性名从当前请求域中获取对应的属性值，随后返回给客户端。具体实现步骤如下所示。

**（1）新增RequestAttributeController类**

RequestAttributeController类的源码详见：spring-annotation-chapter-55工程下的[io.binghe.spring.annotation.chapter55.controller.RequestAttributeController](http://io.binghe.spring.annotation.chapter55.controller.RequestAttributeController)。

```go
@Controller
public class RequestAttributeController {
    @RequestMapping(value = "/request/test1")
    public String test1(HttpServletRequest request) {
        request.setAttribute("name", "binghe");
        return "forward:/request/test2";
    }
    @ResponseBody
    @RequestMapping(value = "/request/test2")
    public String test2(@RequestAttribute("name") String name) {
        return "hello " +  name;
    }
}
```

可以看到，在RequestAttributeController类中，提供了两个方法，分别为test1()方法和test2()方法，test1()方法对应的链接为/request/test1，test2()方法对应的链接为/request/test1。

在test1()方法中将属性存入HttpServletRequest中，也就是存入当前请求域中，随后将请求转发到/request/test2。

请求进入test2()方法后，会通过@RequestAttribute获取当前请求域中指定属性的值，并返回给客户端程序。

#### **5.1 请求方法**

@RequestAttribute注解案例程序，请求转发前的方法结合源码时序图理解的会更加深刻，可以结合图55-2~55-3进行理解。可以看出，整体流程与@RequestParam注解在Spring中执行的流程基本相同，只是部分细节不同，本节，只介绍与@RequestParam注解在Spring中执行的流程不同的部分，直接从HandlerMethodArgumentResolverComposite类的resolveArgument()方法开始解析。

（1）解析HandlerMethodArgumentResolverComposite类的resolveArgument(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer, NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory)。

源码详见：[org.springframework.web.method.support.HandlerMethodArgumentResolverComposite#resolveArgument](http://org.springframework.web.method.support.HandlerMethodArgumentResolverComposite#resolveArgument)(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer, NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory)。

```go
@Override
@Nullable
public Object resolveArgument(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer,  NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory) throws Exception {
    //获取参数解析器
    HandlerMethodArgumentResolver resolver = getArgumentResolver(parameter);
    if (resolver == null) {
        throw new IllegalArgumentException("Unsupported parameter type [" + parameter.getParameterType().getName() + "]. supportsParameter should be called first.");
    }
    //解析参数
    return resolver.resolveArgument(parameter, mavContainer, webRequest, binderFactory);
}
```

可以看到，在HandlerMethodArgumentResolverComposite类的resolveArgument()方法中，首先获取参数解析器resolver对象，随后调用resolver对象的resolveArgument()方法解析参数并返回。当参数为HttpServletRequest时，会调用ServletRequestMethodArgumentResolver类的resolveArgument()方法。

（2）解析ServletRequestMethodArgumentResolver类的resolveArgument(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer, NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory)方法

源码详见：[org.springframework.web.servlet.mvc.method.annotation.ServletRequestMethodArgumentResolver#resolveArgument](http://org.springframework.web.servlet.mvc.method.annotation.ServletRequestMethodArgumentResolver#resolveArgument)(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer, NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory)。

```go
@Override
public Object resolveArgument(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer, NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory) throws Exception {
​
    Class<?> paramType = parameter.getParameterType();
​
    // WebRequest / NativeWebRequest / ServletWebRequest
    if (WebRequest.class.isAssignableFrom(paramType)) {
        if (!paramType.isInstance(webRequest)) {
            throw new IllegalStateException(
                "Current request is not of type [" + paramType.getName() + "]: " + webRequest);
        }
        return webRequest;
    }
​
    // ServletRequest / HttpServletRequest / MultipartRequest / MultipartHttpServletRequest
    if (ServletRequest.class.isAssignableFrom(paramType) || MultipartRequest.class.isAssignableFrom(paramType)) {
        return resolveNativeRequest(webRequest, paramType);
    }
​
    // HttpServletRequest required for all further argument types
    return resolveArgument(paramType, resolveNativeRequest(webRequest, HttpServletRequest.class));
}
```

可以看到，在ServletRequestMethodArgumentResolver类的resolveArgument()方法中，会根据参数的Class对象来判断调用哪种方法，此时会调用resolveNativeRequest()方法。

（3）解析ServletRequestMethodArgumentResolver类的resolveNativeRequest(NativeWebRequest webRequest, ClassrequiredType)方法

源码详见：[org.springframework.web.servlet.mvc.method.annotation.ServletRequestMethodArgumentResolver#resolveNativeRequest](http://org.springframework.web.servlet.mvc.method.annotation.ServletRequestMethodArgumentResolver#resolveNativeRequest)(NativeWebRequest webRequest, ClassrequiredType)。

```go
private <T> T resolveNativeRequest(NativeWebRequest webRequest, Class<T> requiredType) {
    T nativeRequest = webRequest.getNativeRequest(requiredType);
    if (nativeRequest == null) {
        throw new IllegalStateException("Current request is not of type [" + requiredType.getName() + "]: " + webRequest);
    }
    return nativeRequest;
}
```

可以看到，在ServletRequestMethodArgumentResolver类的resolveNativeRequest()方法中，主要就是通过webRequest对象的getNativeRequest()方法获取nativeRequest对象并返回。

其他流程与@RequestParam注解在Spring中执行的流程基本相同，这里不再赘述。

（5）解析InternalResourceView类的renderMergedOutputModel(Map&lt;String, Object&gt; model, HttpServletRequest request, HttpServletResponse response)方法

源码详见：[org.springframework.web.servlet.view.InternalResourceView#renderMergedOutputModel](http://org.springframework.web.servlet.view.InternalResourceView#renderMergedOutputModel)(Map&lt;String, Object&gt; model, HttpServletRequest request, HttpServletResponse response)。

```go
@Override
protected void renderMergedOutputModel(Map<String, Object> model, HttpServletRequest request, HttpServletResponse response) throws Exception {
    //将model对象的属性信息暴露成request的属性信息
    exposeModelAsRequestAttributes(model, request);
    // Expose helpers as request attributes, if any.
    exposeHelpers(request);
    // 获取转发的请求路径信息
    String dispatcherPath = prepareForRendering(request, response);
    // 获取请求转发对象rd
    RequestDispatcher rd = getRequestDispatcher(request, dispatcherPath);
    if (rd == null) {
        throw new ServletException("Could not get RequestDispatcher for [" + getUrl() + "]: Check that the corresponding file exists within your web application archive!");
    }
    // 如果已经包含请求信息或者请求已经提交，进行包含处理
    if (useInclude(request, response)) {
        response.setContentType(getContentType());
        if (logger.isDebugEnabled()) {
            logger.debug("Including [" + getUrl() + "]");
        }
        rd.include(request, response);
    }
    //处理转发请求
    else {
        if (logger.isDebugEnabled()) {
            logger.debug("Forwarding to [" + getUrl() + "]");
        }
        //调用rd对象的formard()方法处理转发请求
        rd.forward(request, response);
    }
}
```

可以看到，InternalResourceView类的renderMergedOutputModel()方法，实际上就是在请求转发的操作，最终会调用RequestDispatcher类型的rd对象的forward()方法实现请求的转发操作。

#### **5.3 访问转发后的方法**

访问请求后的方法执行流程与@RequestParam注解在Spring中执行的流程基本相同。但二者存在如下细节差异。

1. 访问请求后的方法执行流程中会调用RequestAttributeMethodArgumentResolver类中的方法，而@RequestParam注解在Spring中执行的流程中会调用RequestParamMethodArgumentResolver类中的方法。

2. 访问请求后的方法执行流程中会调用ServletRequestAttributes类中的getAttribute()方法获取请求作用域中属性的值，而RequestParam注解在Spring中执行的流程中会调用ServletWebRequest类中的getParameterValues()方法获取参数值。

大家对比@RequestParam注解在Spring中执行的源码流程来分析访问请求后的方法执行流程即可，这里不再赘述。
