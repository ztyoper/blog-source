#### **3.1 事务整体流程**

分析Spring底层事务的源码执行流程时，结合源码执行的时序图，会理解的更加深刻，可以结合图34-1~34-2进行理解。

Spring事务本质上还是基于AOP实现的，事务的整体执行流程与第26章AOP调用通知方法的执行流程基本相同，只是部分细节略有差异。本节，主要介绍与第26章源码解析中存在差异的部分，其他部分可参考第26章的内容。本节直接从ReflectiveMethodInvocation类的proceed()方法开始解析。

（1）解析ReflectiveMethodInvocation类的proceed()方法

源码详见：[org.springframework.aop.framework.ReflectiveMethodInvocation#proceed](http://org.springframework.aop.framework.ReflectiveMethodInvocation#proceed)()。

```go
@Override
@Nullable
public Object proceed() throws Throwable {
    if (this.currentInterceptorIndex == this.interceptorsAndDynamicMethodMatchers.size() - 1) {
        return invokeJoinpoint();
    }
    Object interceptorOrInterceptionAdvice =
        this.interceptorsAndDynamicMethodMatchers.get(++this.currentInterceptorIndex);
    if (interceptorOrInterceptionAdvice instanceof InterceptorAndDynamicMethodMatcher dm) {
        Class<?> targetClass = (this.targetClass != null ? this.targetClass : this.method.getDeclaringClass());
        if (dm.methodMatcher.matches(this.method, targetClass, this.arguments)) {
            return dm.interceptor.invoke(this);
        }
        else {
            return proceed();
        }
    }
    else {
        return ((MethodInterceptor) interceptorOrInterceptionAdvice).invoke(this);
    }
}
```

可以看到，在ReflectiveMethodInvocation类的proceed()方法中，首先会判断如果currentInterceptorIndex的值指向interceptorsAndDynamicMethodMatchers集合的最后一个位置，也就是当前执行的是interceptorsAndDynamicMethodMatchers集合中的最后一个拦截器，则直接执行invokeJoinpoint()方法。

这里，有个特殊情况，就是interceptorsAndDynamicMethodMatchers集合中没有元素，由于currentInterceptorIndex的初始值为-1，也会满足条件，直接执行invokeJoinpoint()方法。

接下来，在ReflectiveMethodInvocation类的proceed()方法中，会挨个获取interceptorsAndDynamicMethodMatchers集合中的拦截器，判断是否是InterceptorAndDynamicMethodMatcher类型，由于此时interceptorsAndDynamicMethodMatchers集合中的拦截器都不是InterceptorAndDynamicMethodMatcher类型的拦截器，所以会直接执行else条件分支的逻辑。也就是执行如下代码片段。

```go
return ((MethodInterceptor) interceptorOrInterceptionAdvice).invoke(this);
```

对于Spring中的事务来说，此时就会执行TransactionInterceptor类的invoke()方法。

（2）解析TransactionInterceptor类的invoke(MethodInvocation invocation)方法

源码详见：org.springframework.transaction.interceptor.TransactionInterceptor#invoke(MethodInvocation invocation)。

```go
@Override
@Nullable
public Object invoke(MethodInvocation invocation) throws Throwable {
    //获取目标Class对象
    Class<?> targetClass = (invocation.getThis() != null ? AopUtils.getTargetClass(invocation.getThis()) : null);
    //开启事务调用目标方法
    return invokeWithinTransaction(invocation.getMethod(), targetClass, new CoroutinesInvocationCallback() {
        @Override
        @Nullable
        public Object proceedWithInvocation() throws Throwable {
            return invocation.proceed();
        }
        @Override
        public Object getTarget() {
            return invocation.getThis();
        }
        @Override
        public Object[] getArguments() {
            return invocation.getArguments();
        }
    });
}
```

可以看到，在TransactionInterceptor类的invoke()方法中，首先会获取目标Class对象，然后以事务的方式调用目标方法，也就是调用目标方法时，会处理事务相关的操作。

（3）解析TransactionAspectSupport类的invokeWithinTransaction(Method method, @Nullable Class&lt;?&gt; targetClass, final InvocationCallback invocation)方法

源码详见：org.springframework.transaction.interceptor.TransactionAspectSupport#invokeWithinTransaction(Method method, @Nullable Class&lt;?&gt; targetClass, final InvocationCallback invocation)。

```go

        }
        finally {
            //清理当前线程中的事务信息
            cleanupTransactionInfo(txInfo);

            TransactionStatus status = txInfo.getTransactionStatus();
            if (status != null && txAttr != null) {
                retVal = VavrDelegate.evaluateTryFailure(retVal, txAttr, status);
            }
        }
        //目标方法执行成功，提交事务
        commitTransactionAfterReturning(txInfo);
        return retVal;
    }
    //处理编程式事务
    else {
        Object result;
        final ThrowableHolder throwableHolder = new ThrowableHolder();

                TransactionInfo txInfo = prepareTransactionInfo(ptm, txAttr, joinpointIdentification, status);
                try {
                    Object retVal = invocation.proceedWithInvocation();
                    if (retVal != null && vavrPresent && VavrDelegate.isVavrTry(retVal)) {
                        // Set rollback-only in case of Vavr failure matching our rollback rules...
                        retVal = VavrDelegate.evaluateTryFailure(retVal, txAttr, status);
                    }
                    return retVal;

                catch (Throwable ex) {
                    if (txAttr.rollbackOn(ex)) {
                        // A RuntimeException: will lead to a rollback.
                        if (ex instanceof RuntimeException) {
                            throw (RuntimeException) ex;
                        }
                        else {
                            throw new ThrowableHolderException(ex);
                        }
                    }
                    else {

                        throwableHolder.throwable = ex;
                        return null;
                    }
                }
                finally {
                    cleanupTransactionInfo(txInfo);
                }
            });
        }
        catch (ThrowableHolderException ex) {
            throw ex.getCause();
        }

                ex2.initApplicationException(throwableHolder.throwable);

            if (throwableHolder.throwable != null) {
                logger.error("Application exception overridden by commit exception", throwableHolder.throwable);
            }
            throw ex2;
        }

        // Check result state: It might indicate a Throwable to rethrow.
        if (throwableHolder.throwable != null) {
            throw throwableHolder.throwable;
        }
        return result;
    }
}
```

可以看到，在TransactionAspectSupport类的invokeWithinTransaction()方法中，对于声明式事务来说，主要完成了如下处理流程。

1. 获取事务的属性源信息。

2. 获取事务中的属性信息。

3. 获取PlatformTransactionManager事务管理器。

4. 生成类中方法的唯一标识，例如会以全类名+方法名作为方法的唯一标识。

5. 处理声明式事务和编程式事务，第29章中的案例程序是基于声明式事务实现的，所以，这里主要分析声明式事务。声明式事务也是实际使用Spring开发项目时，使用的比较多的一种方式。

6. 调用createTransactionIfNecessary()方法按照需要创建事务。

7. 调用invocation的proceedWithInvocation()方法执行环绕通知增强方法。

8. 目标方法抛出异常时，就会调用completeTransactionAfterThrowing()方法根据异常的类型提交事务还是回滚事务。

9. 目标方法执行正常时，就会调用commitTransactionAfterReturning()方法提交事务。

所以，TransactionAspectSupport类的invokeWithinTransaction()方法是Spring实现事务总体流程最核心的方法，这里，以Spring的声明式事务为例，再简化下invokeWithinTransaction()方法的代码，大家就能够看的更清晰些。

```go
//根据需要创建一个事务
TransactionInfo txInfo = createTransactionIfNecessary(ptm, txAttr, joinpointIdentification);
Object retVal;
try {
    //通过环绕通知执行增强方法
    retVal = invocation.proceedWithInvocation();
}
catch (Throwable ex) {
    //目标方法抛出异常，根据异常类型执行事务的提交或者回滚操作
    completeTransactionAfterThrowing(txInfo, ex);
    throw ex;
}
finally {
    //清理当前线程中的事务信息
    cleanupTransactionInfo(txInfo);
}
//目标方法执行成功，提交事务
commitTransactionAfterReturning(txInfo);
return retVal;
```

Spring处理事务最核心的整体流程就是：

1. 创建事务。

2. 执行目标方法。

3. 目标方法执行正常，提交事务。

4. 目标方法执行异常，根据异常的类型决定是提交事务还是回滚事务。

后续在分析Spring创建事务、调用目标方法、提交事务和回滚事务的流程时，都会基于TransactionAspectSupport类的invokeWithinTransaction()方法进行分析。

**这里，可能有小伙伴会问：为什么目标方法都抛出异常了，Spring还会提交事务呢？别急，这个在Spring回滚事务的流程中进行分析。**

```go
protected TransactionInfo createTransactionIfNecessary(@Nullable PlatformTransactionManager tm, @Nullable TransactionAttribute txAttr, final String joinpointIdentification) {
    //如果没有指定名称，就使用方法的唯一标识
    if (txAttr != null && txAttr.getName() == null) {
        txAttr = new DelegatingTransactionAttribute(txAttr) {
            @Override
            public String getName() {
                return joinpointIdentification;
            }
        };
    }
    TransactionStatus status = null;
    if (txAttr != null) {
        if (tm != null) {
            //通过PlatformTransactionManager事务管理器根据事务的传播行为和隔离级别等
            //获取当前活跃的事务或者新创建一个事务
            status = tm.getTransaction(txAttr);
        }
        else {
            if (logger.isDebugEnabled()) {
                logger.debug("Skipping transactional joinpoint [" + joinpointIdentification +
                             "] because no transaction manager has been configured");
            }
        }
    }
    //调用prepareTransactionInfo()方法准备事务的信息
    return prepareTransactionInfo(tm, txAttr, joinpointIdentification, status);
}
```

可以看到，TransactionAspectSupport类的createTransactionIfNecessary()方法中，其实最核心的就是如下两个执行逻辑

2. 调用prepareTransactionInfo()方法准备事务的信息。

```go
    //获取事务对象
    Object transaction = doGetTransaction();
    boolean debugEnabled = logger.isDebugEnabled();
    //判断当前线程是否存在事务，如果存在就处理嵌套事务的逻辑。
    if (isExistingTransaction(transaction)) {
        return handleExistingTransaction(def, transaction, debugEnabled);
    }
​
    //如果超时时间小于默认的超时时间，则抛出InvalidTimeoutException异常
    if (def.getTimeout() < TransactionDefinition.TIMEOUT_DEFAULT) {
        throw new InvalidTimeoutException("Invalid transaction timeout", def.getTimeout());
    }
​
    //当前线程不存在事务，并且事务的传播行为是TransactionDefinition.PROPAGATION_MANDATORY，就会抛出IllegalTransactionStateException异常
    if (def.getPropagationBehavior() == TransactionDefinition.PROPAGATION_MANDATORY) {
        throw new IllegalTransactionStateException(
            "No existing transaction found for transaction marked with propagation 'mandatory'");
    }
    else if (def.getPropagationBehavior() == TransactionDefinition.PROPAGATION_REQUIRED ||

        SuspendedResourcesHolder suspendedResources = suspend(null);
        if (debugEnabled) {
            logger.debug("Creating new transaction with name [" + def.getName() + "]: " + def);
        }
        try {
            //启动事务
            return startTransaction(def, transaction, debugEnabled, suspendedResources);
        }
        catch (RuntimeException | Error ex) {
            resume(null, suspendedResources);
```

（4）解析DataSourceTransactionManager类的doGetTransaction()方法

```go
@Override
protected Object doGetTransaction() {
```

```go
            prepareForCommit(status);

            triggerBeforeCompletion(status);

                }
                unexpectedRollback = status.isGlobalRollbackOnly();
                //清除保存点信息
                status.releaseHeldSavepoint();

                if (status.isDebug()) {
                    logger.debug("Initiating transaction commit");
                }
                unexpectedRollback = status.isGlobalRollbackOnly();
                //如果是独立事务，直接提交事务
                doCommit(status);
            }

                unexpectedRollback = status.isGlobalRollbackOnly();

​

            // marker but still didn't get a corresponding exception from commit.
            if (unexpectedRollback) {
                throw new UnexpectedRollbackException(
                    "Transaction silently rolled back because it has been marked as rollback-only");
            }
        }
        catch (UnexpectedRollbackException ex) {
            // can only be caused by doCommit
            triggerAfterCompletion(status, TransactionSynchronization.STATUS_ROLLED_BACK);
            throw ex;
        }
        catch (TransactionException ex) {
            //如果在提交事务过程中出现异常，则回滚事务
            if (isRollbackOnCommitFailure()) {
                doRollbackOnCommitException(status, ex);

            }
            throw ex;

                triggerBeforeCompletion(status);
            }
            doRollbackOnCommitException(status, ex);
            throw ex;
        }

        // propagated to callers but the transaction still considered as committed.
        try {

            triggerAfterCommit(status);
```

（2）解析TransactionAspectSupport类的completeTransactionAfterThrowing(@Nullable TransactionInfo txInfo, Throwable ex)方法

源码详见：org.springframework.transaction.interceptor.TransactionAspectSupport#completeTransactionAfterThrowing(@Nullable TransactionInfo txInfo, Throwable ex)。

```go
protected void completeTransactionAfterThrowing(@Nullable TransactionInfo txInfo, Throwable ex) {
    //判断当前线程是否存在事务，存在事务才会进一步处理是回滚事务还是提交事务
    if (txInfo != null && txInfo.getTransactionStatus() != null) {
        if (logger.isTraceEnabled()) {
            logger.trace("Completing transaction for [" + txInfo.getJoinpointIdentification() +
                         "] after exception: " + ex);
        }
        //Spring只会对RuntimeException或者Error类型的异常进行回滚操作
        if (txInfo.transactionAttribute != null && txInfo.transactionAttribute.rollbackOn(ex)) {
            try {
                //通过事务管理器进行回滚
                txInfo.getTransactionManager().rollback(txInfo.getTransactionStatus());
            }
            catch (TransactionSystemException ex2) {
                logger.error("Application exception overridden by rollback exception", ex);
                ex2.initApplicationException(ex);
                throw ex2;
            }
            catch (RuntimeException | Error ex2) {
                logger.error("Application exception overridden by rollback exception", ex);
                throw ex2;
            }
        }
        else {
            //如果不满足回滚的条件，目标方法抛出异常时，也会提交事务
            try {
                txInfo.getTransactionManager().commit(txInfo.getTransactionStatus());
            }
            catch (TransactionSystemException ex2) {
                logger.error("Application exception overridden by commit exception", ex);
                ex2.initApplicationException(ex);
                throw ex2;
            }
            catch (RuntimeException | Error ex2) {
                logger.error("Application exception overridden by commit exception", ex);
                throw ex2;
            }
        }
    }
}
```

可以看到，在TransactionAspectSupport类的completeTransactionAfterThrowing()方法中，首先会判断是否存在事务，只有存在事务时，并且txInfo.transactionAttribute.rollbackOn()方法返回true。才会对事务进行回滚或提交操作，如下所示。

```go
if (txInfo.transactionAttribute != null && txInfo.transactionAttribute.rollbackOn(ex)) {
    try {
        txInfo.getTransactionManager().rollback(txInfo.getTransactionStatus());
    }
    /************省略其他代码***********/
}
```

此时，会调用DelegatingTransactionAttribute类的rollbackOn()方法来判断是否符合事务回滚的异常。

源码详见：org.springframework.transaction.interceptor.DelegatingTransactionAttribute#rollbackOn(Throwable ex)

```go

}
```

可以看到，此时会直接调用targetAttribute对象的rollbackOn()方法判断是否符合事务回滚的异常。实际上调用的是RuleBasedTransactionAttribute类的rollbackOn()方法。

源码详见：org.springframework.transaction.interceptor.RuleBasedTransactionAttribute#rollbackOn(Throwable ex)。

```go
@Override
public boolean rollbackOn(Throwable ex) {
    RollbackRuleAttribute winner = null;
    int deepest = Integer.MAX_VALUE;

    if (this.rollbackRules != null) {
        for (RollbackRuleAttribute rule : this.rollbackRules) {
            int depth = rule.getDepth(ex);
            if (depth >= 0 && depth < deepest) {
                deepest = depth;
                winner = rule;
            }
        }
    }
    if (winner == null) {
        return super.rollbackOn(ex);
    }

    return !(winner instanceof NoRollbackRuleAttribute);
}
```

可以看到，在RuleBasedTransactionAttribute类的rollbackOn()方法中，将目标方法抛出的异常和在@Transactional注解上配置的异常进行匹配，如果匹配成功，则获取到的winner对象不是NoRollbackRuleAttribute类型的对象就返回true，否则，返回false。如果目标方法抛出的异常和在@Transactional注解上配置的异常匹配失败，则调用父类的rollbackOn()方法继续判断是否符合事务回滚的异常。此时，就会调用DefaultTransactionAttribute类的rollbackOn()方法。

源码详见：org.springframework.transaction.interceptor.DefaultTransactionAttribute#rollbackOn(Throwable ex)。

```go
@Override

    return (ex instanceof RuntimeException || ex instanceof Error);
}
```

可以看到，在DefaultTransactionAttribute类的rollbackOn()方法中，抛出的异常是RuntimeException或者Error类型，就会返回true。

（3）解析AbstractPlatformTransactionManager类的rollback(TransactionStatus status)方法

源码详见：org.springframework.transaction.support.AbstractPlatformTransactionManager#rollback(TransactionStatus status)。

```go
@Override
public final void rollback(TransactionStatus status) throws TransactionException {
    //如果事务已经提交完成，执行回滚会抛出IllegalTransactionStateException异常
    if (status.isCompleted()) {
        throw new IllegalTransactionStateException("Transaction is already completed - do not call commit or rollback more than once per transaction");
    }
    DefaultTransactionStatus defStatus = (DefaultTransactionStatus) status;
    //执行回滚操作
    processRollback(defStatus, false);
}
```

可以看到，在AbstractPlatformTransactionManager类的rollback()方法中，首先判断事务是否已经提交，如果已经提交，再执行回滚操作就会抛出IllegalTransactionStateException异常，最后会调用processRollback()方法回滚事务。

（4）解析AbstractPlatformTransactionManager类的processRollback(DefaultTransactionStatus status, boolean unexpected)方法

源码详见：org.springframework.transaction.support.AbstractPlatformTransactionManager#processRollback(DefaultTransactionStatus status, boolean unexpected)。

```go
private void processRollback(DefaultTransactionStatus status, boolean unexpected) {
    try {
        boolean unexpectedRollback = unexpected;
        try {
            //触发beforeCompletion()方法的回调
            triggerBeforeCompletion(status);
            //如果事务存在保存掉
            if (status.hasSavepoint()) {
                if (status.isDebug()) {
                    logger.debug("Rolling back transaction to savepoint");
                }
                //回滚到保存点
                status.rollbackToHeldSavepoint();
            }
            //如果当前事务为独立的事务
            else if (status.isNewTransaction()) {
                if (status.isDebug()) {
                    logger.debug("Initiating transaction rollback");
                }
                //直接回滚事务
                doRollback(status);
            }
            else {
                if (status.hasTransaction()) {
                    if (status.isLocalRollbackOnly() || isGlobalRollbackOnParticipationFailure()) {
                        if (status.isDebug()) {
                            logger.debug("Participating transaction failed - marking existing transaction as rollback-only");
                        }
                        //如果当前事务不是独立的事务，则会进行标记，等到所有事务执行完毕后统一回滚
                        doSetRollbackOnly(status);
                    }
                    else {
                        if (status.isDebug()) {
                            logger.debug("Participating transaction failed - letting transaction originator decide on rollback");
                        }
                    }
                }
                else {
                    logger.debug("Should roll back transaction but cannot - no transaction available");
                }
                // Unexpected rollback only matters here if we're asked to fail early
                if (!isFailEarlyOnGlobalRollbackOnly()) {
                    unexpectedRollback = false;
                }
            }
        }
        catch (RuntimeException | Error ex) {
            triggerAfterCompletion(status, TransactionSynchronization.STATUS_UNKNOWN);
            throw ex;
        }
        //触发afterCompletion()方法的回调
        triggerAfterCompletion(status, TransactionSynchronization.STATUS_ROLLED_BACK);
        if (unexpectedRollback) {
            throw new UnexpectedRollbackException("Transaction rolled back because it has been marked as rollback-only");
        }
    }
    finally {
        //清除记录的事务信息，并且恢复挂起的事务
        cleanupAfterCompletion(status);
    }
}
```

可以看到，在AbstractPlatformTransactionManager类的processRollback()方法中，调用doRollback()实现真正回滚事务。

（5）解析DataSourceTransactionManager类的doRollback()方法

```go
@Override
protected void doRollback(DefaultTransactionStatus status) {
    //获取事务对象
    DataSourceTransactionObject txObject = (DataSourceTransactionObject) status.getTransaction();
    //获取数据库连接对象
    Connection con = txObject.getConnectionHolder().getConnection();

    try {
        //通过数据库连接对象回滚事务

    catch (SQLException ex) {
        throw translateException("JDBC rollback", ex);
    }
}
```
