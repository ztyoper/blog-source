### **一、学习指引**

> Spring中的@RequestMapping注解，你真的彻底了解过吗？

基于SpringMVC或者SpringBoot开发过Web应用程序的小伙伴，一定对@RequestMapping这个注解不陌生，在方法上标注了@RequestMapping注解后，通过某个链接就能够访问到对应的方法，那你知道@RequestMapping注解在源码层面的执行流程吗？

本章，就对@RequestMapping注解在源码层面的执行流程一探究竟。

### **二、注解说明**

> 关于@RequestMapping注解的一点点说明~~

在类上标注了@Controller注解或者@RestController注解之后，同时方法上如果标注了@RequestMapping注解，则方法会和某个链接自动建立映射关系，通过链接地址就能够访问到对应的方法。

#### **2.1 注解源码**

@RequestMapping注解的源码详见：[org.springframework.web.bind.annotation.RequestMapping](http://org.springframework.web.bind.annotation.RequestMapping)。

```go
/**
* @author Juergen Hoeller
* @author Arjen Poutsma
* @author Sam Brannen
* @since 2.5
* @see GetMapping
* @see PostMapping
* @see PutMapping
* @see DeleteMapping
* @see PatchMapping
*/
@Target({ElementType.TYPE, ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Mapping
@Reflective(ControllerMappingReflectiveProcessor.class)
public @interface RequestMapping {
​
    String name() default "";
​
    @AliasFor("path")
    String[] value() default {};
​
    /**
* @since 4.2
*/
    @AliasFor("value")
    String[] path() default {};
​
    /**
* GET, POST, HEAD, OPTIONS, PUT, PATCH, DELETE, TRACE.
*/
    RequestMethod[] method() default {};
    String[] params() default {};
​
    /**
* RequestMapping(value = "/something", headers = "content-type=text/*")
*/
    String[] headers() default {};
​
    /**
* consumes = "text/plain"
* consumes = {"text/plain", "application/*"}
* consumes = MediaType.TEXT_PLAIN_VALUE
*/
    String[] consumes() default {};
​
    /**
* produces = "text/plain"
* produces = {"text/plain", "application/*"}
* produces = MediaType.TEXT_PLAIN_VALUE
* produces = "text/plain;charset=UTF-8"
*/
    String[] produces() default {};
}
```

从源码可以看出，@RequestMapping注解是从Spring2.5版本开始提供的注解，可以标注到类和方法上，并且在@RequestMapping注解中提供了多个属性。

1. name：String类型的属性，为请求的URL指定一个名称。

2. value：String数组类型的属性，指定请求的URL。

3. path：从Spring4.2版本开始提供的String数组类型的属性，作用与value属性相同。

4. method：RequestMethod枚举数组类型的属性，用于指定请求的方法，取值可以为RequestMethod枚举类型中的GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS, TRACE。既可以指定单个RequestMethod枚举类型，也可以同时指定多个RequestMethod枚举类型，不指定时，表示处理所有的RequestMethod枚举类型。

5. params：String数组类型的属性，用于指定请求参数，支持简单的表达式，使用params属性时，要求请求的参数Key和Value必须与params属性中配置的Key和Value相同。例如下面的示例所示。

6. @RequestMapping(value = "/binghe", params = {"userName"})：表示请求参数中必须有userName。

7. @RequestMapping(value = "/binghe", params = {"userId = 1001"})：表示请求的参数中Key为userId，值为1001。

8. 可以使用params属性实现同一个URL映射到不同的方法上，请求时根据不同的参数映射到不同的方法上。

9. headers：String数组类型的属性，用于指定请求头信息，主要是限制请求头的信息，当请求头中必须包含某些指定的头信息时，才能让方法处理请求。例如下面的示例所示。

10. @RequestMapping(value = "/binghe", headers = "content-type=text/ * ")

11. consumes：String数组类型的属性，用于指定要接收的请求体（消息体）的类型，只有满足这些类型的请求才会被处理，不指定时，表示处理所有类型。取值可以参见： org.springframework.http.MediaType 。例如下面的示例所示。

12. @RequestMapping(value = "/binghe", consumes = {"text/plain", "application/ * "})

13. @RequestMapping(value = "/binghe", consumes = MediaType.TEXT _ PLAIN _ VALUE)

14. 还有一点就是consumes属性支持类似逻辑非操作，例如下面的示例所示。

15. @RequestMapping(value = "/binghe", consumes = {"!text/plain", "application/ * "})

16. @RequestMapping(value = "/binghe", consumes = !MediaType.TEXT _ PLAIN _ VALUE)

17. produces：String数组类型的属性，用于指定要响应的消息体的类型，指定的类型必须是请求头（Accept）中所包含的类型。当请求头（Accept）中包含指定的类型时才会响应结果，取值可以参见： org.springframework.http.MediaType 。例如下面的实例所示。

18. @RequestMapping(value = "/binghe", produces= {"text/plain", "application/ * "})

19. @RequestMapping(value = "/binghe", produces = MediaType.TEXT _ PLAIN _ VALUE)

20. 还有一点就是produces属性支持类似逻辑非操作，例如下面的示例所示。

21. @RequestMapping(value = "/binghe", produces = {"!text/plain", "application/ * "})

22. @RequestMapping(value = "/binghe", produces = !MediaType.TEXT _ PLAIN _ VALUE)

23. **注意：使用@RequestMapping注解时，只要出现两个或以上的属性时，多个属性之间的关系是与关系，表示必须同时满足条件才会处理。**

#### **2.3 使用场景**

@RequestMapping注解能够使请求的URL链接与方法之间建立映射关系，所以，在使用SpringMVC或者SpringBoot开发Web应用程序时，如果需要建立请求的URL与方法之间的映射关系，都可以使用@RequestMapping注解实现。如果已经明确请求的method类型，也可以使用@RequestMapping注解的衍生注解。

不过需要注意的是：@RequestMapping注解可以标注到类和方法上，而基于@RequestMapping注解的衍生注解只能标注到方法上。

### **三、使用案例**

> 一起实现@RequestMapping注解的案例吧~~

**（1）新增RequestMappingController类**

```go
@RestController
public class RequestMappingController {
    @RequestMapping(value = "/hello", method = {RequestMethod.GET, RequestMethod.POST, RequestMethod.PUT, RequestMethod.OPTIONS, RequestMethod.DELETE, RequestMethod.PATCH})

}
```

```go
public static <T> Map<Method, T> selectMethods(Class<?> targetType, final MetadataLookup<T> metadataLookup) {
    final Map<Method, T> methodMap = new LinkedHashMap<>();
    Set<Class<?>> handlerTypes = new LinkedHashSet<>();
    Class<?> specificHandlerType = null;

    if (!Proxy.isProxyClass(targetType)) {
        specificHandlerType = ClassUtils.getUserClass(targetType);
        handlerTypes.add(specificHandlerType);
    }
    handlerTypes.addAll(ClassUtils.getAllInterfacesForClassAsSet(targetType));

    for (Class<?> currentHandlerType : handlerTypes) {
        final Class<?> targetClass = (specificHandlerType != null ? specificHandlerType : currentHandlerType);

        ReflectionUtils.doWithMethods(currentHandlerType, method -> {
            Method specificMethod = ClassUtils.getMostSpecificMethod(method, targetClass);
            T result = metadataLookup.inspect(specificMethod);
            if (result != null) {
                Method bridgedMethod = BridgeMethodResolver.findBridgedMethod(specificMethod);
                if (bridgedMethod == specificMethod || metadataLookup.inspect(bridgedMethod) == null) {
                    methodMap.put(specificMethod, result);
                }
            }
        }, ReflectionUtils.USER_DECLARED_METHODS);
    }
    return methodMap;
}
```

（4）解析RequestMappingHandlerMapping类的getMappingForMethod(Method method, Class&lt;?&gt; handlerType)方法

源码详见：[org.springframework.web.servlet.mvc.method.annotation.RequestMappingHandlerMapping#getMappingForMethod](http://org.springframework.web.servlet.mvc.method.annotation.RequestMappingHandlerMapping#getMappingForMethod)(Method method, Class&lt;?&gt; handlerType)。

```go
@Override
@Nullable
protected RequestMappingInfo getMappingForMethod(Method method, Class<?> handlerType) {
    //根据传递的方法，创建请求映射信息
    RequestMappingInfo info = createRequestMappingInfo(method);
    //返回的结果数据不为空
    if (info != null) {
        //根据方法对应的类，创建请求映射信息
        RequestMappingInfo typeInfo = createRequestMappingInfo(handlerType);
        //根据类生成的请求映射信息不为空
        if (typeInfo != null) {
            //合并类的请求映射信息和方法的请求映射信息
            info = typeInfo.combine(info);
        }
        //获取请求前缀
        String prefix = getPathPrefix(handlerType);
        //如果获取的请求前缀不为空
        if (prefix != null) {
            //合并请求前缀
            info = RequestMappingInfo.paths(prefix).options(this.config).build().combine(info);
        }
    }
    return info;
}
```

可以看到，在RequestMappingHandlerMapping类的getMappingForMethod()方法中，首先根据传递的方法创建请求映射信息，如果请求映射信息不为null，则根据传递的类创建请求映射信息，如果根据类创建的请求映射信息不为空，就合并类请求映射信息和方法请求映射信息，随后获取请求前缀，如果请求前缀不为空，则再次合并请求前缀。

**这里注意一点的是：会先根据方法创建请求映射信息，这是因为请求映射信息最终需要映射到方法上，通过方法创建的请求映射信息不为空时，才会进一步创建类的请求映射信息，如果不为空，则合并类的请求映射信息。接下来获取请求前缀信息，如果不为空，合并请求前缀信息。**

```go
protected HandlerMethod lookupHandlerMethod(String lookupPath, HttpServletRequest request) throws Exception {

    //通过请求路径精准匹配请求映射信息
    List<T> directPathMatches = this.mappingRegistry.getMappingsByDirectPath(lookupPath);
    //请求映射信息匹配成功
    if (directPathMatches != null) {
        //将请求结果信息添加到matches集合中

    if (matches.isEmpty()) {
        //将register的keySet集合保存的所有请求映射信息都加入到matches集合中去
        //然后依次遍历每个请求映射信息,通过其自身提供的getMatchingCondition()方法对当前requst请求进行条件匹配
  //如果满足条件，加入到matches集合，否则，不会加入matches集合
        addMatchingMappings(this.mappingRegistry.getRegistrations().keySet(), matches, request);
    }
    if (!matches.isEmpty()) {
        //获取matches集合中的第一个元素作为最佳匹配
        Match bestMatch = matches.get(0);
        //如果matches集合中元素的数量大于1
        //做进一步模糊搜索
        if (matches.size() > 1) {
            Comparator<Match> comparator = new MatchComparator(getMappingComparator(request));
            matches.sort(comparator);
            bestMatch = matches.get(0);
            if (logger.isTraceEnabled()) {
                logger.trace(matches.size() + " matching mappings: " + matches);
            }
            if (CorsUtils.isPreFlightRequest(request)) {
                for (Match match : matches) {
                    if (match.hasCorsConfig()) {
                        return PREFLIGHT_AMBIGUOUS_MATCH;
                    }
                }
            }
            else {
                Match secondBestMatch = matches.get(1);
                if (comparator.compare(bestMatch, secondBestMatch) == 0) {
                    Method m1 = bestMatch.getHandlerMethod().getMethod();
                    Method m2 = secondBestMatch.getHandlerMethod().getMethod();
                    String uri = request.getRequestURI();
                    throw new IllegalStateException(
                        "Ambiguous handler methods mapped for '" + uri + "': {" + m1 + ", " + m2 + "}");
                }
            }
        }
        //将当前请求的处理方法设置到request请求对象的BEST_MATCHING_HANDLER_ATTRIBUTE属性中。
        request.setAttribute(BEST_MATCHING_HANDLER_ATTRIBUTE, bestMatch.getHandlerMethod());
        handleMatch(bestMatch.mapping, lookupPath, request);
        return bestMatch.getHandlerMethod();
    }
    else {
        return handleNoMatch(this.mappingRegistry.getRegistrations().keySet(), lookupPath, request);
    }
}
```

可以看到，AbstractHandlerMethodMapping类的lookupHandlerMethod()方法主要是通过请求request定位到处理方法。核心代码已标注注释，这里不再赘述。

```go
    RequestMethodsRequestCondition methods = this.methodsCondition.getMatchingCondition(request);

    }

    if (params == null) {
        return null;
    }

    HeadersRequestCondition headers = this.headersCondition.getMatchingCondition(request);
    if (headers == null) {
        return null;
    }
    //判断@RequestMapping注解提供的consumers条件是否匹配
    ConsumesRequestCondition consumes = this.consumesCondition.getMatchingCondition(request);
    if (consumes == null) {
        return null;
    }
    //判断@RequestMapping注解提供的produces条件是否匹配
    ProducesRequestCondition produces = this.producesCondition.getMatchingCondition(request);
    if (produces == null) {
        return null;
    }
    PathPatternsRequestCondition pathPatterns = null;
    if (this.pathPatternsCondition != null) {
        pathPatterns = this.pathPatternsCondition.getMatchingCondition(request);
        if (pathPatterns == null) {
            return null;
        }
    }
    //对于形如@PostMapping({"/binghe/login", "/binghe/auth"})的情况处理
    PatternsRequestCondition patterns = null;
    if (this.patternsCondition != null) {
        patterns = this.patternsCondition.getMatchingCondition(request);
        if (patterns == null) {
            return null;
        }
    }
    //自定义请求限制
    RequestConditionHolder custom = this.customConditionHolder.getMatchingCondition(request);
    if (custom == null) {
        return null;
    }
    //构建全新的请求映射信息
    return new RequestMappingInfo(this.name, pathPatterns, patterns,
                                  methods, params, headers, consumes, produces, custom, this.options);
}
```

```go
    String bestPattern;

    if (condition.isEmptyPathMapping()) {

        uriVariables = getPathMatcher().extractUriTemplateVariables(bestPattern, lookupPath);

    request.setAttribute(BEST_MATCHING_PATTERN_ATTRIBUTE, bestPattern);
```

源码详见：[org.springframework.web.servlet.mvc.condition.PatternsRequestCondition#getMatchingCondition](http://org.springframework.web.servlet.mvc.condition.PatternsRequestCondition#getMatchingCondition)(HttpServletRequest request)。

（3）解析PatternsRequestCondition类的getMatchingPatterns(String lookupPath)方法

源码详见：[org.springframework.web.servlet.mvc.condition.PatternsRequestCondition#getMatchingPatterns](http://org.springframework.web.servlet.mvc.condition.PatternsRequestCondition#getMatchingPatterns)(String lookupPath)。

```go
public List<String> getMatchingPatterns(String lookupPath) {
    List<String> matches = null;
    //由于@RequestMapping注解中可以写多个请求路径，所以这里遍历集合
    for (String pattern : this.patterns) {
        //匹配每个pattern，如果未匹配上，就返回null
        String match = getMatchingPattern(pattern, lookupPath);
        //如果不为null，说明已经匹配上
        if (match != null) {
            matches = (matches != null ? matches : new ArrayList<>());
            //加入到matches集合中
            matches.add(match);
        }
    }
    //如果matches为null，则返回空集合
    if (matches == null) {
        return Collections.emptyList();
    }
    //如果matches长度大于1，也就是匹配上多个请求路径
    if (matches.size() > 1) {
        //对matches集合进行排序，使最佳匹配放在最前面
        matches.sort(this.pathMatcher.getPatternComparator(lookupPath));
    }
    //返回matches集合
    return matches;
}
```

可以看到，PatternsRequestCondition类的getMatchingPatterns()方法是请求匹配过程中的核心所在，在PatternsRequestCondition类的getMatchingPatterns()方法中，主要就是对请求进行匹配，最终都未匹配上，就返回null。如果匹配后的matches集合长度大于1，也就是匹配上多个请求路径，则对matches集合进行排序，使最佳匹配放在最前面，最后返回matches集合。

（4）解析PatternsRequestCondition类的getMatchingPattern(String pattern, String lookupPath)方法

源码详见：[org.springframework.web.servlet.mvc.condition.PatternsRequestCondition#getMatchingPattern](http://org.springframework.web.servlet.mvc.condition.PatternsRequestCondition#getMatchingPattern)(String pattern, String lookupPath)。

```go
@Nullable
private String getMatchingPattern(String pattern, String lookupPath) {
    //精准匹配上，就直接返回
    if (pattern.equals(lookupPath)) {
        return pattern;
    }
    //如果开启了后缀匹配，SpringMVC默认是关闭的，useSuffixPatternMatch默认为false
    if (this.useSuffixPatternMatch) {
        //fileExtensions是后缀集合，比如文件后缀：.pdf，.png等等
        if (!this.fileExtensions.isEmpty() && lookupPath.indexOf('.') != -1) {
            for (String extension : this.fileExtensions) {
                //如果设置了后缀，则将当前pattern添加后缀
                if (this.pathMatcher.match(pattern + extension, lookupPath)) {
                    return pattern + extension;
                }
            }
        }
        //如果没有开启后缀匹配
        else {
            boolean hasSuffix = pattern.indexOf('.') != -1;
            //判断当前请求是否存在后缀
            if (!hasSuffix && this.pathMatcher.match(pattern + ".*", lookupPath)) {
                //进行.*ant风格匹配
                return pattern + ".*";
            }
        }
    }
    //对路径进行ant风格匹配
    if (this.pathMatcher.match(pattern, lookupPath)) {
        return pattern;
    }
    //useTrailingSlashMatch默认为false，表示不开启.
    //开启useSuffixPatternMatch后，使用/binghe/test/不能匹配上/binghe/test
    if (this.useTrailingSlashMatch) {
        if (!pattern.endsWith("/") && this.pathMatcher.match(pattern + "/", lookupPath)) {
            return pattern + "/";
        }
    }
    return null;
}
```

可以看到，在PatternsRequestCondition类的getMatchingPattern()方法中，主要完成了对请求路径的ant风格匹配，其中包含后缀匹配(默认不开启)，useTrailingSlashMatch匹配（默认不开启）等容错处理。

其中，useSuffixPatternMatch和useTrailingSlashMatch其实是在RequestMappingHandlerMapping类中进行提供的，如下所示。

```go

private boolean useSuffixPatternMatch = false;
private boolean useRegisteredSuffixPatternMatch = false;
private boolean useTrailingSlashMatch = false;
```


（6）解析RequestMappingHandlerMapping类的getPathPrefix(Class&lt;?&gt; handlerType)方法

源码详见：[org.springframework.web.servlet.mvc.method.annotation.RequestMappingHandlerMapping#getPathPrefix](http://org.springframework.web.servlet.mvc.method.annotation.RequestMappingHandlerMapping#getPathPrefix)(Class&lt;?&gt; handlerType)。

```go
@Nullable
String getPathPrefix(Class<?> handlerType) {
    //遍历请求的前缀集合
    for (Map.Entry<String, Predicate<Class<?>>> entry : this.pathPrefixes.entrySet()) {
        //如果当前传入的handlerType与遍历出的entry匹配
        if (entry.getValue().test(handlerType)) {
            String prefix = entry.getKey();
            if (this.embeddedValueResolver != null) {
                //通过el解析器解析后，再返回请求前缀，也就是说请求前缀支持el表达式
                prefix = this.embeddedValueResolver.resolveStringValue(prefix);
            }
            return prefix;
        }
    }
    return null;
}
```

可以看到，在RequestMappingHandlerMapping类的getPathPrefix()方法中，首先会遍历请求的前缀集合，如果当前传入的handlerType与遍历出的entry匹配，则获取请求前缀，如果el解析器不为null，则请求前缀会经过el解析器解析后，再返回。也就是说，请求前缀可以支持el表达式。

可以看到，在通过@RequestMapping注解进行方法定位处理时，会采用一定的容错处理机制，从某种程度上来讲，就是在扩大匹配范围。
