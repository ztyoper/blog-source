### **一、学习指引**

> Spring中的@RequestHeader注解，你真的彻底了解过吗？

在前面介绍的绑定控制器方法参数的注解中，基本都是绑定的请求参数和请求体中的数据，在Spring中，提供了一个@RequestHeader注解可以解析存放在请求头中的参数。

本节，就对@RequestHeader注解获取参数的案例和执行流程一探究竟。

### **二、注解说明**

> 关于@RequestHeader注解的一点点说明~~

使用@RequestHeader注解可以获取到存放在请求头中的参数信息。

#### **2.1 注解源码**

@RequestHeader注解的源码详见：[org.springframework.web.bind.annotation.RequestHeader](http://org.springframework.web.bind.annotation.RequestHeader)。

```go
/*
* @author Juergen Hoeller
* @author Sam Brannen
* @since 3.0
* @see RequestMapping
* @see RequestParam
* @see CookieValue
*/
@Target(ElementType.PARAMETER)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface RequestHeader {
    @AliasFor("name")
    String value() default "";
    /**
* @since 4.2
*/
    @AliasFor("value")
    String name() default "";
    boolean required() default true;
    String defaultValue() default ValueConstants.DEFAULT_NONE;
}
```

从源码可以看出，@RequestHeader注解是从Spring3.0开始提供的注解，只能标注到参数上，并且在@RequestHeader注解中，提供了如下属性信息。

1. value：String类型的属性，用于指定消息头的名称。

2. name：Spring从4.2版本开始提供的String类型的属性，作用与value属性相同。

3. required：boolean类型的属性，用于指定是否必须有此消息头。true：必须有，false：非必须有。如果设置为true时，请求中没有此消息头会强制报错，默认为true。

4. defaultValue：String类型的属性，用于指定消息头的默认值。

#### **2.2 使用场景**

如果需要在方法中获取请求头中的参数，就可以使用@RequestHeader注解实现从请求头中获取消息头的参数值，并将其赋值给控制器类中的方法的形参。

### **三、使用案例**

> 一起实现@RequestHeader注解的案例吧~~

本节，就基于@RequestHeader注解实现一个简单的案例程序，具体实现步骤如下所示。

**（1）新增RequestHeaderController类**

RequestHeaderController类的源码详见：spring-annotation-chapter-49工程下的[io.binghe.spring.annotation.chapter49.controller.RequestHeaderController](http://io.binghe.spring.annotation.chapter49.controller.RequestHeaderController)。

```go
@RestController
public class RequestHeaderController {
    @RequestMapping(value = "/header")
    public String getHeader(@RequestHeader(value = "header-name") String name){
        return "{\"header-name\" : \"" + name + "\" }";
    }
}
```

可以看到，在RequestHeaderController类中的getHeader()方法中，使用@RequestHeader注解获取消息头中名称为header-name的value值，并将其设置给name参数，最终返回组装好的json数据。

也可以使用Map集合接收@RequestHeader注解解析的消息头信息，如下代码所示。

```go
@RequestMapping(value = "/header/map")
public String getHeaderMap(@RequestHeader Map<String, String> map){
    return "{\"header-name\" : \"" + map + "\" }";
}
```

### **五、源码解析**

> 源码时序图整清楚了，那就整源码解析呗！

@RequestHeader注解在Spring源码层面的执行流程与@RequestParams注解在Spring源码层面的执行流程基本相同，@RequestParams注解执行流程中会调用RequestParamMethodArgumentResolver类中的方法，而在@RequestHeader注解执行的过程中，则会调用RequestHeaderMethodArgumentResolver类中的方法。

最后在AbstractNamedValueMethodArgumentResolver类的resolveArgument()方法中，调用resolveName()方法获取参数值时，@RequestParams注解执行流程中会调用RequestParamMethodArgumentResolver类中的resolveName()方法，而@RequestHeader注解执行的过程中则会调用RequestHeaderMethodArgumentResolver类中的resolveName()方法。

在RequestHeaderMethodArgumentResolver类中的resolveName()方法中，会调用ServletWebRequest类中的getHeaderValues()方法获取消息头中的数据。最终都会调用Tomcat中类的相关方法获取参数值。

本节的源码解析部分可以参见第46章的源码解析部分，本节不再赘述具体源码解析流程。
