### **一、学习指引**

> Spring中的@ModelAttribute注解，你真的彻底了解过吗？

Spring支持将数据存入某个数据结构，例如Model、Map、ModelMap中，然后使用@ModelAttribute注解从这些数据结构中将数据获取出来，赋值给方法中的参数。那么问题来了，你了解过Spring中的@ModelAttribute注解吗？

### **二、注解说明**

> 关于@ModelAttribute注解的一点点说明~~

@ModelAttribute注解支持将数据存入某个数据结构，然后在方法的参数上使用@ModelAttribute注解从数据结构中获取之前存入的数据。

#### **2.1 注解源码**

@ModelAttribute注解的源码详见：[org.springframework.web.bind.annotation.ModelAttribute](http://org.springframework.web.bind.annotation.ModelAttribute)。

```go
/**
* @author Juergen Hoeller
* @author Rossen Stoyanchev
* @author Sebastien Deleuze
* @since 2.5
* @see ControllerAdvice
*/
@Target({ElementType.PARAMETER, ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Reflective
public @interface ModelAttribute {
    @AliasFor("name")
    String value() default "";
    /**
* @since 4.3
*/
    @AliasFor("value")
    String name() default "";
    /**
* @since 4.3
*/
    boolean binding() default true;
}
```

从源码可以看出，@ModelAttribute注解是从Spring2.5版本开始提供的注解，可以标注到参数和方法上。当标注到方法上时，表示执行控制器类的方法之前，会先执行使用@ModelAttribute注解标注的方法向Model、Map、ModelMap等数据结构中存入数据。当标注到参数上时，能够从Model、Map、ModelMap等数据结构中获取数据，并赋值给参数。

在@ModelAttribute注解中，提供了如下属性。

1. value：String类型的属性，如果注解标注到方法上，表示存入数据时的Key，存入数据的值是方法的返回值。如果注解标注到参数上，则可以从Model、Map和ModelMap等数据结构中获取数据，此时表示要获取的数据的Key。

2. name：从Spring4.3版本开始提供的String类型的属性，作用与value属性相同。

3. binding：从Spring4.3版本开始提供的boolean类型的属性，表示是否支持绑定数据，true：支持，false：不支持。默认为true。

#### **2.2 使用场景**

在基于SpringMVC或者SpringBoot开发Web应用程序时，如果需要在控制器方法执行之前执行一些方法，处理一些数据逻辑，然后将数据存储到诸如Model、Map和ModelMap等数据结构中。随后，在控制器方法中自动获取之前存储的数据，并将其绑定到方法的参数上，此时就可以使用@ModelAttribute注解实现。

### **五、源码解析**

> 源码时序图整清楚了，那就整源码解析呗！

@ModelAttribute注解在Spring源码层面的执行流程也可以从执行@ModelAttribute标注的方法和执行控制器方法两个方面分析@ModelAttribute注解在Spring源码层面的执行流程。

#### **5.1 执行@ModelAttribute标注的方法**

如果@ModelAttribute注解标注到方法上时，当执行控制器方法之前，会先执行使用@ModelAttribute注解标注的方法。@ModelAttribute标注到方法上的执行流程与@RequestParams注解的执行流程基本相同，只是部分细节不同。本节，只介绍与@RequestParams注解执行流程不同的部分。

本节，直接从RequestMappingHandlerAdapter类的invokeHandlerMethod()方法开始解析。

（1）解析RequestMappingHandlerAdapter类的invokeHandlerMethod(HttpServletRequest request, HttpServletResponse response, HandlerMethod handlerMethod)方法

源码详见：[org.springframework.web.servlet.mvc.method.annotation.RequestMappingHandlerAdapter#invokeHandlerMethod](http://org.springframework.web.servlet.mvc.method.annotation.RequestMappingHandlerAdapter#invokeHandlerMethod)(HttpServletRequest request, HttpServletResponse response, HandlerMethod handlerMethod)。

```go
@Nullable
protected ModelAndView invokeHandlerMethod(HttpServletRequest request, HttpServletResponse response, HandlerMethod handlerMethod) throws Exception {
    /*****************省略其他代码***************/
    //执行使用@ModelAttribute注解标注的方法
    modelFactory.initModel(webRequest, mavContainer, invocableMethod);
    /*****************省略其他代码***************/
    //执行控制器中的方法
    invocableMethod.invokeAndHandle(webRequest, mavContainer);
    if (asyncManager.isConcurrentHandlingStarted()) {
        return null;
    }
​
    return getModelAndView(mavContainer, modelFactory, webRequest);
}
```

可以看到，RequestMappingHandlerAdapter类的invokeHandlerMethod()方法中，在RequestMappingHandlerAdapter类的invokeHandlerMethod()方法中，会先执行使用@ModelAttribute注解标注的方法，也就是调用modelFactory的initModel()方法。然后再执行控制器中的方法，也就是调用invocableMethod的invokeAndHandle()方法。

接下来，重点分析执行使用@ModelAttribute注解标注的方法，也就是invocableMethod的invokeAndHandle()方法的执行流程。

（2）解析ModelFactory类的initModel(NativeWebRequest request, ModelAndViewContainer container, HandlerMethod handlerMethod)方法

源码详见：[org.springframework.web.method.annotation.ModelFactory#initModel](http://org.springframework.web.method.annotation.ModelFactory#initModel)(NativeWebRequest request, ModelAndViewContainer container, HandlerMethod handlerMethod)。

```go
public void initModel(NativeWebRequest request, ModelAndViewContainer container, HandlerMethod handlerMethod) throws Exception {
    Map<String, ?> sessionAttributes = this.sessionAttributesHandler.retrieveAttributes(request);
    container.mergeAttributes(sessionAttributes);
    //执行标注了@ModelAttribute注解的方法
    invokeModelAttributeMethods(request, container);
    //将方法的执行结果存放到container中
    for (String name : findSessionAttributeArguments(handlerMethod)) {
        if (!container.containsAttribute(name)) {
            Object value = this.sessionAttributesHandler.retrieveAttribute(request, name);
            if (value == null) {
                throw new HttpSessionRequiredException("Expected session attribute '" + name + "'", name);
            }
            container.addAttribute(name, value);
        }
    }
}
```

可以看到，在ModelFactory类的initModel()方法中，会调用invokeModelAttributeMethods()方法执行标注了@ModelAttribute注解的方法。

（3）解析ModelFactory类的invokeModelAttributeMethods(NativeWebRequest request, ModelAndViewContainer container)方法

源码详见：[org.springframework.web.method.annotation.ModelFactory#invokeModelAttributeMethods](http://org.springframework.web.method.annotation.ModelFactory#invokeModelAttributeMethods)(NativeWebRequest request, ModelAndViewContainer container)。

```go
private void invokeModelAttributeMethods(NativeWebRequest request, ModelAndViewContainer container) throws Exception {
    while (!this.modelMethods.isEmpty()) {
        InvocableHandlerMethod modelMethod = getNextModelMethod(container).getHandlerMethod();
        //判断方法上是否标注了@ModelAttribute注解
        ModelAttribute ann = modelMethod.getMethodAnnotation(ModelAttribute.class);
        Assert.state(ann != null, "No ModelAttribute annotation");
        if (container.containsAttribute(ann.name())) {
            if (!ann.binding()) {
                container.setBindingDisabled(ann.name());
            }
            continue;
        }
        //执行方法的逻辑，获取返回值
        Object returnValue = modelMethod.invokeForRequest(request, container);
        //如果方法没有返回值，也就是使用void修饰的方法，则跳过本次循环
        if (modelMethod.isVoid()) {
            if (StringUtils.hasText(ann.value())) {
                if (logger.isDebugEnabled()) {
                    logger.debug("Name in @ModelAttribute is ignored because method returns void: " +
                                 modelMethod.getShortLogMessage());
                }
            }
            continue;
        }
        //如果方法有返回值，则获取返回值的名称，也就是后续会存入container的Key
        String returnValueName = getNameForReturnValue(returnValue, modelMethod.getReturnType());
        if (!ann.binding()) {
            container.setBindingDisabled(returnValueName);
        }
        //将对应的Key和方法的返回值存入container
        if (!container.containsAttribute(returnValueName)) {
            container.addAttribute(returnValueName, returnValue);
        }
    }
}
```

可以看到，在ModelFactory类的invokeModelAttributeMethods()方法中，会判断方法上是否标注了@ModelAttribute注解，如果没有标注@ModelAttribute注解，则直接抛出异常。否则，判断如果container中存在以@ModelAttribute注解的name属性命名的属性名称，则判断如果注解中不支持绑定数据，则调用container的setBindingDisabled()方法关闭绑定数据的功能。

如果container中不存在以@ModelAttribute注解的name属性命名的属性名称，就调用modelMethod的invokeForRequest()方法执行被@ModelAttribute注解标注的方法逻辑，并获取返回值。如果被@ModelAttribute注解标注的方法没有返回值，也就是void类型的方法，则打印日志并跳过本次循环。

否则，调用getNameForReturnValue()方法获取返回值的名称，最终将返回值的名称为Key，调用modelMethod的invokeForRequest()方法返回的结果为Value，存入container()中。

这就是为什么在@ModelAttribute注解标注的方法返回数据后，能够使用@ModelAttribute注解标注的方法参数中获取到值的原因。

（4）解析InvocableHandlerMethod类的invokeForRequest(NativeWebRequest request, @Nullable ModelAndViewContainer mavContainer, Object... providedArgs)方法

源码详见：[org.springframework.web.method.support.InvocableHandlerMethod#invokeForRequest](http://org.springframework.web.method.support.InvocableHandlerMethod#invokeForRequest)(NativeWebRequest request, @Nullable ModelAndViewContainer mavContainer, Object... providedArgs)。

```go
@Nullable
public Object invokeForRequest(NativeWebRequest request, @Nullable ModelAndViewContainer mavContainer,  Object... providedArgs) throws Exception {
    //获取方法的参数
    Object[] args = getMethodArgumentValues(request, mavContainer, providedArgs);
    if (logger.isTraceEnabled()) {
        logger.trace("Arguments: " + Arrays.toString(args));
    }
    //返回执行方法并返回结果数据
    return doInvoke(args);
}
```

后续调用getMethodArgumentValues()方法获取参数的执行流程与@RequestParams注解在Spring源码层面的执行流程基本相同，@RequestParams注解执行流程中会调用RequestParamMethodArgumentResolver类中的方法，而在@ModelAttribute注解执行的过程中，则会调用ModelAttributeMethodProcessor类中的方法。

在InvocableHandlerMethod类的invokeForRequest()方法中获取到执行参数后，就会调用doInvoke()方法，并将获取到的参数传递到doInvoke()方法中，并返回执行结果。

（5）返回ModelFactory类的invokeModelAttributeMethods(NativeWebRequest request, ModelAndViewContainer container)方法

在ModelFactory类的invokeModelAttributeMethods(NativeWebRequest request, ModelAndViewContainer container)方法中，调用modelMethod的invokeForRequest()执行@ModelAttribute注解标注的方法，获取到结果数据后，会调用getNameForReturnValue()方法获取返回结果的名称。

（6）解析ModelFactory类的getNameForReturnValue(@Nullable Object returnValue, MethodParameter returnType)方法

源码详见：[org.springframework.web.method.annotation.ModelFactory#getNameForReturnValue](http://org.springframework.web.method.annotation.ModelFactory#getNameForReturnValue)(@Nullable Object returnValue, MethodParameter returnType)。

```go
public static String getNameForReturnValue(@Nullable Object returnValue, MethodParameter returnType) {
    ModelAttribute ann = returnType.getMethodAnnotation(ModelAttribute.class);
    if (ann != null && StringUtils.hasText(ann.value())) {
        return ann.value();
    }
    else {
        Method method = returnType.getMethod();
        Assert.state(method != null, "No handler method");
        Class<?> containingClass = returnType.getContainingClass();
        Class<?> resolvedType = GenericTypeResolver.resolveReturnType(method, containingClass);
        return Conventions.getVariableNameForReturnType(method, resolvedType, returnValue);
    }
}
```

可以看到，在ModelFactory类的getNameForReturnValue()方法中，首先获取@ModelAttribute注解的信息，如果@ModelAttribute注解的信息不为空，并且value属性不为空，则返回value属性的值。否则，就根据一定的规则生成返回结果的名称信息。

至此，在ModelFactory类的invokeModelAttributeMethods()方法中调用@ModelAttribute注解标注的方法并返回了结果数据，同时，也已经获取到了结果数据对应的名称，接下来，就会调用container的addAttribute()方法来存储数据。

（7）解析ModelAndViewContainer类的addAttribute(String name, @Nullable Object value)方法

源码详见：[org.springframework.web.method.support.ModelAndViewContainer#addAttribute](http://org.springframework.web.method.support.ModelAndViewContainer#addAttribute)(String name, @Nullable Object value)。

```go
public ModelAndViewContainer addAttribute(String name, @Nullable Object value) {
    getModel().addAttribute(name, value);
    return this;
}
```

可以看到，在ModelAndViewContainer类的addAttribute()方法中，会将数据存入到对应的Model中。其中，getModel()方法的代码如下所示。

```go
public ModelMap getModel() {
    if (useDefaultModel()) {
        return this.defaultModel;
    }
    else {

            this.redirectModel = new ModelMap();

        return this.redirectModel;
    }
}
```

至此，@ModelAttribute注解标注的方法流程分析完毕。

#### **5.2 执行控制器方法**

@ModelAttribute标注到控制器方法参数上的执行流程与@RequestParams注解的执行流程基本相同，只是部分细节不同。本节，只介绍与@RequestParams注解执行流程不同的部分。

本节，直接从ServletInvocableHandlerMethod类的invokeAndHandle()方法开始解析。

（1）解析ServletInvocableHandlerMethod类的invokeAndHandle(ServletWebRequest webRequest, ModelAndViewContainer mavContainer, Object... providedArgs)方法

源码详见：[org.springframework.web.servlet.mvc.method.annotation.ServletInvocableHandlerMethod#invokeAndHandle](http://org.springframework.web.servlet.mvc.method.annotation.ServletInvocableHandlerMethod#invokeAndHandle)(ServletWebRequest webRequest, ModelAndViewContainer mavContainer, Object... providedArgs)。

```go
public void invokeAndHandle(ServletWebRequest webRequest, ModelAndViewContainer mavContainer, Object... providedArgs) throws Exception {
    //执行方法逻辑，获取方法的返回值
    Object returnValue = invokeForRequest(webRequest, mavContainer, providedArgs);
    setResponseStatus(webRequest);
    //执行的方法返回值为null
    if (returnValue == null) {
        if (isRequestNotModified(webRequest) || getResponseStatus() != null || mavContainer.isRequestHandled()) {
            disableContentCachingIfNecessary(webRequest);
            mavContainer.setRequestHandled(true);
            return;
        }
    }
    else if (StringUtils.hasText(getResponseStatusReason())) {
        mavContainer.setRequestHandled(true);
        return;
    }
​
    mavContainer.setRequestHandled(false);
    Assert.state(this.returnValueHandlers != null, "No return value handlers");
    try {
        //处理返回结果
        this.returnValueHandlers.handleReturnValue(
            returnValue, getReturnValueType(returnValue), mavContainer, webRequest);
    }
    catch (Exception ex) {
        if (logger.isTraceEnabled()) {
            logger.trace(formatErrorForReturnValue(returnValue), ex);
        }
        throw ex;
    }
}
```

可以看到，在ServletInvocableHandlerMethod类的invokeAndHandle()方法中，主要是调用invokeForRequest()方法来执行目标方法的逻辑并获取返回的结果数据，最终通过returnValueHandlers的handleReturnValue()方法处理返回结果。

其中，invokeForRequest()方法的执行流程与@RequestParams注解的执行流程基本相同，@RequestParams注解执行流程中会调用RequestParamMethodArgumentResolver类中的方法，而在@ModelAttribute注解执行的过程中，则会调用ModelMethodProcessor类中的方法。大家可以参照图51-4~51-5和@RequestParams注解的执行流程进行分析，这里不再赘述。
