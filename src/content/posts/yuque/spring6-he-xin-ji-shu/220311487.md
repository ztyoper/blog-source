### **一、学习指引**

> Spring中的@Controller注解，你真的彻底了解过吗？

不管是使用SpringMVC，还是使用SpringBoot开发Web程序时，@Controller注解都是使用的比较多的注解，使用@Controller注解主要是将当前类标注为表现层的控制器。那你对@Controller注解真的了解了吗？

### **二、注解说明**

> 关于@Controller注解的一点点说明~~

Spring基于@Component注解扩展了@Controller注解，@Controller注解主要标注到控制器类上。

#### **2.1 注解源码**

@Controller注解的源码详见：org.springframework.stereotype.Controller。

```go
/**
* @author Arjen Poutsma
* @author Juergen Hoeller
* @since 2.5
* @see Component
* @see org.springframework.web.bind.annotation.RequestMapping
* @see org.springframework.context.annotation.ClassPathBeanDefinitionScanner
*/
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Component
public @interface Controller {
    @AliasFor(annotation = Component.class)
    String value() default "";
​
}
```

从源码可以看出，@Controller注解是从Spring2.5版本开始提供的注解，只能标注到类上，并且在@Controller注解上标注了@Component注解，说明@Controller注解是基于@Component注解扩展出的注解。并且在@Controller注解中提供了一个value属性。

1. value：Spring类型的属性，表示注入IOC容器时Bean的唯一标识。

#### **2.2 使用场景**

当基于SpringMVC或者SpringBoot开发Web应用时，标注到类上表示控制器类，控制器类往往会对外提供接口，并且@Controller注解能够解析当前类中的方法，如果当前类中存在公有方法，并且方法上标注了@RequestMapping注解（含：@GetMapping注解、@PostMapping注解、@PutMapping注解、@DeleteMapping注解和@PatchMapping注解），则可以建立方法映射，对外提供访问链接，通过访问特定的链接就能够映射到对应的方法上。

#### **5.1 DispatcherServlet基础知识**

Tomcat启动时，会通过DispatcherServlet启动SpringMVC，并且DispatcherServlet通过SPI机制来加载SpringMVC中默认提供的组件，这个SPI的核心就在spring-webmvc模块中的[org.springframework.web.servlet](http://org.springframework.web.servlet)包下的DispatcherServlet.properties文件，如图43-4所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/477bb066804a4dfefcc2dc411849994035d11606476359b933c4115ffbd6cc4b.png)

打开文件重点关注如图43-5所示的配置项。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/11a00a00b1a1e5e3a512137c4dfc231affa5657fc53426cac930caab154e97f5.png)

由图43-5可以看出，在DispatcherServlet.properties文件中，提供了各个组件会提供的默认实现类。但是，DispatcherServlet在初始化配置的组件时，并没有在当前容器中发现各个组件默认的实现类。

在SpringMVC中，会通过HandlerMapping寻找实现了Controller接口的组件，调用Controller组件的功能则是通过HandlerAdaptor实现的。而扫描@Controller注解则是通过RequestMappingHandlerMapping实现的，RequestMappingHandlerMapping主要的功能就是在初始化时，扫描出当前容器中所有标注了@Controller注解的类，随后建立对应的映射关系。检测到有请求到来时，就会通过这些对应的映射关系找到对应的方法，进行处理后，将结果返回。

当请求使用@Controller注解标注实现的类中的方法时，是通过RequestMappingHandlerAdapter完成的处理过程。RequestMappingHandlerAdapter主要负责获取到RequestMappingHandlerMapping返回的结果后，进行一些数据绑定、数据校验等逻辑处理，调用目标方法处理请求，处理返回值等等。

源码详见：[org.springframework.context.event.SimpleApplicationEventMulticaster#multicastEvent](http://org.springframework.context.event.SimpleApplicationEventMulticaster#multicastEvent)(final ApplicationEvent event, @Nullable ResolvableType eventType)。

```go
@Override
public void multicastEvent(final ApplicationEvent event, @Nullable ResolvableType eventType) {
    ResolvableType type = (eventType != null ? eventType : resolveDefaultEventType(event));
    Executor executor = getTaskExecutor();
    for (ApplicationListener<?> listener : getApplicationListeners(event, type)) {
        if (executor != null) {
            executor.execute(() -> invokeListener(listener, event));
        }
        else {
            invokeListener(listener, event);
        }
    }
}
```

可以看到，在SimpleApplicationEventMulticaster类的multicastEvent()方法中，会遍历所有通过getApplicationListeners()方法获取到的事件监听器，如果线程池executor不为null，则调用executor的execute异步执行invokeListener()方法来触发监听器方法，否则，直接同步调用invokeListener()方法来触发监听器方法。
