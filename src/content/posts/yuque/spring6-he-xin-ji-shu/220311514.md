### **一、学习指引**

> Spring中的@SessionAttributes注解，你真的彻底了解过吗？

在全面的文章中，介绍了@SessionAttribute注解，@SessionAttribute注解只能标注到方法的参数上，能够通过属性名称即可从当前Session的作用域中获取对应的数据。

本章，就简单介绍下@SessionAttributes注解，尽管两个注解相似度比较高，仅仅相差一个字母s，但二者的差异还是蛮大的。

### **二、注解说明**

> 关于@SessionAttributes注解的一点点说明~~

@SessionAttributes注解能够将数据保存到当前Session的作用域中，随后可以使用@SessionAttributes注解从当前作用域中获取数据，也可以使用HttpSession从当前作用域中获取数据。

#### **2.1 注解源码**

@SessionAttributes注解的源码详见：[org.springframework.web.bind.annotation.SessionAttributes](http://org.springframework.web.bind.annotation.SessionAttributes)。

```go
/**
* @author Juergen Hoeller
* @author Sam Brannen
* @since 2.5
*/
@Target({ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
@Inherited
@Documented
public @interface SessionAttributes {
​
    @AliasFor("names")
    String[] value() default {};
    /**
* @since 4.2
*/
    @AliasFor("value")
    String[] names() default {};
    Class<?>[] types() default {};
}
```

从源码可以看出，@SessionAttributes注解是从Spring2.5版本开始提供的注解，只能标注到类上，并且在@SessionAttributes注解中提供了如下属性。

1. value：String数组类型的属性，表示要存入Session作用域中的名称。

2. names：String数组类型的属性，作用与value属性相同。

3. types：Class数组类型的属性，表示要存入Session域中的类的Class类型。

#### **2.2 使用场景**

在基于SpringMVC或者SpringBoot开发应用程序时，如果不想使用Servlet API操作Session数据，就可以使用@SessionAttributes注解实现把数据存入Session作用域。这样，就能够与Servlet API进行解耦，无需一次次手动向Session作用域中保存数据和读取数据。

### **三、使用案例**

> 一起实现@SessionAttributes注解的案例吧~~

本节，就基于@SessionAttributes注解实现一个简单的案例程序。具体场景就是：在控制器类上标注@SessionAttributes注解，并指定要存入Session作用域中的名称为name。在控制器类中提供两个API，一个是/sessions/test1，另一个是/sessions/test2。访问/sessions/test1时，会将name属性和其对应的值存入当前Session会话，并将当前访问请求重定向到/sessions/test2，此时会通过@SessionAttribute注解通过属性名从当前Session作用域中获取存入的值，并返回给客户端，具体实现的步骤如下所示。

**（1）新增SessionAttributesController类**

SessionAttributesController类的源码详见：spring-annotation-chapter-57工程下的[io.binghe.spring.annotation.chapter57.controller.SessionAttributesController](http://io.binghe.spring.annotation.chapter57.controller.SessionAttributesController)。

```go
@Controller
@SessionAttributes(value = {"name"})
public class SessionAttributesController {
​
    @RequestMapping(value = "/sessions/test1")
    public String test1(Model model) {
        model.addAttribute("name","binghe");
        return "redirect:/sessions/test2";
    }
​
    @ResponseBody
    @RequestMapping(value = "/sessions/test2")
    public String test2(@SessionAttribute("name") String name) {
        return "hello " +  name;
    }
}
```

可以看到，在SessionAttributesController类上标注了@SessionAttributes注解，并指定了要存入Session作用域中的属性的名称为name。在SessionAttributesController类中提供了两个方法，一个是test1()方法，另一个是test2()方法，在test1()方法中会接收一个请求作用域中Model对象，并且在Model对象中存入Key为name，Value为binghe的数据。如果SessionAttributesController类上没有标注@SessionAttributes注解，则存储的数据只能在当前请求作用域中生效。此时已经在SessionAttributesController类上标注了@SessionAttributes注解，则会在Session作用域中生效。

随后，在test1()中会将请求重定向到test2()方法中，在test2()方法中会通过@SessionAttribute注解（注意：不是SessionAttributes注解，没有s），从当前Session中获取名称为name的属性值，并返回给客户端。
