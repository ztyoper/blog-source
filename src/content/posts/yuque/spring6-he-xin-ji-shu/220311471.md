### **一、学习指引**

> 你了解过Spring嵌套事务的最佳实践吗？

在基于Spring开发应用程序时，涉及到事务操作时，最常使用的就是在方法上标注@Transactional注解。但是，有时由于项目逻辑比较复杂，调用的方法比较多，可能就会出现外层方法标注了@Transactional注解，而内层方法也会标注@Transactional注解的现象，造成事务的嵌套，如果对Spring事务的传播机制不太了解的话，可能就会造成实际的结果数据和预期的结果数据不一致。

本章，就以案例的形式专门聊聊Spring嵌套事务的最佳实践。

### **二、最佳实践**

> 以案例的形式来说明Spring事务嵌套的最佳实践！

本章的案例程序以大家最熟悉的下单减库存为例来说明Spring嵌套事务的最佳实践案例。

#### **2.2 最佳实践场景一**

**场景一：为外部方法无事务注解，内部方法添加REQUIRED事务传播类型。**

（1）在OrderService类的submitOrder()方法上不添加注解，如下所示。

```go
public void submitOrder(){
    //生成订单
    Order order = new Order();
    long number = Math.abs(new Random().nextInt(500));
    order.setId(number);
    order.setOrderNo("order_" + number);
    orderDao.saveOrder(order);
    //减库存
    productService.updateProductStockCountById(1, 1L);
}
```

（2）在ProductService类的updateProductStockCountById()方法上添加@Transactional(propagation = Propagation.REQUIRED)注解，如下所示。

```go
@Transactional(propagation = Propagation.REQUIRED)
public void updateProductStockCountById(Integer stockCount, Long id){
    productDao.updateProductStockCountById(stockCount, id);
    int i = 1 / 0;
}
```

（3）运行Main类中的main()方法，抛出了如下异常。

```go
Exception in thread "main" java.lang.ArithmeticException: / by zero
```

这是因为在ProductService类的updateProductStockCountById()方法中存在如下代码引起的。

```go
int i = 1 / 0;
```

（4）查询order_info表和product_info表中的数据，如下所示。

```go

+----+-----------------+---------------+-------------+

```

可以看到，当OrderService类的submitOrder()方法上不添加注解，并且ProductService类的updateProductStockCountById()方法上添加@Transactional(propagation = Propagation.REQUIRED)注解，同时ProductService类的updateProductStockCountById()方法抛出异常时，OrderService类的submitOrder()方法执行成功，向数据库保存了订单信息。ProductService类的updateProductStockCountById()方法执行抛出异常执行失败，并没有扣减库存。

**总结：外部方法无事务注解，内部方法添加REQUIRED事务传播类型时，内部方法抛出异常，内部方法执行失败，不会影响外部方法的执行，外部方法执行成功。**
