### **一、学习指引**

> Spring中的@CookieValue注解，你真的彻底了解过吗？

Spring中在绑定控制器方法参数方面，除了提供了获取请求参数数据、消息头数据和消息体数据外，还提供了一个@CookieValue注解能够获取Cookie中的数据，并将其绑定到控制器中的方法参数上。

本章，就简单聊聊@CookieValue注解的使用案例、在Spring底层执行的源码时序图和源码执行流程。

### **二、注解说明**

> 关于@CookieValue注解的一点点说明~~

使用@CookieValue注解可以从消息头中获取到Cookie的值，并将Cookie值赋值给方法的形参。

#### **2.1 注解源码**

@CookieValue注解的源码详见：[org.springframework.web.bind.annotation.CookieValue](http://org.springframework.web.bind.annotation.CookieValue)。

```go
/**
* @author Juergen Hoeller
* @author Sam Brannen
* @since 3.0
* @see RequestMapping
* @see RequestParam
* @see RequestHeader
* @see org.springframework.web.bind.annotation.RequestMapping
*/
@Target(ElementType.PARAMETER)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface CookieValue {
    @AliasFor("name")
    String value() default "";
    /**
* @since 4.2
*/
    @AliasFor("value")
    String name() default "";
    boolean required() default true;
    String defaultValue() default ValueConstants.DEFAULT_NONE;
}
```

从源码可以看出，@CookieValue注解是从Spring3.0开始提供的注解，只能标注到方法的参数上，并且在@CookieValue注解中提供了如下属性信息。

1. value：String类型的属性，用于指定Cookie的名称。

2. name：Spring4.2版本开始提供的String类型的属性，作用与value属性相同。

3. required：boolean类型的属性，用于指定是否必须有Cookie信息。true：必须有，false：非必须有。如果设置为true时，请求中没有此Cookie信息会强制报错，默认为true。

4. defaultValue：String类型的属性，用于指定Cookie的默认值。

#### **2.2 使用场景**

如果需要在方法中获取Cookie值，就可以使用@CookieValue注解实现从请求头中获取Cookie的参数值，并将其赋值给控制器类中的方法的形参。

@RestController
public class CookieValueController {

### **五、源码解析**

> 源码时序图整清楚了，那就整源码解析呗！

@CookieValue注解在Spring源码层面的执行流程与@RequestParams注解在Spring源码层面的执行流程基本相同，@RequestParams注解执行流程中会调用RequestParamMethodArgumentResolver类中的方法，而在@CookieValue注解执行的过程中，则会调用ServletCookieValueMethodArgumentResolver类和AbstractCookieValueMethodArgumentResolver类中的方法。

这里，直接从HandlerMethodArgumentResolverComposite类的resolveArgument()方法开始解析。

（1）解析HandlerMethodArgumentResolverComposite类的resolveArgument(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer, NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory)方法

源码详见：[org.springframework.web.method.support.HandlerMethodArgumentResolverComposite#resolveArgument](http://org.springframework.web.method.support.HandlerMethodArgumentResolverComposite#resolveArgument)(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer, NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory)。

```go
@Override
@Nullable
public Object resolveArgument(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer,
NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory) throws Exception {
    HandlerMethodArgumentResolver resolver = getArgumentResolver(parameter);
    if (resolver == null) {
        throw new IllegalArgumentException("Unsupported parameter type [" +
                parameter.getParameterType().getName() + "]. supportsParameter should be called first.");
    }
    return resolver.resolveArgument(parameter, mavContainer, webRequest, binderFactory);
}
```

可以看到，在HandlerMethodArgumentResolverComposite类的resolveArgument()方法中，会调用resolver解析器的resolveArgument()方法来解析参数信息，此时，会调用AbstractNamedValueMethodArgumentResolver类的resolveArgument()方法。

（2）解析AbstractNamedValueMethodArgumentResolver类的resolveArgument(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer, NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory)方法

源码详见：[org.springframework.web.method.annotation.AbstractNamedValueMethodArgumentResolver#resolveArgument](http://org.springframework.web.method.annotation.AbstractNamedValueMethodArgumentResolver#resolveArgument)(MethodParameter parameter, @Nullable ModelAndViewContainer mavContainer, NativeWebRequest webRequest, @Nullable WebDataBinderFactory binderFactory)。

（3）调用ServletCookieValueMethodArgumentResolver类的resolveName(String cookieName, MethodParameter parameter, NativeWebRequest webRequest)方法

源码详见：[org.springframework.web.servlet.mvc.method.annotation.ServletCookieValueMethodArgumentResolver#resolveName](http://org.springframework.web.servlet.mvc.method.annotation.ServletCookieValueMethodArgumentResolver#resolveName)(String cookieName, MethodParameter parameter, NativeWebRequest webRequest)。

```go
@Override
@Nullable
protected Object resolveName(String cookieName, MethodParameter parameter,
NativeWebRequest webRequest) throws Exception {
    //获取HttpServletRequest对象
    HttpServletRequest servletRequest = webRequest.getNativeRequest(HttpServletRequest.class);
    Assert.state(servletRequest != null, "No HttpServletRequest");
    //获取Cookie信息
    Cookie cookieValue = WebUtils.getCookie(servletRequest, cookieName);
    if (Cookie.class.isAssignableFrom(parameter.getNestedParameterType())) {
        return cookieValue;
    }
    //Cookie不为空获取Cookie的Value值
    else if (cookieValue != null) {
        return this.urlPathHelper.decodeRequestString(servletRequest, cookieValue.getValue());
    }
    else {
        return null;
    }
}
```

可以看到，在ServletCookieValueMethodArgumentResolver类的resolveName()方法，首先获取HttpServletRequest对象，随后获取Cookie信息cookieValue，如果Cookie是parameter参数中的NestedParameterType类型，则直接返回cookieValue。否则，如果cookieValue不为空，就返回cookieValue中的Value值。

（4）解析WebUtils类的getCookie(HttpServletRequest request, String name)方法

源码详见：[org.springframework.web.util.WebUtils#getCookie](http://org.springframework.web.util.WebUtils#getCookie)(HttpServletRequest request, String name)。

```go
@Nullable
public static Cookie getCookie(HttpServletRequest request, String name) {
    Assert.notNull(request, "Request must not be null");
    Cookie[] cookies = request.getCookies();
    if (cookies != null) {
        for (Cookie cookie : cookies) {
            if (name.equals(cookie.getName())) {
                return cookie;
            }
        }
    }
    return null;
}
```

可以看到，在WebUtils类的getCookie()方法中，首先会通过request对象的getCookies()方法获取所有的Cookie信息，并将其封装到Cookie数组cookies中。如果cookies不为null，则遍历cookies数组，判断如果传递的name与当前遍历出的cookie的name相等，则直接返回当前cookie对象。否则，继续下一次循环，继续遍历cookies数组，直到遍历完cookies数组后返回null。

其他部分的源码解析流程，大家可以参考@RequestParams注解在Spring源码层面的执行流程，这里不再赘述。
