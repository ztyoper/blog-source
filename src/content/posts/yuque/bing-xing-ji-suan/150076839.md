# 4.Pthreads进行共享内存编程

### 4.1 进程、线程和Pthreads

> - 进程是正在运行（或挂起）的程序的 `实例`
> - 线程大体上是 `轻量级` 的进程
> - 轻量级：为了 `运行共享内存` 的程序，由进程生成的 `轻量级` 进程就是 `线程` ， `轻量级线程` 由此得名。
> - 线程：除了各自拥有独立的栈和程序计数器外，为了方便，线程们基本可以共享 `进程` 所有其他区域。

### 4.2 “Hello World”程序

#### 1.“Hello World”程序第一个版本

```c
#include<stdio.h>
#include<stdlib.h>
#include<pthread.h>

int thread_count;//全局变量
void* Hello(void* rank);
int main(int argc , char* argv[]){//main函数参数一定不能错，不玩没有输出，但不报错
    long i ;
    pthread_t* thread_handles;
    thread_count = strtol(argv[1],NULL,10);

    thread_handles = (pthread_t* )malloc(thread_count * sizeof(pthread_t));
    
    for(i = 0; i<thread_count; i++){
        pthread_create(&thread_handles[i],NULL,Hello, (void*)i);//貌似thread_handles[0]也能执行
    }

    printf("Hello from the main thread\n");

    for(i = 0; i<thread_count; i++){
        pthread_join(thread_handles[i],NULL);
    }

    free(thread_handles);
    
    return 0;
}
void* Hello (void* rank){
    long my_rank =(long) rank;

    printf("Hello from thread %ld of %d\n",my_rank, thread_count);//一般不嵌套pthread_create使用，因为没有那么多线程。

    return NULL;
}
```

```c
int pthread_create(
    pthread_t *th    			/* out */, 				//线程的指针一般是&thread_handles[i]
    const pthread_attr_t *attr    			/* in */,	//获取指定线程函数返回结果,我们不用这个参数，直接传入NULL
    void *(* func)(void *)    			/* in */, 		//函数名，激活的线程将要执行的任务
    void *arg    			/* in */);					//函数的参数，一般会强转为void*，不强转会报警告note,但不报错
```

> 1. 导入#include&lt;pthread.h&gt;还是无法执行，只能输入命令行：（不管task.json里面是gcc.exe还是g++.exe都不行）
>    1. gcc -g -Wall -o pth_hello pth_hello.c -lpthread
>       1. -g：启动调试
>       2. -Wall：打开警告
>       3. -lpthread 连接第三方库：libpthread.a
>          1. libpthread.a是linux下的静态库名
>          2. libpthread.so是linux下的动态库名
>          3. libpthread.dl是windows下的动态库名
>    2. 因此文件必须是c文件，不能是cpp文件。
>    3. ./pth_hello 4 这里的4是argv[1]，也就是线程数
> 2. pthread_t 就是pthread_type
> 3. 局部变量名（函数中）和全局变量名重复时，局部变量的优先级更高。
> 4. `thread_count = strtol(argv[1],NULL,10);` :(string to long)
>    1. argv[0] 是默认.exe编译文件名./1.o
>    2. 如果指针不是NULL
>       1. 就指向argv[1]字符串的第一个无效字符（也就是非数值字符）
>    3. 如果指针是NULL
>       1. 我们一般写 `10` ，表示这个整数值所用的基（进位计数制）是10进制。
> 5. `pthread_create(&thread_handles[i],NULL,Hello, (void*)i);` ：
>    1. thread_handles是指针，thread_handles[i]是数据，&thread_handles[i]该数据的地址。最初只是分配了一个pthread大小空间，pthread_create感觉是激活该线程。让其可以进行工作；
>    2. NULL:我们不用这个参数，直接传入NULL
>    3. Hello :函数名，激活的线程将要执行的任务。
>    4. （void*）i：将 `i` 强转为void*后,作为函数 `Hello` 的参数，不要强转会报警告 `note` ,但不报错。
>    5. 线程一旦激活，马上执行。
> 6. `pthread_join(thread_handles[i],NULL);` ：
>    1. 关闭已经执行完的线程，不会提前扼杀掉。从线程执行完函数就结束了。
> 7. `long my_rank =(long) rank;` ：
>    1. rank 是void* 指针，假如 `i` 是3，则(void*)是无类型指针： `0x00000000003`
>    2. `(long)rank` :又变回3了。

### 4.4 临界区（pi的近似值求解）

$\pi ≈ 4* \left (1 - \frac{1}{3} + \frac{1}{5} - \frac{1}{7} + \frac{1}{9}....+(-1)^n *\frac{1}{2n-1}\right) = \sum_{i=1}^{n} {(-1)^n *\frac{1}{2n+1}}$

#### 1.串行代码

```c
串行伪代码
double factor = 1.0;
double sum = 1.0;
for(int i = 0; i<n; i++; factor = -factor){
    sum+=factor/(2*i+1);
}
```

#### 2.并行代码

##### 1.计算pi的pthread函数1

```c
void* Thread_sum(void* rank){
    long my_rank = (long)rank;
    double factor;
    long long my_n = n / thread_count;
    long long my_first_i = my_n * my_rank;
    long long my_last_i = my_first_i + my_n;
    if(my_first_i % 2 == 0){
        factor = 1.0;
    }else{
        factor = -1.0;
    }
    for(int i = my_first_i; i<my_last_i; i++,factor = -factor){
        sum+=factor/(2 * i + 1);
    }

}
```

> 上述函数存在问题：没有把`sum+=`设置为临界区，如果线程数越多，前一个线程对sum进行了增加操作，下一个线程sum = sum + factor/(2 * i - 1);中读到的sum仍然是原来没有添加前的sum，最终与pi的误差也会越来越大。（我们称之为`竞争条件`）

### 4.5 互斥量（pi的近似值求解）

#### 1.计算pi的pthread函数4代码

```c
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>

int thread_count; // 线程数
int n = 1024;
double sum = 0.0; // 全局和
pthread_mutex_t  mutex_p;//互斥量相当于资源数为1的信号量，一次只允许一个线程进入临界区操作。注意：不能定义指针!!!
void *Thread_sum(void *rank);
int main(int argc, char *argv[])
{
    long i;
    pthread_t *thread_handles;
    thread_count = strtol(argv[1], NULL, 10);

    thread_handles = (pthread_t *)malloc(thread_count * sizeof(pthread_t));

    //1.初始化互斥量
    pthread_mutex_init(&mutex_p, NULL);

    for (i = 0; i < thread_count; i++)
    {
        pthread_create(&thread_handles[i], NULL, Thread_sum, (void *)i);
    }

    printf("Hello from the main thread\n");

    for (i = 0; i < thread_count; i++)
    {
        pthread_join(thread_handles[i], NULL);
    }

    free(thread_handles);
    //销毁互斥量
    pthread_mutex_destroy(&mutex_p);

    printf("pi的近似值为： %lf\n", 4 * sum);

    return 0;
}
void *Thread_sum(void *rank)
{
    long my_rank = (long)rank;
    printf("hello from thread  = %d\n", my_rank);
    double factor, my_sum = 0.0;
    long long my_n = n / thread_count;
    long long my_first_i = my_n * my_rank;
    long long my_last_i = my_first_i + my_n;
    if (my_first_i % 2 == 0)
    {
        factor = 1.0;
    }
    else
    {
        factor = -1.0;
    }
    for (int i = my_first_i; i < my_last_i; i++, factor = -factor)
    {
        my_sum += factor / (2 * i + 1);
    }
    pthread_mutex_lock(&mutex_p);
    sum += my_sum;
    pthread_mutex_unlock(&mutex_p);
}
```

> 1. 互斥量相当于资源数为1的信号量，一次只允许一个线程进入临界区操作。
> 2. 注意：不能定义指针!!!，只能这样： `pthread_mutex_t  mutex_p;`

互斥量与忙等待的对比：

![9A964ED95A1E29ADD1084D58D493F5EB.jpg](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/a935f6631e2f5d8d97a0c93c84adec1427370d93d29d0e9a6735b60eb3d3a586.jpg)

> 1. 每一个核负责一个线程，不管线程数是否大于核数。
> 2. 忙等待：虽然计算完my_sum的核，但没有进入临界区的这种核，只能占着资源等待， `顺序` 进入临界区的机会。
> 3. 互斥量：计算完my_sum的核，但没有进入临界区的这种核，会控制剩余的线程继续计算其他线程的my_sum，不会像忙等待拜拜占用计算资源。
> 4. 但忙等待是让线程顺序进入临界区，可以计算
>    $B = A_1A_2A_3A_4...$
>    这样的有顺序的矩阵相乘。而使用互斥量进入临界区却不行，因为不能保证进入临界区的线程的顺序。

```c
//使用互斥量之前必须初始化
pthread_mutex_init(pthread_mutex_t *m,						//互斥量指针
                   const pthread_mutexattr_t *a);			//这个参数不用，直接NULL
//销毁互斥量
pthread_mutex_destroy(pthread_mutex_t *m);					//互斥量指针

//上锁
pthread_mutex_lock(pthread_mutex_t *m);						//互斥量指针
//解锁
pthread_mutex_unlock(pthread_mutex_t *m);					//互斥量指针
//非阻塞版lock,如果没有获取到锁，就继续执行，不会被阻塞
pthread_mutex_trylock(&mutex)
它用于尝试以非阻塞方式获取互斥锁（mutex）的所有权。

具体来说，尝试获取互斥锁的过程如下：
	如果互斥锁当前没有被其他线程占有，则该函数会立即获取互斥锁，并返回 0 表示成功获取锁。
	如果互斥锁当前被其他线程占有，则该函数会立即返回一个非零值，表示无法获取锁。

通过使用 pthread_mutex_trylock 函数，线程可以尝试获取锁而不会被阻塞。
这对于需要在获取锁时避免线程阻塞的情况非常有用。通常情况下，
我们可以在调用 pthread_mutex_trylock 之前，先使用 pthread_mutex_init 初始化 mutex 对象，
然后再使用 pthread_mutex_lock 或 pthread_mutex_trylock 进行加锁操作。
需要注意的是，当使用 pthread_mutex_trylock 时，我们需要谨慎处理返回值，
根据返回值进行相应的处理逻辑，以确保正确地处理互斥锁的获取与释放。
```

### 4.6 信号量

#### 1.使用pthread发送消息都第一次尝试

```c
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#define MSG_MAX 100

int thread_count; // 线程数

char *message[16]; // 信箱
void *Send_msg(void *rank);
int main(int argc, char *argv[])
{
    long i;
    pthread_t *thread_handles;
    thread_count = strtol(argv[1], NULL, 10);

    thread_handles = (pthread_t *)malloc(thread_count * sizeof(pthread_t));

    for (i = 0; i < thread_count; i++)
    {
        pthread_create(&thread_handles[i], NULL, Send_msg, (void *)i);

void *Send_msg(void *rank)
{
    long my_rank = (long)rank;
    // printf("hello from thread  = %d\n", my_rank);
    long dest = (my_rank + 1) % thread_count;                  // 给谁发消息
    long source = (my_rank + thread_count - 1) % thread_count; // 收谁的消息
    char *my_msg = malloc(MSG_MAX * sizeof(char));
    sprintf(my_msg, "Hello to %ld ,from %ld\n", dest, my_rank);

    message[dest] = my_msg;//全局信箱

    if(message[my_rank] != NULL){
        printf("Thread %ld > %s\n",my_rank, message[my_rank]);
    }else{
        printf("Thread %ld > No message from %ld\n",my_rank,source);
    }
```

#### 2.使用pthread发送消息都第二次尝试，使用互斥量数组

```c
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#define MSG_MAX 100

int thread_count;          // 线程数
pthread_mutex_t mutex[16]; // 先保证大于线程数
char *message[16];         // 信箱
void *Send_msg(void *rank);
int main(int argc, char *argv[])
{
    long i;
    pthread_t *thread_handles;
    thread_count = strtol(argv[1], NULL, 10);

    thread_handles = (pthread_t *)malloc(thread_count * sizeof(pthread_t));
    //初始化互斥量
    for (i = 0; i < thread_count; i++)
    {
        pthread_mutex_init(&mutex[i],NULL);
    }

    for (i = 0; i < thread_count; i++)
    {
        pthread_create(&thread_handles[i], NULL, Send_msg, (void *)i);
    }

    for (i = 0; i < thread_count; i++)
    {
        pthread_join(thread_handles[i], NULL);
    }
    //销毁互斥量
    for (i = 0; i < sizeof(mutex)/sizeof(pthread_mutex_t); i++)
    {
        pthread_mutex_destroy(&mutex[i]);
    }

    free(thread_handles);

    return 0;
}
void *Send_msg(void *rank)
{
    long my_rank = (long)rank;
    // printf("hello from thread  = %d\n", my_rank);
    long dest = (my_rank + 1) % thread_count;                  // 给谁发消息
    long source = (my_rank + thread_count - 1) % thread_count; // 收谁的消息
    char *my_msg = malloc(MSG_MAX * sizeof(char));
    sprintf(my_msg, "Hello to %ld ,from %ld\n", dest, my_rank);
    pthread_mutex_lock(&mutex[dest]);
    message[dest] = my_msg; // 全局信箱
    pthread_mutex_unlock(&mutex[dest]);

    pthread_mutex_lock(&mutex[my_rank]);
    if (message[my_rank] != NULL)
    {
        printf("Thread %ld > %s\n", my_rank, message[my_rank]);
    }
    else
    {
        printf("Thread %ld > No message from %ld\n", my_rank, source);
    }
    pthread_mutex_unlock(&mutex[my_rank]);
    return NULL;
}
```

它的意图是在该线程输出自己的信息时，可能正在放入消息，需要等放完消息（锁一下），才能获取信箱中的消息。

#### 3.使用pthread发送消息都第三次尝试，使用信号量数组

```c
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include<semaphore.h>
#define MSG_MAX 100

int thread_count;          // 线程数
sem_t semaphores[16];       //先保证信号量的个数，信号量是需要初始化值的，也就是初始资源数
char *message[16];         // 信箱
void *Send_msg(void *rank);
int main(int argc, char *argv[])
{
    long i;
    pthread_t *thread_handles;
    thread_count = strtol(argv[1], NULL, 10);

    thread_handles = (pthread_t *)malloc(thread_count * sizeof(pthread_t));
    //初始化信号量
    for (i = 0; i < thread_count; i++)
    {
        sem_init(&semaphores[i],0,0);
    }

    for (i = 0; i < thread_count; i++)
    {
        pthread_create(&thread_handles[i], NULL, Send_msg, (void *)i);
    }

    for (i = 0; i < thread_count; i++)
    {
        pthread_join(thread_handles[i], NULL);
    }
    //销毁互斥量
    for (i = 0; i < sizeof(semaphores)/sizeof(pthread_mutex_t); i++)
    {
        sem_destroy(&semaphores[i]);
    }

    free(thread_handles);

    return 0;
}
void *Send_msg(void *rank)
{
    long my_rank = (long)rank;
    // printf("hello from thread  = %d\n", my_rank);
    long dest = (my_rank + 1) % thread_count;                  // 给谁发消息
    long source = (my_rank + thread_count - 1) % thread_count; // 收谁的消息
    char *my_msg = malloc(MSG_MAX * sizeof(char));
    sprintf(my_msg, "Hello to %ld ,from %ld\n", dest, my_rank);
    
    message[dest] = my_msg; // 全局信箱
    sem_post(&semaphores[dest]);

    sem_wait(&semaphores[my_rank]);
    if (message[my_rank] != NULL)
    {
        printf("Thread %ld > %s\n", my_rank, message[my_rank]);
    }
    else
    {
        printf("Thread %ld > No message from %ld\n", my_rank, source);
    }
    return NULL;
}
```

### 4.7 路障和条件变量

> 路障的作用：
> 1. 统计程序耗时
> 2. 作为调试使用

#### 1.忙等待和互斥量共同实现路障

```c
int counter = 0; 
int thread_count;
pthread_mytex_t barrier_mutex;

void* Thread_work(...){
    /*Barrier*/
    pthread_mutex_lock(&barrier_mutex);
    counter++;
    pthread_mutex_unlock(&barrier_mutex);
    while(counter < thread_count);
```

> 缺点：
> 1. 使用忙等待会浪费CPU资源
> 2. 有多少个路障必须要有多少个不同的共享的counter变量，因为原counter变量置0必定会出问题。

#### 2.信号量来实现路障

```c
int counter = 0;
sem_t count_sem;   // 将初始化为1
sem_t barrier_sem; // 将初始化为0
void *Thread_work()
{
    int j ;
    /*Barrier*/
    sem_wait(&count_sem);//依次进入，临界区是counter++
    if(counter == thread_count - 1){
        counter = 0;//复用counter变量作为下一个阻塞变量使用。所以要置为0
        sem_post(&count_sem);
        for(j = 0 ; j<thread_count- 1; j++){//最慢的线程执行thread_count - 1次
            sem_post(&barrier_sem);
        }
    }else{
        counter++;
        sem_post(&count_sem);
        sem_wait(&barrier_sem);
    }
}
```

> - 假设 `thread_count = 4，0，1，2` 被阻塞在第 `18` 行，当线程 `3` 执行for循环的时候，线程 `0，1，2` 依次继续运行。而最慢的线程 `3` 不会第 `18` 行阻塞，因为进入的是 `if` 不是 `else` 。
> - 这感觉就像伪阻塞，只有最慢线程 `for` 循环运行的快，才能相当于阻塞了所有线程。一般执行多次循环之后， `barrier_sem` 已经是较大的正数， `sem_wait` 才慢慢开始解锁。
> - 每一个被 `18行` 阻塞的线程，不会将 `barrier_sem` 减 `1` 。
> - 优点：
>    - 使用信号量，阻塞的线程不白白占用CPU资源。
>    - 复用 `counter` 变量和 `count_sem` 变量作为下一个阻塞变量使用。
> - 缺点：
>    - `barrier_sem` 无法重用。如果最慢的线程 `3` 执行完 `if` 后，很快的通过第二个路障的 `sem_wait(&barrier_sem)` 就使有个倒霉线程无法通过第一个路障的 `sem_wait(&barrier)` 。

#### 3.条件变量来实现路障

```c
int counter = 0;
pthread_mutex_t mutex; //实现counter++临界访问
pthread_cond_t cond_var; //实现线程的阻塞
void * Thread_work(void* rank)
{
    long my_rank = (long)rank;
    int j ;
    /*Barrier*/
    pthread_mutex_lock(&mutex);
    counter++;
    if(counter == thread_count){
        counter = 0;
        pthread_cond_broadcast(&cond_var);//唤醒被条件变量阻塞的所有线程
    }else{
        while(pthread_cond_wait(&cond_var,&mutex) != 0);
    }
    pthread_mutex_unlock(&mutex);
}
```

```c
pthread_cond_wait相当于循序执行下面三条语句：
```

### 4.8 读写锁

```c

```

```c
//初始化
pthread_rwlock_init(pthread_rwlock_t *rwlock_,    			//读写锁指针
                    const pthread_rwlockattr_t *attr		//与互斥量一样不使用第二个参数，直接NULL
                   );
//销毁
pthread_rwlock_destroy(pthread_rwlock_t *l);				//读写锁指针
//读锁
pthread_rwlock_rdlock(pthread_rwlock_t *l);					//读写锁指针
//写锁
pthread_rwlock_wrlock(pthread_rwlock_t *l);					//读写锁指针
//解锁
pthread_rwlock_unlock(pthread_rwlock_t *l);					//读写锁指针
```

> 1. 任何线程拥有了读锁，则任何请求写锁的线程将阻塞在写锁函数的调用上。
> 2. 如果任何线程拥有了写锁，则任何想获取读或写锁的线程，将阻塞在它们对应的锁函数上。
> 3. 多个线程可以同时获取读锁。
> 4. Member链表查找操作，Insert和Delete是增删操作。
