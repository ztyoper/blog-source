### **三、重现问题**

为了更好的重现问题，我们以代码的形式给出案例，在案例代码中，会模拟实现一个文件下载客户端，并且会在多个线程中调用文件客户端下载文件。具体实现步骤如下所示。

**（1）实现FileClient类**

FileClient类主要是模拟实现文件客户端，提供了初始化客户端的initClient()方法，以及下载文件的方法downloadFile()方法。

源码详见：[io.binghe.concurrent.design.thread.close.common.FileClient](http://io.binghe.concurrent.design.thread.close.common.FileClient)。

public class FileClient {
​
  public void initClient(){
    System.out.println(Thread.currentThread().getName() + "初始化文件客户端开始");
    long startTime = System.currentTimeMillis();
    try {
      Thread.sleep(1000);
     } catch (InterruptedException e) {
      throw new RuntimeException(e);
     }
    System.out.println(Thread.currentThread().getName() + "初始化文件客户端完毕，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
​
  public void downloadFile(String fileName){
    System.out.println(Thread.currentThread().getName() + "下载文件开始");
    long startTime = System.currentTimeMillis();

      Thread.sleep(2000);
     } catch (InterruptedException e) {
      throw new RuntimeException(e);
     }
    System.out.println(Thread.currentThread().getName() + "下载文件完毕，下载的文件为：" + fileName + ", 耗时：" + (System.currentTimeMillis() - startTime) + "ms");

### **四、分析问题**

虽然写的案例代码中，看似输出的结果信息是正确的，但是我们结合真实的场景来分析下。真实场景下，导出报表数据时，由于统计的数据可能存在关联性，处理这些数据的时候，很大程度上不能使用多个线程去处理。也就是说，对于在业务上强关联的数据，不能分割成多个线程去处理，而是在同一个线程中处理这些数据，处理完后直接导出文件即可。并且在系统中创建的文件客户端对象，在多个线程间共享的话，也可能存在数据错乱的问题。所以，在分析统计强关联的数据时，我们需要在同一个线程中进行。

那看到这里，我相信有不少小伙伴会说，那就直接放到一个线程里执行不就完事儿了？但是，还有一个注意点就是，像这种比较耗时的导出文件的操作，不能阻塞后端服务接收请求的线程，所以，还是需要异步处理。但是异步处理时，关联性强的业务需要放在一个线程中执行任务。

想必不要小伙伴都知道怎么处理了，放到只有一个线程的线程池里不就完事儿了？其实咱菜哥也是这么想的，老王也是让他先这样试试，结果菜哥写出了FileThreadPoolTest类，源码详见：[io.binghe.concurrent.design.thread.close.wrong.FileThreadPoolTest](http://io.binghe.concurrent.design.thread.close.wrong.FileThreadPoolTest)。

```go
public class FileThreadPoolTest {
  private static final int COUNT = 10;
  private static final ThreadPoolExecutor THREAD_POOL_EXECUTOR = new ThreadPoolExecutor(
      1,
      1,
      30,
      TimeUnit.SECONDS,
      new LinkedBlockingQueue<>(100));
​
  public static void main(String[] args) throws InterruptedException {
    CountDownLatch countDownLatch = new CountDownLatch(COUNT);
    FileService fileService = new FileServiceImpl();
    for (int i = 1; i <= COUNT; i++){
      int finalI = i;
      THREAD_POOL_EXECUTOR.execute(() -> {
        fileService.downloadFile("binghe00" + finalI);
        countDownLatch.countDown();
       });
     }
    countDownLatch.await();
    THREAD_POOL_EXECUTOR.shutdown();
   }
}
```

可以看到，在模拟的案例中，我们将其修改成所有的下载任务都在线程池中同一个线程中执行，这样就不会因为在多个线程中执行任务而发生数据错乱了。

小菜按照这个思路修改了导出报表的功能，经测试，也不会出现数据错乱的问题了。不过这种解决方案不是最优的，在并发设计模式中，有一种设计模式叫做串行线程封闭模式，比较适合这种场景。。。
