其实大家对生产者消费者模式并不陌生了，生产者和消费者模式中有三个重要角色，生产者、任务队列、消费者。生产者提交任务到队列，消费者从队列中取出任务进行处理。市面上比较成熟的消息中间件，像RocketMQ、RabbitMQ、Kafka以及ActiveMQ等，都是基于生产者和消费者模式进行设计的，也在大量的项目中得到的广泛的应用。

### **三、个人文库核心需求**

“为了便于你理解，我还是写几个接口和类来模拟个人文库系统，实现流程与个人文库系统相似”。

“好的”，小菜回应到。

对于个人文库系统来说，用户可以将自己的文档上传到文库中进行管理，个人文库系统会存储这些文档，并且会存储用户的业务数据。另外，个人文库系统后续根据用户的需要，可以根据文档的名称、文档里的关键词进行检索，以便快速定位和搜索用户上传过的文档，这就需要为上传的文档简历索引。所以，对于个人文库项目来说，核心业务有三个，分别是：存储文档、存储业务数据、建立文档索引，如图24-1所示。

而这三个核心功能的数据，要分别存储到不同的服务器上，比如存储文档时，要将文档存储到文件服务器。存储业务数据时，要将业务数据存储到数据库服务器。建立文档索引时，需要将索引文档存储到搜索引擎服务器，如图24-2所示。

### **四、问题分析**

仔细分析下个人文库系统的业务，其实对于用户来说，用户在个人文库系统中进行操作时，存储文档和存储业务的逻辑是用户可以直接触发的业务逻辑，为文档建立索引，则是用户上传完文档后，个人文库系统自身需要处理的事情，并且为文档生成索引是个比较耗时的操作。

但是，在个人文库的实现中，却把这三个步骤全部串行化执行在同一个业务逻辑中，使用的用户少时，问题还不太明显，只要使用的用户人数多起来，就会非常卡了，如图24-3所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/92af5fbe5a3d754756176ae65b403f70d5f4b86360c48f415d96bc6293aaa890.png)

将本就对用户操作关系不大的，并且非常耗时的建立文档索引的逻辑放到用户操作的逻辑中执行，一旦使用人数比较多时，就可能造成卡顿，给用户直观的感受可能就是页面卡死了，对用户的体验是非常差的。

### **五、模拟实现**

为了更直观的重现问题，这里，我们以简单的类和接口来模拟实现优化前的个人文库系统的核心逻辑，在模拟实现的个人文库代码中，主要包含三个接口和三个实现类，以及一个测试类，类图如图24-4所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/9fb8fe85f8df5b65dda40e93c3e52b2a4df596dc2952f87cd3d1f1d5fea20890.png)

根据类图，我们可以快速模拟实现个人文库系统的代码，具体实现步骤如下所示。

**（1）实现DBService类**

DBService类表示模拟实现的存储数据的接口，源码详见：concurrent-design-patterns-producer-comsumer工程下的[io.binghe.concurrent.design.pc.wrong.service.DBService](http://io.binghe.concurrent.design.pc.wrong.service.DBService)。

```go
public interface DBService {
  void save(String businessData);
}
```

**（2）实现DBServiceImpl类**

DBServiceImpl类表示模拟实现的存储数据的实现类，源码详见：concurrent-design-patterns-producer-comsumer工程下的[io.binghe.concurrent.design.pc.wrong.impl.DBServiceImpl](http://io.binghe.concurrent.design.pc.wrong.impl.DBServiceImpl)。

```go
public class DBServiceImpl implements DBService {
  @Override
  public void save(String businessData) {
    System.out.println("保存业务数据开始");
    long startTime = System.currentTimeMillis();
    System.out.println("保存业务数据成功：" + businessData);
    System.out.println("保存业务数据结束，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
}
```

**（3）实现UploadService接口**

UploadService接口表示模式实现的上传存储文件的接口，源码详见：concurrent-design-patterns-producer-comsumer工程下的[io.binghe.concurrent.design.pc.wrong.service.UploadService](http://io.binghe.concurrent.design.pc.wrong.service.UploadService)。

```go
public interface UploadService {
  void upload(String ... fileNames);
}
```

**（4）实现UploadServiceImpl类**

UploadServiceImpl类表示模式实现的上传存储文件的实现类，源码详见：concurrent-design-patterns-producer-comsumer工程下的[io.binghe.concurrent.design.pc.wrong.service.UploadServiceImpl](http://io.binghe.concurrent.design.pc.wrong.service.UploadServiceImpl)。

```go
public class UploadServiceImpl implements UploadService {
  @Override
  public void upload(String... fileNames) {
    System.out.println("上传文件开始");
    long startTime = System.currentTimeMillis();
    System.out.println("上传文件成功，上传的文件如下所示：");
    Arrays.stream(fileNames).forEach(System.out::println);
    System.out.println("上传文件结束，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
}
```

**（5）实现IndexService接口**

IndexService接口表示模式实现的建立文档索引的接口，源码详见：concurrent-design-patterns-producer-comsumer工程下的[io.binghe.concurrent.design.pc.wrong.service.IndexService](http://io.binghe.concurrent.design.pc.wrong.service.IndexService)。

```go
public interface IndexService {
  void index(String ... fileNames);
}
```

**（6）实现IndexServiceImpl类**

IndexServiceImpl类表示模式实现的建立文档索引的类，源码详见：concurrent-design-patterns-producer-comsumer工程下的[io.binghe.concurrent.design.pc.wrong.service.IndexServiceImpl](http://io.binghe.concurrent.design.pc.wrong.service.IndexServiceImpl)。

```go
public class IndexServiceImpl implements IndexService {
  @Override
  public void index(String... fileNames) {
    System.out.println("索引文件数据开始");
    long startTime = System.currentTimeMillis();
    try {
      Thread.sleep(5000);
     } catch (InterruptedException e) {
      throw new RuntimeException(e);
     }
    System.out.println("索引文件数据成功");
    System.out.println("索引文件数据结束，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
}
```

可以看到，为了模拟建立文档索引的耗时操作，这里使线程休眠了5秒。

**（7）实现PCWrongTest类**

PCWrongTest类表示程序代码的测试类，源码详见：concurrent-design-patterns-producer-comsumer工程下的[io.binghe.concurrent.design.pc.wrong.PCWrongTest](http://io.binghe.concurrent.design.pc.wrong.PCWrongTest)。

```go
public class PCWrongTest {
​
  public static void main(String[] args) {
    System.out.println("总体任务开始");
    long startTime = System.currentTimeMillis();
​
    DBService dbService = new DBServiceImpl();
    dbService.save("bingheSaveData");
​
    UploadService uploadService = new UploadServiceImpl();
    uploadService.upload("bingheUploadFile001", "bingheUploadFile002");
​
    IndexService indexService = new IndexServiceImpl();
    indexService.index("bingheIndexFile001", "bingheIndexFile002");
​
    System.out.println("总体任务结束，耗时：" + (System.currentTimeMillis() - startTime));
   }
}
```

接下来，我们就运行下PCWrongTest类，看看将与用户操作无关的，并且耗时的建立文档索引操作的逻辑，放到用户操作的业务逻辑中的耗时情况。

运行下PCWrongTest类，输出的结果信息如下所示。

```go
总体任务开始
保存业务数据开始
保存业务数据成功：bingheSaveData
保存业务数据结束，耗时：0ms
上传文件开始
上传文件成功，上传的文件如下所示：
bingheUploadFile001
bingheUploadFile002
上传文件结束，耗时：61ms
索引文件数据开始
索引文件数据成功
索引文件数据结束，耗时：5001ms
总体任务结束，耗时：5068
```

从输出的结果信息可以看出，虽然建立文档索引的逻辑与用户操作无关，但是将其放到用户操作的业务逻辑中，明显已经严重影响用户操作的性能体验。

所以，建立文档索引本就是系统后台自己处理的事情，不要与用户操作相关的逻辑关联，将其分离出来，能够极大的提升系统的性能。
