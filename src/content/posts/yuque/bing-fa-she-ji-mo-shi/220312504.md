承诺模式本质上还是多个线程并行执行项目， 当项目中存在多个关联性不强的业务，哪怕多个关联性不强的业务之间存在一定的关联性，比如业务A和业务B，业务A虽然和业务B在主体逻辑的执行上关联性不大，但是业务A的执行需要业务B的执行结果，此时，都可以使用承诺模式实现。

那使用承诺模式要如何实现程序的并行执行呢？其实就是可以先开始一个任务的执行，并且得到一个用于获取这个任务执行结果的凭据对象，不用等到这个任务执行完毕再去执行其他的业务逻辑，如果需要获取执行任务的结果，可以调用凭据对象的相关方法来获取结果数据。

### **四、优化代码**

在案例程序中，我们模拟了用户下单支付成功后的操作，也就是向用户发送积分和优惠券，这次优化的重点就是并行执行向用户发送积分和发送优惠券的逻辑，但是不能影响结果的正确性。

这里，为了更好的实现功能，我们单独实现一个Promisor类来执行异步任务。

说完，老王便开始敲起了代码，不一会儿，就实现了Promisor类。

Promisor类的源码详见：concurrent-design-patterns-promise工程下的[io.binghe.concurrent.design.promise.right.Promisor](http://io.binghe.concurrent.design.promise.right.Promisor)。

```go
public class Promisor {
  public Future<Object> compute(IntegralService integralService) {
    //创建一个异步任务
    FutureTask<Object> futureTask = new FutureTask<>(() -> {
      //发送积分
      System.out.println("发送积分任务开始");
      long integralStartTime = System.currentTimeMillis();
      Integral integral = integralService.sendIntegral();
      System.out.println("发送积分任务结束，当前发送积分耗时：" + (System.currentTimeMillis() - integralStartTime) + "ms");
      return integral;
     });
    new Thread(futureTask).start();
    return futureTask;
   }
}
```

可以看到，在基于Promise模式优化案例代码时，将两个关联性不强的其中一个业务分离到Promisor类的compute()方法中，并将主要的业务逻辑封装到futureTask的实现中，最终，启动一个线程来执行futureTask任务，并且不等待线程执行完成就直接返回futureTask对象，这里的futureTask对象就是Promise凭据对象。

实现完Promisor类的代码，老王又开始写测试类PromiseRightTest的代码，弹指一挥间，老王便写完了PromiseRightTest类的代码。

PromiseRightTest类的源码详见：concurrent-design-patterns-promise工程下的[io.binghe.concurrent.design.promise.right.PromiseRightTest](http://io.binghe.concurrent.design.promise.right.PromiseRightTest)。

可以看到，在PromiseRightTest类的代码中，通过向Promisor类的compute()方法传递IntegralService接口的对象，实现异步执行发送积分的任务，此时Promisor类的compute()方法会直接返回Promise对象。这里，体现了尽可能早的调用Promisor的compute()方法来执行异步任务。

随后，便开始执行发送优惠券的任务，当执行完发送优惠券的任务后，调用Promise对象的isDone()检测发送积分的任务是否已经完毕。接下来，会调用Promise对象的get()方法来获取异步发送积分的任务结果，此时如果异步发送积分的任务还没执行完毕，get()方法就会阻塞，直到发送积分的异步任务执行完毕。

发送积分和发送优惠券的任务都执行完毕后，就会打印最终的结果数据。

### **五、本章总结**

基于承诺模式可以实现真正并行执行关联性不强的业务，在执行异步任务时，无需等待异步任务执行完毕即可直接返回一个凭据对象，后续可以根据这个凭据对象来获取异步任务的执行结果，极大的提高了程序的性能和系统的并发度。本章，基于Promise模式实现了发送积分和发送优惠券两个任务的并行执行，并且使用到了JDK中的FuturerTask类。
