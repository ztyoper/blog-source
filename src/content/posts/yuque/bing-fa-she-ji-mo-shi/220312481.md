### **三、一探究竟**

“等效不可变对象的意思就是创建出来的对象基本符合不可变的原则和特征，但是还是存在部分差异，在某些情况下这些对象的内部状态可能会发生变化”，老王来到会议室，边打开电脑边说，“这么说的话可能有点不好理解，我们结合JDK中的CopyOnWriteArrayList类进行分析，其实CopyOnWriteArrayList类就是一个典型的等效不可变类”。

“我了解过CopyOnWriteArrayList类，在添加、修改和删除元素时，不会在原来的数组上操作，会创建一个新的数组，添加、修改和删除完元素时，会将引用指向新的数组对象。遍历和读取元素时，会在原来的数组上操作”，小菜说道。

“对，是的，对CopyOnWriteArrayList的读操作会在原来的数组上进行，写操作会创建一个新的数组对象，今天我们就好好讲讲这个CopyOnWriteArrayList类”，老王边说边打开了CopyOnWriteArrayList的源码，继续说道：“来看下CopyOnWriteArrayList的源码，我们结合源码说它为何是一个等效不可变类”。

```go
public class CopyOnWriteArrayList<E>
    implements List<E>, RandomAccess, Cloneable, java.io.Serializable {
    private static final long serialVersionUID = 8673264195747942595L;
​
    /** The lock protecting all mutators */
    final transient ReentrantLock lock = new ReentrantLock();
​
    /** The array, accessed only via getArray/setArray. */
    private transient volatile Object[] array;
​
    /**
    * Gets the array. Non-private so as to also be accessible
    * from CopyOnWriteArraySet class.
    */
    final Object[] getArray() {
        return array;
    }
​
    /**
    * Sets the array.
    */
    final void setArray(Object[] a) {
        array = a;
    }
    /**************暂时忽略其他代码***************/
}
```

“这里，可以看到，在CopyOnWriteArrayList类中，会维护一个Object类型的数组array，并且会通过getArray()和setArray()方法来访问array数组”，老王打开CopyOnWriteArrayList类的源码结合上述代码片段对小菜说。

“接下来，咱们再来看看CopyOnWriteArrayList类遍历元素的方法，这个方法就是iterator()方法”。

```go
public Iterator<E> iterator() {
    return new COWIterator<E>(getArray(), 0);
}
```

“可以看到，在iterator()方法遍历数组时，会调用getArray()方法获取CopyOnWriteArrayList本身的array数组，基于这个array数组遍历其中的元素”。

“我们再来看看向CopyOnWriteArrayList中添加元素的方法”，说着老王便定位到如下的代码片段。

```go
public boolean add(E e) {
    final ReentrantLock lock = this.lock;
    lock.lock();
    try {
        Object[] elements = getArray();
        int len = elements.length;
        Object[] newElements = Arrays.copyOf(elements, len + 1);
        newElements[len] = e;
        setArray(newElements);
        return true;
    } finally {
        lock.unlock();
    }
}
```

可以看到，在boolean add(E e)方法中，首先获取ReentrantLock锁，获取到锁之后，调用getArray()方法获取array引用，并将其赋值给Object数组类型的局部变量elements，获取elements数组的长度，随后将elements数组的元素复制到一个比elements数组长度加1的数组中，并将结果赋值给Object类型的数组newElements。

接下来，将传入的参数e添加到newElements数据的末尾。随后调用setArray()方法将newElements数组赋值给array引用。最后返回true并释放ReentrantLock锁。

通过上述分析，可以得知，当有多个线程同时执行boolean add(E e)方法时，只有获取到ReentrantLock锁的线程才能执行boolean add(E e)方法的逻辑。并且添加元素时，首先会将array指向的原来的数组复制一份副本出来，在数组副本中执行添加元素的操作，添加成功后将数组副本赋值给array引用。整个添加元素的过程不会影响从CopyOnWriteArrayList中读取数据。

“所以，在CopyOnWriteArrayList中会创建一个新数组进行数据的写操作，在原来数组的基础上进行读操作”，老王补充道。

“这些能听懂吧？”，老王问小菜。

“能听懂”，小菜回应说。

“好，那我们举例说明一下为何CopyOnWriteArrayList中的array数组是一个等效不可变对象，而不是一个不可变对象”。

### **四、探究等效不可变**

“根据我们之前对CopyOnWriteArrayList的分析，在array数组被创建之后，其实数组中的数据就不会被修改了，就算是向CopyOnWriteArrayList中添加和移除元素，也不会直接修改CopyOnWriteArrayList中的array数组，而是会创建一个数组，替换CopyOnWriteArrayList中原来的数组”，老王总结道。

“但是为什么说CopyOnWriteArrayList中的array只能算是一个等效不可变对象呢？这是因为array数组保存的元素是对象，每个对象内部的状态是可以变化的，所以array对象算不上是真正的不可变对象，最多算是等效不可变对象”。

“老大，这里我有点听不懂了”。

“不急，我们写个代码示例来说明下”，于是老王又开始噼里啪啦的敲起了键盘，不到一分钟，敲了一个CopyOnWriteArrayListTest类。源码详见：concurrent-design-patterns-immutable工程下的[io.binghe.concurrent.design.cow.CopyOnWriteArrayListTest](http://io.binghe.concurrent.design.cow.CopyOnWriteArrayListTest)。

```go
public class CopyOnWriteArrayListTest {
    @Test
    public void testCopyOnWriteArrayList(){
        List<User> list = new CopyOnWriteArrayList<>();
        User user = new User("binghe001");
        list.add(user);
​
        User user1 = list.get(0);
        System.out.println("user1对象的hashCode为===>>" + user1.hashCode() + "数据为===>>" + user1.toString());
​
        user.setName("binghe002");
​
        User user2 = list.get(0);
        System.out.println("user2对象的hashCode为===>>" + user2.hashCode() + "数据为===>>" + user2.toString());
​
    }
}
```

“CopyOnWriteArrayListTest类的实现也比较简单，就是提供了一个testCopyOnWriteArrayList()方法对CopyOnWriteArrayList进行测试。首先会在testCopyOnWriteArrayList()方法中创建一个CopyOnWriteArrayList类型的list集合对象，再创建一个user对象，此时user对象的name为binghe001，将user对象放入list集合中，随后从list集合中取出user对象打印其hashCode和存储的数据。”，老王喝了口水。

“接下来是重点，我们通过user的setName()方法将name修改为binghe002，再从list集合中获取到user对象，随后打印其hashCode和存储的数据，这里能看懂吗？”，老王问小菜。

“这里，为啥要打印hashCode呢？用户的名称变了，hashCode会不一样吧？”，小菜小声的说。

“呵呵”，老王笑了笑，“那我们运行下代码看看执行结果吧”。

老王运行了下代码，输出的结果信息如下所示。

```go
user1对象的hashCode为===>>1323468230数据为===>>User{name='binghe001'}
user2对象的hashCode为===>>1323468230数据为===>>User{name='binghe002'}
```

“咦？怎么hashCode值一样呢？”，小菜嘀咕着。

“怎么样，跟想象的不太一样吧？”，老王说道：“其实，在CopyOnWriteArrayList中，对于array数组来说，数组中的元素不会改变，也就是说，数组中的元素不会从hashCode为1001，变成hashCode为1002，但是CopyOnWriteArrayList没有办法限制调用者的行为。就像测试代码中写的，向CopyOnWriteArrayList中添加name为binghe001的user对象后，又将name设置为binghe002，尽管user对象的name值变化了，但是其hashCode是不变的”。

“这里听明白了”，小菜说道。

“CopyOnWriteArrayList中的array数组存储的对象元素是不可变的，但是对象元素内部的状态可能会被调用者修改，所以，array数组是等效不可变对象”，老王继续补充道。

“这下应该明白了吧，再给你讲讲CopyOnWriteArrayList里的一个很重要的写时复制技术吧”。

### **五、写时复制技术**

“写时复制技术理解起来也比较简单，所谓的写时复制技术，从字面意思理解就是写的时候复制出一个副本，读的时候还是读原来的数据。这样做的优点就是在读取CopyOnWriteArrayList中的数据时，可以完全无锁化处理，能够极大的提升读取数据的性能。这里，我们结合图解的方式以CopyOnWriteArrayList为例说说写时复制技术”。

“先来看通过CopyOnWriteArrayList的get()方法读取数据的情况”，说着老王便画了一张读取CopyOnWriteArrayList中的数据图，如图7-1所示。

“CopyOnWriteArrayList中的成员变量array指向内部数组的首地址，使用CopyOnWriteArrayList类中的get()方法读取数据时，会从array引用指向的原来的内部数组中读取数据。”，老王解释道。

“我们再来看看使用Iterator迭代器遍历CopyOnWriteArrayList的情况”，老王又画了一张使用Iterator迭代器遍历数组的图，如图7-2所示。

“使用Iterator迭代器遍历CopyOnWriteArrayList时，实际上遍历的还是CopyOnWriteArrayList中array引用指向的原来的内部数组。如果使用E get(int index)方法获取CopyOnWriteArrayList中的数据时，另一个线程向CopyOnWriteArrayList中添加元素，此时的效果如何呢？我们再来看一张图”，此时老王又画了一张读数据时向CopyOnWriteArrayList中添加数据的图，如图7-3所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/1fbf6e9e218501c634753dd2f609a70d22b6bec55301ae35f0f305ed42d36453.png)

“当使用get()方法读取CopyOnWriteArrayList中的数据时，如果此时有其他线程对CopyOnWriteArrayList进行写操作，则get()方法还是从原来的数组中读取数据，而其他线程向CopyOnWriteArrayList中添加数据时，首先会将原来的数组复制一份副本出来，在复制出来的数组副本中添加数据，然后将array引用指向新的数组副本。”，老王补充道。

“当使用Iterator遍历CopyOnWriteArrayList时，会直接在array引用指向的原来的数组上进行遍历操作，如果此时有其他线程删除CopyOnWriteArrayList中的元素，则其他线程首先会将原来的数组复制一份副本出来，在复制出来的数组副本中删除对应的元素，然后将array引用指向新的数组副本。”，老王继续道：“好了，这就是咱们今天要讲的内容了，看看哪里还有不懂的吗？”。

### **六、本章总结**

本章，主要以CopyOnWriteArrayList为例，介绍了等效不可变类，等效不可变类并不是严格意义上的不可变类，等效不可变类中的对象内部状态可能会发生变化，但是对象一经创建，其hashCode等信息是不会变化的。另外，重点介绍了写时复制技术。

无论是CopyOnWriteArrayList还是写时复制技术，比较适合应用在读多写少的场景，在读少写多，或者读写相差不大的场景，不太适用。
