在某些社区电商项目中，对于商品来说，有些商品的访问链接是非常长的，不利于商品访问的跟踪和监控，此时，就需要对商品的链接进行处理，通过长链接再生成一个短链接存储起来，用户既可以通过长链接访问商品，也可以通过短链接访问商品。

这就好比是公众号的文章，同一篇公众号的文章，也会存在一个长链接和一个短链接，用户既可以通过长链接访问公众号的文章，也可以通过短链接访问公众号的文章，例如下面是冰河技术微信公众号的同一篇文章，但是大家打开后发现在浏览器地址栏显示出的却不是同一个链接地址，一个链接地址很长，一个链接地址却很短。

1. 长链接：《 实践出真知：全网最强秒杀系统架构解密！！ 》

2. 短链接：《 实践出真知：全网最强秒杀系统架构解密！！ 》

那短链接是怎么生成的呢？又怎么会出现商品404的重大事故问题呢？

### **一、故事背景**

由于大量的用户反馈社区电商项目的商品链接太长，不便于识别和转发给好友，同时，运维也反馈商品链接太长，不利于监控和跟踪商品的访问情况。于是公司的技术部门决定为商品在长链接的基础上再生成一个短链接存储，这样用户既可以通过原有的长链接访问商品，也可以通过生成的短链接访问商品。

最终，这个需求被分到了小菜的头上，经过小菜的不懈努力，最终完成了商品长链接到短链接的转换，没想到提交测试后，却出现了访问商品链接404的重大问题。

#### **2.2 技术流程**

站在技术角度分析流程时，就需要考虑到部分细节的实现问题了，站在用户的角度看，虽然用户既能够通过长链接访问商品，也能够通过短链接访问商品。但是，站在技术角度和实现角度来说，最终还是通过长链接实现的对商品的访问功能。这就需要在基于商品长链接的基础上生成短链接时，保存长短链接的映射关系，如图30-3所示。

### **四、代码实现**

根据代码的类结构关系，代码的实现过程如下所示。

**（1）实现Goods类**

Goods类表示商品的实体类，源码详见：concurrent-design-patterns-active-object工程下的[io.binghe.concurrent.design.active.object.wrong.Goods](http://io.binghe.concurrent.design.active.object.wrong.Goods)。

```go
public class Goods {
  private Long id;

  private String longUrl;
  
    public Goods() {
   }
  
  public Goods(Long id, String goodsName, String longUrl) {
    this.id = id;
    this.goodsName = goodsName;
    this.longUrl = longUrl;
   }
  /******省略getter/setter**********/
```

**（2）实现URLService接口**

URLService接口的主要功能是定义了根据长链接转换短链接的方法、保存长短链接映射关系的方法和根据短链接从长短链接映射关系中获取长链接的方法。

源码详见：concurrent-design-patterns-active-object工程下的[io.binghe.concurrent.design.active.object.wrong.URLService](http://io.binghe.concurrent.design.active.object.wrong.URLService)。

```go
public interface URLService {
  String getShortUrl(String longUrl);
  void saveUrl(String shortUrl, String longUrl);
  String getLongUrlByShortUrl(String shortUrl);
}
```

**（3）实现URLServiceImpl类**

URLServiceImpl类主要是URLService接口的实现类，主要实现了根据长链接转换短链接的方法、保存长短链接映射关系的方法和根据短链接从长短链接映射关系中获取长链接的方法。

源码详见：concurrent-design-patterns-active-object工程下的[io.binghe.concurrent.design.active.object.wrong.URLServiceImpl](http://io.binghe.concurrent.design.active.object.wrong.URLServiceImpl)。

```go
public class URLServiceImpl implements URLService{
​
  private static final ConcurrentMap<String, String> URL_MAP = new ConcurrentHashMap<>();
  @Override
  public String getShortUrl(String longUrl) {
    System.out.println("长链接转换短链接开始");
    long startTime = System.currentTimeMillis();
    try{
      return URLTransfer.generateShortLink(longUrl);
     }finally {
      System.out.println("长链接转换短链接结束，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
     }
   }
​
  @Override
  public void saveUrl(String shortUrl, String longUrl) {
    System.out.println("保存长短链接的映射关系开始");
    long startTime = System.currentTimeMillis();
    try {
      Thread.sleep(1000);
      URL_MAP.put(shortUrl, longUrl);
      System.out.println("保存长短链接的映射关系结束，短链接：" + shortUrl + ", 长链接：" + longUrl);
     } catch (InterruptedException e) {
      throw new RuntimeException(e);
     }
    System.out.println("保存长短链接的映射关系结束，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
​
  @Override
  public String getLongUrlByShortUrl(String shortUrl) {
    return URL_MAP.get(shortUrl);
   }
}
```

**（4）实现GoodsService接口**

GoodsService接口是商品业务相关的接口，主要定义了保存商品信息的方法。

源码详见：concurrent-design-patterns-active-object工程下的[io.binghe.concurrent.design.active.object.wrong.GoodsService](http://io.binghe.concurrent.design.active.object.wrong.GoodsService)。

```go
public interface GoodsService {
  String saveGoods(Goods goods);
}
```

**（5）实现GoodsServiceImpl类**

GoodsServiceImpl类是GoodsService接口的实现了，除了要实现GoodsService接口中定义的saveGoods()方法外，还要调用URLService接口定义的getShortUrl方法来实现长短链接的转换，并调用URLService接口定义的saveUrl()方法保存长短链接的映射关系。

源码详见：concurrent-design-patterns-active-object工程下的[io.binghe.concurrent.design.active.object.wrong.GoodsServiceImpl](http://io.binghe.concurrent.design.active.object.wrong.GoodsServiceImpl)。

```go
public class GoodsServiceImpl implements GoodsService{
​
  private URLService urlService = new URLServiceImpl();
​
  @Override
  public String saveGoods(Goods goods) {
    //保存商品
    this.saveGoodsToDb(goods);
    String longUrl = goods.getLongUrl();
    String shortUrl = urlService.getShortUrl(longUrl);
    urlService.saveUrl(shortUrl, longUrl);
    return shortUrl;
   }
​
  private void saveGoodsToDb(Goods goods){
    System.out.println("保存商品到数据库开始");
    long startTime = System.currentTimeMillis();
    try {
      Thread.sleep(2000);
      System.out.println("保存商品到数据库完毕，保存的数据为：" + goods.toString());
     } catch (InterruptedException e) {
      throw new RuntimeException(e);
     }
    System.out.println("保存商品到数据库结束，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
}
```

至此，商品长短链接的转换功能主要的业务逻辑就开放完毕了。
