两阶段终止模式会分为准备阶段和执行阶段，准备阶段就是通知目标线程准备停止，这一阶段主要是设置一个标志变量指示目标线程可以准备停止了。而执行阶段则是检查准备阶段设置的线程停止标识和信号，在此基础上确定线程停止的时机，并适当进行一定的“清理”工作。那么，在实际项目中，改如何应用两阶段终止模式呢？

其实，这里的报警发送器就是报警管理器中的线程，也就是说，报警发送器其实就是一个个上报告警信息的线程。报警管理器和报警发送器的关系就有点类似于操作系统中的进程和线程的关系，报警管理器就类似于操作系统中的进程，报警发送器就类似于操作系统中的线程，一个报警管理器中可以包含多个报警发送器。最终，会由报警管理器中的报警发送器上报告警信息。

搞清楚监控报警系统的大体执行流程后，就比较清楚基于两阶段终止模式优化哪部分流程了，其实就是要**基于两阶段终止模式优化报警发送器线程的退出流程，使其能够执行完任务后优雅的退出。**

如果不使用两阶段终止模式优化报警发送器线程的退出流程，就可能导致当前报警发送器线程还没执行完任务，就已经退出的问题，这就会造成任务的丢失，可能会导致一些重要的监控报警信息没有被上传到报警监控大盘，如图16-3所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/5746ede71627b81b8ca1e33b979125ff7709fd299e937e95f27da8e7d82fcf9c.png)

可以看到，如果在报警发送器线程退出时，不采用相应的措施时，会导致报警发送线程还未执行完任务就会退出，导致上报告警信息的流程被中断，可能导致部分上报告警信息的任务丢失，最终可能导致部分重要的监控告警信息没有被采集到报警监控大盘。

所以，在报警发送器线程退出之前，要执行完对应的任务，然后再退出，实现报警发送器线程的优雅退出，这样就不会导致上报监控报警信息的任务丢失，如图16-4所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/19f101a311343c43aa1dc4249e7fca9a41b55f44b40e2e14f4bce3d92aacbcd8.png)

可以看到，当报警发送器线程收到退出的信号时，将任务执行完毕后，再退出，就不会丢失上报告警信息的任务了，这样就能够实现报警发送器的优雅退出。

所以，对于监控报警系统来说，我们可以基于两阶段终止模式优化报警发送器的退出流程，使其能够执行完上报告警信息的任务后，再退出，实现优雅退出的目的。

### **四、代码设计**

在代码设计上，如果使用了两阶段终止模式，就不能简单粗暴的中断线程的执行了，而是为线程的执行设置一个标志位，标志这个线程是否正在执行。这个标志位就是两阶段终止模式中控制线程启停的标志位，又可以成为TerminationToken。

当线程接收到中断退出的信号时，需要具备继续完成剩余任务的能力，如何实现这些逻辑呢？其实，可以让报警管理器中的报警发送器符合一定的规则和标准，在Java中，可以基于接口来定义一些规则和标准，所以，我们可以让报警管理器实现一定的接口标准。

#### **4.1 通用代码设计**

在两阶段终止模式中，通用的，也是最核心的代码类结构如图16-5所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/3209f05a4914e724b0a9867c098bbc3490a3363181402372f4aee2c0bdcf6a60.png)

可以看到，两阶段终止模式中，最核心的部分包含如下接口和类。

1. ThreadOwner类：表示基于两节点终止模式退出的线程的拥有者，一般是创建线程类，并且知晓线程的工作内容，可以安全并且优雅的停止线程。

2. Termination接口：停止的线程要实现的接口，其中有一个terminate()方法。

3. terminate()方法：线程停止时要执行的方法。

4. AbstractTerminationThread抽象类：要停止的线程需要继承的抽象类，包含如下方法。

5. terminate()方法：向要停止的线程发送信号标志。

6. doTerminate()方法：线程停止时，执行的一些业务逻辑操作，留给子类实现。

7. doRun()方法：线程处理逻辑的方法，相当于Thread类的run()方法，留给子类实现。

8. doCleanup()方法：线程停止后执行一些清理工作，留给子类实现。

9. TerminationToken类：封装了线程停止的标识toShutdown，toShutdown标识用来标识线程是否可以停止，noExecuteTaskCount用来记录线程还有多少未完成的任务数量，当noExecuteTaskCount记录的未完成的任务数量为0时，可以优雅的中断并退出对应的线程。

10. ConcreteTerminationThread类：具体业务中实现的线程类，主要实现AbstractTerminationThread抽象类中的doRun()方法，在doRun()方法中实现线程的处理逻辑，并且根据实际场景需要实现doTerminate()方法和doCleanup()方法。

#### **5.1 实现TerminationToken类**

TerminationToken类的源码详见：concurrent-design-patterns-two-phase-termination工程下的[io.binghe.concurrent.design.two.phase.alarm.right.TerminationToken](http://io.binghe.concurrent.design.two.phase.alarm.right.TerminationToken)。

在TerminationToken类中，主要封装了线程启停的标识toShutdown，并封装了记录线程未执行任务数量的noExecuteTaskCount，并且当多个线程共享一个TerminationToken实例时，会通过队列的方式记录所有要停止的线程。其中，在TerminationToken类中实现的核心方法如下所示。

```go
public boolean isToShutdown() {
  return toShutdown;
}
​
public void setToShutdown(boolean toShutdown) {
  this.toShutdown = toShutdown;
}
​
public void register(Termination thread) {
  coordinatedThreads.add(new WeakReference<>(thread));
}
​
public void notifyThreadTermination(Termination thread) {
  WeakReference<Termination> wrThread;
  Termination otherThread;
​
  while ((wrThread = coordinatedThreads.poll()) != null) {
    otherThread = wrThread.get();
    if (otherThread != null && otherThread != thread) {
      otherThread.terminate();
     }
   }
}
```

其中，各个方法的含义如下所示。

1. isToShutdown()方法：返回线程是否停止的标识。

2. setToShutdown()方法：设置线程是否停止的标识。

3. register()：将要停止的线程注册到coordinatedThreads队列中。

4. notifyThreadTermination()：唤醒要停止的线程，执行线程的terminate()方法来停止线程。

#### **5.2 实现AbstractTerminationThread类**

AbstractTerminationThread类的源码详见：concurrent-design-patterns-two-phase-termination工程下的[io.binghe.concurrent.design.two.phase.alarm.right.AbstractTerminationThread](http://io.binghe.concurrent.design.two.phase.alarm.right.AbstractTerminationThread)。

AbstractTerminationThread类就是要停止的线程需要继承的抽象类，继承了Java中的Thread类，并且实现了Termination接口，在AbstractTerminationThread类中最核心的方法就是terminate()方法和run()方法，并且定义了交给子类实现的doTerminate()方法、doCleanup()方法和doRun()方法，如下所示。

```go
@Override
public void terminate() {
  //设置标志实例对象为true
  System.out.println("设置中断标志对象为中断状态");
  this.terminationToken.setToShutdown(true);
​
  try {
    doTerminate();
   } finally {
    // 如果没有等待的任务，则强制去停止线程
    if (terminationToken.noExecuteTaskCount.get() <= 0) {
      super.interrupt();
     }
   }
}
​
​
@Override
public void run() {
  Exception ex = null;
  try {
    for (;;) {
      //先判断中断实例的标识是否为true，同时没有未完成的任务
      System.out.println("执行告警线程的逻辑，此时中断标志位：" + terminationToken.isToShutdown() + ", 未完成的任务数量：" + terminationToken.noExecuteTaskCount.get());
      if (terminationToken.isToShutdown() && terminationToken.noExecuteTaskCount.get() <= 0) {
        //所有线程已经终止，跳出循环
        System.out.println("中断标志为true，没有未完成的任务，告警线程退出");
        break;
       }
      // 执行具体的业务逻辑
      doRun();
     }
   } catch (Exception e) {
    // 中断线程可能给调用interrupt被中断
    ex = e;
    if (e instanceof InterruptedException) {
      // 中断线程响应退出
      System.out.println("中断响应：" + e);
     }
   } finally {
    try {
      System.out.println("告警线程停止，回调终止后的清理工作");
      doCleanup(ex);
     } finally {
      // 通知terminationToken管理的所有线程实例退出
      System.out.println("标志实例对象中一个线程终止，通知其他线程终止");
      terminationToken.notifyThreadTermination(this);
     }
   }
}
​
protected void doTerminate() {
​
}
​
protected void doCleanup(Exception ex) {
​
}
​
protected abstract void doRun() throws InterruptedException;
```

#### **5.3 实现AlarmSendingThread类**

AlarmSendingThread类的源码详见：concurrent-design-patterns-two-phase-termination工程下的[io.binghe.concurrent.design.two.phase.alarm.right.AlarmSendingThread](http://io.binghe.concurrent.design.two.phase.alarm.right.AlarmSendingThread)。

AlarmSendingThread就是要通过两阶段终止模式停止的线程，并且也是上报告警信息的线程，即报警发送器线程，在AlarmSendingThread类中，最核心的方法就是doRun()方法和sendAlarm()方法，如下所示。

```go
@Override
protected void doRun() throws InterruptedException {
  // 执行业务逻辑 从告警队列中取告警信息，上报到监控系统中
  AlarmInfo alarmInfo;
  alarmInfo = alarmQueues.take();
  System.out.println("告警线程从队列中拉取到告警信息：" + alarmInfo);
​
  // 告警任务数量-1
  terminationToken.noExecuteTaskCount.decrementAndGet();
​
  // 发送告警信息
  try {
    doSendAlarm();
    System.out.println("告警信息：" + alarmInfo + "上报完成");
   } catch (Exception e) {
    e.printStackTrace();
   }
​
  // 如果当前告警类型是恢复告警，则需要清空当前告警的统计信息重置为空
  if (Objects.equals(alarmInfo.getAlarmType(), AlarmType.RESUME)) {
    System.out.println("告警：" + alarmInfo + "已恢复，清空告警次数");
    submittedAlarmRegistry.remove(alarmInfo.getUniqueIdByAlarmType(AlarmType.FAULT));
    submittedAlarmRegistry.remove(alarmInfo.getUniqueIdByAlarmType(AlarmType.RESUME));
   }
}
​
public int sendAlarm(AlarmInfo alarmInfo) {
  if (terminationToken.isToShutdown()) {
    // 已终止
    System.err.println("终止执行:" + alarmInfo);
    return -1;
   }
  try {
    //放入到告警队列中
    AtomicInteger prevSubmittedCounter;
    prevSubmittedCounter = submittedAlarmRegistry.putIfAbsent(alarmInfo.getUniqueId(), new AtomicInteger());
    if (prevSubmittedCounter == null) {
      System.out.println("当前没有编号为报警" + alarmInfo.getId()+"的告警信息，将其放到告警队列中");
      // 代表之前该类型的告警为空，未完成的任务+1
      terminationToken.noExecuteTaskCount.incrementAndGet();
      // 放入到告警队列中
      alarmQueues.put(alarmInfo);
     } else {
      System.out.println("编号为报警" + alarmInfo.getId() + "告警故障还没恢复，不需要重复上报告警，只是增加告警次数");
      // 当前的故障还没有恢复，不需要重复上报告警，只是增加告警数量的次数
      return prevSubmittedCounter.incrementAndGet();
     }
   } catch (InterruptedException e) {
    e.printStackTrace();
   }
  return 0;
}
```

#### **5.4 实现AlarmManager类**

AlarmManager类的源码详见：concurrent-design-patterns-two-phase-termination工程下的[io.binghe.concurrent.design.two.phase.alarm.right.AlarmManager](http://io.binghe.concurrent.design.two.phase.alarm.right.AlarmManager)。

AlarmManager类就是监控报警系统中的报警管理器，在AlarmManager类中可以有多个上报告警信息的报警发送器线程，这里的报警发送器其实就是AlarmSendingThread类的对象。在AlarmManager类中，会将构造方法私有化，对外提供AlarmManager类的单例对象，并且会在init()方法中启动报警发送器线程，通过sendAlarm()方法发送报警信息，通过shutdown()方法停止线程，如下所示。

public void init() {

}
​
public int sendAlarm(String id, AlarmType alarmType, String extra) {
  AlarmInfo alarmInfo = new AlarmInfo(id, alarmType, extra);

public synchronized void shutdown() {
  if (shutdownRequested) {
    throw new IllegalStateException("已经调用了shutdown方法...");

}
