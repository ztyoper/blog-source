在小菜公司实现的社区电商系统中，当用户成功下单后，会给用户发送积分和优惠券，并且会通过消息推送的形式告知用户：“恭喜您获得一张XX元的优惠券”。像这种消息推送，一般在大厂都会有单独的消息推送服务，只需要业务系统对接消息推送的接口即可，整体流程如图35-1所示。

可以看到，忽略掉技术实现的技术，在社区电商项目中，消息推送的流程还是比较简单的。当订单服务调用支付服务发起支付请求，支付服务支付成功后，会回调订单服务的接口来同步支付状态，或者订单服务会调用支付服务的接口查询支付状态，如果支付成功，则订单服务会调用积分服务和优惠劵服务向用户对应的账户增加积分和优惠券，增加积分和优惠券成功后，就会调用消息推送服务，向用户的手机APP推送消息通知。

如果是让你设计和开发这个推送消息服务的流程，你会怎么设计呢？其实，大家不难想到，推送消息大部分场景下都是调用第三方推送服务，或者公司专门的消息推送服务，这就涉及到网络交互的问题，网络本身就是不稳定的，如果是同步调用的话，那性能肯定就比较低，如果下单的用户比较多，那性能问题就会更加突出了。再加上给用户推送消息通知，对于整个交易链路来说，其实并不是太核心的业务。

### **三、代码复现**

这里，为了更好的让小伙伴们在脑海中复现出代码的执行逻辑，这里，我们就模拟一个简单的代码案例，主要就是模拟实现每条消息使用一个线程来进行推送。具体代码的实现步骤如下所示。

**（1）实现MessageService接口**

MessageService接口主要是推送消息的业务接口，其中定义了一个发送消息的sendMessage()方法。

源码详见：[io.binghe.concurrent.design.thread.pool.wrong.MessageService](http://io.binghe.concurrent.design.thread.pool.wrong.MessageService)。

```go
public interface MessageService {
  void sendMessage(String message);
}
```

**（2）实现MessageServiceImpl类**

MessageServiceImpl是MessageService接口的实现类，主要实现了MessageService接口中定义的sendMessage()方法，并模拟实现了消息推送功能。

源码详见：[io.binghe.concurrent.design.thread.pool.wrong.MessageServiceImpl](http://io.binghe.concurrent.design.thread.pool.wrong.MessageServiceImpl)。

```go
public class MessageServiceImpl implements MessageService{
  @Override
  public void sendMessage(String message) {
    System.out.println(Thread.currentThread().getName() + "-消息推送开始");
    long startTime = System.currentTimeMillis();
    try {
      Thread.sleep(2000);
      System.out.println(Thread.currentThread().getName() + "-消息推送完毕，推送的消息为：" + message);
     } catch (InterruptedException e) {
      throw new RuntimeException(e);
     }
    System.out.println(Thread.currentThread().getName() + "-消息推送结束，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
}
```

**（3）实现MessageTest类**

MessageTest类模拟了异步推送消息的流程，会为每条消息的推送都开启一个线程。

源码详见：[io.binghe.concurrent.design.thread.pool.wrong.MessageTest](http://io.binghe.concurrent.design.thread.pool.wrong.MessageTest)。

```go
public class MessageTest {
  public static void main(String[] args) throws InterruptedException {
    int count = 500;
    CountDownLatch countDownLatch = new CountDownLatch(count);
    MessageService messageService = new MessageServiceImpl();
    for (int i = 0; i < count; i++){
      new Thread(() -> {
        messageService.sendMessage("恭喜您获得到一张50元的优惠券");
        countDownLatch.countDown();
       }, "message-send-thread-" + i).start();
     }
    countDownLatch.await();
   }
}
```

大家可以自行运行MessageTest类的源码查看执行效果，可以不断的增加count的值，当count值达到一定程度时，可能就会出现OOM问题，这里不再赘述。接下来，我们继续分析问题。

### **四、问题分析**

这种为每条消息都开启一个线程进行推送，如果业务体量不大，下单人数不多，勉强还能接受。但是，这种方案在生产环境是经不起考验的，根本原因还是这种不断创建线程的操作根本就不合理。其实，学习《实战高并发设计模式》这么久后，大家应该对线程有所了解了，其实创建线程本身就是一个比较重的操作，线程也会占用系统的资源，这里说的资源主要是内存资源。

其实，在Java中并不能无限制的创建线程，创建线程的数量在理论上有一个公式，这个公式如下所示。

```go
可创建线程数量=（进程的最大内存 - JVM分配的内存 - 操作系统保留的内存）/ 每个线程栈的大小
```

JVM提供了-Xss和-XX:ThreadStackSize参数来调整线程栈的大小，如果在启动JVM进程时，没有设置-Xss和-XX:ThreadStackSize参数，那默认的线程栈大小就是1MB，也就是1024KB。

另外，在Java中创建线程，会在JVM中创建一个Thread对象，当调用Thread的start()方法启动线程时，会在操作系统层面创建一个操作系统的编程，最终会将Java线程与操作系统的线程进行映射。这个映射关系在Windows操作系统中是1对1的关系，也就是创建一个Java线程，就会在Windows操作系统中创建一个系统线程与之对应。如果是Linux操作系统，那这个线程的映射关系就是M对N的关系，M和N不一定相等。

还有一点需要注意的是：操作系统创建的线程所占用的内存资源，并不是JVM的内存资源，而是操作系统中剩余的内存资源，这个剩余的内存资源其实就是（进程的最大内存 - JVM分配的内存 - 操作系统保留的内存）得出的结果数据，这样一来，为JVM分配的内存越大，则操作系统可以创建的线程就越少。

**注意：线程占用的内存资源并不是操作系统为JVM分配的内存，很多小伙伴的理解都有误区。**

我们分析完创建线程的问题后，接下来，再继续分析本章的案例，如果有大量的用户下单成功，那可能就会创建成千上万的线程来执行推送消息的逻辑，此时，就可能出现由于Java进程占用大量内存，代码性能急剧下降，如果为JVM分配的内存过大，可能还会抛出创建线程失败的错误。那我们要如何解决这些问题呢？
