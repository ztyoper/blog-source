### **二、回滚参数**

线程池的参数都是通过ThreadPoolExecutor类的构造方法传递给线程池的，我们再来回滚下线程池的构造方法，如下所示。

    this(corePoolSize, maximumPoolSize, keepAliveTime, unit, workQueue,
         Executors.defaultThreadFactory(), defaultHandler);

可以看到，虽然ThreadPoolExecutor类提供了多个不同的构造方法，但是最终还是调用的参数最多的构造方法来创建线程池对象，如下所示。

```go
public ThreadPoolExecutor(int corePoolSize,
int maximumPoolSize,
long keepAliveTime,
TimeUnit unit,
BlockingQueue<Runnable> workQueue,
ThreadFactory threadFactory,
RejectedExecutionHandler handler) {
    if (corePoolSize < 0 ||
        maximumPoolSize <= 0 ||
        maximumPoolSize < corePoolSize ||
        keepAliveTime < 0)
        throw new IllegalArgumentException();
    if (workQueue == null || threadFactory == null || handler == null)
        throw new NullPointerException();
    this.acc = System.getSecurityManager() == null ?
            null :
            AccessController.getContext();
    this.corePoolSize = corePoolSize;
    this.maximumPoolSize = maximumPoolSize;
    this.workQueue = workQueue;
    this.keepAliveTime = unit.toNanos(keepAliveTime);
    this.threadFactory = threadFactory;
    this.handler = handler;
}
```

调用上述构造方法时，需要传递七个参数，七个参数的具体含义如下所示。

1. corePoolSize：表示线程池中的核心线程数。

2. maximumPoolSize：表示线程池中的最大线程数。

3. keepAliveTime：表示线程池中的线程空闲时，最多能够保持多久的时间而终止。换句话说，就是当线程池中的线程数量超过corePoolSize时，如果此时没有新的任务提交，核心线程外的线程不会立即销毁，而是需要等待keepAliveTime时间后才会终止。

4. unit：表示keepAliveTime的时间单位。

5. workQueue：表示线程池中的阻塞队列，同于存储等待执行的任务。

6. threadFactory：表示用来创建线程的线程工厂。创建线程池时，会提供一个默认的线程工厂来创建线程，默认的线程工厂创建的线程，会具有相同的优先级，并且是设置了线程名称的非守护线程。

7. handler：表示线程池拒绝处理任务时的策略。如果线程池中的workQueue阻塞队列满了，同时，线程池中的线程数已达到maximumPoolSize，并且没有空闲的线程，此时继续向线程池提交任务，就需要采取某种策略来拒绝任务的执行。

其中，corePoolSize、maximumPoolSize和workQueue三个参数之间的关系如下所示。

（1）当线程池中运行的线程数小于corePoolSize时，如果此时向线程池中提交任务，即使线程池中存在空闲线程，也会直接创建新线程来执行任务。

（2）如果线程池中运行的线程数大于corePoolSize，并且小于maximumPoolSize时，只有当workQueue队列已满时，才会创建新的线程来执行新提交的任务。

（3）如果调用ThreadPoolExecutor类的构造方法时，传递的corePoolSize和maximumPoolSize参数相同，那么创建的线程池的大小是固定的。此时，如果向线程池中提交任务，并且workQueue队列未满时，就会将新提交的任务保存到workQueue队列中，等待空闲的线程，从workQueue队列中获取任务并执行。

（4）如果线程池中运行的线程数大于maximumPoolSize，并且此时workQueue队列已满，则会触发指定的拒绝策略来拒绝任务的执行。

通过ThreadPoolExecutor类创建线程池时，可以使用如下的形式来创建线程池。

```go
new ThreadPoolExecutor(0, 10,
            60L, TimeUnit.SECONDS,
            new SynchronousQueue<Runnable>());
```

### **三、深入参数**

上一节，还是对线程池的核心参数进行了简单的回顾，本节，我们就深入解析下线程池的核心参数。

**（1）corePoolSize参数**

corePoolSize参数是线程池中的核心线程数，核心线程是线程池预先分配的线程，当创建线程池时，就会在线程池中分配核心数量的线程，此时，一旦有任务提交过来，核心线程会立即执行任务。corePoolSize参数设置的核心线程如图38-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/dcf09a64118d1cf0f765303c106369ea4806ef5051005839f625f904a5f561e0.png)

线程池中的线程一般会在线程池中保留，除非将allowCoreThreadTimeOut参数设置为true，或者执行的run()方法抛出异常，核心线程都会被销毁。当执行的run()方法抛出异常时，还是会创建新的线程来代替抛出异常的核心线程，当将allowCoreThreadTimeOut参数设置为true时，核心线程会被销毁掉，

**（2）maximumPoolSize参数**

maximumPoolSize参数是线程池中的最大线程数，当线程池中的核心线程都在执行任务，并且任务队列中也已经填满了要执行的任务，但是线程池中的线程数小于最大线程数，此时当有新任务到来时，线程池中就会创建新的线程来执行任务，此时新创建的线程就是非核心线程、如图38-2所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/d4427f233d45b21502077d33580116e60cb662a4a90a2286defc72a5224c7a44.png)

当线程池中的线程核心线程足以执行任务时，空闲的非核心线程超出空闲时间时，就会被系统回收。

这里，可能有些小伙伴就会有疑问：线程池设计了核心线程数，为何还要设计一个最大线程数呢？对于这个问题，我们可以想象这样一个场景：一个系统的平时任务不多，平时也就每秒可能只会执行5~10个任务，只设置一个核心线程数基本没啥问题，但是当并发流量上来时，可能会每秒钟执行100个甚至更多的任务，此时我们就不能将核心线程数corePoolSize由10修改成100甚至更大的值。

即使我们修改了这个值，那并发数很快下来的话，还是使用100个核心线程甚至更多，就会造成资源的浪费。所以，线程池提供了maximumPoolSize参数来设置最大线程数。

线程池中的核心线程都在执行任务，并且任务队列中也已经填满了要执行的任务，但是线程池中的线程数小于最大线程数，此时当有新任务到来时，线程池中就会创建新的线程来执行任务。所以，maximumPoolSize参数使得线程池具备了动态调整线程数量的能力。

**（3）workQueue参数**

workQueue参数主要用于设置线程池中的任务队列，可以设置成有界队列ArrayBlockingQueue，可以设置成无界队列LinkedBlockingQueue，也可以设置成只能有一个元素的同步队列SynchronousQueue，还可以设置成具有优先级的队列PriorityBlockingQueue。设置一个任务队列，主要是当线程池中的核心线程都在执行任务，但线程池中的当前线程数量小于最大线程数时，对要执行的任务起到一个缓冲作用，不至于新任务到来时，就立即拒绝任务的执行。

并且在线程池中实现了任务队列，这里也在线程池中体现了生产者消费者模式。

其他参数，大家就参考第二节的内容即可，这里不再赘述。
