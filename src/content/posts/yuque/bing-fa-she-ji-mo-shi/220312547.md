### **二、案例背景**

对于电商业务来说，一个非常常见的场景就是分析统计热点商品，由于电商平台的商品类目和商品非常多，自然不能直接通过关系型数据库来进行统计。其中一种有效的方式就是通过日志来分析统计。日志文件里一般会记录请求的信息（比如请求的类型、请求编号、调用的接口、请求方式等等）、商品的ID、请求时间戳等等。

对于案例中的社区电商系统来说，也是采用了日志文件的方式来分析统计数据，日志文件中就是记录了请求的类型、请求编号、请求方式、调用的接口、商品ID、请求时间戳等等。并且会每小时生成一个日志文件，如图49-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/81c20775aa8c9efb5d918994b1a9e73a32da5e9c90194be5777510a9a2805e32.png)

可以看到，社区电商系统在运行的过程中，会记录请求的类型、请求编号、请求方式、调用的接口、商品ID、请求时间戳等等信息，并且会每隔一个小时生成一个新的日志文件。统计热点商品时，就会基于这些日志文件进行分析统计。

```go
public class FileServiceImpl implements FileService {
  @Override
  public Map<String, Integer> readAnalysisGoods(String... fileNames) {
    System.out.println("读取并分析日志文件开始");
    long startTime = System.currentTimeMillis();
    for (String fileName : fileNames){
      System.out.println("读取并分析" + fileName + "文件开始");
      long fileStartTime = System.currentTimeMillis();
      try {
        Thread.sleep(1000);
       } catch (InterruptedException e) {
        e.printStackTrace();
       }
      System.out.println("读取并分析" + fileName + "文件结束，耗时：" + (System.currentTimeMillis() - fileStartTime) + "ms");
​

    System.out.println("读取并分析日志文件结束，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
    return Collections.emptyMap();
   }
}
```

### **四、问题分析**

在分析统计热点商品时，往往会指定一个时间范围去统计，因此，在统计热点商品时，需要找到符合时间范围条件的日志文件，读取文件的内容进行分析统计，如图49-2所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/35ba727746a45158d02dc5cb18a99cb6f8cba33efff5c67360a194117313bfd5.png)

此时文件的读取和分析是由一个线程串行执行的，只有一个日志文件读取和分析完毕，才会读取和分析下一个文件，直到符合时间范围的所有日志文件都读取和分析完毕为止，最终分析、统计、汇总出符合要求的热门商品。这种实现方式在商品体量不大，用户访问体量不大，运营分析统计的时间跨度不大的情况下没啥问题。

但是如果商品非常多，用户访问量比较高，并且运营需要分析统计的时间跨度比较长，那这种分析统计热点商品的实现方式就有很大的性能问题了，如图49-3所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/b50d2e2e63ffec83271612ddfe72ecda7a65b655d0e2f50dc6fecc025f5d1a1e.png)

可以看到，如果用户访问量很大，每小时生成的日志文件就比较大，加上运营分析统计热点商品的时间跨度完全由运营自己掌控，运营很有可能会分析统计比较长的一段时间内的热点商品。

所以，如果每个日志文件的体积比较大，统计热点商品的时间跨度比较长，分析统计热点商品性能比较差，过程比较耗时。如果不能及时分析统计出结果数据，会为运营后续的策略和投放产生重大的影响。

所以，这种串行化分析统计热点商品的方案需要优化。这种场景下，其实比较适合使用并发编程中的主仆模式。
