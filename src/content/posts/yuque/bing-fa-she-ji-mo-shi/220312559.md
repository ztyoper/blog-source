通过读取日志数据来实现实时分析统计交易额的功能时，将实时读取日志文件到得出最终的结果数据，都写到一个业务方法中，性能是比较低的。从业务角度分析，可以将通过读取日志数据来实现实时分析统计交易额的功能通过流水线模式分为：读取日志、分割日志、分析统计和推送大屏等几个步骤，并且不同流水线的各个步骤之间可以并行执行任务，这样能够极大的提升整体的执行效率。

### **一、故事背景**

小菜在开发实时统计社区电商系统交易额的功能时，看似一个非常简单的功能，但是开发完成后，提交测试反馈的结果是性能太差。但是目前以小菜的功力无法独立解决性能差的问题。在老王的指导下，小菜明白了性能差的原因，也知道了解决这种场景问题的最佳方案是流水行模式。

在老王的指导下，小菜也知晓了到底什么是流水线模式，但是真要是自己在项目中实现流水线模式，还是有点困难的，毕竟没有流水线模式的真实项目经验。于是，小菜还是找到老王，让老王为其讲讲如何基于流水线模式优化试试统计交易额的功能。老王这个大好人，不仅为小菜讲解了如何基于流水线模式优化实时统计交易额的功能，更是将流水线的通用代码封装成了通用的框架类源码。

可以看到，优化前将读取日志、分割日志、分析统计和推送大屏的逻辑，都写到了同一个方法中，每个步骤之间都是串行执行的，读取日志后，才能对日志进行分割，分割完日志，才能进行分析统计，分析统计完才能推送到交易大屏。整个方法只有将当前结果数据推送到交易大屏后，才能读取下一批日志。由此可知，整体的执行性能是多么差。

### **四、类代码实现**

设计完类结构后，接下来，就可以对写代码了。限于篇幅，我们不再写流水线模式的通用框架型代码，大家可以查看concurrent-design-patterns-pipeline-framework工程下的源码，这里不再赘述。

这里，我们着重介绍下，基于流水线模式实现的业务代码，主要是介绍concurrent-design-patterns-pipeline工程下的[io.binghe.concurrent.design.pipeline.right.AnalysisTask](http://io.binghe.concurrent.design.pipeline.right.AnalysisTask)类。

在AnalysisTask类中，我们将实时统计交易额的功能基于流水线模式总体上分为了四个大的步骤：读取日志、分割日志、分析统计和推送大屏。接下来，我们就简单介绍下AnalysisTask类的代码。

#### **4.1 类结构介绍**

AnalysisTask类的结构如下所示。

```go
public class AnalysisTask implements Runnable{
​
  private volatile AtomicLong analysisResult = new AtomicLong(0);
​
  private int fileLineNum;
​
  public AnalysisTask(int fileLineNum) {
    this.fileLineNum = fileLineNum;
   }
​
  @Override
  public void run() {
    //输入String, 输出Long，输出结果为累加值
    SimplePipeline<String, Long> pipeline = this.buildPipeline();
    pipeline.init(pipeline.newDefaultPipelineContext());
    try {
      this.readFile(pipeline);
     } catch (InterruptedException e) {
      e.printStackTrace();
     }
    pipeline.shutdown(1, TimeUnit.MINUTES);
   }
  /**************省略其他代码**************/
}
```

可以看到，AnalysisTask类实现了Runnable接口，所以AnalysisTask类可以看作是一个线程的任务类，启动线程后就会执行run()方法。在AnalysisTask类中定义了一个volatile修饰的成员变量analysisResult，这个变量中就是实时统计出的最新的结果数据，同时，定义了一个int类型的成员变量fileLineNum，表示模拟分析多少行日志数据，具体的值主要由构造函数传入。

#### **4.2 任务编排**

重点是run()方法中的逻辑，在run()方法中，首先会构建一个SimplePipeline类型的流水线pipeline，构建流水线的过程就会将分割日志、分析统计和推送大屏几个步骤编排好顺序，这个逻辑主要是在buildPipeline()方法中，如下所示。

```go
private SimplePipeline<String, Long> buildPipeline() {
  final ExecutorService executor = new ThreadPoolExecutor(1,1,60,TimeUnit.SECONDS,new ArrayBlockingQueue<>(1024),(r) -> {
      Thread t = new Thread(r, "thread-execute-pipeline");
      t.setDaemon(true);
      return t;
     },new ThreadPoolExecutor.CallerRunsPolicy());
  final SimplePipeline<String, Long> pipeline = new SimplePipeline<>(executor);
​
  //模拟读取日志文件每一行数据，对读取到的每一行数据进行拆分，输入String，输出String
  Pipe<String, String> splitFilePipe = splitFilePipe();
  pipeline.addAsWorkerThreadBasedPipe(splitFilePipe, 1);
​
  //模拟统计计算，List<String>，输出Long
  Pipe<String, Long> longPipe = buildLongPipe();
  pipeline.addAsWorkerThreadBasedPipe(longPipe, 1);
​
  //模拟推送到大屏，输入Long，输出Long
  Pipe<Long, Long> pushPipe = buildPushPipe();
  pipeline.addAsWorkerThreadBasedPipe(pushPipe, 1);
​
  return pipeline;
}
```

回到run()方法，随后会调用readFile()方法读取文件的内容，当前流水线执行完毕后，会调用流水线的shutdown()方法关闭流水线。

#### **4.3 读取日志**

读取日志的方法是在run()方法中调用readFile()方法完成的，如下所示。

```go
//模拟读取文件
private void readFile(SimplePipeline<String, Long> pipeline) throws InterruptedException {
  String line;
  for (int i = 1; i <= fileLineNum; i++){
    line = "100" + i + "-" + new Random().nextInt(999);
    System.out.println("当前读取到的文件行内容===>>>"+ line);
    pipeline.process(line);
   }
}
```

可以看到，readFile()方法会模拟读取日志的数据，模拟的日志格式也比较简单，使用中划线分隔日志的内容，中划线前面是订单的编号，中划线后面是订单金额，每生成一条日志数据，就会调用pipeline对象的process()方法进行处理。

#### **4.4 分割日志**

分割日志的逻辑主要由splitFilePipe()方法完成，如下所示。

```go
//模拟读取文件
private Pipe<String, String> splitFilePipe() {
  return new AbstractPipe<String, String>() {
    @Override
    protected String doProcess(String input) throws PipeException {
      //模拟读取日志文件并分割日志
      return input.split("-")[1];
     }
   };
}
```

可以看到，在分割日志的逻辑中，会输入一个String类型的数据，输出一个String类型的数据，具体的逻辑就是将输入数据按照中划线进行分割，获取数组的第2个元素，也就是获取订单的金额数据并返回。

#### **4.5 分析统计**

分析统计的逻辑主要由buildLongPipe()方法完成，如下所示。

```go
private Pipe<String, Long> buildLongPipe() {
  return new AbstractPipe<String, Long>() {
    @Override
    protected Long doProcess(String input) throws PipeException {
      return analysisResult.addAndGet(Long.parseLong(input));
     }
   };
}
```

可以看到，在分析统计的逻辑中，会输入一个String类型的数据，输出一个Long类型的数据，其中，输入的String数据就是从分割日志步骤中输出的结果数据。另外，在分析统计的逻辑中，会直接将输入的数据转换成Long类型，并累加到analysisResult上并返回数据。

#### **4.6 推送大屏**

推送大屏的逻辑主要由buildPushPipe()方法完成，如下所示。

```go
//模拟推送大屏，这里只是打印
private Pipe<Long, Long> buildPushPipe() {
  return new AbstractPipe<Long, Long>() {
    @Override
    protected Long doProcess(Long input) throws PipeException {
      System.out.println("当前统计出的结果数据为===>>>" + input);
      return input;
     }
   };
}
```

可以看到，在推送大屏的逻辑中，会输入一个Long类型的数据，输出一个Long类型的数据，其中，输入的Long类型的数据就是在分析统计逻辑中得出的结果数据。另外，在推送大屏的逻辑中，我们只是简单的打印了结果数据的日志，并将输入的数据直接返回。

至此，基于流水线模式优化实时统计交易额的功能就完成了，本章实现的代码还是需要大家好好体会下实现逻辑和实现思想的。
