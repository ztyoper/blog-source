实际项目中，有很多业务场景都可以使用承诺模式进行优化。总体来说，承诺模式本质上还是多个线程并行执行项目， 当项目中存在多个关联性不强的业务，哪怕多个关联性不强的业务之间存在一定的关联性，比如业务A和业务B，业务A虽然和业务B在主体逻辑的执行上关联性不大，但是业务A的执行需要业务B的执行结果，此时，都可以使用承诺模式实现。

### **三、问题重现**

“在正式讲如何使用承诺模式优化文件同步助手项目之前，我们再来明确下文件助手的需求”，老王说到。

文件同步助手的需求主要是：将服务器上存储的图片同步到云端，比如将本地服务器上存储的图片同步到阿里云或者腾讯云。具体的逻辑就是：文件同步助手项目会监听本地服务器的目录，一旦目录中发生变化，就会将变化的文件同步到阿里云或者腾讯云，在监听的过程中，为了避免同步的文件有误，还会启动扫描任务，定时扫描本地目录的文件，对比变化的文件，将文件同步到阿里云或者腾讯云。

在业务逻辑上可以将文件助手总体划分成三部分：与远程服务器建立连接、监听或扫描本地文件、同步文件到远程服务器。在小菜实现的代码中，这三部分是串行执行的，每一部分的执行都是比较耗时的，同步文件到远程服务器的任务需要等到与远程服务器建立连接的任务和扫描本地文件的任务执行完毕后再执行，如图22-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/ce6dc2bb38d5bbda9a528fb50de040d86be60396fb0caab7b45d963d6d582111.png)

可以看到，如果连接远程服务器的任务和监听或者扫描本地文件的任务执行非常慢，在这种串行执行任务的模式下，要经过较长的时间才能开始同步文件到远程服务器，性能是非常差的。

“这个我们之前已经分析过了，这里确认可以听懂吧？”，老王问小菜。

“可以听懂”，小菜回应到。

“好，那我们继续吧”。

### **四、优化策略**

既然串行执行文件助手的三部分业务逻辑性能很差，那我们可以想办法将其并行化。这里，我们可以分析下，对于与远程服务器建立连接、监听或扫描本地文件、同步文件到远程服务器，这三部分业务逻辑来说，与远程服务器建立连接和监听或扫描本地文件执行完毕后，才能开始同步远程服务器，并且在业务逻辑上，与远程服务器建立连接和监听或扫描本地文件关联并不大，这两部分可以实现并行执行，整体如图22-2所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/dda8585209a2c647139a478264ac267d739ed1f61e12af68846ade588a31922d.png)

此时，与远程服务器建立连接和监听或扫描本地文件的任务并行执行，能够大大缩短整体任务的执行耗时，提升项目的整体性能和并发度，这里，可以基于Promise模式，也就是承诺模式实现与远程服务器建立连接和监听或扫描本地文件的任务并行执行。

“老大，这里有个问题”，小菜说道。

“嗯，你说”，老王回应道。

“如果与远程服务器建立连接非常耗时，扫描本地文件的操作已经完成了，与远程服务器建立连接的操作还没完成，怎么处理呢？”。

“这不就是Promise模式可以处理的问题吗”。

这里，再来看一张图，如图22-3所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/4cfb52e68b8708ccc0d19f0b16e1c13f31617a562699bb313e9ef3b57ca03c77.png)

在Promise模式中，异步执行与远程服务器建立连接的操作，并且会立刻返回一个Promise凭据对象，后续可以继续执行监听和扫描本地文件的逻辑，当监听和扫描文件的逻辑执行完毕，可以通过Promise凭据对象来获取与远程服务器建立连接的同步器对象，此时，如果与远程服务器建立连接的逻辑还没有执行完毕，则通过Promise凭据对象来获取与远程服务器建立连接的同步器对象的方法就会阻塞。

当与远程服务器建立连接的逻辑执行完毕，则通过Promise凭据对象来获取与远程服务器建立连接的同步器对象的方法就会返回同步器对象。这样，就可以开始执行同步文件的逻辑。

此时，整体耗时取决于并行执行的多个任务中，耗时最长的任务，而串行执行任务时，整体耗时是每个任务耗时的累加和，这样就能够极大的提升整体任务的性能和并发度。

### **五、代码设计**

回到代码上，基于Promise模式实现文件同步助手项目时，按照业务逻辑可以设计出如下类结构图，如图22-4所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/ea752bd672b6127a91015d5048b1e75c0c7bb5f90dd0ad06620b067cd2a602db.png)

其中各接口和类的说明如下所示。

1. FileSyncer接口：同步本地文件到远程服务器的接口，定义了连接远程服务器的方法、上传文件的方法和关闭与远程服务器连接的方法。

2. FileSyncerImpl类：同步本地文件到远程服务器的实现类，实现了FileSyncer接口，并实现了FileSyncer接口的连接远程服务器的方法、上传文件的方法和关闭与远程服务器连接的方法。

3. FileSyncerConfig：同步文件的配置类，主要封装了连接远程服务器的地址、用户名和密码，以及文件要传递到远程服务器的目录。

4. FileSyncerInfo：同步文件的对象类，主要封装了同步的文件信息，包括文件字节流、文件名称和文件大小。

5. FileSyncerPromior：Promise模式的核心类，主要提供了异步连接远程服务器的execute()方法。

6. FileSyncerScanner：扫描本地文件的扫描器类，主要提供了扫描文件的scanFile()方法。

7. FileSyncerTask：同步文件的整体任务类，实现了Runnable接口，在run()方法中执行同步文件的整体逻辑。

8. FileSyncerClientThreadPool：同步文件的客户端线程池。

9. FileSyncerThreadPool：同步文件的异步线程池。

10. FileSyncerTest：同步文件的测试类。

**（4）实现FileSyncerPromisor类**

FileSyncerPromisor类是Promise模式的核心类，主要提供了异步连接远程服务器的execute()方法。

源码详见：concurrent-design-patterns-promise工程下的[io.binghe.concurrent.design.promise.sync.FileSyncerPromis](http://io.binghe.concurrent.design.promise.sync.FileSyncerPromise)or。

```go
public class FileSyncerPromisor {
​
  private static final FileSyncerPromisor INSTANCE = new FileSyncerPromisor();
​
  private FileSyncerPromisor(){}
​
  public static FileSyncerPromisor getInstance(){
    return INSTANCE;
   }
​
  public Future<FileSyncer> execute(FileSyncerConfig fileSyncerConfig){
    FutureTask<FileSyncer> futureTask = new FutureTask<>(()->{
      FileSyncer fileSyncer = new FileSyncerImpl();
      fileSyncer.connect(fileSyncerConfig.getServerAddress(), fileSyncerConfig.getUsername(), fileSyncerConfig.getPassword(), fileSyncerConfig.getServerDir());
      return fileSyncer;
     });
    FileSyncerThreadPool.execute(futureTask);
    return futureTask;
   }
}
```

**（5）实现FileSyncerTask类**

FileSyncerTask类是同步文件的整体任务类，实现了Runnable接口，在run()方法中执行同步文件的整体逻辑。

源码详见：concurrent-design-patterns-promise工程下的[io.binghe.concurrent.design.promise.sync.FileSyncerTask](http://io.binghe.concurrent.design.promise.sync.FileSyncerTask)。

```go
public class FileSyncerTask implements Runnable{
​
  private final FileSyncerConfig fileSyncerConfig;
​
  public FileSyncerTask(FileSyncerConfig fileSyncerConfig) {
    this.fileSyncerConfig = fileSyncerConfig;
   }
​
  @Override
  public void run() {
    System.out.println("同步文件总体开始");
    long startTime = System.currentTimeMillis();
    //连接远程服务器成功的文件同步器
    FileSyncer fileSyncer = null;
    try{
      //异步执行连接远程服务器的操作
      Future<FileSyncer> promise = FileSyncerPromisor.getInstance().execute(fileSyncerConfig);
      //扫描本地文件
      List<FileSyncerInfo> fileSyncerInfoList = FileSyncerScanner.getInstance().scanFile("binghe");
      if (fileSyncerInfoList == null || fileSyncerInfoList.isEmpty()){
        System.out.println("扫描的文件为空");
        return;
       }
      //可能会阻塞
      fileSyncer = promise.get();
      if (fileSyncer == null){
        System.out.println("连接远程服务器失败");
        return;
       }
      //上传文件
      this.uploadFile(fileSyncer, fileSyncerInfoList);
     }catch (Exception e){
      e.printStackTrace();
     }finally {
      if (fileSyncer != null){
        fileSyncer.disconnect();
       }
     }
    System.out.println("同步文件结束，总体耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
​
  private void uploadFile(FileSyncer fileSyncer, List<FileSyncerInfo> fileSyncerInfoList){
    fileSyncerInfoList.stream().forEach((fileSyncerInfo) -> {
      try {
        fileSyncer.uploadFile(fileSyncerInfo);
       } catch (Exception e) {
        e.printStackTrace();
       }
     });
   }
}
```
