主仆模式本质上就是一种分而治之的思想，最核心的思想就是将一个比较大的任务分解成若干个比较小的子任务，并且会由专门的工作线程来并行执行这些拆分后的子任务，得出子任务的分析结果后，再整合各个子任务的处理结果，形成最终的结果数据。以这种分而治之的思想，很适合并行执行任务的场景。

### **一、故事背景**

小菜在老王的指导下，分析出了社区电商系统分析统计热点商品性能问题的原因所在，也明白了到底什么是主仆模式，但是，还有一个问题就是小菜刚刚对主仆模式有所了解，还不知道如何在项目中使用主仆模式开发功能，为了尽快的完成热点商品统计功能的优化工作，小菜决定还是请教老王。在老王耐心的指导下，最终，基于主仆模式优化了热点商品的统计功能。

### **二、问题回顾**

统计社区电商系统中的热点商品时，会通过分析统计访问商品的日志文件来统计出最终的TopN热点商品，对于商品的日志文件来说，会每隔1小时生成一个新的日志文件。并且在统计热点商品时，往往会指定一个时间范围去统计，因此，在统计热点商品时，需要找到符合时间范围条件的日志文件，读取文件的内容进行分析统计，如图51-1所示。

如果整个过程采用串行化方式执行，当商品非常多，用户访问量比较高，并且运营需要分析统计的时间跨度比较长时，这种统计方式就会出现很严重的性能问题，如图51-2所示。

经过分析，社区电商系统根据日志文件统计热点商品，并且每隔一段时间会新生成一个日志文件的业务，就很适合使用主仆模式来优化业务场景。

### **五、优化类实现**

本节，我们就实现基于主仆模式优化统计热点商品功能的代码，具体的实现步骤如下所示。

**（1）实现HotGoodsSlave类**

HotGoodsSlave类是主仆模式中的工作线程，每个工作线程会被分配指定的任务执行。

源码详见：[io.binghe.concurrent.design.master.slave.right.HotGoodsSlave](http://io.binghe.concurrent.design.master.slave.right.HotGoodsSlave)。

```go
public class HotGoodsSlave extends AbstractTerminationThread {
​
  /**
* 存储商品id和个数的map
*/
  private final ConcurrentMap<String, AtomicInteger> hotGoodsMap;
​
  /**
* Slave要执行的任务
*/
  private final BlockingQueue<BufferedReader> workQueue;
​
  public HotGoodsSlave(ConcurrentMap<String, AtomicInteger> hotGoodsMap) {
    this.hotGoodsMap = hotGoodsMap;
    this.workQueue = new ArrayBlockingQueue<>(128);
   }
​
  public void submitTask(BufferedReader task){
    try {
      workQueue.put(task);
      terminationToken.noExecuteTaskCount.incrementAndGet();
     } catch (InterruptedException e) {
      e.printStackTrace();
     }
   }
​
  @Override
  protected void doRun() throws InterruptedException {
    BufferedReader bufferedReader = workQueue.take();
    try{
      String line;
      while ((line = bufferedReader.readLine()) != null){
        String[] lineArray = line.split("-");
        HotGoodsLog hotGoodsLog = new HotGoodsLog(lineArray[0], lineArray[1]);
        System.out.println("读取到的文件内容为：" + hotGoodsLog.toString());
        AtomicInteger hotGoodsCount = hotGoodsMap.putIfAbsent(hotGoodsLog.getGoodsId(), new AtomicInteger(1));
        if (Objects.isNull(hotGoodsCount)){
          hotGoodsCount = new AtomicInteger();
         }
        hotGoodsCount.incrementAndGet();
       }
     }catch (Exception e){
      e.printStackTrace();
     }finally {
      terminationToken.noExecuteTaskCount.decrementAndGet();
      try {
        bufferedReader.close();
       } catch (IOException e) {
        e.printStackTrace();
       }
     }
   }
}
```

可以看到，在HotGoodsSlave类中，对外提供了一个submitTask()方法用于提交任务，并且任务会被存放到workQueue工作队列中。真正是在doRun()方法中执行任务，在doRun()方法中，会从workQueue工作队列中获取任务，也就是获取到bufferedReader对象，通过bufferedReader对象来读取并解析文件的内容，将统计出的结果数据放入hotGoodsMap中。

从HotGoodsSlave类中，也可以看出，我们的日志文件格式是以-进行分割的，如下所示。

```go
1001-1672763654354
1002-1672763655354
1001-1672763654354
1003-1672763654354
```

横线前面是商品的id，后面是时间戳。

**（2）实现HotGoodsEnumeration类**

HotGoodsEnumeration类实现了JDK中的Enumeration接口，主要是遍历日志文件生成InputStream文件流。

源码详见：[io.binghe.concurrent.design.master.slave.right.HotGoodsEnumeration](http://io.binghe.concurrent.design.master.slave.right.HotGoodsEnumeration)。

```go
public class HotGoodsEnumeration implements Enumeration<InputStream> {
​
  private Iterator<String> iterator;
  private String fileRoot;
​
  public HotGoodsEnumeration(Set<String> fileNames, String fileRoot){
    this.iterator = fileNames.iterator();
    this.fileRoot = fileRoot;
   }
​
​
  @Override
  public boolean hasMoreElements() {
    return iterator.hasNext();
   }
​
  @Override
  public InputStream nextElement() {
    String fileName = iterator.next();
    InputStream in = null;
    try {
      in = new FileInputStream(fileRoot + fileName);
     } catch (FileNotFoundException e) {
      throw new RuntimeException(e);
     }
    return in;
   }
}
```

**（3）实现HotGoodsMaster类**

HotGoodsMaster类是主仆模式中的主线程，主要负责将任务分配给Slave线程，并收集Slave线程的执行结果。

源码详见：[io.binghe.concurrent.design.master.slave.right.HotGoodsMaster](http://io.binghe.concurrent.design.master.slave.right.HotGoodsMaster)。

为了更好的说明HotGoodsMaster类的执行流程，这里，我们将HotGoodsMaster类进行拆解介绍。

1. getHotGoods()方法

getHotGoods()方法是HotGoodsMaster类对外提供的方法，主要传递一个BufferedReader缓冲字符流对象，最终获取一个封装了结果的ConcurrentMap对象，如下所示。

```go
public ConcurrentMap<String, AtomicInteger> getHotGoods(BufferedReader bufferedReader) throws IOException {
  ConcurrentMap<String, AtomicInteger> hotGoodsMap = new ConcurrentSkipListMap<>();
  //创建Slave
  HotGoodsSlave[] hotGoodsSlaves = this.createSlave(hotGoodsMap);
  //为Slave分配任务
  this.dispatchTask(bufferedReader, hotGoodsSlaves);
  for (int i = 0; i < SLAVE_COUNT; i++){
    hotGoodsSlaves[i].terminate();
   }
  return hotGoodsMap;
}
```

可以看到，在getHotGoods()方法中。会调用createSlave()方法创建并启动Slave线程，并且会调用dispatchTask()方法为每个Slave线程分配任务，最终调用slave线程的terminate()方法来等待终止线程。最后，返回hotGoodsMap对象。

1. createSlave()方法

createSlave()方法是创建并启动Slave线程的方法，如下所示。

```go
private HotGoodsSlave[] createSlave(ConcurrentMap<String, AtomicInteger> hotGoodsMap) {
  HotGoodsSlave[] hotGoodsSlaves = new HotGoodsSlave[SLAVE_COUNT];
  HotGoodsSlave slave;
  for (int i = 0; i < SLAVE_COUNT; i++){
    slave = new HotGoodsSlave(hotGoodsMap);
    hotGoodsSlaves[i] = slave;
    slave.start();
   }
  return hotGoodsSlaves;
}
```

可以看到，在createSlave()方法中，会创建并启动SLAVE_COUNT个线程，实际就是2个Slave线程，并将其存储hotGoodsSlaves数组中并返回hotGoodsSlaves数组。

1. dispatchTask()方法

dispatchTask()方法是为每个Slave线程分配任务的方法，如下所示。

```go
private void dispatchTask(BufferedReader bufferedReader, HotGoodsSlave[] hotGoodsSlaves) throws IOException {
  String line;
  Set<String> fileNames = new HashSet<>();
  int fileCount = 0;
  int slaveIndex = -1;
  BufferedReader fileReader;
  while ((line = bufferedReader.readLine()) != null){
    fileNames.add(line);
    fileCount++;
    if (fileCount % FILE_COUNT == 0){
      slaveIndex = (slaveIndex + 1) % SLAVE_COUNT;
      fileReader = getFileReadByFileNames(fileNames);
      //提交任务
      hotGoodsSlaves[slaveIndex].submitTask(fileReader);
      fileNames.clear();
      fileCount = 0;
     }
   }
  if (fileCount > 0){
    fileReader = getFileReadByFileNames(fileNames);
    slaveIndex = (slaveIndex + 1) % SLAVE_COUNT;
    hotGoodsSlaves[slaveIndex].submitTask(fileReader);
   }
}
```

可以看到，在dispatchTask()方法中，会将指定的日志文件分配给对应的Slave线程去读取并分析结果。

至此，基于主仆模式优化统计热点商品的核心代码就实现完毕了。
