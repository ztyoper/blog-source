生产者消费者模式，在某些场景下，尽管并发请求量高，只要消费者的消费速度大于生产者的生产速度，则只需要少量的消费者线程即可处理对应的任务，不会过度的占用服务器资源。总之，生产者消费者模式可以使多个应用之间解耦，支持异步处理任务，平衡生产者和消费者之间的速度差异。

### **三、优化分析**

之前，初步基于线程池完成了对个人文库系统的优化，总体流程如图26-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/34b2dcff35a0cc98e94d4ec4f5bc98c756fe7d6820fa798aaccbd0086e9d19ae.png)

但是这种方式有个弊端，如果并发量很高，线程池中的活跃线程数已达最大值，并且任务队列已满，此时再有新的任务到来时，就会触发拒绝策略。如果拒绝策略没选好，会影响用户体验，并且此时线程池处于高度饱和状态，CPU会频繁发生切换，在一定程度上也会引起系统的性能问题。

并且在对线程池进行调优时，如果线程数设置的太小，无法充分利用服务器的资源，提升并发性能。如果线程数设置的过大，就会造成CPU频繁切换，同样会引起性能问题。

对于像个人文库系统这种场景来说，最好的方式就是使用生产者消费者模式进行优化，那具体如何优化呢？其实，整体逻辑还是比较简单的，如图26-2所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/f66aa506f07ad76cdbbcdd7546306aba1beb111e173983b2935ae3cdfc039fc5.png)

基于生产者消费者优化后的个人文库系统，在上传完文件后，会将文件数据写入任务队列，然后直接返回结果。后续使用其他线程消费任务队列中的数据，为文件建立索引。

### **五、优化实现**

在代码实现上，细心的小伙伴应该已经发现了，在基于生产者消费者模式优化个人文库系统时，Termination接口、AbstractTerminationThread抽象类和TerminationToken类好像在哪里看到过。没错，这些接口和类就是实现两阶段终止模式抽象出来的最核心的类，我们在实现两阶段终止模式时，就已经使用过这些类。

所以，这里，我将这些接口和类进一步分离出来，放到了concurrent-design-patterns-thread工程下，以便后续代码引用，不再重复开发。

接下来，就基于生产者消费者模式模拟实现个人文库系统，核心代码的具体实现步骤如下所示。

**（1）实现Channel接口**

Channel接口是抽象出来的任务队列的通道接口。

源码详见：concurrent-design-patterns-producer-comsumer工程下的[io.binghe.concurrent.design.pc.right.Channel](http://io.binghe.concurrent.design.pc.right.Channel)。

```go
public interface Channel<T> {
  T take() throws InterruptedException;
  void put(T t) throws InterruptedException;
}
```

**（2）实现BlockingQueueChannel类**

BlockingQueueChannel类是任务队列通道的实现类，主要基于JDK中的BlockingQueue实现了Channel接口。

源码详见：concurrent-design-patterns-producer-comsumer工程下的[io.binghe.concurrent.design.pc.right.BlockingQueueChannel](http://io.binghe.concurrent.design.pc.right.BlockingQueueChannel)。

```go
public class BlockingQueueChannel<T> implements Channel<T>{
  private final BlockingQueue<T> queue;
  public BlockingQueueChannel(BlockingQueue<T> queue) {
    this.queue = queue;
   }
  @Override
  public T take() throws InterruptedException {
    return queue.take();
   }
  @Override
  public void put(T t) throws InterruptedException {
    queue.put(t);
   }
}
```

**（3）实现FileIndexThread类**

FileIndexThread类主要是生成文件索引的自定义线程类，考虑到线程的优雅退出问题，这里使用了两阶段终止模式。

源码详见：concurrent-design-patterns-producer-comsumer工程下的[io.binghe.concurrent.design.pc.right.FileIndexThread](http://io.binghe.concurrent.design.pc.right.FileIndexThread)。

```go
public class FileIndexThread extends AbstractTerminationThread {
​
  private final Channel<FileInfo> fileInfoChannel;
​
  public FileIndexThread(Channel<FileInfo> fileInfoChannel) {
    this.fileInfoChannel = fileInfoChannel;
   }
​
  @Override
  protected void doRun() throws InterruptedException {
    FileInfo fileInfo = fileInfoChannel.take();
    System.out.println("异步获取到文件 " + fileInfo.getFileName());
    try{
      this.buildFileIndex(fileInfo);
     }catch (Exception e){
      e.printStackTrace();
     }finally {
      //未完成的人数数量减1
      terminationToken.noExecuteTaskCount.decrementAndGet();
     }
   }
  
  private void buildFileIndex(FileInfo fileInfo) throws InterruptedException {
    System.out.println("生成文件索引开始 " + fileInfo.getFileName());
    long startTime = System.currentTimeMillis();
    Thread.sleep(2000);
    System.out.println("生成文件索引结束 " + fileInfo.getFileName() + "，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
}
```

可以看到，这里为了模拟生成文档索引的耗时操作，特意让线程休眠2秒钟。
