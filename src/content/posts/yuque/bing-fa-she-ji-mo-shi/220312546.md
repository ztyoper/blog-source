串行线程封闭模式的核心思想就是通过将多个并发的任务存入队列实现任务的串行执行，并且会为串行执行的任务创建唯一的一个工作线程进行处理。由于只有一个线程执行任务，自然无需对这些任务所访问的非线程安全对象加锁，从而避免了由于加锁带来的性能开销，也避免了死锁等一系列的问题。

### **一、故事背景**

小菜在老王的指导下使用单线程线程池初步解决了报表系统导出数据错乱的问题，也通过老王了解到使用串行线程封闭模式可以很好的解决问题。并且老王也为小菜详细的讲解了什么是串行线程封闭模式。了解完这些内容后，小菜极力想基于串行线程封闭模式优化报表系统。但是缺乏实际项目应用经验，不得不再次向老王请教，老王还是不厌其烦的为其讲解。

### **二、问题回顾**

公司生产环境的报表系统导出数据时，总是产生数据错乱的问题，经过排查和分析问题，发现是报表系统统计数据时，会将一个大的任务拆分成多个小的子任务，并且同一个任务下的所有子任务之间，具有严格的执行顺序，按照业务逻辑分析，同一个任务下的子任务需要由同一个线程分析和统计，但是生产环境同一个任务下的子任务却出现了由不同线程分析和统计的现象，这就导致了数据错乱的问题，如图48-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/2061eea4e521cd0d889aa36aa627cb070fbf7ac92a6e86c1c569b86a492903da.png)

以上图中的任务A为例，假设任务A下有子任务A-1和子任务A-2两个子任务，子任务A-1和子任务A-2的执行有着严格的执行顺序，也就是说必须执行完子任务A-1，得出结果数据后，再执行子任务A-2。但是，此时却出现了线程A执行子任务A-1，线程C执行子任务A-2的情况，由于无法保证线程A和线程C的执行顺序，此时就会出现数据错乱的问题。

### **三、初步解决**

为了保证按照严格的顺序执行每个任务下的子任务，需要将这些任务放到同一个线程中执行，这样不仅能够按照严格的顺序执行任务，也能够避免由于多线程加锁带来的开销。使用线程池初步解决问题的流程如图48-2所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/c483827a4526765937bc8ce78636907d65036e98cdf2b8a49f0112c28ba338f9.png)

可以看到，使用只有一个线程的线程池执行所有任务，不仅能够保证每个任务的执行顺序，还能避免由于多线程之间的加锁带来的性能开销问题。

### **四、串行线程封闭模式流程**

使用串行线程封闭模式时，会将多个并发执行的任务存入队列实现任务的串行执行，并且会为串行执行的任务创建唯一的一个工作线程进行处理，如图48-3所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/3ed88166a316f576d08e04d2abe484d50a3fc6c9ad3270ec96acc73f2fc0d6de.png)

可以看到，串行线程封闭模式会将多个并发执行的任务放入队列，最终由唯一的一个线程来执行任务。由于只有一个线程执行任务，自然无需对这些任务所访问的非线程安全对象加锁，从而避免了由于加锁带来的性能开销，也避免了死锁等一系列的问题。

### **六、串行线程封闭模式类实现**

关于Termination接口、TerminationToken类和AbstractTerminationThread类的实现可以参考前面的章节，本节不再赘述。这里，我们重点完成其他类的实现，具体实现步骤如下所示。

**（1）实现FileClient类**

FileClient类是模拟下载文件的客户端类，主要提供了初始化文件客户端的initClient()方法和下载文件的downloadFile()方法。

源码详见：[io.binghe.concurrent.design.thread.close.common.FileClient](http://io.binghe.concurrent.design.thread.close.common.FileClient)。

```go
public class FileClient {
​
  public void initClient(){
    System.out.println(Thread.currentThread().getName() + "初始化文件客户端开始");
    long startTime = System.currentTimeMillis();
    try {
      Thread.sleep(1000);
     } catch (InterruptedException e) {
      throw new RuntimeException(e);
     }
    System.out.println(Thread.currentThread().getName() + "初始化文件客户端完毕，耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
​
  public void downloadFile(String fileName){
    System.out.println(Thread.currentThread().getName() + "下载文件开始");
    long startTime = System.currentTimeMillis();
    try {
      Thread.sleep(2000);
     } catch (InterruptedException e) {
      throw new RuntimeException(e);
     }
    System.out.println(Thread.currentThread().getName() + "下载文件完毕，下载的文件为：" + fileName + ", 耗时：" + (System.currentTimeMillis() - startTime) + "ms");
   }
}
```

**（2）实现WorkerThread类**

WorkerThread类是工作线程类，内部维护了一个任务队列和文件客户端对象，并且WorkerThread类会继承AbstractTerminationThread类，实现doRun()方法，并且对外提供downloadFile()方法。

源码详见：[io.binghe.concurrent.design.thread.close.right.WorkerThread](http://io.binghe.concurrent.design.thread.close.right.WorkerThread)。

```go
public class WorkerThread extends AbstractTerminationThread {
  
  private final BlockingQueue<String> workQueue;
  private final FileClient fileClient;
  
  public WorkerThread() {
    this.workQueue = new ArrayBlockingQueue<>(128);
    fileClient = new FileClient();
    fileClient.initClient();
   }
​
  @Override
  protected void doRun() throws InterruptedException {
    //从队列中获取任务并执行
    String file = this.workQueue.take();
    try{
      fileClient.downloadFile(file);
     }finally {
      terminationToken.noExecuteTaskCount.decrementAndGet();
     }
   }
​
  public void downloadFile(String fileName){
    //放入队列
    try {
      this.workQueue.put(fileName);
      terminationToken.noExecuteTaskCount.incrementAndGet();
     } catch (InterruptedException e) {
      e.printStackTrace();
     }
   }
}
```

**（3）实现FileService接口**

FileService接口是文件服务的业务接口，主要提供了下载文件的downloadFile()方法、启动线程的init()方法和关闭线程的shutdown()方法。

源码详见：[io.binghe.concurrent.design.thread.close.right.FileService](http://io.binghe.concurrent.design.thread.close.right.FileService)。

```go
public interface FileService {
  void downloadFile(String fileName);
  void init();
  void shutdown();
}
```

**（4）实现FileServiceImpl类**

FileServiceImpl类是FileService接口的实现类，主要通过workerThread对象实现了FileService接口中定义的方法。

源码详见：[io.binghe.concurrent.design.thread.close.right.FileServiceImpl](http://io.binghe.concurrent.design.thread.close.right.FileServiceImpl)。

```go
public class FileServiceImpl implements FileService{
​
  private final WorkerThread workerThread;
​
  public FileServiceImpl() {
    this.workerThread = new WorkerThread();
   }
​
  @Override
  public void downloadFile(String fileName) {
    System.out.println(Thread.currentThread().getName() + "线程提交任务");
    workerThread.downloadFile(fileName);
   }
​
  @Override
  public void init() {
    workerThread.start();
   }
​
  @Override
  public void shutdown() {
    workerThread.terminate();
   }
}
```

### **七、串行线程封闭模式测试**

对基于串行线程封闭模式优化后的代码进行测试的方式也比较简单，测试类详见：[io.binghe.concurrent.design.thread.close.right.FileRightTest](http://io.binghe.concurrent.design.thread.close.right.FileRightTest)。

```go
public class FileRightTest {
  private static final int COUNT = 5;
  public static void main(String[] args) throws InterruptedException {
    CountDownLatch countDownLatch = new CountDownLatch(COUNT);
    FileService fileService = new FileServiceImpl();
    fileService.init();
    for (int i = 1; i <= COUNT; i++){
      int finalI = i;
      new Thread(()->{
        fileService.downloadFile("binghe00" + finalI);
        countDownLatch.countDown();
       }, "download-file-" + i + "-").start();
     }
    countDownLatch.await();
    fileService.shutdown();
   }
}
```

可以看到，在测试类FileRightTest的main()方法中，会创建一个文件服务对象fileService，调用初始化方法后，循环创建多个线程调用文件服务对象fileService的downloadFile()方法下载文件。
