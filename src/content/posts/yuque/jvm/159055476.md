2. 为什么要设置String_info，不设计utf-8_info不行吗？不行。一个Integer的数字7和一个String的"7"。不能都用utf-8_info来存储。

容器讲解：

1. 操作数栈用于临时存放操作数。
2. 局部变量表数组：用于存储当前方法中所有出现的变量。

1. 索引0处是变量 String[] args
2. 索引0处是变量 i
3. 索引0处是变量 j

字节码运行流程：

1. iconst_0：将常量0放入操作数栈
2. istore_1：将操作数栈弹出，放入局部变量表1号位置
3. iload_1：将局部变量表1中的数据，放（复制）到操作数栈
4. iconst_0：将常量1放入操作数栈
5. iadd：将操作数栈顶部的两个数据进行累加，结果放入栈中
6. istore_2：将操作数栈弹出，放入局部变量表2号位置
7. return：结束方法，返回空

## 3、类的生命周期

### 1、生命周期概述

> 类的生命周期描述了一个类加载、使用、卸载的整个过程

为什么要学习类的生命周期：

1. 类的生命周期本身就是一个 `高频面试题`
2. 生命周期中的初始化阶段频繁出现在 `大厂的笔试` 中
3. 作为后续大量 `知识点的基础`

应用场景：

1. 运行时常量池
2. 类加载器的作用
3. 类的加密和解密（防止反编译出类的信息）
4. 多态的原理
5. 更多知识点的基础

`加载Loading`-&gt;`连接Linking`-&gt;`初始化Initialization`-&gt;`使用Using`-&gt;`卸载Unloading`注：类的卸载在垃圾回收篇中讲解

`连接Linking`又可以细分为：验证-&gt;准备-&gt;解析

最重要的是`初始化Initialization`阶段

### 2、加载阶段

1. 加载(Loading)阶段第一步是 `类加载器` 根据类的 `全限定名` 通过 `不同` 的渠道以 `二进制流` 的方式 `获取字节码信息`

1. 本地文件：磁盘上的字节码文件
2. 动态代理生成：程序运行时使用动态代理生成
3. 通过网络传输的类：早期的Applet技术使用

2. `类加载器` 在加载完类之后，Java虚拟机会将 `字节码` 中的信息保存到 `方法区` 中。 生成一个InstanceKlass对象，保存类的所有信息，里边还包含实现特定功能比如多态的信息。

![tmp23E0.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/19cfab767f23292522e2b90f4a7f127a2bef97c83fd06d450afaef7a6093fa6d.png)

3. 同时，Java虚拟机还会在堆中生成一份与方法区中数据类似的java.lang.Class)对象。 作用是在Java代码中去获取类的信息(反射)以及存储静态字段的数据(JDK8及之后)。

![tmp75E6.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/5d41dd42a52b22ec06111c49755604516ad6bc8badd15bc3f3b29c59026df273.png)![tmpA498.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/210e74249f29b7e164a1850fe004d4126b90a7da76072dc67704c2bd1b65111e.png)![tmpCF92.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/f953a4e427e5bc88fa837f17cf52fd8b769de2c616eafe3564b420e4ae4bf3cf.png)

> 为什么要复制`InstanceKlass`到堆区生成一个java.lang.Class呢？
> 1. `InstanceKlass` 是c++编写的。java代码无法通过反射等方式获取类的信息。
> 2. `InstanceKlass` 存储的信息多，有些是不用的。为了让程序员无法访问到这些不用的信息。就生成一个删减后的 `java.lang.Class` 来和程序猿交互（反射）。 `java.lang.Class` 存储有静态字段的信息。

#### 1、&lt;clinit&gt;初始化方法

![tmp6ECA.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/8a17d3b8fb6331406075dcc225d91ad7df957c2fa9a8e60cbf31af6d8a2ef4b4.png)

准备阶段为静态变量`(static)`分配内存并设置初始值。但是最终`value`值不应该是1吗？因为`1`是在初始化阶段进行初始化获得的。

![tmpA325.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/55e8aedc905322f455272a78dd74f63f8d2991f4a94b17d49a54b9c24ef5fa7c.png)![tmpF29D.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/38a51eb6f93743a715535f51b086642a2551aac87b39f8f01fde1018231d336b.png)

> 如果将`静态代码块`和`显式初始化value`替换位置。那么最终`value`为`1`。也就是`<clinit>`方法中的`执行顺序`与`Java`中编写的顺序是`一致`的

以下`几种方式`会导致类的初始化：

1. 访问一个类的 `静态变量` 或者 `静态方法` ，注意：变量是final修饰的并且等号右边是 `常量` 则 `不会` 触发初始化方法&lt;clinit&gt;。
2. 调用Class.forName(String className)， `会` 触发初始化方法&lt;clinit&gt;

1. ![tmp9758.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/87b3e153e57c484cfd2c734eeae5dc698c5db4eda66d707e11522cd7d49935ee.png)

3. new一个该类的对象时， `会` 触发初始化方法&lt;clinit&gt;
4. 执行Main方法的 `当前类` ， `会` 触发初始化方法&lt;clinit&gt;
5. 添加 `-XX:+TraceClassLoading` 参数可以打印出 `加载并初始化` 的类。 `+` 表示开启该功能。

`<clinit>`指令在特定情况下不会出现，比如：如下几种情况是`不会进行初始化指令`执行的。

1. 无静态代码块且无静态变量赋值语句。
2. 有静态变量的声明，但是没有赋值语句。
   ![tmpE99C.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/ecd4148c659861648ac14fa22e4f6f81738dfab460a32fa165f8a500eeb3e2d7.png)
3. 静态变量的定义使用final关键字，这类变量会在准备阶段直接进行初始化。
   ![tmpE13E.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/7d82b6726d45f5d258ac14a0215c29d52ac85ecaf61512e00a7440dff8d39274.png)

## 4、类加载器

### 1、类加载器的分类

#### 1、什么是类加载器

> 类加载器(ClassLoader)是Java虚拟机提供给应用程序去实现获取类和接口字节码数据的技术。类加载器只参与加载过程中的字节码获取并加载到内存这一部分。

![tmp641E.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/4257586e20e974e4266915675ff1765cf9f8d1b5c7a77649d985d1e4cf18fab3.png)

1. 大部分类加载器是java写的。在jdk中
2. 小部分类加载器是c++写的。在Java虚拟机中
3. 本地接口JNI是用于调用Java虚拟机中的方法，这些方法使用C++编写。

![tmp6717.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/ba8bd7475a1afcabbd95f31bce16f16989b8a7e52e093b32f4101fa3622e0f65.png)

1. Java和c++写的类加载器们完成类的 `加载过程` 。也就是获取字节码文件。
2. 应用程序调用本地接口去生成方法区对象和生成堆上Class对象。

    public Class<?> loadClass(String name) throws ClassNotFoundException {
        return loadClass(name, false);
    }

    protected Class<?> loadClass(String name, boolean resolve)
        throws ClassNotFoundException
    {
        synchronized (getClassLoadingLock(name)) {
            // First, check if the class has already been loaded
            Class<?> c = findLoadedClass(name);
            if (c == null) {
                long t0 = System.nanoTime();
                try {
                    if (parent != null) {
                        c = parent.loadClass(name, false);
                    } else {
                        //native方法
                        c = findBootstrapClassOrNull(name);
                    }
                } catch (ClassNotFoundException e) {
                    // ClassNotFoundException thrown if class not found
                    // from the non-null parent class loader
                }
                //如果所有的类加载器都没有加载过该类
                if (c == null) {
                    // If still not found, then invoke findClass in order
                    // to find the class.
                    long t1 = System.nanoTime();
                    c = findClass(name);

                    // this is the defining class loader; record the stats
                    PerfCounter.getParentDelegationTime().addTime(t1 - t0);
                    PerfCounter.getFindClassTime().addElapsedTimeFrom(t1);
                    PerfCounter.getFindClasses().increment();
                }
            }
            //不执行连接阶段。也就不执行初始化方法<clinit>
            if (resolve) { 
                resolveClass(c);
            }
            return c;
        }
    }

    //找ClassLoader的实现类的重写方法
    protected Class<?> findClass(String name) throws ClassNotFoundException {
    throw new ClassNotFoundException(name);
    }

@SuppressWarnings("removal")
    private static void ensureDriversInitialized() {
        if (driversInitialized) {
            return;
        }
        synchronized (lockForInitDrivers) {
            if (driversInitialized) {
                return;
            }
            String drivers;
            try {
                drivers = AccessController.doPrivileged(new PrivilegedAction<String>() {
                    public String run() {
                        return System.getProperty(JDBC_DRIVERS_PROPERTY);
                    }
                });
            } catch (Exception ex) {
                drivers = null;
            }
            AccessController.doPrivileged(new PrivilegedAction<Void>() {
                public Void run() {
                    
                    ServiceLoader<Driver> loadedDrivers = ServiceLoader.load(Driver.class);
                    Iterator<Driver> driversIterator = loadedDrivers.iterator();

                    try {
                        while (driversIterator.hasNext()) {
                            driversIterator.next();
                        }
                    } catch (Throwable t) {
                        // Do nothing
                    }
                    return null;
                }
            });

            println("DriverManager.initialize: jdbc.drivers = " + drivers);

            if (drivers != null && !drivers.isEmpty()) {
                String[] driversList = drivers.split(":");
                println("number of Drivers:" + driversList.length);
                for (String aDriver : driversList) {

                        println("DriverManager.Initialize: loading " + aDriver);
                        Class.forName(aDriver, true,
                                ClassLoader.getSystemClassLoader());

                }

@CallerSensitive
    public static <S> ServiceLoader<S> load(Class<S> service) {
        //设置想要委派的类加载器，线程上下文默认保存的是应用类加载器。
        ClassLoader cl = Thread.currentThread().getContextClassLoader();

        //后面具体如何扫描classpath:/META-INF/services/java.sql.Driver的就不看了。不好找
        return new ServiceLoader<>(Reflection.getCallerClass(), service, cl);
    }

> 至此，ServiceLoader.load(Driver.class);使用应用类加载器加载驱动类Driver。这种foName式的加载完成后又会调用初始化方法&lt;clinit&gt;，会生成一个实例对象并进行驱动类Driver的注册。只差获取到Connection连接。DriverManager.getConnection()即可获取到当前驱动类Driver的connect。
