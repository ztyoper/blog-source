#### 2.自动配置类原理

> 导入了两个自动配置类：`SecurityAutoConfiguration`,`SecurityFilterAutoConfiguration`

##### 1.SecurityAutoConfiguration

> `SecurityAutoConfiguration`自动配置类详细。

```java
@AutoConfiguration
@ConditionalOnClass({DefaultAuthenticationEventPublisher.class})
@EnableConfigurationProperties({SecurityProperties.class})
@Import({SpringBootWebSecurityConfiguration.class, SecurityDataConfiguration.class})
public class SecurityAutoConfiguration {
    public SecurityAutoConfiguration() {
    }
    @Bean
    @ConditionalOnMissingBean({AuthenticationEventPublisher.class})
    public DefaultAuthenticationEventPublisher authenticationEventPublisher(ApplicationEventPublisher publisher) {
        return new DefaultAuthenticationEventPublisher(publisher);
    }
}
```

> 1. `security` 的所有配置在 `SecurityProperties` ： 以 `spring.security` 开头
> 2. 默认注册的 `defualtSecurityFilterChain` 组件（设置了一些基本的安全过滤）：
>    1. `http.authorizeHttpRequests().anyRequest().authenticated();` ：所有请求都需要认证（登录）
>    2. `http.formLogin();` ：开启表单登录: `spring security` 提供一个默认登录页，未经登录的所有请求都需要登录
>    3. `http.httpBasic();` ： `httpbasic` 方式登录（不用管）
> 3. `@EnableWebSecurity` 生效(a,b,c了解即可，可能学了 `security` 就好理解了)
>    1. `WebSecurityConfiguration` 生效： `web` 安全配置
>    2. `HttpSecurityConfiguration` 生效： `http` 安全规则
>    3. `@EnableGlobalAuthentication` 生效：全局认证生效
>       1. `AuthenticationConfiguration` ：认证配置

```java
@Configuration(proxyBeanMethods = false)
@ConditionalOnWebApplication(type = Type.SERVLET)
class SpringBootWebSecurityConfiguration {SpringBootWebSecurityConfiguration() {}

    @Configuration(proxyBeanMethods = false)
    //我们自己没有设置过滤链的时候，就会导入该默认过滤链
    @ConditionalOnMissingBeanname = {"springSecurityFilterChain"})
    @ConditionalOnClass({EnableWebSecurity.class})
    @EnableWebSecurity
    static class WebSecurityEnablerConfiguration {WebSecurityEnablerConfiguration() {}}

    @Configuration(proxyBeanMethods = false)
    @ConditionalOnDefaultWebSecurity
    static class SecurityFilterChainConfiguration {SecurityFilterChainConfiguration() {}

        @Bean
        @Order(2147483642)
        SecurityFilterChain defaultSecurityFilterChain(HttpSecurity http) throws Exception {
            ((AuthorizeHttpRequestsConfigurer.AuthorizedUrl)http.authorizeHttpRequests().anyRequest()).authenticated();
            http.formLogin();//开启表单登录: spring security提供一个默认登录页，未经登录的所有请求都需要登录
            http.httpBasic();
            return (SecurityFilterChain)http.build();
        }
    }
}
```

> `@EnableWebSecurity`在默认注册的`defualtSecurityFilterChain`组件上标注，并生效。

#### 3.自定义请求授权规则：http.authorizeHttpRequests

> 重要，我们可能需要`自定义请求的授权`，比如开启项目后，我们访问`/`,不是直接跳转到`登录认证界面`，而是跳转到我们定义的`index.html页面`。

![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/0b5033f16c5907f037fc55b56d1b4035ccd1d78fa25f9528c2bac6fd97c502c1.png)

> 1. `/login` 是去经过 `Thymeleaf` 渲染后的 `security` 添加的 `默认login.html` 页面，至于在哪里设置的 `login.html` ，还要学习 `security` 后才明白。
> 2. 默认登录的 `Username:user` `Password` :在项目启动终端输出中
>    ![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/13375276aae8a54544f9062cabbc4b0a42bc35216ad789f11ddc3f9e693d9d0a.png)
> 3. 定义配置文件，调整 `SecurityProperties` 可以改变登录账号和密码。

```properties
spring.security.user.name=zhangsan
spring.security.user.password=123456
```

> 4. 如果我们要访问 `/` ,不是直接跳转到 `登录认证界面` ，而是跳转到我们定义的 `index.html页面` 。应该如何做：

```java
@Configuration
public class AppSecurityConfiguration {
    //自定义过滤链，默认defaultSecurityFilterChain组件就不会被注册。
    @Bean
    SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        //请求授权
        http.authorizeHttpRequests(registry -> {
            registry.requestMatchers("/").permitAll() //1、首页所有人都允许
            .anyRequest().authenticated(); //2、剩下的任意请求都需要 认证（登录）
        });
        
        http.formLogin();//开启表单登录
        return http.build();
    }
}
```

> 效果是访问`/`不需要进行登录（授权），访问`其他路径`任然需要先登录。

#### 4.自定义登录规则：http.formLogin

> 插入一个小知识点：

```java
@Controller
public class PageController {

    @GetMapping("/test")
    public String toTest(){
        return "test";
    }
}//访问test.html页面，路径还是localhost:8080/test而不是localhost:8080/test.html
```

> 我们想自定义登录规则或自定义登录界面的展示。

```java
@EnableMethodSecurity
@Configuration
public class AppSecurityConfiguration {

    @Bean
    SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        //自定义过滤链，默认defaultSecurityFilterChain组件就不会被注册。
        //请求授权
        http.authorizeHttpRequests(registry -> {
            registry.requestMatchers("/").permitAll() //1、首页所有人都允许
                    .anyRequest().authenticated(); //2、剩下的任意请求都需要 认证（登录）
        });

        //表单登录
        //3、表单登录功能：开启默认表单登录功能；Spring Security提供默认登录页
        http.formLogin(formLogin -> {
            formLogin.loginPage("/login").permitAll(); //自定义登录页路径位置/login(会被Thymeleaf渲染)，并且所有人都能访问
            //如果不是.permitAll()，是.authenticated()的话：
            //除了 / 路径的请求，其他请求路径都要先执行（登录）认证。而其他请求路径当然也包括"/login"
            //所以"/login"路径必须是.permitAll()
        });

        return http.build();
    }
}
```

#### 5.自定义用户信息查询规则：UserDetailsService

> 我们需要不同用户都能登录，并且有不同的访问权限。
> 1. 我们要用到 `UserDetailsService` 的实现类 `JDBCDaoImpl` 或 `JdbcUserDetailsManager` 去找·数据库用户·中是否有符合（登录）认证的账号密码，并获取他的所有权限。
> 2. 我们要用到 `UserDetailsService` 的实现类 `InMemoryUserDetailsManager` 去找项目中 `写死的几个用户` 中是否有符合（登录）认证的账号密码，并获取他的所有权限。

![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/ba72655116a2243de0d1046d8e6543a3c50c70724a36ec0df9b66e3a0abe2fc1.png)

```java
@EnableMethodSecurity
@Configuration
public class AppSecurityConfiguration {

    @Bean //查询用户详情；
    UserDetailsService userDetailsService(PasswordEncoder passwordEncoder){
        UserDetails zhangsan = User.withUsername("zhangsan")
        .password(passwordEncoder.encode("1")) //使用密码加密器加密密码进行存储
        .roles("admin", "hr")
        .authorities("file_read", "file_write")
        .build();

        UserDetails lisi = User.withUsername("lisi")
        .password(passwordEncoder.encode("123456"))
        .roles("hr")
        .authorities("file_read")
        .build();

        UserDetails wangwu = User.withUsername("wangwu")
        .password(passwordEncoder.encode("123456"))
        .roles("admin")
        .authorities("file_write","world_exec")
        .build();

        //默认内存中保存所有用户信息
        InMemoryUserDetailsManager manager = new InMemoryUserDetailsManager(zhangsan,lisi,wangwu);
        return manager;
    }


    @Bean //密码加密器
    PasswordEncoder passwordEncoder(){
        return new BCryptPasswordEncoder();
    }
}
```

> 1. 导入 `UserDetailsService` 或者 `PasswordEncoder（密码加密器）` ，都会使配置文件写的账号、密码失效。 `spring.security.user.name=zhangsan` 和 `spring.security.user.password=123456`
> 2. 密码加密器是必须要有的，不然要报错。

#### 6.开启方法级别的精确权限控制

> @EnableMethodSecurity +@PreAuthorize("hasAuthority('world_exec')")

![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/50219e994784aa0a57f28fd1cf3630e2f72ca3c6747685672b5b25ad5bdde837.png)

> 只有王五拥有`word`文件的`执行`权限:`word_exec`。在`AppSecurityConfiguration`上标注`@EnableMethodSecurity`并访问文件`word`的方法上添加`@PreAuthorize("hasAuthority('world_exec')")`，要求先决权限即可。

```java
@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello(){
        return "Hello!Spring Security";
    }

    //只有王五才能访问了
    @PreAuthorize("hasAuthority('world_exec')")//还有其他的：hasAnyRole()...，
    @GetMapping("/world")
    public String world(){
        return "Hello World!!!";
    }
}
```

> 但这里并没有出现`@Secured("文件 r")`，还得学习`security`。
