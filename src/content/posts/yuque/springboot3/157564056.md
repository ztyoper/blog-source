# 7、AOT

## 1. AOT与JIT

**<span style="color: #601BDE">AOT</span>**：<span style="color: var(--asciidoctor-heading-font-color)">Ahead-of-Time</span>（提前**编译**）：**程序执行前**，全部被编译成**机器码**

**<span style="color: #601BDE">JIT</span>**：Just in Time（即时**编译**）: 程序边**编译**，边运行；

**编译：**

- **源代码（.c、.cpp、.go、.java。。。） ===编译=== 机器码**

**语言：**

- **<span style="color: #601BDE">编译</span>** **型语言：编译器**
- **解释型语言：解释器**

### 1. Complier 与 Interpreter

Java相当于是**半编译半解释型语言。**

> <span style="color: rgb(0, 0, 0)">● 编译型语言：编译器 ● 解释型语言：解释器 而Java是JIT 即时编译器 是吗？JIT就是根据是否是热点代码，将其编译为机器码存储在CodeCache中</span>
> <span style="color: rgb(36, 41, 47)">是的，您说得对。Java使用的是JIT（Just-In-Time）即时编译器。在Java中，源代码首先被编译成字节码（Bytecode），然后由Java虚拟机（JVM）在运行时将这些字节码解释执行或者即时编译成本地机器码。</span>
> <span style="color: rgb(36, 41, 47)">JIT编译器会根据程序在运行过程中的实际情况来判断哪些代码是“热点代码”，即频繁执行的部分，然后将这些“热点代码”编译为本地机器码以提高执行效率。编译后的机器码会被存储在CodeCache中，以便在需要时直接执行，而不用再解释执行字节码。</span>
> <span style="color: rgb(36, 41, 47)">通过使用JIT编译器，Java实现了一种折中的方法：保留了跨平台性和灵活性，同时也提高了程序的性能。JIT编译器的存在使得Java程序在运行时能够动态地优化性能，并且根据实际情况进行编译，从而在一定程度上提高了程序的执行效率。</span>

#### 流程概要

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/6fdd2443fa0d7705eaa43c798536b72d82b9fdfeeeb122a4b67259b01f29ea15.png)

> 字节码文件（.class）在执行方法调用时，判断是否编译：
> 1. 是： **编译后执行** 。
> 2. 否： **解释执行** ，并且调用次数统计。
>    1. 如果达到设定的 **阈值** ，将该方法判定为 **热点方法** ，对其进行 **编译** ，并保存在 **CodeCache** 中。
>    2. 如果没有达到设定的 **阈值** ，就算了。

#### 详细流程

> 热点代码：调用次数非常多的代码

![未命名绘图2.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/4bf91f9d8160a2eeb1a988828f387dbaafb1a5ddbc0ccdbc461c6ea29b884b40.png)

> 字节码文件（.class）在执行方法调用时，判断CodeCahe中是否有已编译的机器码：
> 1. 是： **获取机器码并执行** 。
> 2. 否：进行热点探测。
>    1. 如果达到设定的 **阈值** ，将该方法判定为 **热点代码，并-XX:+BackgroundCompilation:默认tue,异步。同步异步检测。**
>       1. 如果是同步，则对其进行 **编译** ，并保存在 **CodeCache** 中。然后执行机器码。
>       2. 如果是异步，则对其进行 **解释执行** ，并且异步地 **编译** 代码并保存在 **CodeCache** 中。
>    2. 如果没有达到设定的 **阈值** ，就解释执行。
> 一般一个springboot项目，一开始没有被标记为`热点代码`的代码。因为热点代码需要`运行一段时间`才会被标记。所以启动慢，以后随着热点代码被编译为机器码存储在CodeCache中越来越多，运行地就越快。

### 5. JVM编译器

<span style="color: rgb(51, 51, 51)">JVM中默认集成了两种即时编译器（解释器），Client Compiler 和 Server Compiler；</span>

- Client Compiler注重启动速度和局部的优化
- Server Compiler更加关注全局优化，性能更好，但由于会进行更多的全局分析，所以启动速度会慢。

<span style="color: rgb(51, 51, 51)">Client Compiler：</span>

- HotSpot VM带有一个Client Compiler **<span style="color: rgb(51, 51, 51)">C1编译器</span>**
- 这种编译器 **<span style="color: rgb(51, 51, 51)">启动速度快</span>** ，但是性能比较Server Compiler来说会差一些。
- 编译后的机器码执行效率没有C2的高

<span style="color: rgb(51, 51, 51)">Server Compiler：</span>

- Hotspot虚拟机中使用的Server Compiler有两种： **<span style="color: rgb(51, 51, 51)">C2</span>** 和 **<span style="color: rgb(51, 51, 51)">Graal</span>** 。
- 在Hotspot VM中，默认的Server Compiler是 **<span style="color: rgb(51, 51, 51)">C2编译器。</span>**

### <span style="color: rgb(51, 51, 51)">6. 分层编译</span>

![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/b6913bfc0da9fd96ddea5486a160b2a02ea207b237f5bf7bbdf5bb100a1bb648.png)

<span style="color: rgb(51, 51, 51)">Java 7开始引入了分层编译(</span>**<span style="color: rgb(48, 48, 48)">Tiered Compiler</span>**<span style="color: rgb(51, 51, 51)">)的概念，它结合了</span>**<span style="color: rgb(51, 51, 51)">C1</span>**<span style="color: rgb(51, 51, 51)">和</span>**<span style="color: rgb(51, 51, 51)">C2</span>**<span style="color: rgb(51, 51, 51)">的优势，追求启动速度和峰值性能的一个平衡。分层编译将JVM的执行状态分为了五个层次。</span>**<span style="color: rgb(51, 51, 51)">五个层级</span>**<span style="color: rgb(51, 51, 51)">分别是：(了解即可)</span>

- 解释执行。
- 执行不带profiling的C1代码。
- 执行仅带方法调用次数以及循环回边执行次数profiling的C1代码。
- 执行带所有profiling的C1代码。
- 执行C2代码。

**<span style="color: rgb(51, 51, 51)">profiling就是收集能够反映程序执行状态的数据</span>**<span style="color: rgb(51, 51, 51)">。其中最基本的统计数据就是方法的调用次数，以及循环回边的执行次数。</span>

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/e535569115ec986a3583bdcb0e8c81a48ffbfcd5a3591f1d32007d19a80f574f.png)

- 图中第①条路径，代表编译的一般情况， **<span style="color: rgb(51, 51, 51)">热点方法</span>** 从解释执行到被3层的C1编译，最后被4层的C2编译。
- 如果 **<span style="color: rgb(51, 51, 51)">方法比较小</span>** （比如Java服务中常见的 **<span style="color: rgb(51, 51, 51)">getter/setter</span>** 方法），3层的profiling没有收集到有价值的数据，JVM就会断定该方法对于C1代码和C2代码的执行效率相同，就会执行图中第②条路径。在这种情况下，JVM会在3层编译之后，放弃进入C2编译， **<span style="color: rgb(51, 51, 51)">直接选择用1层的C1编译运行</span>** 。
- 在 **<span style="color: rgb(51, 51, 51)">C1忙碌</span>** 的情况下，执行图中第③条路径，在解释执行过程中对程序进行 **<span style="color: rgb(51, 51, 51)">profiling</span>** ，根据信息直接由第4层的 **<span style="color: rgb(51, 51, 51)">C2编译</span>** 。
- 前文提到C1中的执行效率是 **<span style="color: rgb(51, 51, 51)">1层&gt;2层&gt;3层</span>** ， **<span style="color: rgb(51, 51, 51)">第3层</span>** 一般要比 **<span style="color: rgb(51, 51, 51)">第2层</span>** 慢35%以上，所以在 **<span style="color: rgb(51, 51, 51)">C2忙碌</span>** 的情况下，执行图中第④条路径。这时方法会被2层的C1编译，然后再被3层的C1编译，以减少方法在 **<span style="color: rgb(51, 51, 51)">3层</span>** 的执行时间。
- 如果 **<span style="color: rgb(51, 51, 51)">编译器</span>** 做了一些比较 **<span style="color: rgb(51, 51, 51)">激进的优化</span>** ，比如分支预测，在实际运行时 **<span style="color: rgb(51, 51, 51)">发现预测出错</span>** ，这时就会进行 **<span style="color: rgb(51, 51, 51)">反优化</span>** ，重新进入 **<span style="color: rgb(51, 51, 51)">解释执行</span>** ，图中第⑤条执行路径代表的就是 **<span style="color: rgb(51, 51, 51)">反优化</span>** 。

<span style="color: rgb(51, 51, 51)">总的来说，C1的编译速度更快，C2的编译质量更高，分层编译的不同编译路径，也就是JVM根据当前服务的运行情况来寻找当前服务的最佳平衡点的一个过程。从JDK 8开始，JVM默认开启分层编译。</span>

上述分层编译了解即可。

**云原生**：Cloud Native； Java小改版；

最好的效果：

存在的问题：

- java应用如果用jar，解释执行，热点代码才编译成机器码；初始启动速度慢，初始处理请求数量少。
- 大型云平台，许多机器都依赖你这个 `.jar` 项目工作，因此要求每一种应用都必须秒级启动。每个应用都要求效率高。

希望的效果：

- java应用也能提前被编译成 **机器码** ，随时 **急速启动** ，一启动就急速运行，最高性能
- 编译成机器码的好处：

- 原来需要另外的服务器安装Java环境，来运行 `.jar项目` 。
- 现在直接编译成 **机器码** 的，只要是Windows X64生成的机器码，这个机器码就可以在所有 Windows X64 系统上 **直接运行，不需要openjdk** 。

**原生**镜像：**native**-image（机器码、本地镜像）

- 把应用打包成能适配本机平台 的可执行文件（机器码、本地镜像）

## 2. GraalVM

[https://www.graalvm.org/](https://www.graalvm.org/)

> **<span style="color: var(--gpts-primary-text-color)">GraalVM</span>**<span style="color: var(--gpts-primary-text-color)">是一个高性能的</span>**<span style="color: var(--gpts-primary-text-color)">JDK</span>**<span style="color: var(--gpts-primary-text-color)">，旨在</span>**<span style="color: var(--gpts-primary-text-color)">加速</span>**<span style="color: var(--gpts-primary-text-color)">用Java和其他JVM语言编写的</span>**<span style="color: var(--gpts-primary-text-color)">应用程序</span>**<span style="color: var(--gpts-primary-text-color)">的</span>**<span style="color: var(--gpts-primary-text-color)">执行</span>**<span style="color: var(--gpts-primary-text-color)">，同时还提供JavaScript、Python和许多其他流行语言的运行时。</span>
> **<span style="color: var(--gpts-primary-text-color)">GraalVM</span>**<span style="color: var(--gpts-primary-text-color)">提供了</span>**<span style="color: var(--gpts-primary-text-color)">两种</span>**<span style="color: var(--gpts-primary-text-color)">运行</span>**<span style="color: var(--gpts-primary-text-color)">Java应用程序</span>**<span style="color: var(--gpts-primary-text-color)">的方式：</span>
> - 1. 在HotSpot JVM上使用 **<span style="color: rgba(0, 0, 0, 0.8)">Graal即时（JIT）编译器，这个不重要，因为原来JVM的C1.C2即时编译器挺好。</span>**
> - 2. 作为 **<span style="color: var(--gpts-primary-text-color)">预先编译（AOT）</span>** 的本机 **<span style="color: var(--gpts-primary-text-color)">可执行文件</span>** 运行（ **<span style="color: var(--gpts-primary-text-color)">本地镜像</span>** ）。
> <span style="color: var(--gpts-primary-text-color)">GraalVM的多语言能力使得在单个应用程序中混合多种编程语言成为可能，同时消除了外部语言调用的成本。</span>

## 3. SpringBoot整合

### 0、项目代码

#### 1、Controller

```java
@RestController
public class HelloController {

//    @Autowired
//    HelloService helloService;

    @GetMapping("/")
    public String hello(){

        //反射调用
        Object invoke = "sayHello";
        try {
            //1、反射获取sayHello方法
            Method sayHello = HelloService.class.getMethod(invoke.toString());
            //2、利用反射获取无参构造器，并创建出对象
            HelloService instance = HelloService.class.getConstructor().newInstance();
            //3、反射执行 instance 的 sayHello 方法
            invoke = sayHello.invoke(instance);
            //4、新版的 GraalVM 可以处理反射，直接编译了。
        } catch (Exception e) {
            throw new RuntimeException(e);
        }

        return "Hello, Spring Boot AOT!!! " + invoke.toString();
    }
}
```

### 6. 常见问题

可能提示如下各种错误，无法构建原生镜像，需要配置环境变量；

- 出现 `cl.exe` 找不到错误
- 出现乱码
- 提示 `no include path set`
- 提示fatal error LNK1104: cannot open file 'LIBCMT.lib'
- 提示 LINK : fatal error LNK1104: cannot open file 'kernel32.lib'
- 提示各种其他找不到
