2. cachePeriod： 缓存周期； 多久不用找服务器要新的。 默认0s，以s为单位
3. cacheControl： **HTTP缓存** 控制； https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Caching 好像不太重要 `默认无` 。
4. **useLastModified** ：是否使用最后一次修改(是否使用lastModified头)。默认true。要配合HTTP Cache规则。

> 若客户端向服务器请求1GB的图片资源，服务器会发送资源和该资源最后修改时间过去。若客户端又发送请求获取该资源时，会请求得到该资源的最后修改时间。
> 1. 如果和本地的最后修改时间一致，就直接使用本地的资源，返回状态码304
> 2. 如果和本地的最后修改时间不同，就再发请求获取最新资源

> 好处是减轻服务器的负担。

> 配置文件方式是修改原有的配置，代码方式是添加新的配置，而且自定义性高（比如定义一种特殊路径只能访问一种特殊资源文件夹）。而且可以使用@EnableWebMvc去禁用boot的默认的配置。

```java
        registry.addResourceHandler("/static/**")

                .setCacheControl(CacheControl.maxAge(1180, TimeUnit.SECONDS));

}
```

###### 3.为什么容器中放一个`WebMvcConfigurer`就能配置底层行为

> 1. WebMvcAutoConfiguration 是一个自动配置类，它里面有一个 `EnableWebMvcConfiguration`
> 2. `EnableWebMvcConfiguration` 继承于 `DelegatingWebMvcConfiguration` ，后者继承于 `WebMvcConfigurationSupport`
> 3. `DelegatingWebMvcConfiguration` 利用自动注入@Autowire把容器中 所有 `WebMvcConfigurer` 注入进来

> 4. 别人调用 `DelegatingWebMvcConfiguration` 的方法配置底层规则，而它调用所有 `WebMvcConfigurer` 的配置底层方法。至于别人在哪调用了 `DelegatingWebMvcConfiguration` 的方法，我没找到，但它说有就有吧。。。

```java
@Autowired(required = false)
public void setConfigurers(List<WebMvcConfigurer> configurers) {
    if (!CollectionUtils.isEmpty(configurers)) {
        this.configurers.addWebMvcConfigurers(configurers);
    }
}
```

###### 1. Ant风格路径用法

<span style="color: rgb(48, 54, 63)">Ant 风格的路径模式语法具有以下规则：</span>

- * ：表示 **<span style="color: rgb(48, 54, 63)">任意数量</span>** 的字符。
- ? ：表示任意 **<span style="color: rgb(48, 54, 63)">一个字符</span>** 。
- ** ：表示 **<span style="color: rgb(48, 54, 63)">任意数量的目录</span>** 。
- {} ：表示一个命名的模式 **<span style="color: rgb(48, 54, 63)">占位符</span>** 。
- [] ：表示 **<span style="color: rgb(48, 54, 63)">字符集合</span>** ，例如 [a-z] 表示小写字母。

<span style="color: rgb(48, 54, 63)">例如：</span>

- *.html 匹配任意名称，扩展名为 .html 的文件。
- /folder1/*/*.java 匹配在 folder1 目录下的任意两级目录下的 .java 文件。
- /folder2/**/*.jsp 匹配在 folder2 目录下任意目录深度的 .jsp 文件。
- /{type}/{id}.html 匹配任意文件名为 {id}.html ，在任意命名的 {type} 目录下的文件。

<span style="color: rgb(48, 54, 63)">注意：Ant 风格的路径模式语法中的特殊字符需要转义，如：</span>

- 要匹配文件路径中的星号，则需要转义为 \\* 。
- 要匹配文件路径中的问号，则需要转义为 \\? 。

###### <span style="color: rgb(48, 54, 63)">2. 模式切换</span>

> ##### <span style="color: rgb(48, 54, 63)">AntPathMatcher 与 PathPatternParser spring.mvc中设置</span>
> - PathPatternParser 在 jmh 基准测试下，有 6~8 倍吞吐量提升，降低 30%~40%空间分配率
> - PathPatternParser 兼容 AntPathMatcher 语法，并支持更多类型的路径模式，默认选择
> - PathPatternParser " **<span style="color: rgb(48, 54, 63)">**</span>** " **<span style="color: rgb(48, 54, 63)">多段匹配</span>** 的支持 **<span style="color: rgb(48, 54, 63)">仅允许在模式末尾使用</span>**

```java
    @GetMapping("/a*/b?/{p1:[a-f]+}")
    public String hello(HttpServletRequest request, 
                        @PathVariable("p1") String path) {

        log.info("路径变量p1： {}", path);
```

```java
public class RequestContextFilter extends OncePerRequestFilter {
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain) throws ServletException, IOException {
        ServletRequestAttributes attributes = new ServletRequestAttributes(request, response);
        //将当前request和当前response打包成attributes
        this.initContextHolders(request, attributes);
        try {
            filterChain.doFilter(request, response);
        } finally {
            this.resetContextHolders();
            if (this.logger.isTraceEnabled()) {
                this.logger.trace("Cleared thread-bound request context: " + request);
            }
            attributes.requestCompleted();
        }
    }
    private void initContextHolders(HttpServletRequest request, ServletRequestAttributes requestAttributes) {
        //将打包好的attributes暂存起来。之后可以在任何地方获取到当前的request和response
        RequestContextHolder.setRequestAttributes(requestAttributes, this.threadContextInheritable);
        if (this.logger.isTraceEnabled()) {
            this.logger.trace("Bound request context to thread: " + request);
        }
    }
}
```

## 5.ErrorMvcAutoConfiguration错误处理

### 1. 默认机制

> **错误处理的自动配置**都在`ErrorMvcAutoConfiguration`中，两大核心机制：
> - 1. SpringBoot 会 **<span style="color: #601BDE">自适应</span>** **处理错误** ， **<span style="color: #601BDE">响应页面</span>** 或 **<span style="color: #601BDE">JSON数据</span>**
> - 2. **<span style="color: #601BDE">SpringMVC的错误处理机制</span>** 依然保留， **<span style="color: #601BDE">MVC处理不了</span>** ，才会 **<span style="color: #601BDE">交给boot进行处理</span>**

### ![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/59e865528025501ebf6c6f6476a302e7cd4c8e12c1d07e96d00a2869eba518a5.png)

### 2. SpringMVC定义错误处理

> `@ExceptionHandler`捕获的异常不会在页面上展示出来。而`springboot方式的`异常说是处理。不如说是在控制台打印`一堆错误堆栈`后的`页面跳转`。`ProblemDetailsExceptionHandler`类也是标注了`@ExceptionHandler`,因此在配置文件移动该类后，一些它管理的异常也会被它捕获，并且不会在终端输出错误堆栈。

##### 1.只针对单个业务类的错误处理

> 3. 这方法是对异常进行捕获并打印 `json` 格式的结果到页面上，如果同样有一个对异常进行捕获并跳转页面的 `自定义页面响应` 方法。 `@ExceptionHandler(Exception.class)` 一样的话，两个异常捕获方法都会失效，无法捕获异常。后者加了 `@RequestMapping(produces = {"text/html"})` 也不管用，而且貌似 `@RequestMapping(produces = {"text/html"})` 是加在有 `@RequestMapping` 注解修饰的接口方法上的。反正只要有一个以上标有 `@ExceptionHandler(Exception.class)` 的异常捕获方法，这几个方法都会失效。因此弄一个返回 `json` 一个 `返回页面` 的设想是不可行的。

##### 2.针对所有业务类的错误处理

> 使用`@ControllerAdvice + @ExceptionHandler`进行统一异常处理，所有业务类出现的错误都可以被接收

```java
@ControllerAdvice //这个类是集中处理所有 @Controller 发生的错误
public class GlobalExceptionHandler {
    /**
     * 1、@ExceptionHandler 标识一个方法处理错误，默认只能处理这个类发生的指定错误
     * 2、@ControllerAdvice 统一处理所有错误
     */
    @ResponseBody //对象写出为json
    @ExceptionHandler(Exception.class)
    public String handleException1(Exception e){
        System.out.println(e);//java.lang.ArithmeticException: / by zero
        return "json : Ohho~~~统一处理，原因："+e;
    }
    @ExceptionHandler(ArithmeticException.class)
    public String handleException2(Exception e, Model model){
        model.addAttribute("msg", e);
        e.printStackTrace();
        return "welcome_error";
    }
}
```

> 1. 弄一个返回 `json` 一个 `返回页面` ，如果它们的 `@ExceptionHandler(Exception.class)` 一样，就直接运行异常了其他的和只针对单个业务类的错误处理一样。

```java
	@Override
	public ModelAndView resolveErrorView(HttpServletRequest request, HttpStatus status, Map<String, Object> model) {
		ModelAndView modelAndView = resolve(String.valueOf(status.value()), model);
		if (modelAndView == null && SERIES_VIEWS.containsKey(status.series())) {
            //templates和四个静态资源目录下没有对应的精确码.html，并且错误code是5xx或4xx
            //将精确码String.valueOf(status.value())替换成模糊码SERIES_VIEWS.get(status.series())再走一遍resolve方法
			modelAndView = resolve(SERIES_VIEWS.get(status.series()), model);
		}
		return modelAndView;
	}
	private ModelAndView resolve(String viewName, Map<String, Object> model) {
		String errorViewName = "error/" + viewName;
		TemplateAvailabilityProvider provider = this.templateAvailabilityProviders.getProvider(errorViewName,
				this.applicationContext);
		if (provider != null) {
            //templates下有对应的精确码.html，返回modelAndView
			return new ModelAndView(errorViewName, model);
		}
        //templates下没有对应的精确码.html，调用resolveResource查询四个静态资源目录下面
		return resolveResource(errorViewName, model);
	}
	private ModelAndView resolveResource(String viewName, Map<String, Object> model) {
		for (String location : this.resources.getStaticLocations()) {
			try {
				Resource resource = this.applicationContext.getResource(location);
				resource = resource.createRelative(viewName + ".html");
				if (resource.exists()) {
                    //四个静态资源目录下有对应的精确码.html，返回modelAndView
					return new ModelAndView(new HtmlResourceView(resource), model);
				}
			}
			catch (Exception ex) {
			}
		}
        //四个静态资源目录下有对应的精确码.html，返回null
		return null;
	}
```

## 7. 全面接管SpringMVC

> - SpringBoot 默认配置好了 SpringMVC 的所有常用特性。
> - 如果我们需要全面接管SpringMVC的所有配置并 **禁用默认配置** ，仅需要编写一个自己写的 `WebMvcConfigurer` 配置类，并标注 `@EnableWebMvc` 即可。
> - 全手动模式
>    - `@EnableWebMvc` : 禁用默认配置,在自己写的 `WebMvcConfigurer` 配置类上定义 `@EnableWebMvc` 。
>    - **自己写** `WebMvcConfigurer` 组件：去全部重新定义MVC的底层行为，就像SpringMVC框架下自己定义的那样。
> - 手自一体模式
>    - **自己写的** `WebMvcConfigurer` 组件会被添加到默认 `WebMvcConfigurer们` 中一同定义底层行为。当然也可以通过配置文件修改默认 `WebvcConfigurer们` 的参数。
> - 全自动模式
>    - 直接写业务，也不管配置文件。

### 1. WebMvcAutoConfiguration 到底自动配置了哪些规则

> SpringMVC自动配置场景给我们配置了如下所有**默认行为**

1. `WebMvcAutoConfiguration` web场景的自动配置类

1. 支持 `RESTful` 的 `filter` ： `HiddenHttpMethodFilter` ，多了 `PUT` 和 `DELETE`
2. 支持 `非POST` 请求，请求体携带数据： `FormContentFilter`
3. 导入 `EnableWebMvcConfiguration` ：

1. `RequestMappingHandlerAdapter` ，暂时不知道，要看 `SpringMVC` 才知道。
2. `WelcomePageHandlerMapping` ： **欢迎页功能** 支持（模板引擎目录、静态资源目录放 `index.html` ），项目访问 `/` 就默认展示这个页面。
3. `RequestMappingHandlerMapping` ：找每个请求由谁处理的映射关系。
4. `ExceptionHandlerExceptionResolver` ：默认的异常解析器
5. `LocaleResolver` ：国际化解析器
6. `ThemeResolver` ：主题解析器，和后端没有任何关系，完全靠前端。
7. `FlashMapManager` ：临时数据共享
8. `FormattingConversionService` ： 数据格式化 、类型转化
9. `Validator` ： 数据校验 `JSR303` 提供的数据校验功能
10. `WebBindingInitializer` ：请求参数的封装与 `绑定`
11. `ContentNegotiationManager` ：内容协商管理器

4. `WebMvcAutoConfigurationAdapter` 配置生效，它是一个 `WebMvcConfigurer` ，定义mvc底层组件

1. 定义好 `WebMvcConfigurer` **底层组件默认功能；所有功能详见列表**
2. 视图解析器： `InternalResourceViewResolver` ， `jsp` 页面渲染功能。可以不管。
3. 视图解析器： `BeanNameViewResolver` , **视图名（controller方法的返回值字符串）** 就是组件名，默认生成的 `error` 白页视图就是被 `BeanNameViewResolver` 找到的。
4. 内容协商解析器： `ContentNegotiatingViewResolver`
5. 请求上下文过滤器： `RequestContextFilter` : 任意位置直接获取当前请求 。这个比较重要。
6. `configureResourceChain` 静态资源链规则，目前都是前端在管理静态资源了。就不用这个了。
7. `ProblemDetailsExceptionHandler` ：错误详情，这个类也被 `@ControllerAdvice` 修饰SpringMVC内部常见的异常会被它捕获

5. 定义了MVC默认的底层行为: `WebMvcConfigurer`

### 2. @EnableWebMvc 禁用默认行为

1. `@EnableWebMvc` 给容器中导入 `DelegatingWebMvcConfiguration` 组件，他是 `WebMvcConfigurationSupport` 的子类。
2. `WebMvcAutoConfiguration` 有一个核心的条件注解, `@ConditionalOnMissingBean(WebMvcConfigurationSupport.class)` ，容器中没有 `WebMvcConfigurationSupport` ， `WebMvcAutoConfiguration` 才生效.
3. @EnableWebMvc 导入 `WebMvcConfigurationSupport` 导致 `WebMvcAutoConfiguration` 失效。导致禁用了默认行为

> - @EnableWebMVC 禁用了 Mvc的自动配置
> - WebMvcConfigurer 定义SpringMVC底层组件的功能类

### 4. 最佳实践

> SpringBoot 已经默认配置好了**Web开发**场景常用功能。我们直接使用即可。

#### 三种方式

| 方式 | 用法 | 效果 |  |
| --- | --- | --- | --- |
| **全自动** | 直接编写控制器逻辑 |  | 全部使用**自动配置默认效果** |
| **<span style="color: #DF2A3F">手自一体</span>** | `@Configuration`+配置`WebMvcConfigurer`+*<span style="color: rgb(213, 97, 97)">配置 WebMvcRegistrations</span>**<span style="color: rgb(48, 54, 63)"></span>* | **不要标注**`@EnableWebMvc` | **保留自动配置效果****手动设置部分功能**定义MVC底层组件 |
| **全手动** | `@Configuration`+配置`WebMvcConfigurer` | **标注**`@EnableWebMvc` | **禁用自动配置效果****全手动设置** |

**总结：**

> **给容器中写一个配置类`@Configuration`实现 `WebMvcConfigurer`但是不要标注 `@EnableWebMvc`注解，实现手自一体的效果。**
