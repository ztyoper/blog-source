#### 2.生命周期全流程

![tmp57AA.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/44a672519977bacf710826865dfb080247ec21208d72f35d17ddd91df8895f86.png)

```java
/**
 * Listener先要从 META-INF/spring.factories 读到
 *
 * 1、引导： 利用 BootstrapContext 引导整个项目启动
 *      starting：              应用开始，SpringApplication的run方法一调用，只要有了 BootstrapContext 就执行
 *      environmentPrepared：   环境准备好（把启动参数等绑定到环境变量中），但是ioc还没有创建；【调一次】
 * 2、启动：
 *      contextPrepared：       ioc容器创建并准备好，但是sources（主配置类）没加载。并关闭引导上下文；组件都没创建  【调一次】
 *      contextLoaded：         ioc容器加载。主配置类加载进去了。但是ioc容器还没刷新（我们的bean没创建）。
 *      =======截止以前，ioc容器里面还没造bean呢=======
 *      started：               ioc容器刷新了（所有bean造好了），但是 runner 没调用。
 *      ready:                  ioc容器刷新了（所有bean造好了），所有 runner 调用完了。
 * 3、运行
 *     以前步骤都正确执行，代表容器running。
 整个灰色方框框住的6个过程部分会try-catch异常，如果failed启动失败，会执行fialed方法。
 */
```

### 2. 事件触发时机

#### 1. 各种回调监听器

- `BootstrapRegistryInitializer` ： **<span style="color: #601BDE">感知特定阶段：</span>** 感知 **引导初始化**

分析**<span style="color: #601BDE">感知特定阶段（执行位置，哪个地方进行了调用）：（后面的几种回调监听器也是这么分析）</span>**

![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/e139b8f87f73142aa11314d34d30bd0e727b997507e551e4ab8d7c14116169f8.png)![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/c71970e0a91831740d15e8004a724f107b30dd21d2c26a0333eec453fdcf44b3.png)![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/f981edd2564fc1432dd595501c8a4830eb89a4a61c2d26850b3cba37f8b565ce.png)

> 这样就找到了该`回调监听器`在<span style="color: #601BDE">`SpringApplicationRunListener`</span>**<span style="color: #601BDE">全阶段生命周期中的哪一个阶段进行了调用。</span>**

> 注册时机（**<span style="color: #601BDE">哪个地方进行了注册</span>**）：`bootstrapRegistryInitializers`组件的注入是如何实现的呢？毕竟不能为null把。

![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/d7f110c839a2245727a1bd040351af38731f28b4b0f803365543c78ca26bb23c.png)![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/e0d44090a9e583aa53cd4c03c2f1488ea920a5bfd2dab7670e2167065347bd56.png)![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/efe3164cde9522614b5c42ba58e5b148f6841bc26e7e29b6e7846c716d5d5b4f.png)

> 由上，因此可以使用<span style="color: rgb(213, 97, 97)">`META-INF/spring.factories`</span>配置自己的`BootstrapRegistryInitializer`。
> 而且下面两个方法：`setIntializers`和`setLinsters`分别扫描注册了全局的<span style="color: rgb(213, 97, 97)">`META-INF/spring.factories`</span>里面的`ApplicationContextInitializer`和`ApplicationListner`。

> 创建自己的`BootstrapRegistryInitializer`的几种方式：
>    - <span style="color: rgb(213, 97, 97)">`META-INF/spring.factories`</span>
>    - 创建引导上下文 <span style="color: rgb(213, 97, 97)">`bootstrapContext`</span> 的时候触发。
>    - application. `addBootstrapRegistryInitializer();`
>    - 场景： <span style="color: rgb(213, 97, 97)">`进行密钥校对授权。一年的软件使用权过后，不让你使用了。`</span>

- ApplicationContextInitializer： **<span style="color: #601BDE">感知特定阶段：</span>** 感知ioc容器初始化

> 创建自己的`ApplicationContextInitializer`的几种方式：
>    - <span style="color: rgb(213, 97, 97)">`META-INF/spring.factories`</span>
>    - application. `addInitializers();`

- **<span style="color: #601BDE">ApplicationListener： 感知全阶段：基于</span>** <span style="color: #601BDE">`事件机制`</span> **<span style="color: #601BDE">，感知事件。 一旦到了哪个阶段可以做别的事。</span>**

> 创建自己的<span style="color: #601BDE">`ApplicationListener`</span>的几种方式：
>    - <span style="color: rgb(25, 30, 30)">`@Bean`</span> 或 <span style="color: rgb(25, 30, 30)">`@EventListener`</span> ： <span style="color: rgb(25, 30, 30)">`事件驱动`</span>
>    - <span style="color: rgb(25, 30, 30)">`SpringApplication.addListeners(…)`</span> 或 <span style="color: rgb(25, 30, 30)">`SpringApplicationBuilder.listeners(…)`</span>
>    - <span style="color: rgb(25, 30, 30)">`META-INF/spring.factories`</span>

- **<span style="color: #601BDE">SpringApplicationRunListener： 感知全阶段生命周期 + 各种阶段都能自定义操作； 功能更完善。</span>**

> 创建自己的<span style="color: #601BDE">`SpringApplicationRunListener`</span>的方式：
>    - <span style="color: rgb(213, 97, 97)">`META-INF/spring.factories`</span>

- **<span style="color: #601BDE">ApplicationRunner: 感知特定阶段：感知应用就绪Ready。卡死应用，就不会就绪</span>**

> 创建自己的<span style="color: #601BDE">`ApplicationRunner`</span>的方式：
>    - <span style="color: rgb(25, 30, 30)">`@Bean`</span>

- **<span style="color: #601BDE">CommandLineRunner： 感知特定阶段：感知应用就绪Ready。卡死应用，就不会就绪</span>**

> 创建自己的<span style="color: #601BDE">`CommandLineRunner`</span>的方式：
>    - <span style="color: rgb(25, 30, 30)">`@Bean`</span>

**最佳实战**：

- 如果项目启动前做事： `BootstrapRegistryInitializer` 和 `ApplicationContextInitializer`
- 如果想要在项目启动完成后做事： <span style="color: #601BDE">`ApplicationRunner`</span> **<span style="color: #601BDE">和</span>** <span style="color: #601BDE">`CommandLineRunner`</span>
- **<span style="color: #601BDE">如果要干涉生命周期做事：</span>** <span style="color: #601BDE">`SpringApplicationRunListener`</span>
- **<span style="color: #601BDE">如果想要用事件机制：</span>** <span style="color: #601BDE">`ApplicationListener`</span>

> 项目启动完成后做事,创建自己的`ApplicationRunner`和`CommandLineRunner`，runner在哪执行的分析方法和分析`BootstrapRegistryInitializer`执行位置的方法一样。

```java
@Bean
    public ApplicationRunner applicationRunner(){
        return  args -> {
            System.out.println("===ApplicationRunner 运行了.....");
        };//返回了一个ApplicationRunner的匿名实现类。使用的lamda方式
    }
    @Bean
    public CommandLineRunner commandLineRunner(){
        return  args -> {
            System.out.println("===CommandLineRunner 运行了.....");
        };//返回了一个CommandLineRunner的匿名实现类。使用的lamda方式
    }
```

#### 2. 完整触发流程

<span style="color: rgb(25, 30, 30)">`9大事件`</span><span style="color: rgb(25, 30, 30)">触发顺序&时机</span>

1. <span style="color: var(--asciidoctor-code-font-color)">`ApplicationStartingEvent`</span> ：应用启动但未做任何事情, 除过注册listeners and initializers.
2. <span style="color: var(--asciidoctor-code-font-color)">`ApplicationEnvironmentPreparedEvent`</span> ： Environment 准备好，但context 未创建.
3. <span style="color: var(--asciidoctor-code-font-color)">`ApplicationContextInitializedEvent`</span> : ApplicationContext 准备好，ApplicationContextInitializers 调用，但是任何bean未加载
4. <span style="color: var(--asciidoctor-code-font-color)">`ApplicationPreparedEvent`</span> ： 容器刷新之前，bean定义信息加载
5. <span style="color: var(--asciidoctor-code-font-color)">`ApplicationStartedEvent`</span> ： 容器刷新完成， runner未调用

<span style="color: rgb(25, 30, 30)">=========以下就开始插入了</span>**<span style="color: rgb(25, 30, 30)">探针机制</span>**<span style="color: rgb(25, 30, 30)">============</span>

6. <span style="color: var(--asciidoctor-code-font-color)">`AvailabilityChangeEvent`</span> ： <span style="color: var(--asciidoctor-code-font-color)">`LivenessState.CORRECT`</span> 应用存活； **<span style="color: var(--asciidoctor-code-font-color)">存活探针</span>**
7. <span style="color: var(--asciidoctor-code-font-color)">`ApplicationReadyEvent`</span> : 任何runner被调用
8. <span style="color: var(--asciidoctor-code-font-color)">`AvailabilityChangeEvent`</span> ： <span style="color: var(--asciidoctor-code-font-color)">`ReadinessState.ACCEPTING_TRAFFIC`</span> **<span style="color: var(--asciidoctor-code-font-color)">就绪探针</span>** ，可以接请求
9. <span style="color: var(--asciidoctor-code-font-color)">`ApplicationFailedEvent`</span> ：启动出错

![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/3ee2c557f97054560c7e65ec3adf42c240b20911815eaee91ab24b6728c05e2d.png)

#### 3. SpringBoot 事件驱动开发

> **应用启动过程生命周期事件感知（9大事件）**、**应用运行中事件感知（无数种）**。而`ApplicationListener`不仅可以感知SpringBoot应用启动过程的事件，还能感知运行时的事件。

- **事件发布** ： `ApplicationEventPublisherAware` 或 `注入：ApplicationEventMulticaster`
- **事件监听** ： `组件 + @EventListener` 或者继承 `ApplicationListener` 类。

##### 2.事物监听驱动方式

> 将要添加的服务进行事物监听，不进行组件注入，降低了耦合。

```java
@RestController
public class LoginController {
    /**
     * 增加业务
     * @param username
     * @param passwd
     * @return
     */
    @GetMapping("/login")
    public String login(@RequestParam("username") String username,
                        @RequestParam("passwd")String passwd){
        //业务处理登录
        System.out.println("业务处理登录完成....");

        //TODO 发送事件.
        //1、创建事件信息
        LoginSuccessEvent event = new LoginSuccessEvent(new UserEntity(username, passwd));
        //2、发送事件
        eventPublisher.sendEvent(event);

        return username+"登录成功";
    }
}
```

> 定义登录成功事件。所有事件都推荐继承 ApplicationEvent

```java
public class LoginSuccessEvent  extends ApplicationEvent {
    /**
     * @param source 是该事件需要携带出去的数据， 代表是谁登录成了
     */
    public LoginSuccessEvent(UserEntity source) {
        super(source);
    }
}
```

> 定义事件发布者。感觉`EventPublisher`有点像代理类。貌似使用`@Autowire`注入也行。

```java
@Service
public class EventPublisher implements ApplicationEventPublisherAware {

    /**
     * 底层发送事件用的组件，SpringBoot会通过ApplicationEventPublisherAware接口自动注入给我们
     * 事件是广播出去的。所有监听这个事件的监听器都可以收到
     */
    ApplicationEventPublisher applicationEventPublisher;

    /**
     * 所有事件都可以发
     * @param event
     */
    public void sendEvent(ApplicationEvent event) {
        //调用底层API发送事件
        applicationEventPublisher.publishEvent(event);
    }

    /**
     * 会被自动调用，把真正发事件的底层组组件给我们注入进来
     */
    @Override
    public void setApplicationEventPublisher(ApplicationEventPublisher applicationEventPublisher) {
        this.applicationEventPublisher = applicationEventPublisher;
    }
}
```

> 设置订阅LoginSuccessEvent事件的订阅者的第一种方式：继承`ApplicationListener`

```java
//表示在所有收到该事件的订阅者中第2个执行。数字越小，优先级越高。
//这里因为方法没用@EventListener注解，只能标注在该类上。
@Order(2)
@Service
public class AccountService implements ApplicationListener<LoginSuccessEvent> {
    public void addAccountScore(String username){
        System.out.println(username +" 加了1分");
    }
    @Override
    public void onApplicationEvent(LoginSuccessEvent event) {
        System.out.println("=====  AccountService  收到事件 =====");
        UserEntity source = (UserEntity) event.getSource();
        addAccountScore(source.getUsername());
    }
}
```

@Service
public class CouponService {

#### 2. SPI机制

> - **<span style="color: #DF2A3F">Java中的SPI（Service Provider Interface）是一种软件设计模式，用于</span>** **<span style="color: #601BDE">在应用程序中动态地发现和加载组件</span>** **<span style="color: #DF2A3F">。</span>** **SPI是一种思想，SPI的思想** 是，定义一个接口或抽象类，然后通过在classpath中定义实现该接口的类来实现对组件的动态发现和加载。
> - SPI的主要目的是解决在应用程序中使用可插拔组件的问题。例如，一个应用程序可能需要使用不同的日志框架或数据库连接池，但是这些组件的选择可能取决于运行时的条件。通过使用SPI，应用程序可以在运行时发现并加载适当的组件，而无需在代码中硬编码这些组件的实现类。
> - 在Java中，默认的 **SPI** 的实现方式是通过在 `META-INF/services` 目录下创建一个以服务接口全限定名为名字的文件，文件中包含实现该服务接口的类的全限定名。当应用程序启动时，Java的SPI机制会自动扫描classpath中的这些文件，并根据文件中指定的类名来加载实现类。
> - 通过使用SPI，应用程序可以实现更灵活、可扩展的架构，同时也可以避免硬编码依赖关系和增加代码的可维护性。
