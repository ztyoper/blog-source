#### 2.自定义 SpringApplication 的底层设置

> SpringApplication.run调用会经过两步,第二步先生成`SpringApplication`对象再执行`run`方法

```java

public static ConfigurableApplicationContext run(Class<?> primarySource, String... args) {
    return run(new Class<?>[] { primarySource }, args);
}
public static ConfigurableApplicationContext run(Class<?>[] primarySources, String[] args) {
    return new SpringApplication(primarySources).run(args);
}
```

```java
@SpringBootApplication //主程序类
public class Boot306FeaturesApplication {
    public static void main(String[] args) {
        //1.生成SpringApplication对象
        SpringApplication application = new SpringApplication(Boot306FeaturesApplication.class);
        //程序化调整【SpringApplication的参数】
        //application.setDefaultProperties();
        //【配置文件优先级高于程序化调整的优先级】
        application.setBannerMode(Banner.Mode.OFF);
        //2、SpringApplication 运行起来
        application.run(args);
    }
}
```

## 2.Profile

> 环境隔离能力；快速切换开发、测试、生产环境
> 作用：
> 1. **标识环境** ：指定哪些组件、配置在哪个环境生效
> 2. **切换环境** ：这个环境对应的所有组件和配置就应该生效

### <span style="color: rgb(48, 54, 63)">2.1. 使用</span>

#### 2.1.1 指定环境

> - Spring Profiles 提供一种 **<span style="color: rgb(48, 54, 63)">隔离配置</span>** 的方式，使其仅在 **<span style="color: rgb(48, 54, 63)">特定环境</span>** 生效；
> - 任何 @Component , @Configuration 或 @ConfigurationProperties 可以使用 @Profile 标记，来指定何时被加载。【 **<span style="color: rgb(48, 54, 63)">容器中的组件</span>** 都可以被 <span style="color: rgb(213, 97, 97)">`@Profile`</span> 标记】
> - 知识点：@profile是用来标记容器中的组件的。因此使用场景：
>    - <span style="color: rgb(48, 54, 63)">`@Component`</span> 上面标记 <span style="color: rgb(48, 54, 63)">`@Profile("xxx")`</span> ，表明在场景 <span style="color: rgb(48, 54, 63)">`"xxx"`</span> 下，该组件才会被加入到容器中。
>    - @Bean上面标记 <span style="color: rgb(48, 54, 63)">`@Profile("xxx")`</span> ，表明在场景 <span style="color: rgb(48, 54, 63)">`"xxx"`</span> 下，该组件才会被加入到容器中。
>    - @Import在配置类中导入 <span style="color: rgb(48, 54, 63)">`Cat.class`</span> ， <span style="color: rgb(48, 54, 63)">`@Profile`</span> 标记在Cat类上是 <span style="color: rgb(48, 54, 63)">`可以起作用的`</span> 。
>    - @Bean在配置类中导入 <span style="color: rgb(48, 54, 63)">`Cat.class`</span> ， <span style="color: rgb(48, 54, 63)">`@Profile`</span> 标记在Cat类上是 <span style="color: rgb(48, 54, 63)">`不可以起作用的`</span> 。

#### 2.1.2 默认环境

```properties
# 指定默认环境,默认是“default”,我们不推荐去修改默认环境
spring.profiles.default=xxx
```

> 环境隔离：
> 1、标识环境
> 1）、区分出几个环境：`dev`（开发环境）、`test`（测试环境）、`prod`（生产环境）
> 2）、指定每个组件在哪个环境下生效；`default`环境：默认环境
> 通过：`@Profile({"test"})`标注
> 一个组件没有标注任何`@Profile`，代表任意环境下`该组件`都能放入容器中。<span style="color: rgb(48, 54, 63)">不标注</span><span style="color: rgb(48, 54, 63)">`@Profile`</span><span style="color: rgb(48, 54, 63)">的组件永远都存在。</span>
> 3）、默认激活指定的环境`dev`，标注`@Profile({"dev"})`的组件才会生效。
> 4）、如果一个组件标注了`@Profile({"default"})`，在激活了`"dev"`环境的情况下，组件不会生效。

#### 2.1.3 激活环境

> 2、激活环境
> 配置文件激活：`spring.profiles.active=dev`
> 命令行激活：`java -jar xxx.jar --spring.profiles.active=dev`

```properties
# 激活指定的一个或多个环境
spring.profiles.active=dev
#spring.profiles.active=dev,prod,test
```

#### 2.1.4 环境包含

> 注意：
> 1. spring.profiles.active 和 spring.profiles.default 只能用到 **<span style="color: rgb(48, 54, 63)"></span>** <span style="color: rgb(48, 54, 63)">`无 profile 的文件`</span> 中，如果在 application-dev.properties 中编写就是 **<span style="color: rgb(48, 54, 63)">无效的</span>**
> 2. 也可以额外添加生效文件，而不是激活替换。比如：

```properties
# 包含指定环境，不管你激活哪个环境，这个都要有。 总是要生效的环境
#spring.profiles.include=dev,test

spring.profiles.include[0]=common
spring.profiles.include[1]=local
```

最佳实战：

- **生效的环境** = **激活的环境/默认环境** + **包含的环境**
- 项目里面这么用

- 基础的配置 `mybatis` 、 `log` 、 `xxx` ：写到 **包含环境中**
- 需要动态切换变化的 `db` 、 `redis` ：写到 **激活的环境中**

### <span style="color: rgb(48, 54, 63)">2.3. Profile 配置文件</span>

- `application-{profile}.properties` 可以作为 **指定环境的配置文件** 。
- 激活这个环境， **配置** 就会生效。最终生效的所有 **配置** 是

- `application.properties` ：主配置文件，任意时候都生效
- `application-{profile}.properties` ：指定环境配置文件，激活指定环境生效

profile优先级 &gt; application

```java
3、配置文件怎么使用Profile功能
 	1）、application.properties： 主配置文件。任何情况下都生效
 	2）、其他Profile环境下命名规范：  application-{profile标识}.properties：
 比如：application-dev.properties
 	3）、激活指定环境即可：  配置文件激活、命令行激活
 	4）、效果：
 项目的所有生效配置项 = 激活环境配置文件的所有项 + 主配置文件和激活文件不冲突的所有项
 如果发生了配置冲突，以激活的环境配置文件为准。
 application-{profile标识}.properties 优先级高于 application.properties

主配置和激活的配置都生效，优先以激活的配置为准，spring.profiles.active 
和spring.profiles.default 只能用到 无 profile 的文件中，
如果在application-dev.properties中编写就是无效的
```

## <span style="color: rgb(48, 54, 63)">3. 外部化配置</span>

> **场景**：线上应用如何**快速修改配置**，并应**用最新配置**？
> - SpringBoot 使用 **配置优先级** + **外部配置** 简化配置更新、简化运维。
> - 只需要给 `jar` 应用所在的文件夹放一个 `application.properties` 最新配置文件，重启项目就能自动应用最新配置

### <span style="color: rgb(48, 54, 63)">3.1. 配置优先级</span>

<span style="color: rgb(48, 54, 63)">Spring Boot 允许将</span>**<span style="color: rgb(48, 54, 63)">配置外部化</span>**<span style="color: rgb(48, 54, 63)">，以便可以在不同的环境中使用相同的应用程序代码。</span>

<span style="color: rgb(48, 54, 63)">我们可以使用各种</span>**<span style="color: rgb(48, 54, 63)">外部配置源</span>**<span style="color: rgb(48, 54, 63)">，包括</span><span style="color: rgb(213, 97, 97)">Java Properties文件</span><span style="color: rgb(48, 54, 63)">、</span><span style="color: rgb(213, 97, 97)">YAML文件</span><span style="color: rgb(48, 54, 63)">、</span><span style="color: rgb(213, 97, 97)">环境变量</span><span style="color: rgb(48, 54, 63)">和</span><span style="color: rgb(213, 97, 97)">命令行参数</span><span style="color: rgb(48, 54, 63)">。</span>

<span style="color: rgb(213, 97, 97)">@Value</span><span style="color: rgb(48, 54, 63)">可以获取值，也可以用</span><span style="color: rgb(213, 97, 97)">@ConfigurationProperties</span><span style="color: rgb(48, 54, 63)">将所有属性绑定到</span><span style="color: rgb(213, 97, 97)">java object</span><span style="color: rgb(48, 54, 63)">中</span>

**<span style="color: rgb(48, 54, 63)">以下是 SpringBoot 属性源加载顺序。</span>****<span style="color: #601BDE">后面的会覆盖前面的值</span>**<span style="color: #601BDE">。由低到高，高优先级配置覆盖低优先级</span>

1. **<span style="color: #601BDE">默认属性</span>** （通过 <span style="color: rgb(213, 97, 97)">`SpringApplication.setDefaultProperties`</span> 指定的）
2. @PropertySource 指定加载的配置（需要写在 @Configuration 类上才可生效）

3. **<span style="color: #601BDE">配置文件（</span>** **<span style="color: #601BDE">application.properties/yml</span>** **<span style="color: #601BDE">等）</span>**
4. RandomValuePropertySource 支持的 random.* 配置（如：@Value("${random.int}")）
5. OS 环境变量
6. Java 系统属性（ System.getProperties() ）
7. JNDI 属性（来自 java:comp/env ）
8. ServletContext 初始化参数

> <span style="color: rgb(48, 54, 63)">结论：配置可以写到很多位置，常见的优先级顺序：</span>
> - <span style="color: rgb(48, 54, 63)">`命令行`</span> &gt; <span style="color: rgb(48, 54, 63)">`配置文件`</span> &gt; <span style="color: rgb(48, 54, 63)">`springapplication配置`</span>

**<span style="color: #601BDE">配置文件优先级</span>**<span style="color: rgb(48, 54, 63)">如下：(</span>**<span style="color: rgb(48, 54, 63)">后面覆盖前面，包是指项目打成的jar包</span>**<span style="color: rgb(48, 54, 63)">)</span>

1. **<span style="color: rgb(48, 54, 63)">jar 包内</span>** 的 application.properties/yml
2. **<span style="color: rgb(48, 54, 63)">jar 包内</span>** 的 application-{profile}.properties/yml
3. **<span style="color: rgb(48, 54, 63)">jar 包外</span>** 的 application.properties/yml
4. **<span style="color: rgb(48, 54, 63)">jar 包外</span>** 的 application-{profile}.properties/yml

**<span style="color: rgb(48, 54, 63)">建议</span>**<span style="color: rgb(48, 54, 63)">：</span>**<span style="color: rgb(48, 54, 63)">用一种格式的配置文件</span>**<span style="color: rgb(48, 54, 63)">。</span><span style="color: rgb(48, 54, 63)">`如果.properties和.yml同时存在,则.properties优先`</span>

> <span style="color: rgb(48, 54, 63)">结论：</span><span style="color: rgb(48, 54, 63)">`包外 > 包内`</span><span style="color: rgb(48, 54, 63)">； 同级情况：</span><span style="color: rgb(48, 54, 63)">`profile配置文件（-dev的文件） > application配置文件`</span>

**<span style="color: #601BDE">所有参数均可由命令行传入，使用</span><span style="color: #601BDE">`--参数项=参数值`</span><span style="color: #601BDE">，将会被添加到环境变量中，并优先于</span><span style="color: #601BDE">`配置文件`</span><span style="color: #601BDE">。</span>**

**<span style="color: #601BDE">比如</span><span style="color: #601BDE">`java -jar app.jar --name="Spring"`</span><span style="color: #601BDE">,可以使用</span><span style="color: #601BDE">`@Value("${name}")`</span><span style="color: #601BDE">获取</span>**

> 演示场景：
> - 包内： application.properties `server.port=8000`
> - 包内： application-dev.properties `server.port=9000`
> - 包外： application.properties `server.port=8001`
> - 包外： application-dev.properties `server.port=9001`
> 启动端口？：命令行 &gt;`9001`&gt;`8001`&gt;`9000`&gt;`8000`

> 效果：优先级由高到低。
> - 命令行 &gt; 包外 `config` 直接子目录 &gt; 包外 `config` 直接子目录 &gt; 包外根目录 &gt; 包内目录
> - 同级比较：
>    - profile配置 &gt; 默认配置
>    - properties配置 &gt; yaml配置

> 总结：
> 优先级高的秘密是:properties文件逐级加载，有相同的就覆盖前面的，所以`最后加载的生效`。也就是：
> `包外 > 包内`假如都是·`包内（包外）`，那就越深的包，优先级也越高（最后加载生效）。<span style="color: rgb(48, 54, 63)">同级情况：</span><span style="color: rgb(48, 54, 63)">`profile配置文件（-dev的文件） > application配置文件`</span><span style="color: rgb(48, 54, 63)">。</span>
> <span style="color: rgb(48, 54, 63)">上面所有内容就是概括为这些总结。。。确实很少。但运维时有用。</span>
> <span style="color: rgb(48, 54, 63)">首个外部目录的名字必须是config，推测内部的也是。其他名字是没有效的。</span>

#### 4.2.1 注解

JUnit5的注解与JUnit4的注解有所变化,更多注解与断言在这个官网里面：

[https://junit.org/junit5/docs/current/user-guide/#writing-tests-annotations](https://junit.org/junit5/docs/current/user-guide/#writing-tests-annotations)

- **@Test :** 表示方法是测试方法。但是与JUnit4的@Test不同，他的职责非常单一不能声明任何属性，拓展的测试将会由Jupiter提供额外测试

- **@BeforeEach :** 表示在每个单元测试之前执行， `每个方法运行打印一次`

> **@BeforeEach**每一个测试方法都会有， 使用**@BeforeEach注解的方法必须是非静态的。**

- **@AfterEach :** 表示在每个单元测试之后执行， `每个方法运行打印一次`
- **@BeforeAll :** 表示在所有单元测试之前执行， `只打印一次`

> 使用**@BeforeAll注解的方法必须是静态的。**

#### 4.2.3 嵌套测试

> <span style="color: #323232">JUnit 5 可以通过 Java 中的内部类和@Nested 注解实现嵌套测试，从而可以更好的把相关的测试方法组织在一起。在内部类中可以使用@BeforeEach 和@AfterEach 注解，而且嵌套的层次没有限制。</span>

```java
package com.atguigu.boot3.features;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Nested;
import org.junit.jupiter.api.Test;

import java.util.EmptyStackException;
import java.util.Stack;

import static org.junit.jupiter.api.Assertions.*;

class QianTaoTest{
    @Nested
    @DisplayName("A stack")
    class TestingAStackDemo {

        Stack<Object> stack;

        @Test
        @DisplayName("is instantiated with new Stack()")
        void isInstantiatedWithNew() {
            new Stack<>();
        }

        @Nested
        @DisplayName("when new")
        class WhenNew {

            @BeforeEach
            void createNewStack() {
                stack = new Stack<>();
            }

            @Test
            @DisplayName("is empty")
            void isEmpty() {
                assertTrue(stack.isEmpty());
            }

            @Test
            @DisplayName("throws EmptyStackException when popped")
            void throwsExceptionWhenPopped() {
                assertThrows(EmptyStackException.class, stack::pop);
            }

            @Test
            @DisplayName("throws EmptyStackException when peeked")
            void throwsExceptionWhenPeeked() {
                assertThrows(EmptyStackException.class, stack::peek);
            }

            @Nested
            @DisplayName("after pushing an element")
            class AfterPushing {

                String anElement = "an element";

                @BeforeEach
                void pushAnElement() {
                    stack.push(anElement);
                }

                @Test
                @DisplayName("it is no longer empty")
                void isNotEmpty() {
                    assertFalse(stack.isEmpty());
                }

                @Test
                @DisplayName("returns the element when popped and is empty")
                void returnElementWhenPopped() {
                    assertEquals(anElement, stack.pop());
                    assertTrue(stack.isEmpty());
                }

                @Test
                @DisplayName("returns the element when peeked but remains not empty")
                void returnElementWhenPeeked() {
                    assertEquals(anElement, stack.peek());
                    assertFalse(stack.isEmpty());
                }
            }
        }
    }
}
```

#### 4.2.4 参数化测试

> <span style="color: #121212">参数化测试是JUnit5很重要的一个新特性，它使得用</span><span style="color: #121212">`不同的参数多次运行测试`</span><span style="color: #121212">成为了可能，也为我们的单元测试带来许多便利。</span>
> <span style="color: #121212">利用</span>**@ValueSource**<span style="color: #121212">等注解，指定入参，我们将可以使用不同的参数进行多次单元测试，而不需要每新增一个参数就新增一个单元测试，省去了很多冗余代码。</span>
> **@ValueSource**: 为参数化测试指定入参来源，支持八大基础类以及String类型,Class类型
> **@NullSource**: 表示为参数化测试提供一个null的入参
> **@EnumSource**: 表示为参数化测试提供一个枚举入参
> **@CsvFileSource**：表示读取指定CSV文件内容作为参数化测试入参
> **@MethodSource**：表示读取指定方法的返回值作为参数化测试入参(注意方法返回需要是一个流，也可以是一个List集合)

```java
@ParameterizedTest //指定为参数化测试方法就需要这个注解
@ValueSource(strings = {"one", "two", "three"})
@DisplayName("参数化测试1")
public void parameterizedTest1(String string) {
    System.out.println(string);
    Assertions.assertTrue(StringUtils.isNotBlank(string));
}


@ParameterizedTest
@MethodSource("method")    //指定方法名
@DisplayName("方法来源参数")
public void testWithExplicitLocalMethodSource(String name) {
    System.out.println(name);
    Assertions.assertNotNull(name);
}

static Stream<String> method() {
    return Stream.of("apple", "banana");
}
```

##### 1.**@CsvFileSource测试**

```java
@ParameterizedTest ///testdata.csv只能放在resource目录下面，不能放在test/java下面
@CsvFileSource(resources = "/testdata.csv", numLinesToSkip = 1)
public void testAdd(int a, int b, int expected) {
    assertEquals(expected, Math.addExact(a, b));
}
```

> 1. `numLinesToSkip` 是跳过第一行，因为第一行一般是包含列名的标题行
> 2. `Math.add()` 方法在结果溢出时不会抛出异常，而是会返回相加后的结果。例如，如果 `a` 和 `b` 分别是 `Integer.MAX_VALUE` 和 `1` ，那么 `Math.addExact(a, b)` 的结果将是 `Integer.MAX_VALUE + 1` ，即 `Integer.MIN_VALUE` ，因为 `整数溢出` 。在这种情况下，方法将抛出 `ArithmeticException` 异常。确保你能够及时处理这种情况。
