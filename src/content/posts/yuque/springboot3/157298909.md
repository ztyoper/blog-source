# 6、可观测性

> 可观测性 Observability

对线上应用进行观测、监控、预警...

- 健康状况【组件状态、存活状态】 `Health`
- 运行 **指标** 【cpu、内存、垃圾回收、吞吐量、响应成功率...】 `Metrics`
- 链路追踪
- ...

#### 1. 常用端点

| ID | 描述 |
| --- | --- |

| `health` | 显示应用程序运行状况信息。 |

| `info` | 显示应用程序信息。 |
| `integrationgraph` | 显示Spring`integrationgraph`。需要依赖`spring-integration-core`。 |
| `loggers` | 显示和修改应用程序中日志的配置。 |
| `liquibase` | 显示已应用的所有Liquibase数据库迁移。需要一个或多个`Liquibase`组件。 |
| `metrics` | 显示当前应用程序的“指标”信息。 |
| `mappings` | 显示所有`@RequestMapping`路径列表。 |
| `scheduledtasks` | 显示应用程序中的计划任务。 |
| `sessions` | 允许从Spring Session支持的会话存储中检索和删除用户会话。需要使用Spring Session的基于Servlet的Web应用程序。 |
| `shutdown` | 使应用程序正常关闭。默认禁用。 |

#### 2. 定制端点

> - `健康监控` ：返回存活、死亡
> - `指标监控` ：次数、率

##### 1.定制健康监控指标

> 定义一个我们需要监控的组件。该组件中有一个`check`方法可以返回实时状态码。

```java
@Component
public class MyHahaComponent {

    public  int check(){
        //业务代码判断这个组件是否该是存活状态
        return 1;
    }

}
```

> 定一个`MyHahaComponent`组件的`健康监控指标`类，专门监控`MyHahaComponent`组件的健康情况。

```java
@Component
public class MyHahaHealthIndicator extends AbstractHealthIndicator {

    @Autowired
    MyHahaComponent myHahaComponent;
    /**
     * 健康检查
     * @param builder
     * @throws Exception
     */
    @Override
    protected void doHealthCheck(Health.Builder builder) throws Exception {
        //自定义检查方法
        int check = myHahaComponent.check();
        if(check == 1){
            //构建存活状态
            builder.up()
                    .build();
        }else {
            //构建下线状态
            builder.down()
                    .build();
        }
    }
}
```

> 1. `MyHahaHealthIndicator` 名字 `后缀` 必须是 `xxxHealthIndicator`
> 2. 有两种定义我们健康监控器的方法。
>    1. 实现 `HealthIndicator` 接口来定制组件的健康状态对象 `(Health)` 返回
>    2. 继承 `AbstractHealthIndicator` 接口来定制组件的健康状态对象 `(Health)` 返回
>    3. 我们这里使用的是第二种方法，因为第二种方法有参数 `build`

![tmp885E.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/3b5e2753063a8ad0c6f89a35e382ec5654319ae35eed107e61be3407309a8939.png)

> 但还是没有`MyHahaHealthIndicator`组件的健康指标。因为我们必须开启配置如下：

```properties

#访问http://localhost:8080/actuator/health
#断点的enable默认是true,因此可以不配第一个
management.endpoint.health.enabled=true
#将所有配置了健康检测的模块的健康状态全部展示出来，而不是只有项目的状态

```

![tmp9FCB.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/2239186d723c11c023bfb2262988108f698df250445fc9b9159cbf0914397fb2.png)

> `MyHahaHealthIndicator`组件的健康指标出现了，但是没有细节`details`,我们将`健康监控`构建的监控指标增加`details`:

```java
@Component
public class MyHahaHealthIndicator extends  AbstractHealthIndicator{

    @Autowired
    MyHahaComponent myHahaComponent;
    /**
     * 健康检查
     * @param builder
     * @throws Exception
     */
    @Override
    protected void doHealthCheck(Health.Builder builder) throws Exception {
        //自定义检查方法
        int check = myHahaComponent.check();
        if(check == 1){
            //构建存活状态
            builder.up()
                   .withDetail("code","1000")
                   .withDetail("msg","活的很健康")
                   .withDetail("data","我的名字叫haha")
                    .build();
        }else {
            //构建下线状态
            builder.down()
                   .withDetail("code","1001")
                   .withDetail("msg","死的很健康")
                   .withDetail("data","我的名字叫haha完蛋")
                    .build();
        }
    }
}
```

##### 2.1.定制运行监控指标

```java
@Component
public class MyHahaComponent {
    Counter counter = null;
    /**
     * 当只有一个构造器时，会覆盖掉空参构造器，
     因此注册MyHahaHealthIndicator组件到ioc容器时，该唯一构造器所需参数会被注入进来。
     * 注入 meterRegistry 来保存和统计所有指标
     * @param meterRegistry
     */
    public MyHahaComponent(MeterRegistry meterRegistry){
        //得到一个名叫 myhaha.hello 的计数器
        counter = meterRegistry.counter("myhaha.hello");
    }
    public  int check(){
        //业务代码判断这个组件是否该是存活状态
        return 1;
    }

    //调用
    public void hello(){
        System.out.println("hello");
        counter.increment();
    }
}
```

```java
@RestController
public class HelloController {

    @Autowired
    MyHahaComponent myHahaComponent;

    @GetMapping("/hello")
    public String hello(){
        //业务调用,在运行监控指标中便可以看到hello执行的次数。
        myHahaComponent.hello();
        return "哈哈哈";
    }
}
```

### 2. 配置 Prometheus 拉取哪些数据

```yaml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090']

  - job_name: 'redis'
    static_configs:
      - targets: ['redis:6379']

  - job_name: 'kafka'
    static_configs:
      - targets: ['kafka:9092']

 #拉取项目数据
  - job_name: 'spring-boot-actuator-exporter'
    metrics_path: '/actuator/prometheus' #指定抓取的路径
    static_configs:
      - targets: ['172.28.28.157:8001']
        labels:
          nodename: 'app-demo'
```

> 1. `localhost:9090` 是 `prometheus` 镜像的 `宿主机` 的 `IP+端口` 也就是 `172.28.28.157:9090` 。为什么要配置?
>    1. ![image.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/b35321d7a04f6f4dddcb2fba2c273b7515f21c70a668ce869aa41d8a87cb8371.png)
>    2. 尽管 `docker run prometheus` 时指定了端口，但还是要在配置文件中配置。记住 `配置文件prometheus.yml` 的位置要放在 `/data/prometheus/` 下面
> 2. `172.28.28.157:8001` 是 `wsl` 的 `ip` 和 `java.jar` 项目的镜像的端口。
