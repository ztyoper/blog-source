### 一、为什么需要熔断？

分布式架构中一个服务常常会调用第三方服务，这个第三方服务可能是一个RPC接口、数据库或者第三方的API等。外部服务的稳定性是不能绝对保证的，如果依赖的第三方服务出现了不稳定的情况，比如请求的响应时间变长，那么服务自身调用第三方服务的响应时间也会变长，这是级联效应，服务自身的线程（协程）可能会堆积请求，最终可能耗尽业务自身的线程（协程），最终服务本身也变得不可用。

因此，需要暂时切断不稳定的服务调用，避免局部不稳定的因素导致整个分布式系统的雪崩。

### 二、通用熔断策略

- 慢调用比例 ( `SLOW_REQUEST_RATIO` )：选择以慢调用比例作为阈值，需要设置允许的慢调用 RT（即最大的响应时间），请求的响应时间大于该值则统计为慢调用。当单位统计时长（ `statIntervalMs` ）内请求数目大于设置的最小请求数目，并且慢调用的比例大于阈值，则接下来的熔断时长内请求会自动被熔断。经过熔断时长后熔断器会进入探测恢复状态（HALF-OPEN 状态），若接下来的一个请求响应时间小于设置的慢调用 RT 则结束熔断，若大于设置的慢调用 RT 则会再次被熔断。
- 异常比例 ( `ERROR_RATIO` )：当单位统计时长（ `statIntervalMs` ）内请求数目大于设置的最小请求数目，并且异常的比例大于阈值，则接下来的熔断时长内请求会自动被熔断。经过熔断时长后熔断器会进入探测恢复状态（HALF-OPEN 状态），若接下来的一个请求成功完成（没有错误）则结束熔断，否则会再次被熔断。异常比率的阈值范围是 `[0.0, 1.0]` ，代表 0% - 100%。
- 异常数 ( `ERROR_COUNT` )：当单位统计时长内的异常数目超过阈值之后会自动进行熔断。经过熔断时长后熔断器会进入探测恢复状态（HALF-OPEN 状态），若接下来的一个请求成功完成（没有错误）则结束熔断，否则会再次被熔断。

配置模板说明如下所示：

**（1）templates部分说明**

熔断组件会根据请求的接口或者熔断组件注解的resourceName属性值匹配规则模板，动态生成一个具体的熔断规则。

- observerMode：是否开启观察者模式，true：开启；false：不开启。如果开启观察者模式，则只会打印日志，不会实际出发熔断。如果不开启观察者模式，则根据实际规则决定是否触发熔断。
- breakerType: 熔断模式，1：基于Sentinel的单机熔断模式，2：基于Redis的集群熔断模式
- resource：熔断规则生效的埋点资源名称，配置的值为访问的API接口（支持正则表达式 / * 匹配），以及熔断注解中的resourceName属性对应的值。resource支持通配符，例如，/表示所有的接口，/a/b表示所有以/a/b开头的接口。另外，当同时存在 / 和 /a/b 开头的规则时，优先匹配最长模板规则，例如，/a/b/test 会按照/a/b的模板生成规则，/c/b/test则会使用/的模板生成规则。
- strategy：熔断策略，取值如下所示：

- 0：慢调用比例策略。
- 1：异常比例策略。
- 2：异常数策略。

- timeWindowMs：触发熔断后持续的时间（整数类型，单位：ms），资源（resource）进入熔断状态后，在配置的熔断时长内，请求都会快速失败。熔断结束后进入探测恢复模式（HALF-OPEN）。根据实际情况设置探测周期，一般情况下设置10s左右即可，具体需要根据业务场景压测确定。

- 慢调用策略：经过熔断时长后熔断器进入探测恢复状态，如果接下来的一个请求响应时间小于设置的最大RT，则结束熔断，否则，会再次被熔断。
- 异常策略：经过熔断时长后熔断器进入探测恢复状态，如果接下来的一个请求没有异常，则结束熔断。否则，会再次被熔断。

- minRequestAmount：静默数量（整数类型），如果当前统计周期内对资源的访问数量小于静默数量，那熔断器就处于静默期。静默数量，也就是触发熔断的最小请求数量。如果当前统计周期内的请求数小于此值，即使达到熔断条件规则，也不会触发熔断。
- statIntervalMs：统计的时间窗口长度（整数类型，单位ms），熔断器的统计周期，单位是毫秒，不建议将此值设置的太大或者太小，大部分场景设置10s左右即可，具体需要根据业务场景压测确定。
- maxAllowedRtMs：仅对慢调用比例策略生效（整数值，单位ms），maxAllowedRtMs是判断请求是否是慢调用的临界值，如果请求的响应时间小于或者等于maxAllowedRtMs，就不是慢调用。否则，就是慢调用。如果strategy配置的是0，则此值为必填项。
- threshold：说明如下：

- 慢调用比例策略：threshold表示慢调用比例的阈值（小数表示，例如0.1表示10%），当前资源的慢调用比例如果高于threshold，则熔断器就会断开，否则保持闭合状态。
- 异常比例策略：threshold表示异常比例的阈值小数表示，例如0.1表示10%。
- 异常数策略：threshold表示异常计数的阈值。

- siteCodes：站点数组，值为0表示所有站点，-1表示没有站点，其他值为具体的站点值。
- platforms：平台数组，值为0表示所有平台，-1表示没有平台，其他值为具体的平台值。
- currencies：币种数组，值为0表示所有币种，-1表示没有币种，其他值为具体的币种值。

**（2）skipPrefixs部分说明**

数据类型为字符串数组，具体值是接口的访问前缀或者完整接口API，例如，/api/test配置到skipPrefixs中，则即使为/api/test接口配置了熔断规则并且达到了熔断条件时，也不会触发熔断。

#### 3.2 熔断注解与扩展点接口

在熔断组件中，主要对外提供了三个注解，分别是@HttpBreaker注解，@ReactorBreaker注解和@MethodBreaker注解。后续业务在对接熔断组件时，只需在对应的方法上添加相应的注解即可，业务根据实际情况决定是否需要实现熔断组件的扩展点接口，为熔断组件提供熔断参数支持。后续无论是访问接口，还是调用普通方法，只要是触发了熔断注解标注的方法，就会在真正执行目标方法前，自动触发AOP切面逻辑，在AOP切面中实现熔断逻辑，并异步动态生成具体接口和方法的熔断规则。

**（1）@HttpBreaker注解**

源码实现如下：

textjavascripttypescriptcsshtmlbashjsonmarkdownpythonjavaccpprubygorustphpsqlyaml Copy

```plain
            `   @Documented @Target(ElementType.METHOD) @Retention(RetentionPolicy.RUNTIME) public @interface HttpBreaker {      /**      * 扩展点实现类的BeanName      * 需要与标注方法时对应的扩展点接口实现类的BeanName相同      */     String pointerName() default Constants.DEFAULT_POINTER_NAME;      /**      * 指定忽略哪些规则，取值为枚举类型      * 取值包含：SITE_CODE, PLATFORM, CURRENCY      * 填写哪些值后，对应的数据不参与规则校验，同时，也不会拼接到内存的key中      */     SkipRule[] skipRules() default {SkipRule.PLATFORM, SkipRule.CURRENCY}; }   `
```

通过普通HTTP接口触发的熔断注解，可标注到@Controller接口方法上，也可以标注到@Service或者@Component实现类的方法上，凡是通过HTTP接口触发的方法都可以使用此注解，注解提供了两个属性。

- pointerName： String类型，扩展点实现类的BeanName，此值需要与当前注解标注方法时对应的口站点接口实现类的Bean名称相同（扩展点接口后续会介绍）。
- skipRules：SkipRule枚举数组类型，表示熔断时忽略某些规则校验，可选的值有：SITE _ CODE：忽略站点，PLATFORM：忽略平台，CURRENCY：忽略币种。

例如在整个熔断规则校验中，忽略站点，则注解配置如下。

textjavascripttypescriptcsshtmlbashjsonmarkdownpythonjavaccpprubygorustphpsqlyaml Copy

```plain
            `   @HttpBreaker(skipRules = {SkipRule.PLATFORM.SITE_CODE})   `
```

需要忽略站点和平台，则注解配置如下所示。

textjavascripttypescriptcsshtmlbashjsonmarkdownpythonjavaccpprubygorustphpsqlyaml Copy

```plain
            `   @HttpBreaker(skipRules = {SkipRule.PLATFORM.SITE_CODE, SkipRule.PLATFORM})   `
```

**（3）@MethodBreaker注解**

源码实现如下：

```plain
            `   @Documented @Target(ElementType.METHOD) @Retention(RetentionPolicy.RUNTIME) public @interface MethodBreaker {      /**      * 需要与Nacos配置的某个规则的resource名称一致      * 主要用于普通方法，不是走Web接口      */     String resourceName();      /**      * 扩展点实现类的BeanName      * 需要与标注方法时对应的扩展点接口实现类的BeanName相同      */     String pointerName() default Constants.DEFAULT_POINTER_NAME;      /**      * 指定忽略哪些规则，取值为枚举类型      * 取值包含：SITE_CODE, PLATFORM, CURRENCY      * 填写哪些值后，对应的数据不参与规则校验，同时，也不会拼接到内存的key中      */     SkipRule[] skipRules() default {SkipRule.PLATFORM, SkipRule.CURRENCY}; }   `
```

**（4）扩展点接口**

源码如下：

textjavascripttypescriptcsshtmlbashjsonmarkdownpythonjavaccpprubygorustphpsqlyaml Copy

```plain
            `   public interface BreakerPointer {     /**      * 交由业务具体实现      * @param joinPoint ProceedingJoinPoint对象      * @return 返回参与校验的参数      */     BreakerParams getBreakerParams(ProceedingJoinPoint joinPoint); }   `
```

扩展点接口的使用场景：

- 各业务方法参数不统一，尤其是业务方法中的参数位置、参数名称不统一
- 熔断组件无法通过切面明确获取到熔断参数
- 其他无法明确获取熔断参数的场景

再加上业务开发人员在写方法时，肯定知晓方法参数里哪些数据时需要熔断的参数，例如，站点、平台和币种等。所以，熔断组件会将部分参数值的获取操作以扩展点接口的形式交由业务扩展实现，通过切面对象获取到参数后，快速返回。

**注意：BreakerPointer的getBreakerParams()方法中，获取到参数即可快速返回，不要阻塞BreakerPointer的getBreakerParams()方法。**

**（4）实现扩展点接口**

在某些业务场景下，由于熔断参数字段值的获取方式不统一，熔断组件虽然能够通过切面获取到方法的参数值，但不确定具体哪个参数是需要的熔断数据依据。所以，熔断组件单独提供了扩展点接口，由业务根据自身需要进行实现，获取到对应的参数值后，快速返回即可。这里，以@HttpBreaker标注到Controller接口方法上为例，实现扩展点的示例如下所示。

首先，在接口方法上标注@HttpBreaker注解。

textjavascripttypescriptcsshtmlbashjsonmarkdownpythonjavaccpprubygorustphpsqlyaml Copy

```plain
            `   @HttpBreaker(pointerName = "customBreakerPointer", skipRules = {SkipRule.PLATFORM, SkipRule.CURRENCY}) @RequestMapping(value="/api/test") public String testBreaker(HttpServletRequest request){     /***************省略具体逻辑*************/     return "success"; }   `
```

其中，

① @HttpBreaker注解中的pointerName = "customBreakerPointer"表示熔断组件在运行过程中加载BeanName为customBreakerPointer的扩展点接口实现类，来获取熔断参数。

② skipRules = {SkipRule.PLATFORM, SkipRule.CURRENCY}表示熔断组件会忽略基于平台和币种的熔断。

随后，创建一个扩展点接口的实现类。

textjavascripttypescriptcsshtmlbashjsonmarkdownpythonjavaccpprubygorustphpsqlyaml Copy

```plain
            `   @Component("customBreakerPointer") public class CustomBreakerPointer implements BreakerPointer {     @Override     public BreakerParams getBreakerParams(ProceedingJoinPoint joinPoint){         HttpServletRequest request = (HttpServletRequest)joinPoint.getArgs()[0];         String siteCode = request.getHeader("siteCode");         return new BreakerParams(siteCode, "111", "222");     } }   `
```

**需要重点注意的地方：**

① 扩展点接口上的@Component注解中的value属性值，也就是customBreakerPointer，一定要和@HttpBreaker注解的pointerName属性值相同，这样熔断组件才会正确加载扩展点接口的实现类。

② 由于使用@HttpBreaker标注的方法只有一个HttpServletRequest参数，所以在扩展点实现类的getBreakerParams()方法中，使用joinPoint.getArgs()[0]获取参数，并强转为HttpServletRequest类型，如果方法中有多个参数，使用joinPoint.getArgs()获取参数数组后，按照实际方法参数的顺序，依次从参数数组中获取参数后，强转为对应的数据类型即可。

③ 如果多个需要熔断的方法参数相同，多个方法可以共用一个扩展点接口实现类。如果多个需要熔断的方法参数不同，则需要为参数不同的多个方法分别实现扩展点接口，在扩展点接口实现类上指定不同的@Component的value值，与对应的需要熔断的方法上添加的@XxxBreaker注解的pointerName属性值相同即可。

④ 这里以@HttpBreaker标注到Controller接口的方法上为例进行说明，也可以将其标注到通过HTTP接口触发的Service方法以及Component方法上。另外，@ReactorBreaker注解和@MethodBreaker注解关于扩展点接口的规则与@HttpBreaker注解相同。

例如，这里再给出两个不同参数的Http接口和对应的扩展点接口实现类。

### 五、注意点

无论是调用接口触发熔断，还是调用普通方法触发熔断，熔断组件都会抛出BreakerException异常，BreakerException会封装code状态码和Mesasage异常消息。其中，code状态码固定为1000000001，message固定为system is busy。调用接口和普通方法有两种不同的处理方式。

**（1）调用接口触发熔断**

调用接口时，无论熔断注解是标注到Controller接口的方法上，还是Service实现类的方法上，触发熔断时，会向接口调用方返回如下数据。

textjavascripttypescriptcsshtmlbashjsonmarkdownpythonjavaccpprubygorustphpsqlyaml Copy

```plain
            `   {     "code": 1000000001,     "msg": "system is busy",     "data": "" }   `
```

重要：如果对接熔断组件的项目自身实现了XxxExceptionHandler来全局捕获异常，并返回指定数据。此时需要项目自身实现的XxxExceptionHandler继承熔断组件内置的BreakerExceptionHandler，如下所示。

textjavascripttypescriptcsshtmlbashjsonmarkdownpythonjavaccpprubygorustphpsqlyaml Copy

```plain
            `   @RestControllerAdvice public class XxxExceptionHandler extends BreakerExceptionHandler{     /***************省略具体逻辑*************/ }   `
```

也可以在项目自身实现的XxxExceptionHandler中，添加熔断组件内置的BreakerExceptionHandler类捕获BreakerException异常的方法，此时项目自身实现的XxxExceptionHandler可以不再继承熔断组件内置的BreakerExceptionHandler类，如下所示。

textjavascripttypescriptcsshtmlbashjsonmarkdownpythonjavaccpprubygorustphpsqlyaml Copy

```plain
            `   @RestControllerAdvice public class XxxExceptionHandler {    @ExceptionHandler(value = BreakerException.class)     public BreakerResult<String> breakerExceptionHandler(BreakerException e){         return new BreakerResult<>(e.getCode(), e.getMessage(), Constants.EMPTY_STRING);     } }   `
```

**（2）调用普通方法触发熔断**

在未通过HTTP接口触发的普通方法上标注熔断注解，并且调用方法触发熔断时，同样会抛出BreakerException异常，此时需要调用方捕获BreakerException异常后，根据具体情况做逻辑处理，例如：
