即时通讯SDK除了要实现发送单聊和群聊消息外，还有一些对外来说非常重要的方法，那就是获取用户的在线状态信息。但是，获取用户的在线状态时，又不能简单的返回一个标识用户是否在线的状态。那要如何设计和实现呢？

### **一、前言**

即时通讯SDK是为大后端平台或者其他业务系统快速接入IM即时通讯功能而设计和开发的SDK工具包，既然即时通讯SDK是为快速接入IM即时通讯功能而设计和开发的SDK工具包，那即时通讯SDK肯定要对外提供发送单聊和群聊的方法，除了这些方法外，还需要提供哪些方法呢？

其实，在发送单聊和群聊消息时，即时通讯后端服务都是会为在线的用户直接推送消息，那业务系统里如何知道哪些用户在线，哪些用户离线呢？此时，就需要即时通讯SDK对外提供一些用户在线状态相关的方法。

### **二、本节诉求**

对即时通讯SDK中获取用户在线状态相关的信息进行统一设计和实现，大后端平台或者其他业务系统对接IM即时通讯功能时，只需要引入即时通讯SDK，调用相关的方法即可获取用户的在线状态信息。

在正式设计和实现之前，我们要思考下对于即时通讯SDK来说，只是对外提供一个判断当前用户是否在线的方法是远远不够的。在某些场景下，我们还需要根据一批用户来筛选出在线的用户列表，根据一批用户来筛选出在线用户的ID与终端列表的对应关系等等。所以，在满足判断用户是否在线的基本诉求下，还需要实现根据一批用户来筛选出在线的用户列表和根据一批用户来筛选出在线用户的ID与终端列表的对应关系等等需求。

### **四、编码实现**

具体实现步骤如下所示。

**（1）修改IMSender接口**

主要是在IMSender接口中添加用户在线状态相关的方法。

源码详见：io.binghe.im.sdk.interfaces.sender.IMSender。

```go
Map<Long, List<IMTerminalType>> getOnlineTerminal(List<Long> userIds);
Boolean isOnline(Long userId);
List<Long> getOnlineUser(List<Long> userIds);
```

其中，每个方法的含义如下所示。

1. getOnlineTerminal()：根据传入的用户ID列表获取在线用户与其终端的对应关系。

2. isOnline()：判断某个用户是否在线，在线返回true，不在线返回false。

3. getOnlineUser()：根据传入的用户ID列表筛选出在线的用户ID列表。

**（2）修改DefaultIMSender类**

主要是在DefaultIMSender类中添加用户在线状态相关的方法。这里，我们还是单独讲解每一个方法。

首先是getOnlineTerminal()方法，主要的作用就是根据传入的用户ID列表获取在线用户与其终端的对应关系。

源码详见：io.binghe.im.sdk.interfaces.sender.impl.DefaultIMSender#getOnlineTerminal。

```go
@Override
public Map<Long, List<IMTerminalType>> getOnlineTerminal(List<Long> userIds) {
  if (CollectionUtil.isEmpty(userIds)){
    return Collections.emptyMap();
   }
  Map<String, IMUserInfo> userMap = new HashMap<>();
  for (Long userId : userIds){
    for (Integer terminal : IMTerminalType.codes()){
      String key = String.join(IMConstants.REDIS_KEY_SPLIT, IMConstants.IM_USER_SERVER_ID, userId.toString(), terminal.toString());
      userMap.put(key, new IMUserInfo(userId, terminal));
     }
   }
  //从Redis批量获取数据
  List<String> serverIdList = distributedCacheService.multiGet(userMap.keySet());
  int idx = 0;
  Map<Long, List<IMTerminalType>> onlineMap = new HashMap<>();
  for (Map.Entry<String, IMUserInfo> entry : userMap.entrySet()){
    if (!StrUtil.isEmpty(serverIdList.get(idx++))){
      IMUserInfo imUserInfo = entry.getValue();
      List<IMTerminalType> imTerminalTypeList = onlineMap.computeIfAbsent(imUserInfo.getUserId(), o -> new LinkedList<>());
      imTerminalTypeList.add(IMTerminalType.fromCode(imUserInfo.getTerminal()));
​
     }
   }
  return onlineMap;
}
```

可以看到，在getOnlineTerminal()方法中，首先判断传入的用户ID列表是否为空，如果为空，则直接返回一个空Map集合。否则，构造以用户ID和终端为Key，用户数据模型为Value的映射关系。随后，通过映射关系的Key集合从分布式缓存中批量获取即时通讯后端服务的ID列表。随后根据后端服务的ID列表筛选出在线用户，并构造出在线用户与其终端列表的对应关系，最终返回在线用户与其终端的对应关系。

isOnline()方法的主要作用就是判断某个用户是否在线，在线返回true，不在线返回false。

源码详见：io.binghe.im.sdk.interfaces.sender.impl.DefaultIMSender#isOnline。

```go
@Override
public Boolean isOnline(Long userId) {
  String redisKey = String.join(IMConstants.REDIS_KEY_SPLIT, IMConstants.IM_USER_SERVER_ID, userId.toString(), "*");
  Set<String> keys = distributedCacheService.keys(redisKey);
  return !CollectionUtil.isEmpty(keys);
}
```

可以看到，由于在分布式IM即时通讯系统中，支持某个用户同时登录多个不同类型的设备，所以，在判断用户是否在线时，只要某个设备类型下在线，就会返回true，否则返回false。

getOnlineUser()方法的主要作用就是根据传入的用户ID列表筛选出在线的用户ID列表。

源码详见：io.binghe.im.sdk.interfaces.sender.impl.DefaultIMSender#getOnlineUser。

```go
@Override
public List<Long> getOnlineUser(List<Long> userIds) {
  return new LinkedList<>(this.getOnlineTerminal(userIds).keySet());
}
```

可以看到，getOnlineUser()方法中会调用getOnlineTerminal()方法，并获取得到的Map的Key的Set集合，将其封装到LinkedList集合中并返回。
