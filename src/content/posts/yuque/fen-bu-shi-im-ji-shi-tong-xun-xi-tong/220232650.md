### **三、代码设计**

如何让即时通讯后端服务同时支持TCP和WebSocket两种长连接方式，并且兼顾到良好的性能、扩展性和优雅性呢？相信学过[《Seckill分布式秒杀系统》](https://articles.zsxq.com/id_52v1wwqt8uez.html)和[《分布式IM即时通讯系统》](https://articles.zsxq.com/id_dm9trllv5sac.html)的小伙伴，能够第一时间想到一个最基本的原则：**面向接口编程，而非面向具体实现类编程，具体业务依赖接口，并不关心接口的具体实现类，接口可以具有多个实现类，各个实现类之间可以通过简单的配置实现灵活切换。**

在即时通讯后端服务中，我们主要使用Netty进行消息的收发，了解过Netty的小伙伴，或者学习过[《RPC手撸专栏》](https://articles.zsxq.com/id_6gfgwev2uw0p.html)的小伙伴，应该都比较清楚，基于Netty开发应用程序时，会有通用的代码设计模板。那我们如何将这些通用的代码设计落地到即时通讯后端服务，并且要同时支持TCP和WebSocket两种长连接方式呢？

这里，我们先来看一张图，如图1-1所示。

可以看到，对于即时通讯后端服务来说，最终依赖的还是服务的接口，并非具体的实现类。一个服务接口可提供多个实现类，具体根据配置项决定启用哪个实现类，也可以同时支持多个实现类。

在具体代码设计上，对于服务接口来说，我们可以提供一个启动服务的方法和一个停止服务的方法，并且可以提供一个服务是否准备就绪的方法，基于TCP的实现类和基于WebSocket的实现类都会实现这个服务接口，如图1-2所示。

可以看到，映射到具体代码时，无论是实现TCP连接还是WebSocket连接，最终都是要实现IMNettyServer接口，具体业务逻辑中依赖的是IMNettyServer接口，而非TcpSocketServer类和WebSocketServer类，方便后续的维护和扩展。

### **四、代码实现**

梳理清楚代码设计的逻辑后，在代码实现层面就比较简单了，具体实现步骤如下所示。

**（1）新增IMNettyServer接口**

IMNettyServer接口是启动Netty服务的通用接口。

源码详见：io.binghe.im.server.application.netty.IMNettyServer。

```java
public interface IMNettyServer {
    boolean isReady();
    void start();
    void shutdown();
}
```

其中，各方法的含义如下所示。

1. isReady()方法：服务是否准备就绪。

2. start()方法：启动服务。

3. shutdown()方法：停止服务。

**（2）新增TcpSocketServer类**

TcpSocketServer类是基于TCP实现的Netty服务启动类，实现了IMNettyServer接口。

源码详见：io.binghe.im.server.application.netty.tcp.TcpSocketServer。

```java
@Component
@ConditionalOnProperty(prefix = "tcpsocket", value = "enable", havingValue = "true",matchIfMissing = true)
public class TcpSocketServer implements IMNettyServer {
    private final Logger logger = LoggerFactory.getLogger(TcpSocketServer.class);
    ​
    private volatile boolean ready = false;
    ​
    @Value("${tcpsocket.port}")
    private int port;
    ​
    private EventLoopGroup bossGroup;
    private EventLoopGroup workGroup;
    ​
    @Override
    public boolean isReady() {
        return ready;
    }
    ​
    @Override
    public void start() {
        ServerBootstrap bootstrap = new ServerBootstrap();
        bossGroup = new NioEventLoopGroup();
        workGroup = new NioEventLoopGroup();
        bootstrap.group(bossGroup, workGroup)
        .channel(NioServerSocketChannel.class)
        .childHandler(new ChannelInitializer<Channel>(){
            @Override
            protected void initChannel(Channel ch) throws Exception {
                ChannelPipeline pipeline = ch.pipeline();
                pipeline.addLast(new IdleStateHandler(120, 0, 0, TimeUnit.SECONDS));
                pipeline.addLast("encode", null);
                pipeline.addLast("decode", null);
                pipeline.addLast("handler", null);
            }
        }).option(ChannelOption.SO_BACKLOG, 5)
        .childOption(ChannelOption.SO_KEEPALIVE, true);
        try{
            bootstrap.bind(port).sync().channel();
            this.ready = true;
            logger.info("TcpSocketServer.start|服务启动正常,监听端口:{}", port);
        }catch (InterruptedException e){
            logger.error("TcpSocketServer.start|服务启动异常:{}", e.getMessage());
        }
    }
    ​
    @Override
    public void shutdown() {
        if (bossGroup != null && !bossGroup.isShuttingDown() && !bossGroup.isShutdown()){
            bossGroup.shutdownGracefully();
        }
        if (workGroup != null && !workGroup.isShuttingDown() && !workGroup.isShutdown()){
            workGroup.shutdownGracefully();
        }
        this.ready = false;
        logger.info("TcpSocketServer.shutdown|服务停止");
    }
}
```

可以看到，TcpSocketServer类实现了IMNettyServer接口，并实现了IMNettyServer接口的方法，并且此时我们还未实现TCP通讯的编解码器和处理数据通讯的ChannelHandler类，所以，无论是编解码器还是处理数据通讯的ChannelHandler，在pipline中我们暂时都是将其设置为null。

另外，在TcpSocketServer类上标注了@ConditionalOnProperty注解，并且在port成员变量上标注了@Value注解，这些注解的值都可以在application.yml文件中进行配置。当application.yml文件中进行了如下配置时，即可将TcpSocketServer类的对象加载到IOC容器中，并且可以为port成员变量赋值。

```java
tcpsocket:
    enable: true
    port: 8879
```

**（3）新增WebSocketServer类**

WebSocketServer类是基于WebSocket实现的Netty服务启动类，实现了IMNettyServer接口。

源码详见：io.binghe.im.server.application.netty.ws.WebSocketServer。

```java
@Component
@ConditionalOnProperty(prefix = "websocket", value = "enable", havingValue = "true",matchIfMissing = true)
public class WebSocketServer implements IMNettyServer {
    private final Logger logger = LoggerFactory.getLogger(WebSocketServer.class);
    ​
    private volatile boolean ready = false;
    ​
    @Value("${websocket.port}")
    private int port;
    ​
    private EventLoopGroup bossGroup;
    private EventLoopGroup workGroup;
    ​
    @Override
    public boolean isReady() {
        return ready;
    }
    ​
    @Override
    public void start() {
        ServerBootstrap bootstrap = new ServerBootstrap();
        bossGroup = new NioEventLoopGroup();
        workGroup = new NioEventLoopGroup();
        bootstrap.group(bossGroup, workGroup)
        .channel(NioServerSocketChannel.class)
        .childHandler(new ChannelInitializer<Channel>() {
            // 添加处理的Handler，通常包括消息编解码、业务处理，也可以是日志、权限、过滤等
            @Override
            protected void initChannel(Channel ch) {
                // 获取职责链
                ChannelPipeline pipeline = ch.pipeline();
                pipeline.addLast(new IdleStateHandler(120, 0, 0, TimeUnit.SECONDS));
                pipeline.addLast("http-codec", new HttpServerCodec());
                pipeline.addLast("aggregator", new HttpObjectAggregator(65535));
                pipeline.addLast("http-chunked", new ChunkedWriteHandler());
                pipeline.addLast(new WebSocketServerProtocolHandler("/im"));
                pipeline.addLast("encode", null);
                pipeline.addLast("decode", null);
                pipeline.addLast("handler", null);
            }
        })
        .option(ChannelOption.SO_BACKLOG, 5)
        .childOption(ChannelOption.SO_KEEPALIVE, true);
        ​
        try {
            bootstrap.bind(port).sync().channel();
            this.ready = true;
            logger.info("WebSocketServer.start|websocket server 初始化完成,端口：{}", port);
        } catch (InterruptedException e) {
            logger.info("WebSocketServer.start|websocket server 初始化异常", e);
        }
    }
    ​
    @Override
    public void shutdown() {
        if(bossGroup != null && !bossGroup.isShuttingDown() && !bossGroup.isShutdown() ) {
            bossGroup.shutdownGracefully();
        }
        if(workGroup != null && !workGroup.isShuttingDown() && !workGroup.isShutdown() ) {
            workGroup.shutdownGracefully();
        }
        this.ready = false;
        logger.info("WebSocketServer.shutdown|websocket server 停止");
    }
}
```

可以看到，WebSocketServer类实现了IMNettyServer接口，并实现了IMNettyServer接口的方法，并且此时我们还未实现WebSocket通讯的编解码器和处理数据通讯的ChannelHandler类，所以，无论是编解码器还是处理数据通讯的ChannelHandler，在pipline中我们暂时都是将其设置为null。

另外，在WebSocketServer类上标注了@ConditionalOnProperty注解，并且在port成员变量上标注了@Value注解，这些注解的值也都可以在application.yml文件中进行配置。当application.yml文件中进行了如下配置时，即可将WebSocketServer类的对象加载到IOC容器中，并且可以为port成员变量赋值。


**（4）新增UserChannelContextCache类**

在前面的文章中，我们提到过，用户终端与即时通讯后端服务建立连接后，即时通讯后端服务会以用户ID和用户的终端类型为Key，用户终端与即时通讯后端服务建立的连接对象为Value，将其缓存到本地内存。那具体是如何实现的呢？

其实这个逻辑就是在UserChannelContextCache类中实现的，但是在具体实现时，底层的存储结构并不是直接以用户ID和用户的终端类型为Key，用户终端与即时通讯后端服务建立的连接对象为Value来存储数据，而是在UserChannelContextCache类中设计了一个Map&lt;Long, Map&lt;Integer, ChannelHandlerContext&gt;&gt;类型的私有成员变量来存储数据。

外层Map的Key为用户的ID，内层Map的Key为用户的终端类型，内存Map的Value为ChannelHandlerContext，也就是用户与即时通讯后端服务建立连接的ChannelHandler上下文。这种结构设计更加清晰、简单、明了。

源码详见：io.binghe.im.server.application.netty.cache.UserChannelContextCache。

```java
public class UserChannelContextCache {
    private static Map<Long, Map<Integer, ChannelHandlerContext>> channelMap = new ConcurrentHashMap<>();
    ​
    public static void addChannelCtx(Long userId, Integer channel, ChannelHandlerContext ctx){
        channelMap.computeIfAbsent(userId, key -> new ConcurrentHashMap<>()).put(channel, ctx);
    }
    ​
    public static void removeChannelCtx(Long userId, Integer terminal){
        if (userId != null && terminal != null && channelMap.containsKey(userId)){
            Map<Integer, ChannelHandlerContext> userChannelMap = channelMap.get(userId);
            if (userChannelMap.containsKey(terminal)){
                userChannelMap.remove(terminal);
            }
        }
    }
    ​
    public static ChannelHandlerContext getChannelCtx(Long userId, Integer terminal){
        if (userId != null && terminal != null && channelMap.containsKey(userId)){
            Map<Integer, ChannelHandlerContext> userChannelMap = channelMap.get(userId);
            if (userChannelMap.containsKey(terminal)){
                return userChannelMap.get(terminal);
            }
        }
        return null;
    }
    ​
    public static Map<Integer, ChannelHandlerContext> getChannelCtx(Long userId){
        if (userId == null){
            return null;
        }
        return channelMap.get(userId);
    }
}
```

可以看到，在UserChannelContextCache类中主要提供了存储用户连接的方法、移除用户连接的方法和获取用户连接的方法。具体逻辑比较简单，这里，不再赘述。

**（5）新增IMServerRunner类**

即时通讯后端服务启动时，就需要启动Netty服务，并且需要监听对应的端口。在即时通讯后端服务的设计中，默认提供了TCP和WebSocket两种连接方式，并且两种连接方式可以共存，也可以随时切换。那在即时通讯后端服务启动的过程中，如何做到同时启动SpringBoot已经加载的Netty服务实现类呢？

这里，就需要使用到SpringBoot的一个扩展点，这个扩展点就是CommandLineRunner接口，CommandLineRunner接口中的run()方法就是SpringBoot在启动的过程中会调用的一个方法，我们可以创建一个IMServerRunner类来实现CommandLineRunner接口，在实现的run()方法中来启动SpringBoot已经加载的Netty服务实现类，并且可以做到无论有多少个Netty服务的实现类被加载到SpringBoot中，这些服务的实现类都会随着SpringBoot的启动而启动。同时，可以在IMServerRunner类的对象被销毁之前，关闭对应的Netty服务。

源码详见：io.binghe.im.server.application.netty.runner.IMServerRunner。

```java
@Component
public class IMServerRunner implements CommandLineRunner {
    @Autowired
    private List<IMNettyServer> imNettyServers;

    public boolean isReady(){
        for (IMNettyServer imNettyServer : imNettyServers){
            if (!imNettyServer.isReady()){
                return false;
            }
        }
        return true;
    }
    ​
    @Override
    public void run(String... args) throws Exception {
        if (!CollectionUtil.isEmpty(imNettyServers)){
            imNettyServers.forEach(IMNettyServer::start);
        }
    }
    ​
    @PreDestroy
    public void destroy(){
        if (!CollectionUtil.isEmpty(imNettyServers)){
            imNettyServers.forEach(IMNettyServer::shutdown);
        }
    }
}
```
