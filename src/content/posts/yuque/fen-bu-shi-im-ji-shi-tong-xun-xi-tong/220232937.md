### **五、编码实现**

具体的实现步骤如下所示。

**（1）实现AuthRuleChainService类**

AuthRuleChainService类是账号安全校验规则的具体实现类。

源码详见：io.binghe.im.platform.common.risk.rule.service.impl.AuthRuleChainService。

```java
@Component
public class AuthRuleChainService extends BaseRuleChainService implements RuleChainService {
    private final Logger logger = LoggerFactory.getLogger(AuthRuleChainService.class);
    ​
    @Value("${bh.im.rule.authRule.order}")
    private Integer authRuleOrder;
    ​
    @Override
    public HttpCode execute(HttpServletRequest request, Object handler) {
        //判断当前处理器是否是一个控制器方法处理器（即是否是映射到 @RequestMapping、@GetMapping 等方法）。访问静态资源（如 favicon.ico、.css、.js）不会被拦截
        if (!(handler instanceof HandlerMethod)) {
            return HttpCode.SUCCESS;
        }
        UserSession userSession = this.getUserSession(request);
        if (userSession == null){
            logger.error("AuthRuleChainService|未登录，url|{}",request.getRequestURI());
            throw new IMException(HttpCode.NO_LOGIN);
        }
        request.setAttribute(IMPlatformConstants.SESSION, userSession);
        return HttpCode.SUCCESS;
    }
    ​
    @Override
    public int getOrder() {
        return authRuleOrder == null ? RuleEnum.AUTH.getCode() : authRuleOrder;
    }
    ​
    @Override
    public String getServiceName() {
        return RuleEnum.AUTH.getMesaage();
    }
}
```

可以看到，在AuthRuleChainService类中，通过@Value注解注入了账号安全校验规则在拦截器规则链中的排序序号，并且使用@Autowired注解注入了slidingWindowLimitService对象。

在execute()方法中，判断如果当前handler不是HandlerMethod类型，就直接返回成功状态码。否则，获取userSession对象，如果获取到的userSession对象为空，则直接返回未登录状态码。否则，将获取到的userSession对象设置到request的session属性中，最后返回成功状态码。

在getOrder()方法中，如果通过@Value注入的排序序号为空，则返回默认的排序序号，否则返回通过@Value注解注入的排序序号。

在getServiceName()方法中，返回RuleEnum枚举中AUTH字段的message值。

**（2）修改BaseRuleChainService类**

主要是在BaseRuleChainService类中新增获取userSession对象的getUserSession()方法。

源码详见：io.binghe.im.platform.common.risk.rule.service.base.BaseRuleChainService#getUserSession。

```java
protected UserSession getUserSession(HttpServletRequest request){
  //从 http 请求头中取出 token
  String token = request.getHeader(IMPlatformConstants.ACCESS_TOKEN);
  if (StrUtil.isEmpty(token)) {
    logger.error("BaseRuleChainService|未登录，url|{}",request.getRequestURI());
    throw new IMException(HttpCode.NO_LOGIN);
   }
  //验证 token
  if(!JwtUtils.checkSign(token, jwtProperties.getAccessTokenSecret())){
    logger.error("BaseRuleChainService|token已失效，url|{}",request.getRequestURI());
    throw new IMException(HttpCode.INVALID_TOKEN);
   }
  // 存放session
  String strJson = JwtUtils.getInfo(token);
  if (StrUtil.isEmpty(strJson)){
    logger.error("BaseRuleChainService|token已失效，url|{}",request.getRequestURI());
    throw new IMException(HttpCode.INVALID_TOKEN);
   }
  return JSON.parseObject(strJson, UserSession.class);
}
```

### **六、使用账号安全校验规则**

在项目中使用账号安全校验规则时，只需要在项目的application.yml文件中，添加如下配置即可。

```java
bh:
  im:
   rule:
    authRule:
     order: 10 # 排序序号为10
```

这段配置表示开启了账号安全校验规则，排序序号为10。

**注意：账号安全校验规则与其他的校验规则不同，账号安全校验规则是必须执行的校验规则，无论如何，都需要执行账号安全校验规则，而XSS漏洞校验规则、滑动窗口IP校验规则和资源访问校验规则，可以视具体情况配置是否开启。**
