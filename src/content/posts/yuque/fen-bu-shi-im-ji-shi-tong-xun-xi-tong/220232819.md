### **三、Token刷新机制概述**

Token刷新机制是指在用户登录或使用API时，通过生成和更新访问令牌（Token）来实现身份验证和权限管理的一种机制。它通常用于保护用户数据和资源免受未经授权的访问。

刷新机制的基本原理如下：

1. 用户登录时，系统会为其颁发一个访问令牌（Access Token），该令牌包含了用户的身份信息和权限。

2. 访问令牌具有一定的有效期限，在过期之前，用户可以使用该令牌进行身份验证和访问授权。

3. 当访问令牌即将过期时，用户可以使用刷新令牌（Refresh Token）向服务器请求更新访问令牌。

4. 服务器收到刷新令牌后，会验证其合法性，并根据用户的身份和权限重新生成一个新的访问令牌，并返回给用户。

5. 用户使用新的访问令牌进行后续的操作和访问授权。

Token刷新机制的好处包括：

1. 提高系统的安全性：通过限制令牌的有效期限，可以减少令牌被盗用的风险。

2. 提升用户体验：用户无需频繁重新登录，只需使用刷新令牌更新访问令牌即可。

3. 简化权限管理：刷新令牌可以通过各种方式存储，如数据库、缓存等，使权限管理更加灵活和可控。

需要注意的是，刷新令牌的安全性非常重要。开发者应该采取适当的措施来保护刷新令牌的传输和存储，以防止被恶意攻击者获取和滥用。

### **四、Token刷新机制流程**

当Token将过期时，客户端可以调用服务端的接口来刷新Token，简易流程如图2-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/ccb13ae05c642c887b4c24071f2dcb2ff89dc1694f6264b3c6681d0afe96fbd7.png)

可以看到，为了增强JWT Token的安全性，用户登录系统后，服务端会生成带有时效性的JWT Token返回给客户端。客户端会将JWT Token保存在本地，在时效性时间范围内，客户端使用当前Token可以访问服务端的资源。但当超过时效性后，客户端就不能再使用当前Token访问服务端资源。

所以，在当前Token失效之前，客户端需要调用服务端的接口来刷新Token，刷新成功后，服务端会返回给客户端一个刷新后的Token，后续客户端会使用刷新后的Token访问服务端的资源。当刷新后的Token即将失效时，客户端还会调用服务端的接口再次刷新Token，以此类推。

**（2）修改UserServiceImpl类**

源码详见：io.binghe.im.platform.user.application.service.impl.UserServiceImpl#refreshToken。

```java
@Override
public LoginVO refreshToken(String refreshToken) {
//验证 token
if (!JwtUtils.checkSign(refreshToken, jwtProperties.getRefreshTokenSecret())) {
    throw new IMException("refreshToken无效或已过期");
}
String strJson = JwtUtils.getInfo(refreshToken);
Long userId = JwtUtils.getUserId(refreshToken);
String accessToken = JwtUtils.sign(userId, strJson, jwtProperties.getAccessTokenExpireIn(), jwtProperties.getAccessTokenSecret());
String newRefreshToken = JwtUtils.sign(userId, strJson, jwtProperties.getRefreshTokenExpireIn(), jwtProperties.getRefreshTokenSecret());
LoginVO vo = new LoginVO();
vo.setAccessToken(accessToken);
vo.setAccessTokenExpiresIn(jwtProperties.getAccessTokenExpireIn());
vo.setRefreshToken(newRefreshToken);
vo.setRefreshTokenExpiresIn(jwtProperties.getRefreshTokenExpireIn());
return vo;
}
```

可以看到，在refreshToken方法中接收refreshToken参数，并对其进行合法性校验，如果校验不通过，则直接抛出refreshToken无效或已过期的异常。否则，从refreshToken参数中解析用户的Session数据。并重新生成accessToken和refreshToken返回给客户端。
