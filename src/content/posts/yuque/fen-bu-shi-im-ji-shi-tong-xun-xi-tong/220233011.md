### **二、本节诉求**

如果一个单体应用系统中某些关键业务只能让一个线程执行，此时可以使用synchronized锁或者Lock锁实现。但是synchronized锁或者Lock锁只能解决单体应用系统下线程的互斥问题，在分布式系统场景下，synchronized锁或者Lock锁就显得力不从心了，此时，就需要使用分布式锁来解决相应的问题。

本章，就从代码层面基于Redisson实现具备良好扩展性的分布式锁。

### **三、代码设计**

在设计分布式锁的代码时，将会从代码场景、代码扩展性和代码类结构等方面进行详细的说明。

#### **3.1 代码场景设计**

如果分布式系统中存在受保护的临界区资源，并且在同一时刻只能有一个线程对这些临界区资源进行变更操作，在这种场景下，Java中提供的synchronized锁或者Lock锁是无能为力的，此时就需要使用分布式锁来解决相应的问题。

在分布式场景下，无论存在多少个应用服务，亦或是存在多少个系统实例，只要是这些应用服务或者系统实例需要互斥的更新临界区资源，使用分布式锁都能够实现在同一时刻只能有一个线程变更临界区资源，如图4-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/1e7a9d51bd0894342a03e055aecadfe2d5f7f4454aaaa38744d4d2ff1c287287.png)

可以看到，在分布式场景下，对临界区资源进行变更时，使用分布式锁能够实现在同一时刻只能有一个线程变更临界区资源，此时，变更临界区资源是线程安全的，不会由于多个线程同时变更临界区资源而造成线程安全的问题。

#### **3.2 代码扩展性设计**

分布式IM即时通讯系统总体上是基于SpringBoot实现，那基于SpringBoot实现的代码如何才能具备良好的扩展性呢？这里，我们再来温习下代码具备良好扩展性的原则。**总体的原则就是面向接口编程，而非面向具体的实现类编程，具体业务逻辑里依赖的是接口，而非实现类，在接口不变的前提下，可以随时切换具体的实现类，也可以随时新增接口的实现类。业务中可以根据配置加载接口的某个具体实现类。**

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/349205647e5cfa6a8acca2966aa4c42e77eb14f7a000d28d3311decd2967b6f8.png)

可以看到，在分布式锁通用代码的设计中，分布式IM即时通讯系统的具体业务只会依赖分布式锁相关的接口，而不会依赖分布式锁的具体实现类。分布式锁接口可以具备多个实现类，例如基于Redis的实现类、基于Redisson的实现类、基于Memcached的实现类、基于Zookeeper的实现类和其他实现类，并且可以通过简单的配置即可在具体业务中加载并实例化分布式锁接口的某个具体实现类对象。

分布式IM即时通讯系统默认会提供基于Redisson实现的分布式锁，大家也可以根据具体的需求和业务场景，基于分布式锁接口扩展其他的实现类。

#### **3.3 代码类结构设计**

通用分布式锁代码是面向接口编程，而非面向具体实现类编程，代码的类结构设计如图4-3所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/573748c78e5c0c4b86e05e43ee99adac2456e5347ed593b9ccc8e60bce50b044.png)

可以看到，在分布式IM即时通讯系统关于分布式锁的通用实现中，会默认基于Redisson实现分布式锁，核心代码逻辑中会包含：DistributedLockFactory接口、DistributedLock接口、RedissonLockFactory类和匿名内部类。

1. DistributedLockFactory：分布式锁工厂接口，提供一个getDistributedLock()方法，通过getDistributedLock()方法就可以获取一个分布式锁实例。

2. DistributedLock：分布式锁接口，接口中定义了分布式锁的常规操作方法，包含加锁、释放锁、判断是否添加分布式锁等方法。

3. 匿名内部类：分布式接口在RedissonLockFactory类中的匿名内部类，实现了DistributedLock分布式锁接口，并基于Redisson的RLock对象实现了DistributedLock分布式锁接口中定义的方法。

4. RedissonLockFactory：分布式锁工厂的实现类，实现了DistributedLockFactory接口，并在实现的DistributedLockFactory接口的方法中基于Redisson的RLock对象，通过DistributedLock接口的匿名内部类实现了DistributedLock接口中定义的分布式锁的常规操作方法。

### **四、代码实现**

在代码实现上，会从分布式锁代码实现和新增配置两个方面进行完善。

#### **4.1 分布式锁代码实现**

分布式锁通用代码核心逻辑的实现步骤如下所示。

**（1）新增DistributedLockFactory接口**

DistributedLockFactory接口的源码详见：io.binghe.im.common.cache.lock.factory.DistributedLockFactory。

```java
public interface DistributedLockFactory {
    DistributedLock getDistributedLock(String key);
}
```

可以看到，DistributedLockFactory接口中定义了一个getDistributedLock()方法，可以通过getDistributedLock()方法获取DistributedLock分布式锁对象。

**（2）新增DistributedLock接口**

DistributedLock接口的源码详见：io.binghe.im.common.cache.lock.DistributedLock。

```java
public interface DistributedLock {
    boolean tryLock(long waitTime, long leaseTime, TimeUnit unit) throws InterruptedException;
    void lock(long leaseTime, TimeUnit unit);
    void unlock();
    boolean isLocked();
    boolean isHeldByThread(long threadId);
    boolean isHeldByCurrentThread();
}
```

可以看到，DistributedLock接口是分布式锁接口，在DistributedLock接口中定义了分布式锁的常规操作方法，包含：加锁、释放锁和是否添加分布式锁等方法。

**（3）新增RedissonLockFactory类**

RedissonLockFactory类的源码详见：io.binghe.im.common.cache.lock.redisson.RedissonLockFactory。

```java
@Component
@ConditionalOnProperty(name = "distributed.lock.type", havingValue = "redisson")
public class RedissonLockFactory implements DistributedLockFactory {
    private final Logger logger = LoggerFactory.getLogger(RedissonLockFactory.class);
    ​
    @Autowired
    private RedissonClient redissonClient;
    ​
    @Override
    public DistributedLock getDistributedLock(String key) {
        RLock rLock = redissonClient.getLock(key);
        return new DistributedLock() {
            @Override
            public boolean tryLock(long waitTime, long leaseTime, TimeUnit unit) throws InterruptedException {
                boolean isLockSuccess = rLock.tryLock(waitTime, leaseTime, unit);
                logger.info("{} get lock result:{}", key, isLockSuccess);
                return isLockSuccess;
            }
            ​
            @Override
            public void lock(long leaseTime, TimeUnit unit) {
                rLock.lock(leaseTime, unit);
            }
            ​
            @Override
            public void unlock() {
                if (isLocked() && isHeldByCurrentThread()) {
                    rLock.unlock();
                }
            }
            @Override
            public boolean isLocked() {
                return rLock.isLocked();
            }
            ​
            @Override
            public boolean isHeldByThread(long threadId) {
                return rLock.isHeldByThread(threadId);
            }
            ​
            @Override
            public boolean isHeldByCurrentThread() {
                return rLock.isHeldByCurrentThread();
            }
        };
    }
}
```

可以看到，RedissonLockFactory类实现了DistributedLockFactory接口，并在实现的DistributedLockFactory接口的方法中基于Redisson的RLock对象，通过DistributedLock接口的匿名内部类实现了DistributedLock接口中定义的分布式锁的常规操作方法。并且在RedissonLockFactory类上使用@ConditionalOnProperty注解标注了当配置文件中的[distributed.lock.type](http://distributed.lock.type)配置项取值为redisson时，才会加载并实例化RedissonLockFactory类的对象。

至此，分布式IM即时通讯系统通用代码的核心逻辑实现完毕。

#### **4.2 新增配置**

在分布式锁的配置中，包含配置类和配置文件，具体新增配置的步骤如下所示。

**（1）新增RedissonConfig类**

RedissonConfig类的源码详见：io.binghe.im.common.cache.config.RedissonConfig。

```java
@Configuration
@ConditionalOnProperty(name = "distributed.lock.type", havingValue = "redisson")
public class RedissonConfig {
    ​
    @Value("${spring.redis.address}")
    private String redisAddress;
    ​
    @Bean(name = "redissonClient")
    @ConditionalOnProperty(name = "redis.arrange.type", havingValue = "single")
    public RedissonClient singleRedissonClient() {
        Config config = new Config();
        config.useSingleServer().setAddress(redisAddress).setDatabase(0);
        return Redisson.create(config);
    }
    ​
    @Bean(name = "redissonClient")
    @ConditionalOnProperty(name = "redis.arrange.type", havingValue = "cluster")
    public RedissonClient clusterRedissonClient(){
        Config config = new Config();
        ClusterServersConfig clusterServersConfig = config.useClusterServers();
        clusterServersConfig.setNodeAddresses(Arrays.asList(redisAddress));
        return Redisson.create(config);
    }
}
```

可以看到，RedissonConfig类的主要作用就是通过@Bean注解向Spring IOC容器中注入RedissonClient类的实例对象，并且在RedissonConfig类上使用@ConditionalOnProperty注解标注了当配置文件中的distributed.lock.type配置项取值为redisson时，才会加载并实例化RedissonConfig类的对象。

考虑到Redis可能以单机方式部署，也可能以集群方式部署，所以在RedissonConfig类中分别定义了向Spring IOC容器中注入单机方式的RedissonClient对象的singleRedissonClient()方法和向Spring IOC容器中注入集群方式的RedissonClient对象的clusterRedissonClient()方法。

在singleRedissonClient()方法上使用@ConditionalOnProperty注解标注了当配置文件中的redis.arrange.type配置项的取值为single时，Spring才会调用singleRedissonClient()方法创建RedissonClient类的对象并将其注入到IOC容器中。

在clusterRedissonClient()方法上使用@ConditionalOnProperty注解标注了当配置文件中的redis.arrange.type配置项的取值为cluster时，Spring才会调用clusterRedissonClient()方法创建RedissonClient类的对象并将其注入到IOC容器中。

**（2）新增配置项**

新增配置项的操作就比较简单了，在src/main/resources目录下的application.yml文件中新增如下配置项。

```java
distribute:
type:
lock: redisson

redis:
arrange:
type: single
```
