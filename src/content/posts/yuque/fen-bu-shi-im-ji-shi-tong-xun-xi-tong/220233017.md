消息中间件是解耦分布式系统的利器，使用消息中间件不仅能够让分布式系统中的各个微服务之间进行解耦，也能够起到削峰填谷的作用，还能异步执行一些非关键链路的业务逻辑。可以这么说，消息中间件已经成为构建分布式系统不可或缺的重要基础组件。

### **一、前言**

在分布式系统中，如何降低各个微服务之间的耦合度？如何对流量进行削峰填谷？相信很多小伙伴心中已经有了答案：使用消息中间件。另外，使用消息中间件也能够异步执行一些非关键链路的业务逻辑，提升系统的性能和吞吐量。

那么问题来了，引入消息中间件的话，我们又如何编写优雅的代码来引入消息中间件呢？能不能做到系统不强制依赖某一款消息中间件呢？如何使我们的系统在引入消息中间件时，也具备高度的可扩展性呢？

### **二、本节诉求**

如果一个单体应用需要解耦来异步执行一些业务逻辑时，可以使用JDK中提供的队列来实现，也可以使用阿里巴巴开源的[Cola](https://github.com/alibaba/cola)框架实现。但是在分布式场景下，无论时使用JDK提供的队列，还是使用阿里巴巴开源的Cola框架，都已经显得力不从心了。此时，就需要引入消息中间件来解决相应的问题。

本章，就实现MQ消息发送的通用代码设计。

### **三、代码设计**

在设计MQ消息发送的通用代码时，同样会从代码场景、代码扩展性和代码类结构等方面进行详情的说明。

#### **3.1 代码场景设计**

如果分布式系统中的各个微服务之间需要异步解耦，此时可以引入消息中间件来完成各个微服务之间的异步解耦。例如，假设存在服务A和服务B两个微服务，服务A在接收到请求后，执行对应的业务逻辑，经过一系列的处理，将数据发送给消息中间件即可返回结果。此时监听消息中间件中数据的服务B就会接收到对应的数据，服务B开始执行业务逻辑，如图5-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/084453aa5dc070d5d7d14cd7b2b7bad960651f4ed587441710d3387649903ff8.png)

可以看到，使用消息中间件降低了服务A和服务B之间的耦合度。并且使用消息中间件时，服务A可以扩展成集群模式，服务B同样可以扩展成集群模式。此时服务A集群中将消息发送到消息中间件后，即可返回，期间并不关心消息数据会被服务B集群中的哪个具体服务实例消费。同样的，服务B集群消费消息中间件中的数据，并不关心这些消息是服务A集群中具体哪个服务实例发送的。

#### **3.2 代码扩展性设计**

分布式IM即时通讯系统总体上是基于SpringBoot实现，那基于SpringBoot实现的代码如何才能具备良好的扩展性呢？这里，我们再来加深下对代码具备良好扩展性的原则的理解。**总体的原则就是面向接口编程，而非面向具体的实现类编程，具体业务逻辑里依赖的是接口，而非实现类，在接口不变的前提下，可以随时切换具体的实现类，也可以随时新增接口的实现类。业务中可以根据配置加载接口的某个具体实现类。**

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/08d499e7c6a566b2264fbe6fcaf441114d933b3030e452afdfe775f45441f642.png)

可以看到，在MQ消息发送通用代码的设计中，分布式IM即时通讯系统的具体业务只会依赖通用发送消息的接口，而不会依赖发送消息的具体实现类。通用发送消息的接口可以具备多个实现类，例如基于RocketMQ的实现类、基于RabbitMQ的实现类、基于Kafka的实现类、基于ActiveMQ的实现类和其他实现类，并且可以通过简单的配置即可在具体业务中加载并实例化通用发送消息接口的某个具体实现类对象。

分布式IM即时通讯系统默认会提供基于RocketMQ实现的发送消息逻辑，大家也可以根据具体的需求和业务场景，基于通用发送消息接口扩展其他的实现类。

#### **3.3 代码类结构设计**

发送消息通用代码是面向接口编程，而非面向具体实现类编程，代码的类结构设计如图5-3所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/011c4d4bc9fb145def703cd8e32adbb0b7d54d5ea6a84660e6291238714e35f1.png)

可以看到，在通用发送消息的实现中，会默认基于RocketMQ消息中间件实现，如下所示。

1. MessageSenderService接口：通用发送消息接口，提供了两个发送消息的方法。

2. send()方法：发送普通消息。

3. sendMessageInTransaction()方法：发送事务消息。

4. RocketMQMessageSenderService类：基于RocketMQ实现MessageSenderService接口。

5. send()方法：发送普通消息。

6. sendMessageInTransaction()方法：发送事务消息。

7. getMessage()方法：构造并获取向RocketMQ中真正发送的消息数据。

### **四、代码实现**

在代码实现上，会从通用发送消息代码实现和新增配置项两个方面进行完善。

#### **4.1 通用发送消息实现**

通用发送消息代码的核心逻辑实现步骤如下所示。

**（1）新增MessageSenderService接口**

源码详见：io.binghe.im.common.mq.MessageSenderService。

```java
public interface MessageSenderService {
    boolean send(TopicMessage message);
    default TransactionSendResult sendMessageInTransaction(TopicMessage message, Object arg){
        return null;
    }
}
```

**（2）新增RocketMQMessageSenderService类**

源码详见：io.binghe.im.common.mq.rocketmq.RocketMQMessageSenderService。

```java
@Component
@ConditionalOnProperty(name = "message.mq.type", havingValue = "rocketmq")
public class RocketMQMessageSenderService implements MessageSenderService {
    ​
    @Autowired
    private RocketMQTemplate rocketMQTemplate;
    ​
    @Override
    public boolean send(TopicMessage message) {
        try{
            SendResult sendResult = rocketMQTemplate.syncSend(message.getDestination(), this.getMessage(message));
            return SendStatus.SEND_OK.equals(sendResult.getSendStatus());
        }catch (Exception e){
            return false;
        }
    }
    ​
    @Override
    public TransactionSendResult sendMessageInTransaction(TopicMessage message, Object arg) {
        return rocketMQTemplate.sendMessageInTransaction(message.getDestination(), this.getMessage(message), arg);
    }
    ​
    //构建ROcketMQ发送的消息
    private Message<String> getMessage(TopicMessage message){
        JSONObject jsonObject = new JSONObject();
        jsonObject.put(IMConstants.MSG_KEY, message);
        return MessageBuilder.withPayload(jsonObject.toJSONString()).build();
    }
}
```

可以看到RocketMQMessageSenderService类实现了MessageSenderService接口，并实现了MessageSenderService接口中定义的方法。并且在RocketMQMessageSenderService类上使用@ConditionalOnProperty注解标注了当配置文件中的message.mq.type配置项取值为rocketmq时，才会加载并实例化RocketMQMessageSenderService类的对象。

至此，分布式IM即时通讯系统发送MQ消息通用代码的核心逻辑实现完毕。

#### **4.2 新增配置项**

新增配置项的操作就比较简单了，在src/main/resources目录下的application.yml文件中新增如下配置项。

```java
rocketmq:
name-server: 127.0.0.1:9876
producer:
group: im-server-group
​
message:
mq:
type: rocketmq
```
