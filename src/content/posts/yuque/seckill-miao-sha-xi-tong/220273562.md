### **四、准备压测环境**

准备压测环境时，需要对环境进行区分，流量染色与数据隔离，关闭秒杀系统的限流、将压测流量添加到白名单、对必要的功能进行挡板设置、做好监控准备。

**（1）对环境进行区分**

一般情况下，会将程序的运行环境分为开发环境、测试环境、预发布环境和生产环境。在对系统进行压测时，以生产环境最佳，能够真正测试出生产环境的系统性能，但是，在生产环境进行压测需要做好流量和数据的隔离操作，不要影响到正常流量和用户的正常数据。

如果不具备在生产环境做压测的条件，可以在预发布环境进行压测，但是预发布环境，虽然天然与生产环境隔离，能够做到业务隔离、数据隔离，风险也是可控的，但是在预发布环境上很难构建出与生产环境一样的业务场景和系统环境，并打通全链路的数据。

**还一个需要注意的就是：在生产环境进行压测，需要做好隔离工作，并且要在流量低峰期进行。**

**（2）流量染色与数据隔离**

在生产环境进行压测时，需要做好流量染色和数据隔离工作。一种非常简单的流量染色方式就是在请求头中加特定的标识，请求进入系统，业务系统和中间件能够识别出流量标识，此时根据流量标识对业务进行逻辑隔离和数据隔离。在数据库层面我们可以在上产环境的数据库中创建影子表，影子表的表结构与实际业务数据表相同，在表名称上可以添加一个test_前缀，或者其他的标识，以便于和真实业务表做区分。在缓存层面，同样可以在对应的缓存KEY的基础上，添加一个test_前缀。

压测开始前，我们要提前生成影子表，并且将必要的数据导入到影子表中。

进行压测时，如果系统检测到流量染色的标签，则将数据库的读写操作路由到影子库，也就是以test_开头的数据表中，对于缓存的读写操作也路由到以test_开头的KEY上。

当压测结束后，将影子表中的数据清空即可。

**这里，需要注意的是：无论是流量染色，还是数据隔离，我们都需要对秒杀交易链路上的业务系统和中间件进行改造，要支持正常流量和压测流量同时进入系统而不会造成流量和数据混乱。**

**（3）关闭秒杀系统的限流**

在对秒杀系统进行压测前，需要关闭秒杀系统的限流，这里需要从如下几个方面进行处理。

1. 屏蔽单机限流策略，压测结束后恢复。

2. 屏蔽或删除Sentinel中的限流，结束压测后在开启或者恢复。

3. 屏蔽业务网关限流，压测结束后恢复。

4. 屏蔽流量网关限流，压测结束后恢复。

**（4）将压测流量添加到白名单**

如果在真实场景下，系统的核心交易链路中存在一些安全校验功能的话，可以提前将压测流量放入白名单，防止校验不通过对压测结果产生影响。

**（5）对必要的功能进行挡板设置**

在真正压测之前，还有一个需要考虑的问题就是当前压测系统的范围，不要让压测流量蔓延到所有的系统，对一些必要的功能进行挡板设置。例如，一些调用了需要付费的第三方接口，像短信、按调用次数收费的一些接口等，可以对这些接口设置功能挡板，在实际压测过程中，就不要真正去调用短信接口发短信，也不必真正调用一些付费接口，最大程度避免由于压测导致的额外成本问题。

**（6）做好监控准备**

在对系统进行压测之前，就需要对接好监控系统，监控系统能够实时采取压测过程中的各项指标数据，实时展示，并且实时报警。在对秒杀系统压测时，可以使用Promethues进行系统监控，有关Promethues的安装脚本，安装脚本详见：项目的environment/[docker-compose.yml](http://docker-compose.yml)中。

### **五、选择压测工具**

工欲善其事，必先利其器，在正式压测之前，我们还要选择一款压测工具，常见的压测工具有Apache JMeter、Apache Bench、Wrk，当然有条件的话也可以使用阿里云PTS进行压测。

这几款工具的对比详见：[https://help.aliyun.com/document_detail/434264.html](https://help.aliyun.com/document_detail/434264.html)。

这里，我们进行压测就先选择JMeter，JMeter可以实现单机压测和分布式压测。JMeter的下载链接为：[https://jmeter.apache.org/download_jmeter.cgi](https://jmeter.apache.org/download_jmeter.cgi)。

### **六、编写压测脚本**

在编写压测脚本之前，我们需要在JMeter中安装jpgc-Standard Set 插件，具体安装方式我在知乎找了一篇文章，大家按照《[Jmeter梯度测试](https://zhuanlan.zhihu.com/p/402091005)》这篇文章安装即可。

另外，我把在JMeter中编写好的[seckill-full-test.jmx](http://seckill-full-test.jmx)脚本文件放到了项目中，详见：environment/jmeter/full/[seckill-full-test.jmx](http://seckill-full-test.jmx)。

并且在压测的过程中需要模拟多个账号操作，这里我也批量生成了Token，将生成的Token放到了[tokens.csv](http://tokens.csv)文件中，详见：environment/jmeter/full/[tokens.csv](http://tokens.csv)。

大家获取到本章对应的源码时，将[seckill-full-test.jmx](http://seckill-full-test.jmx)文件和[tokens.csv](http://tokens.csv)文件放到同一个目录下，在JMeter中安装好jpgc-Standard Set 插件，导入[seckill-full-test.jmx](http://seckill-full-test.jmx)文件后，如图121-1所示。

### **七、实施压测过程**

在实施压测的过程中，我们可以先进行单链路测试，再进行全链路测试，先进行小流量测试，再进行大流量测试，先在JMeter图形界面中对脚本进行调试，当流量跑通时，再通过命令行进行测试。

正式进行压测时，可以将命令行切换到JMeter的bin目录下，输入如下命令进行压测。

```go
jmeter -n -t ~/binghe/seckill/seckill-full-test.jmx -l ~/binghe/seckill/report/seckill-full-test-result.jtl -e -o ~/binghe/seckill/report/seckill-full-test-report
```

执行命令后，即可开始进行正式压测了。
