### **一、前言**

对于秒杀系统来说，越是前置处理刷单流量、攻击流量和无效请求，秒杀系统就越安全。如果能够将秒杀系统的刷单流量、攻击流量和无效请求阻挡在整个交易链路之外，则秒杀系统很少甚至不会受到这些刷单流量、攻击流量和无效请求的影响。

要知道，其实在整个秒杀活动过程中，秒杀系统承接的大部分流量基本都是刷单流量、攻击流量和无效请求。所以，我们如果能够将这些流量阻挡在秒杀系统之外，则会大大提高秒杀系统的稳定性和可靠性，也会节省不少服务器的资源和成本。

### **二、本章诉求**

搭建流量网关项目，在流量网关项目中开发流量规则脚本，前置化处理流量请求。并对搭建的流量网关项目进行简单的测试。重点掌握流量网关服务与脚本分离的架构模型与处理方式，并能够灵活应用到自身实际项目中。

### **三、搭建流量网关项目**

搭建流量网关项目的具体步骤如下所示。

#### **3.1新建流量网关工程**

新增seckill-nginx工程，并在seckill-nginx工程下新增对应的文件夹，如图92-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/759d8db38d863761174561facb39fa58c3c38a5e7352811245b144e537e07602.png)

其中每个文件夹的含义如下所示。

1. conf：存放Nginx的 nginx.conf 配置文件

2. config：主要存放一些常用配置，比如常量配置、负载均衡配置等。

3. domain：主要用来存放server模块的配置。

4. html：存放流量网关相关的html页面。

5. lua：主要存放Lua脚本文件。

#### **3.2 新建**[upstream.conf](http://upstream.conf)**文件**

在config目录下新建[upstream.conf](http://upstream.conf)文件，文件内容如下所示。

```go
upstream real_server {
   server localhost:10001 weight=1 max_fails=2 fail_timeout=60s;
}
```

可以看到，在[upstream.conf](http://upstream.conf)文件中主要配置了反向代理的实际服务。

#### **3.3 新建**[domain.com](http://domain.com)**文件**

在domain目录下新建[domain.com](http://domain.com)文件，文件内容如下所示。

```go
server {
    listen       11111;
    server_name localhost;
​
    location / {
        root   html;
        index index.html index.htm;
    }
​
    location ^~ /seckill {
        proxy_pass http://real_server;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
​
    error_page   500 502 503 504 /50x.html;
    location = /50x.html {
        root   html;
    }
}
​
server {
    listen       11112;
    server_name localhost;
​
    location /hello {
        default_type text/plain;
        content_by_lua_block {
            ngx.say("{\"response\" : \"hello world!!!\"}")
        }
    }
}
```

可以看到，[domain.com](http://domain.com)文件中主要是server模块的配置。也就是说，我们把[nginx.conf](http://nginx.conf)文件中有关server模块的配置移动到了[domain.com](http://domain.com)文件中，并且新增了一个监听端口为11112的server模块，这个模块主要是通过Lua脚本输出{"response":"hello world!!!"}。

#### **3.4 修改**[nginx.conf](http://nginx.conf)**文件**

修改conf文件夹下的[nginx.conf](http://nginx.conf)文件，修改后的文件内容如下所示。

```go
worker_processes  8; #工作进程数
error_log logs/error.log; #日志
events {
    worker_connections  1024; #单个进程最大连接数
}
​
http {
    log_format access '$remote_addr - $remote_user [$time_local] "$request" $status '
          '"$upstream_addr" "$upstream_status" "$upstream_response_time"';
​
    include       mime.types;
    default_type application/octet-stream;
    sendfile       on;
    keepalive_timeout  65;
    include D:/Workspaces/myself/seckill/project/seckill/seckill/seckill-nginx/config/upstream.conf;
    include D:/Workspaces/myself/seckill/project/seckill/seckill/seckill-nginx/domain/domain.com;
}
​
```

可以看到，我们已经将反向代理实际服务配置和server模块的配置移出了[nginx.conf](http://nginx.conf)文件，并且通过include将[upstream.conf](http://upstream.conf)文件和[domain.com](http://domain.com)文件引入了[nginx.conf](http://nginx.conf)文件中。

至此，流量网关的项目就搭建完毕了。

### **四、测试流量网关项目**

```go
nginx -s quit
start nginx
tasklist /fi "imagename eq nginx.exe"
```
