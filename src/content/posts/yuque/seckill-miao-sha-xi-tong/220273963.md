### **一、前言**

当“一声令下”，秒杀活动开始，此时，大量用户会点击抢购按钮，大量请求流量瞬间涌入秒杀系统，秒杀系统压力倍增，最常见的表现就是CPU使用率升高，IO等待时间变长。

此时，最直接有效的方式就是在整个秒杀系统的入口处进行限流。如果已经限流，进入秒杀系统的流量还是很大，则需要对秒杀交易链路上的一些非核心服务进行降级，以此减轻秒杀系统的负担。

### **二、本章诉求**

在流量网关层面实现IP维度和用户维度的初步限流，让大家直观的感受下通过流量网关限流的效果，并了解流量网关限流的基本原理，最终将流量网关灵活应用到自身实际项目中。

### **三、限流概述**

有关限流的基本原理，大家可以参见《[第79章：限流削峰](https://articles.zsxq.com/id_ktkdpqp8u1bm.html)》一章的内容，本节，主要介绍流量网关的限流。

这里，流量网关的限流基于内置变量和自定义变量实现，依赖Nginx自带的限流功能，针对用户请求的来源IP地址或者自定义的关键参数进行限流。Nginx限流规则的语法如下所示。

```go
limit_req_zone <变量名> zone=<限流规则名称>:<内存大小> rate=<速率阈值>r/s;
```

其中，每个参数的含义如下所示。

1. limit _ req _ zone：限流的关键字，主要定义限流的规则。

2. &lt;变量名&gt;指的是限流的关键参数，也就是根据什么来限流。

3. zone：限流的关键字，后面可以指定限流规则名称。

4. &lt;限流规则名称&gt;自定义的限流规则名称，可以通过指定限流规则名称来指定使用哪个限流规则。

5. &lt;内存大小&gt;：使用多大的内存来实现限流功能。

6. rate：限流的关键字，后面可以指定限流的阈值。

7. &lt;速率阈值&gt;：指定限流的阈值，r/s表示每秒允许通过的请求数。

更多有关Nginx的限流说明，可以参见《[Nginx核心技术](https://binghe.gitcode.host/md/core/nginx/2023-07-23-%E3%80%8ANginx%E6%A0%B8%E5%BF%83%E6%8A%80%E6%9C%AF%E3%80%8B%E7%AC%AC01%E7%AB%A0-%E5%AE%89%E8%A3%85Nginx.html)》专栏。

### **四、基于IP维度限流**

基于IP维度限流指的是根据用户的来源IP地址进行限流，此种场景下可能会存在被误杀的可能，比如多个用户在同一个局域网内，出口IP可能是同一个，此时就很容易触发限流。所以，如果大家参与618和双11秒杀大促，最好是用自己的4G或者5G网络。

#### **4.1 实现IP限流**

基于IP维度实现限流的具体步骤如下所示。

**（1）新增**[common.conf](http://common.conf)**文件**

源码详见：seckill-nginx工程下的config/[common.conf](http://common.conf)。

在seckill-nginx工程的config文件夹下新增[common.conf](http://common.conf)文件，添加按照IP限流的规则，如下所示。

```go
#根据ip限流
limit_req_zone $binary_remote_addr zone=limit_by_ip:10m rate=1r/s;
```

**（2）修改**[nginx.conf](http://nginx.conf)**文件**

在[nginx.conf](http://nginx.conf)文件中导入[common.conf](http://common.conf)文件，如下所示。

```go
include D:/Workspaces/myself/seckill/project/seckill/seckill/seckill-nginx/config/common.conf;
```

将[nginx.conf](http://nginx.conf)放到OpenResty的conf目录下。

**（3）修改**[domain.com](http://domain.com)**文件**

源码详见：seckill-nginx工程下的domain/[domain.com](http://domain.com)。

在[domain.com](http://domain.com)文件的^~ /seckill模块下新增 limit_req zone=limit_by_ip burst=1 nodelay;来引用根据IP限流的规则，如下所示。

```go
location ^~ /seckill {
    limit_req zone=limit_by_ip burst=1 nodelay;
    proxy_pass http://real_server;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

**（4）新增**[503_fail.html](http://503_fail.html)**文件**

源码详见：seckill-nginx工程下的html/[503_fail.html](http://503_fail.html)。

文件内容如下所示。

```go

    <meta charset="UTF-8">
    <title>被限流了</title>

</head>

    <p  style="padding-left:240px;font-size:xx-large;color:red;">被限流了，请稍后再试！！</p>

</div>
```

将其放到OpenResty的html目录下。

### **五、基于用户维度限流**

基于用户维度限流指的是根据用户进行限流，这种限流策略比较精准，不会误杀用户。

#### **5.1 实现用户限流**

基于用户维度实现限流的具体步骤如下所示。

**（1）修改**[common.conf](http://common.conf)**文件**

源码详见：seckill-nginx工程下的config/[common.conf](http://common.conf)。

修改seckill-nginx工程的config文件夹下的[common.conf](http://common.conf)文件，添加按照用户限流的规则，如下所示。

```go
#根据用户限流
limit_req_zone $user_id zone=limit_by_user:10m rate=1r/s;
```

**（2）修改**[domain.com](http://domain.com)**文件**

源码详见：seckill-nginx工程下的domain/[domain.com](http://domain.com)。

在[domain.com](http://domain.com)文件中添加模拟用户id的Lua脚本，如下所示。

```go
#模拟用户id
set_by_lua_block $user_id{
    return "binghe";
}
```

并且在^~ /seckill模块下引用按照用户限流的规则，如下所示。

```go
location ^~ /seckill {
    limit_req zone=limit_by_user burst=1 nodelay;
    proxy_pass http://real_server;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```
