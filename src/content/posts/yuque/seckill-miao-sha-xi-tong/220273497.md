### **一、前言**

在前面整合Sleuth实现链路追踪时，我们是通过查看日志的情况来了解系统调用的链路情况，这并不是一种很好的解决方案，如果系统所包含的微服务越来越多，通过查看日志的方式来分析系统的调用是非常复杂的，在实际项目中根本不可行。

此时，我们可以将Sleuth和ZipKin进行整合，利用ZipKin将日志进行聚合，将链路日志进行可视化展示，并支持全文检索。

### **二、本章诉求**

整合Sleuth与Zipkin，实现链路追踪的可视化，利用ZipKin将日志进行聚合，将链路日志进行可视化展示，并支持全文检索。掌握Sleuth整合Zipkin的原理和实现方案，掌握Zipkin数据持久化的实现方案，并能够将其灵活应用到自身实际项目中。

### **三、ZipKin核心架构**

Zipkin 是 Twitter 的一个开源项目，它基于Google Dapper论文实现，可以收集微服务运行过程中的实时链路数据，并进行展示。

#### **3.1 ZipKin概述**

Zipkin是一种分布式链路跟踪系统，能够收集微服务运行过程中的实时调用链路信息，并能够将这些调用链路信息展示到Web界面上供开发人员分析，开发人员能够从ZipKin中分析出调用链路中的性能瓶颈，识别出存在问题的应用程序，进而定位问题和解决问题。

#### **3.2 ZipKin核心架构**

ZipKin的核心架构如图105-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/2656bbecc73502d55b6ebe0bcecd6cb4bf9ba533b3937278322ab98ed3bd1249.png)

注：图片来源：[https://zipkin.io/pages/architecture.html](https://zipkin.io/pages/architecture.html)

其中，ZipKin核心组件的功能如下所示。

1. Reporter：ZipKin中上报链路数据的模块，主要配置在具体的微服务应用中。

2. Transport：ZipKin中传输链路数据的模块，此模块可以配置为Kafka，RocketMQ、RabbitMQ等。

3. Collector：ZipKin中收集并消费链路数据的模块，默认是通过http协议收集，可以配置为Kafka消费。

4. Storage：ZipKin中存储链路数据的模块，此模块的具体可以配置为ElasticSearch、Cassandra或者MySQL，目前ZipKin支持这三种数据持久化方式。

5. API：ZipKin中的API 组件，主要用来提供外部访问接口。比如给客户端展示跟踪信息，或是开放给外部系统实现监控等。

6. UI： ZipKin中的UI 组件，基于API组件实现的上层应用。通过UI组件用户可以方便并且很直观地查询和分析跟踪信息。

Zipkin在总体上会分为两个端，一个是Zipkin服务端，一个是Zipkin客户端，客户端主要是配置在微服务应用中，收集微服务中的调用链路信息，将数据发送给ZipKin服务端。

### **四、整合ZipKin**

Zipkin总体上分为服务端和客户端，我们需要下载并启动ZipKin服务端的Jar包，在微服务中集成ZipKin的客户端。

#### **4.1 下载安装ZipKin服务端**

（1）下载ZipKin服务端Jar文件，可以直接在浏览器中输入如下链接进行下载。

```go
https://repo1.maven.org/maven2/io/zipkin/zipkin-server/
```

这里，我选择的是2.24.3版本，点进去下载[zipkin-server-2.24.3-exec.jar](http://zipkin-server-2.24.3-exec.jar)文件，整体下载链接如下所示。

```go
https://repo1.maven.org/maven2/io/zipkin/zipkin-server/2.24.3/zipkin-server-2.24.3-exec.jar
```

如果大家使用的是Linux操作系统，也可以在命令行输入如下命令进行下载。

```go
wget https://repo1.maven.org/maven2/io/zipkin/zipkin-server/2.24.3/zipkin-server-2.24.3-exec.jar
```

这里，我通过浏览器下载的ZipKin服务端Jar文件为：[zipkin-server-2.23.3-exec.jar](http://zipkin-server-2.23.3-exec.jar)。

（2）在命令行输入如下命令启动ZipKin服务端。

```go
java -jar zipkin-server-2.24.3-exec.jar
```

（3）由于ZipKin服务端启动时，默认监听的端口号为9411，所以，在浏览器中输入[http://localhost:9411链接就可以打开ZipKin的界面，如图105-2所示。](http://localhost:9411链接就可以打开ZipKin的界面，如图105-2所示。)

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/87215fdcabc9dc5de5fdc92a9451f43b6cee8562f222e6de2dd607e6fd6c1f96.png)

在浏览器中输入[http://localhost:9411链接能够打开上述页面就说明ZipKin服务端已经准备好啦。](http://localhost:9411链接能够打开上述页面就说明ZipKin服务端已经准备好啦。)

#### **4.2 整合ZipKin客户端**

（1）在秒杀系统的[pom.xml](http://pom.xml)文件中引入ZipKin依赖，如下所示。

```go
<zipkin.version>2.2.8.RELEASE</zipkin.version>

​
<dependency>
    <groupId>org.springframework.cloud</groupId>

    <artifactId>spring-cloud-starter-zipkin</artifactId>

    <version>${zipkin.version}</version>

</dependency>
```

去掉如下配置项。

```go
<dependency>
    <groupId>org.springframework.cloud</groupId>

    <artifactId>spring-cloud-starter-sleuth</artifactId>

</dependency>
```

（2）在网关服务微服务的Nacos配置中添加如下配置。

```go
# Sleuth && Zipkin
spring.sleuth.web.client.enabled=true
spring.sleuth.sampler.probability=1.0
spring.zipkin.enabled=true
spring.zipkin.base-url=http://127.0.0.1:9411
spring.zipkin.discoveryClientEnabled=false
spring.zipkin.sender.type=web
```

其中各配置的说明如下所示。

1. spring.sleuth.sampler.probability ：表示Sleuth的采样百分比。

2. spring.zipkin.base-url ：ZipKin服务端的地址。

3. spring.zipkin.discovery-client-enabled ：配置成false，使Nacos将其当成一个URL，不要按服务名处理。

（3）分别启动秒杀活动微服务、秒杀商品微服务和网关微服务，在Apixfox中访问保存秒杀商品的接口，如图105-3所示。
