### **一、前言**

在前面的文章中，我们对秒杀系统进行了各种优化措施，对于秒杀系统进行了由单体到微服务的架构升级和代码重构，使其能够承载更高的并发。对秒杀系统进行了异步化设计，进一步提升了整体的性能和吞吐量。

同时，为了进一步提升秒杀场景下商品库存和订单数据的高并发读写性能，对商品的库存数据进行了分库分表和分桶设计与实现，对订单数据进行了分库分表设计与实现。

### **二、本章诉求**

对秒杀系统的流量进行隔离，不要让秒杀系统的流量对其他业务产生影响，从业务、系统和数据三个维度分析秒杀系统的流量隔离策略，并能够在实际项目中灵活运用。

### **三、隔离总体概述**

秒杀商品与普通商品相比，最大的区别就是流量不同。秒杀商品的流量会瞬时上涨到峰值，而普通商品的流量则比较均衡。所以，对于普通商品来说，销量是越多越好，平台或者商家一般会准备充足的货源。而对于秒杀商品来说，库存就比较少了，大量用户在秒杀开始时，会去抢购少量的商品，瞬时流量很大。

秒杀商品的瞬时流量很大，普通商品流量比较均衡，如果将这两类的商品混合在一起进行交易，则秒杀商品的流量极有可能对普通商品的交易流程造成冲击，甚至导致普通商品无法正常交易的现象。所以，为了不让极少量的秒杀商品的流量影响到大多数普通商品的交易流程，需要单独搭建秒杀系统来承接秒杀流量，将秒杀商品流量与普通商品流量进行隔离。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/e4a367b13c6624714c090eb5a0005356f7ad5a03b14fe3efafbbd149f792158a.png)

隔离一般可以通过业务隔离、系统隔离和数据隔离三种策略进行落地实现，接下来，我们就一起讨论下这三种隔离策略。

### **四、业务隔离**

业务隔离，其实就是将秒杀的业务和其他业务进行隔离。从业务隔离的角度来说，运营人员或者商家想参与秒杀活动时，提前将参与秒杀活动的商品进行提报来隔离B端的业务。用户想参与秒杀活动时，提前预约自己想抢购的商品来隔离C端业务。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/1a2100eb4d3e6710e52ecba81572eb6af96b4567e76efa25c864b4a4ddbc47e0.png)

#### **4.1 隔离B端业务**

秒杀业务可以与其他业务进行隔离。其实秒杀业务发展到目前阶段，对于秒杀商品来说，由于它的特殊性和稀缺性，一般在投放秒杀商品时，会进行单独的提报。像天猫这种头部电商平台，会有专门的秒杀商品提报系统。如果平台的运营人员或者商家想参与秒杀活动，就需要根据自己的计划在提报系统里进行提报，想提报系统里输入参与秒杀活动的商品编号、秒杀的开始时间、秒杀的结束时间、秒杀商品的库存、限购策略、自定义风控规则、参与秒杀的用户级别、限购地区等等信息。

这样，平台就能够根据这些信息预估出大致的流量和并发量，再结合现有系统的一些资源，评估是否需要进行扩容，是否需要限流，使用何种降级和熔断策略等等。

#### **4.2 隔离C端业务**

如果想隔离C端的业务，则对于C端用户来说，可以在参与秒杀活动前，提前预约自己要抢购的商品。这样的话，平台可以根据每种参与秒杀活动商品的预约人数，也能够大致推算出当前秒杀活动的大致流量，也能够结合现有系统的资源，评估是否需要进行扩容，是否需要限流，使用何种降级和熔断策略等等。

所以说，业务隔离对于建设秒杀系统来说是非常重要的。

### **五、系统隔离**

系统隔离，其实就是要将秒杀系统与其他系统进行隔离，系统隔离也是要将就隔离策略的，要在系统稳定可靠与隔离成本之前进行权衡。

#### **5.1 系统隔离策略**

但是，如果将秒杀系统交易链路上涉及到的各个服务都进行物理隔离的话，势必会大大增加成本。试想，就头部电商平台秒杀系统交易链路上涉及到的各个服务而言，少则几十上百个，多则几百上千个，要是都进行物理隔离，重新部署一套的话，那成本是非常高的，也不太现实。所以，会采用物理隔离和逻辑隔离相结合的隔离策略。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/fc3e355ab9db6bf2bda6a20a77c7c48f44ef27087694d72c0bf98fea9a5c74f8.png)

对于流量冲击比较大的核心系统，一般可以采取隔离隔离的方式，将这些流量冲击比较大的核心系统单独部署。对于流量不是很大的交易链路末端的系统，就可以采用逻辑隔离的方式。

**这里，给大家分享一个经验，经过多年的实践和总结，一般头部电商平台在建设秒杀系统时，会隔离的系统有：秒杀商详页系统、秒杀结算页系统、购物车系统、订单系统。像交易链路末端的收银台系统、支付系统等流量比较可控，物理隔离的意义不大。**

#### **5.2 基础设施隔离**

在系统隔离层面上，除了要将秒杀系统本身进行隔离外，还需要对建设秒杀系统来说，使用的一些基础设施进行隔离。比如，对秒杀系统使用专门的域名进行隔离、对使用的负载均衡器（大厂一般会使用诸如Nginx、LVS和HAProxy这样的软件负载均衡器，别问我为什么，因为大厂业务体量高，集群规模大，使用F5这种硬件负载均衡成本太高，你懂得）进行隔离，对使用的网关进行隔离，对流量冲击比较大的核心系统使用单独的微服务集群，对分布式缓存进行单独部署。

也就是说，流量经过秒杀系统专有的域名流向秒杀系统，经过秒杀系统专有的负载均衡器将流量路由到秒杀系统的微服务集群。

#### **5.3 隔离案例**

由于我们自己搭建并研发的秒杀系统使用Dubbo注解的方式实现了微服务，Dubbo就可以以分组的形式来实现独立的微服务集群，实现方式也比较简单。假设使用Dubbo注解的形式实现了微服务，可以使用Dubbo注解中的group属性来实现微服务集群分组。

**1.定义商品Dubbo接口**

```go
public interface SeckillGoodsDubboService {
    SeckillGoodsDTO getSeckillGoods(Long id, Long version);
}
```

**2.普通商品微服务分组实现**

```go
@Component
@DubboService(version = "1.0.0", group = "product-center")
public class SeckillGoodsDubboServiceImpl implements SeckillGoodsDubboService {
    private final Logger logger = LoggerFactory.getLogger(SeckillGoodsDubboServiceImpl.class);
    @Autowired
    private SeckillGoodsService seckillGoodsService;
​
    @Override
    public SeckillGoodsDTO getSeckillGoods(Long id, Long version) {
        return seckillGoodsService.getSeckillGoods(id, version);
    }
}
```

**3.秒杀商品微服务分组实现**

```go
@Component
@DubboService(version = "1.0.0", group = "product-seckill")
public class SeckillGoodsDubboServiceImpl implements SeckillGoodsDubboService {
    private final Logger logger = LoggerFactory.getLogger(SeckillGoodsDubboServiceImpl.class);
    @Autowired
    private SeckillGoodsService seckillGoodsService;
​
    @Override
    public SeckillGoodsDTO getSeckillGoods(Long id, Long version) {
        return seckillGoodsService.getSeckillGoods(id, version);
    }
}
```

**注意：普通商品微服务和秒杀商品微服务肯定是不同的微服务实例，所以，代码不用改动，只需要修改注解的配置。**

对于商品的服务提供者实现了微服务集群分组，那如何调用秒杀商品的微服务集群呢？实现起来也比较简单。

**4.调用秒杀商品微服务分组**

### **六、数据隔离**

数据隔离其实就是需要将秒杀的商品数据与其他数据进行隔离，常用的方案就是对参与秒杀的商品进行打标，为其加上秒杀的标识。如果对商品打上秒杀的标识，我们就可以在秒杀的任何环节都可以将这些流量正确的路由到秒杀系统的专有微服务集群中。

其实，电商平台的商品系统设计远远比我们想象的要复杂，对于商品打标来说，也会有很多规则。但是我们可以简化理解，简单点理解商品打标，就是给商品添加一个特殊的标签。最简单的一种实现方式就是在商品信息中预留一个字段，标识商品是不是秒杀商品，或者设计一个中间表，标识下当前商品是哪场秒杀活动的秒杀商品。

亦或者设计一个long类型的字段来存储商品的各种标签属性，long类型是64位的，我们可以使用其中的某一位来标识当前商品是否是秒杀商品，在改变某一位的值是，就需要对其进行二进制操作了。使用long类型数据的某一位来标识商品的某个标签属性，这样一个字段就可以标识多个商品的属性，业务的扩展性也比较高。
