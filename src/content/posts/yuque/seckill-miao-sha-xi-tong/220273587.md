对于秒杀场景来说，首先需要存在秒杀活动，后续的秒杀商品都是关联到秒杀活动下的，也就是说，在秒杀系统中，用户抢购商品首先都是要选中特定的活动进行。所以，对于秒杀系统来说，第一个最核心的业务，也是第一个需要开发的业务就是秒杀活动。

### **一、前言**

秒杀活动从业务上来讲，分为C端和B端业务，C端业务就是面向用户端的秒杀活动抢购入口，B端业务主要是面向运营的活动管理系统。用户可以通过秒杀活动进入抢购商品，运营则可以通过秒杀活动来宣传和推广平台，并对具体的秒杀活动进行管理。

### **二、本章诉求**

从用户端和运营端两种不同的角度充分梳理清楚秒杀活动的业务流程，了解用户和运营分别可以在秒杀活动中做哪些事情，并对秒杀活动需要提供的接口进行简单的设计。

### **三、流程设计**

对秒杀活动而言，需要充分考虑秒杀活动使用的场景和人群，毫无疑问，用户在秒杀系统中抢购商品，需要从秒杀活动（无论是活动入口还是秒杀广告页）进入抢购活动下的商品。除此之外，还有一种角色的用户需要管理秒杀活动，那就是运营。所以，从业务流程上来说，秒杀活动的具体业务流程可以分成运营端业务流程和用户端业务流程。

#### **3.1 运营端流程设计**

可以想象一下，如果你是运营人员，你最想如何管理秒杀活动呢？接下来，就站在运营人员的角度来简单梳理下，秒杀活动需要为运营提供的功能。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/935be4b5ec529a2628e4ae0f220f7301a2aa9573fd363c05711dc778da4c54ae.png)

对于运营端来说，当运营人员登录系统后，可以查看秒杀活动列表、添加秒杀活动、上线秒杀活动、下线秒杀活动、针对特定的秒杀活动发布相应的秒杀商品、查看秒杀活动下的商品等等。如果活动下架后，对于运营来说，就只能查看下线活动下的商品，不能继续更新秒杀活动的状态，也不能针对秒杀活动来发布商品了。

#### **3.2 用户端流程设计**

相对于运营端来说，用户端针对秒杀活动的业务流程就比较简单了，用户端登录系统后可以查看上线的秒杀活动列表、并可以通过秒杀活动查看活动下发布的商品信息。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/5258a72ad664a3419b63eb606b74665f5c6175eec5db7dc7e8b50434628d54b4.png)

### **四、接口设计**

从运营端和用户端梳理完业务流程后，大概就知道在秒杀系统中，针对秒杀活动要提供哪些功能了，进而结合数据模型，就能够大概推测出秒杀活动要提供哪些接口，以及接口的参数和影响数据大概是什么样子了。

#### **4.1 总体接口设计**

对于秒杀活动来说，业务精简后总体上需要提供的接口有：保存秒杀活动、根据状态获取秒杀活动列表、根据时间和状态获取秒杀活动列表、获取秒杀活动详情以及更新秒杀活动状态。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/e91493dcd00594adc40c6e902becf0e3365a4272003e2b7a10ea6539a8b4e4c6.png)

其中，运营人员可以使用所有的接口来对秒杀活动进行全面的管理。对于用户来说，则只能访问获取秒杀活动列表和秒杀活动详情的接口，不能访问保存秒杀活动和更新秒杀活动状态的接口。

#### **4.2 保存秒杀活动**

保存秒杀活动的接口链接可以设计成类似http://{ip:port}/activity/saveSeckillActivity的形式，其中，{ip:port}可以根据实际情况进行替换。

接口参数类似如下所示。

```go
{
    "activityName": 活动名称,
    "startTime": 开始时间,
    "endTime": 结束时间,
    "activityDesc":活动描述
}
```

返回的结果数据类似如下所示。

```go
{
    "code":状态码,
    "data":提示信息
}
```

#### **4.3 根据状态获取秒杀活动列表**

根据状态获取秒杀活动列表的接口链接可以设计成类似http://{ip:port}/activity/getSeckillActivityList的形式，其中，{ip:port}可以根据实际情况进行替换。

接口参数类似如下所示。

```go
{
    "status": 状态
}
```

返回的结果数据类似如下所示。

```go
{
    "code":状态码,
    "data": [
              {
                  "id":活动id,
                  "activityName": 活动名称,
                  "startTime": 开始时间,
                  "endTime": 结束时间,
                  "status": 状态,
                  "activityDesc": 活动描述
              }
            ]
}
```

### **五、总结**

本章，主要从运营端和用户端分别梳理了秒杀活动的业务流程，其中，运营端主要是对秒杀活动进行全面的管理，而用户端则只能查看秒杀活动的信息。对于秒杀系统中的秒杀活动来说，业务精简后需要提供的接口包括：保存秒杀活动、根据状态获取秒杀活动列表、根据时间和状态获取秒杀活动列表、获取秒杀活动详情以及更新秒杀活动状态，并对这些接口简单的设计了接口的链接格式和数据交互格式。
