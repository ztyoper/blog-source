### **一、前言**

对于秒杀系统来说，用户端才是真正承接高并发、大流量的端口，对于用户端来说，追求的是极致的性能、稳定性和可靠性，业务流程要尽量简化，不要有过多的复杂逻辑，用户在商品页面，即可直接发起抢购操作。

### **二、本章诉求**

对于秒杀商品业务来说，用户端也会比运营端更加精简。用户端不会对秒杀商品进行更新操作，只会查看秒杀活动下的商品，并对符合条件的商品进行抢购下单。

当然，本章，只是先从商品角度简单实现符合抢购的逻辑，在后续不断的完善中，还会校验用户是否有资格抢购相应的商品。

### **三、用户端流程设计**

用户在登录秒杀系统后，能够通过秒杀活动查看秒杀商品，并对符合条件的商品进行抢购，简化后的流程如图20-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/8df26e28d0ebde20aa6d483d1f71971f1db5e98ef57c8b9c80a74d37c9cb27f1.png)

可以看到，用户在抢购商品时，会对秒杀商品和秒杀活动的状态进行校验，流程如下所示。

（1）用户进入商品页面，如果商品为已发布状态，则抢购按钮置灰，不可点击，否则进入下一步。

（2）如果商品为下线状态，则抢购按钮置灰，不可点击，否则进入下一步。

（3）如果秒杀活动未开始，则提示秒杀活动未开始不能抢购，否则进入下一步。

（4）如果秒杀活动已结束，则提示秒杀活动已结束不能抢购，否则进入下一步。

（5）提交抢购的商品信息，跳转到商品下单页面。

**注意：只是站在商品的角度检验了是否符合抢购条件，在后续不断的完善中，还会实现校验用户是否具备资格进行抢购。**

**（2）填充秒杀活动**

使用JS调用后端获取秒杀商品列表的接口，并将获取到的数据填充到页面，核心代码如下所示。

```go
// 定义全局活动数组信息
var g_goodsList = [];
​
jQuery(document).ready(function () {
    var activityId = getParameterByName("activityId");
    $.ajax({
        type:"GET",
        headers:{
            "access-token": get(common_localstorage_key)
        },
        url:"http://"+g_host+"/goods/getSeckillGoodsByActivityId?activityId=" + activityId,
        xhrFields: {withCredentials: true},
        success:function (data) {
            if (data.code == 1001) {
                g_goodsList = data.data;
                reloadDom();
            }else if (data.code == 2012){
                alert("请登录后操作");
                window.location.href = "login.html";
            }
​
            else {
                alert("获取活动信息失败");
            }
        },
        error:function (data) {
            alert("获取活动信息失败");
        }
    })
})
```

用户端向页面填充秒杀商品的逻辑基本与运营端一致，首先定义了一个g_goodsList全局数组，在页面加载时获取秒杀活动列表。这里使用的是Ajax来获取秒杀活动列表，会将登录时获取到的Token放到请求头中一起发送给后端接口。如果后端返回的状态码为1001，说明正确执行了业务逻辑，此时将后端返回的data字段数据赋值给全局数组g_goodsList，并调用reloadDom()方法重载页面的Dom元素。

reloadDom()方法的源码如下所示。

```go
function reloadDom() {
    for (var i = 0; i < g_goodsList.length; i ++){
        var itemVO = g_goodsList[i];
        var dom = "<tr id='goodsDetail"+ itemVO.id +"'>" +
            "<td><img style='width: 100px;height: auto' src='"+ getImageUrl(itemVO.imgUrl) +"'></td>" +
            "<td>"+ itemVO.id +"</td>" +
            "<td>"+ itemVO.goodsName +"</td>" +
            "<td>"+ itemVO.activityId +"</td>" +
            "<td>"+ itemVO.startTime +"</td>" +
            "<td>"+ itemVO.endTime +"</td>" +
            "<td>"+ itemVO.originalPrice +"</td>" +
            "<td>"+ itemVO.activityPrice +"</td>" +
            "<td>"+ itemVO.initialStock +"</td>" +
            "<td>"+ itemVO.availableStock +"</td>" +
            "<td>"+ itemVO.limitNum +"</td>" +
            "<td>"+ itemVO.description +"</td>" +
            "<td>"+ getStatus(itemVO.status) +"</td>" +
            "<td>" + showButton(itemVO) + "</td>" +
            "</tr>";
        $("#container").append($(dom));
    }
}
```

可以看到，在reloadDom()方法中，核心逻辑就是遍历g_goodsList数组来填充id为container的HTML元素。

在reloadDom()方法中，会调用getStatus()方法来根据后端返回的不同状态来显示不同的状态文本信息，如下所示。

```go
function getStatus(status){
    if (status == 0){
        return "已发布";
    }else if (status == 1){
        return "上线";
    }else if (status == -1){
        return "下线";
    }
}
```

可以看到，状态值为0对应已发布，状态值为1对应上线，状态值为-1对应下线。

在reloadDom()方法中，也会调用showButton()方法来根据不同的状态展示不同的按钮。showButton()方法的源码如下所示。

```go
function showButton(itemVO){
    var innerHtml = "";
    if (itemVO.status == 1){
        innerHtml += "<input type='button' data-id='"+ itemVO.id +"' " +
            "data-start-time='"+ itemVO.startTime +"' " +
            "data-end-time='"+ itemVO.endTime +"' value='抢购' onclick='submitGoods(this)'/>"
    }else{
        innerHtml += "<input disabled='disabled' type='button' data-id='"+ itemVO.id +"' " +
            "data-start-time='"+ itemVO.startTime +"' " +
            "data-end-time='"+ itemVO.endTime +"' value='抢购' onclick='submitGoods(this)'/>"
    }
    return innerHtml;
}
```

可以看到，在showButton()方法中，如果商品状态为已上线，则抢购按钮可以正常点击，否则，抢购按钮会被置灰，不能点击。

另外，如果抢购按钮可以正常点击，则会调用submitGoods()方法，submitGoods()方法的源码如下所示。

可以看到，在submitGoods()方法中，会对秒杀活动的时间进行校验，如果当前时间早于秒杀开始时间，则提示秒杀活动还未开始，不能抢购。如果当前时间晚于秒杀结束时间，则提示秒杀活动已经结束，不能抢购。由于目前还未开发秒杀下单页面，所以这里只是简单的弹框提示跳转到下单页面，后续再完善。
