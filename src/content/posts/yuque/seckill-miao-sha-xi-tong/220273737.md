下单扣减商品库存在业务上是非常简单的，但是这种简单的业务放到秒杀系统这种超大流量的并发场景，就显得不是那么容易了，一不小心，就可能会出现商品超卖的问题，一旦出现商品超卖，那么后果就是非常严重的了。

### **一、前言**

在前面的文章中，我们分析了秒杀系统扣减库存一般采用下单减库存的方式。用户选择商品进行下单时，秒杀系统会扣除用户下单时设置的要购买的商品数量，这看似简单的业务，在高并发大流量的秒杀系统中，如果不经过精心的设计，可能就会造成用户实际下单购买的商品数量远远大于商品参加秒杀活动的实际库存数量，出现库存超卖问题。

### **二、本章诉求**

用户下单时，可以借助数据库来解决商品的防超卖问题，在更新数据库中的商品库存时，为更新数据的SQL语句再添加一个条件：只有当前商品的剩余库存大于或者等于用户下单的商品数量时，才会扣减库存，否则，直接提示库存不足，以此来实现防止商品的超卖问题。

**在具体的实现过程中，使用一个小技巧，而不是将判断商品的剩余库存是否大于或者等于用户下单的商品数量和扣减商品库存在业务上分成两个步骤执行。如果将判断商品的剩余库存是否大于或者等于用户下单的商品数量和扣减商品库存在业务上分成两个步骤执行，仅仅依靠数据库的话，大概率还是会出现商品超卖的问题。**

那这个小技巧是啥呢？本章，就基于数据库设计并实现库存防超卖的落地方案。

基于数据库实现库存防超卖的流程如下所示。

（1）用户抢购下单开始，查询商品信息。

（2）如果商品为空，则提示当前商品不存在并结束流程，否则执行第（3）步。

（3）如果商品未上线，则提示当前商品未上线并结束流程，否则执行第（4）步。

（4）如果商品已下架，则提示当前商品已下架并结束流程，否则执行第（5）步。

### **四、编码实现**

基于数据库实现库存防超卖的下单减库存逻辑的实现步骤如下所示。

**（1）新增SeckillPlaceOrderService接口**

SeckillPlaceOrderService接口的源码详见：seckill-application工程下的[io.binghe.seckill.application.order.place.SeckillPlaceOrderService](http://io.binghe.seckill.application.order.place.SeckillPlaceOrderService)。

```go
public interface SeckillPlaceOrderService {
  /**
* 下单操作
*/
  Long placeOrder(Long userId, SeckillOrderCommand seckillOrderCommand);
  /**
* 构建订单
*/
  default SeckillOrder buildSeckillOrder(Long userId, SeckillOrderCommand seckillOrderCommand, SeckillGoodsDTO seckillGoods){
    SeckillOrder seckillOrder = new SeckillOrder();
    BeanUtil.copyProperties(seckillOrderCommand, seckillOrder);
    seckillOrder.setId(SnowFlakeFactory.getSnowFlakeFromCache().nextId());
    seckillOrder.setGoodsName(seckillGoods.getGoodsName());
    seckillOrder.setUserId(userId);
    seckillOrder.setActivityPrice(seckillGoods.getActivityPrice());
    BigDecimal orderPrice = seckillGoods.getActivityPrice().multiply(BigDecimal.valueOf(seckillOrder.getQuantity()));
    seckillOrder.setOrderPrice(orderPrice);
    seckillOrder.setStatus(SeckillOrderStatus.CREATED.getCode());
    seckillOrder.setCreateTime(new Date());
    return seckillOrder;
   }
​
  /**
* 检测商品信息
*/
  default void checkSeckillGoods(SeckillOrderCommand seckillOrderCommand, SeckillGoodsDTO seckillGoods){
    //商品不存在
    if (seckillGoods == null){
      throw new SeckillException(HttpCode.GOODS_NOT_EXISTS);
     }
    //商品未上线
    if (seckillGoods.getStatus() == SeckillGoodsStatus.PUBLISHED.getCode()){
      throw new SeckillException(HttpCode.GOODS_PUBLISH);
     }
    //商品已下架
    if (seckillGoods.getStatus() == SeckillGoodsStatus.OFFLINE.getCode()){
      throw new SeckillException(HttpCode.GOODS_OFFLINE);
     }
    //触发限购
    if (seckillGoods.getLimitNum() < seckillOrderCommand.getQuantity()){
      throw new SeckillException(HttpCode.BEYOND_LIMIT_NUM);
     }
    // 库存不足
    if (seckillGoods.getAvailableStock() == null || seckillGoods.getAvailableStock() <= 0 || seckillOrderCommand.getQuantity() > seckillGoods.getAvailableStock()){
      throw new SeckillException(HttpCode.STOCK_LT_ZERO);
     }
   }
}
```

可以看到，在SeckillPlaceOrderService接口中定义了统一的下单接口placeOrder()方法，并提供了构建订单的buildSeckillOrder()默认方法，在buildSeckillOrder()方法中会根据用户的下单信息和商品信息构建订单对象并返回。另外，在SeckillPlaceOrderService接口中还提供了一个检测商品信息的checkSeckillGoods()方法，在checkSeckillGoods()方法中，对下单时，是否触发了异常情况进行检测。

**（2）新增SeckillPlaceOrderDbService类**

SeckillPlaceOrderDbService类的源码详见：seckill-application工程下的[io.binghe.seckill.application.order.place.impl.SeckillPlaceOrderDbService](http://io.binghe.seckill.application.order.place.impl.SeckillPlaceOrderDbService)。

```go
@Service
@ConditionalOnProperty(name = "place.order.type", havingValue = "db")
public class SeckillPlaceOrderDbService implements SeckillPlaceOrderService {
  @Autowired
  private SeckillGoodsService seckillGoodsService;
  @Autowired
  private SeckillOrderDomainService seckillOrderDomainService;
​
  @Override
  public Long placeOrder(Long userId, SeckillOrderCommand seckillOrderCommand) {
    //获取商品
    SeckillGoodsDTO seckillGoods = seckillGoodsService.getSeckillGoods(seckillOrderCommand.getGoodsId(), seckillOrderCommand.getVersion());
    //检测商品信息
    this.checkSeckillGoods(seckillOrderCommand, seckillGoods);
    //扣减库存不成功，则库存不足
    if (!seckillGoodsService.updateDbAvailableStock(seckillOrderCommand.getQuantity(), seckillOrderCommand.getGoodsId())){
      throw new SeckillException(HttpCode.STOCK_LT_ZERO);
     }
    //构建订单
    SeckillOrder seckillOrder = this.buildSeckillOrder(userId, seckillOrderCommand, seckillGoods);
    //保存订单
    seckillOrderDomainService.saveSeckillOrder(seckillOrder);
    return seckillOrder.getId();
   }
}
```

SeckillPlaceOrderDbService类是基于数据库实现库存防超卖的下单减库存的实现类，实现了SeckillPlaceOrderService接口，并重点实现了SeckillPlaceOrderService接口的placeOrder()方法，并在实现的placeOrder()方法中，会调用SeckillPlaceOrderService接口的checkSeckillGoods()默认方法来检测商品信息，调用SeckillPlaceOrderService接口的buildSeckillOrder()方法来构建订单信息，最终调用seckillOrderDomainService对象的saveSeckillOrder()方法保存订单数据，并返回订单id。

**这里，值得注意的是：在SeckillPlaceOrderDbService类上使用了@ConditionalOnProperty注解指定了name属性的值为**[place.order.type](http://place.order.type)**，havingValue属性的值为db，也就是在SpringBoot的启动配置文件中，当配置的**[place.order.type](http://place.order.type)**的值为db时，SpringBoot会加载并实例化SeckillPlaceOrderDbService类的对象，最终在用户下单时，完成基于数据库实现库存防超卖的下单减库存的逻辑。**

**（3）修改SeckillOrderServiceImpl类**

SeckillOrderServiceImpl类的源码详见：seckill-application工程下的[io.binghe.seckill.application.service.impl.SeckillOrderServiceImpl](http://io.binghe.seckill.application.service.impl.SeckillOrderServiceImpl)。

主要是修改SeckillOrderServiceImpl类中对于saveSeckillOrder()方法的实现，如下所示。

```go
@Override
@Transactional(rollbackFor = Exception.class)
public Long saveSeckillOrder(Long userId, SeckillOrderCommand seckillOrderCommand) {
  if (seckillOrderCommand == null){
    throw new SeckillException(HttpCode.PARAMS_INVALID);
   }
  return seckillPlaceOrderService.placeOrder(userId, seckillOrderCommand);
}
```

可以看到，在saveSeckillOrder()方法中首先判断传递的seckillOrderCommand对象是否为空，如果为空，则参数异常，否则直接调用seckillPlaceOrderService对象的placeOrder()方法进行下单扣减库存逻辑。

**注意：这里新增的配置项与在SeckillPlaceOrderDbService类上使用@ConditionalOnProperty注解新增的配置项对应。**

**（5）修改**[SeckillGoodsMapper.xml](http://SeckillGoodsMapper.xml)**文件**

[SeckillGoodsMapper.xml](http://SeckillGoodsMapper.xml)文件的源码详见：seckill-infrastructure工程下的src/main/resources/io/binghe/seckill/infrastructure/mapper/[SeckillGoodsMapper.xml](http://SeckillGoodsMapper.xml)。

修改[SeckillGoodsMapper.xml](http://SeckillGoodsMapper.xml)文件可以算的上是点睛之笔，主要是修改[SeckillGoodsMapper.xml](http://SeckillGoodsMapper.xml)文件中id为updateAvailableStock的扣减商品库存的SQL语句，修改前的SQL语句如下所示。

```go
<update id="updateAvailableStock">
     update seckill_goods set available_stock = available_stock - #{count} where id = #{id}
  </update>
```

修改后的SQL语句如下所示。

```go
<update id="updateAvailableStock">
   update seckill_goods set available_stock = available_stock - #{count} where id = #{id} and available_stock >= #{count}
</update>
```
