### **一、前言**

在前面的文章中，我们基于QPS实现了单机API限流，可以作为分布式限流的补充和兜底措施。在实现单机限流时，不仅仅只有基于QPS的单机API限流，还可以扩展出许多单机限流模式，例如，可以基于线程池实现单机并发数限流。

### **二、本章诉求**

基于线程池实现单机并发数限流，一旦单机并发数超过一定的阈值（这个阈值通常是线程池最大并发数+队列长度），则根据对应的拒绝策略来达到限流的目的。

### **三、线程池核心流程**

向线程池中提交任务时，线程池会根据具体情况以某种流程执行当前任务，本节，就简单介绍下线程池执行任务的核心流程。

#### **3.1 执行任务的流程**

ThreadPoolExecutor是Java线程池中最核心的类之一，它能够保证线程池按照正常的业务逻辑执行任务，并通过原子方式更新线程池每个阶段的状态。

ThreadPoolExecutor类中存在一个workers工作线程集合，用户可以向线程池中添加需要执行的任务，workers集合中的工作线程可以直接执行任务，或者从任务队列中获取任务后执行。ThreadPoolExecutor类中提供了整个线程池从创建到执行任务，再到消亡的整个流程方法。

线程池执行任务的核心流程可以简化成如图84-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/a15ac53edaee7e33e093376fb7095ac074e95b4e1172a95980feafb185cd4d27.png)

由图84-1可以看出，当向线程池中提交任务时，线程池执行任务的流程如下所示。

（1）向线程池提交任务时，首先会判断线程池中的线程数是否已经达到corePoolSize，如果线程池中的线程数未达到corePoolSize，则直接创建新线程执行任务。否则，进入步骤（2）。

（2）判断线程池中的工作队列是否已满，如果线程池中的工作队列未满，则将任务添加到队列中等待执行。否则，进入步骤（3）。

（3）判断线程池中的线程数是否已经达到maximumPoolSize，如果线程池中的线程数未达到maximumPoolSize，则直接创建新线程执行任务。否则，进入步骤（4）。

（4）执行拒绝策略，在执行拒绝策略时，即可实现基于线程池的并发数限流。

#### **3.2 拒绝策略**

如果线程池中的workQueue阻塞队列满了，同时，线程池中的线程数已达到maximumPoolSize，并且没有空闲的线程，此时继续向线程池提交任务，就需要采取某种策略来拒绝任务的执行。

在ThreadPoolExecutor类的execute()方法中，会在适当的时候调用reject(command)方法来执行拒绝策略。在在ThreadPoolExecutor类中，reject(command)方法的实现如下所示。

```go
final void reject(Runnable command) {
     handler.rejectedExecution(command, this);
}
```

在reject(command)方法中调用了handler的rejectedExecution()方法。这里，在ThreadPoolExecutor类中声明了handler变量，如下所示。

```go
private volatile RejectedExecutionHandler handler;
```

接下来，查看RejectedExecutionHandler的源码，如下所示。

```go
public interface RejectedExecutionHandler {
    void rejectedExecution(Runnable r, ThreadPoolExecutor executor);
}
```

可以看到RejectedExecutionHandler是一个接口，其中定义了一个rejectedExecution()方法。在JDK中，默认有四个类实现了RejectedExecutionHandler接口，分别为：AbortPolicy、CallerRunsPolicy、DiscardOldestPolicy和DiscardPolicy。这四个类也正是线程池中默认提供的四种拒绝策略的实现类。

至于reject(Runnable)方法中具体会执行哪个类的拒绝策略，是根据创建线程池时传递的参数决定的。如果没有传递拒绝策略的参数，则默认会执行AbortPolicy类的拒绝策略。否则会执行传递的类的拒绝策略。

在创建线程池时，除了能够传递JDK默认提供的拒绝策略外，还可以传递自定义的拒绝策略。如果想使用自定义的拒绝策略，则只需要实现RejectedExecutionHandler接口，并重写rejectedExecution(Runnable, ThreadPoolExecutor)方法即可。例如，下面的代码所示。

```go
public class MyPolicy implements RejectedExecutionHandler {
    @Override
    public void rejectedExecution(Runnable r, ThreadPoolExecutor e) {
        if (!e.isShutdown()) {
            r.run();
        }
    }
}
```

完成自定义拒绝策略后，使用如下方式创建线程池。

```go
new ThreadPoolExecutor(0, 100,
            60L, TimeUnit.SECONDS,
            new SynchronousQueue<Runnable>(),
            Executors.defaultThreadFactory(),
            new MyPolicy());
```

#### **4.2 新增ConcurrentRateLimiterPolicy类**

ConcurrentRateLimiterPolicy类是自定义的线程池拒绝策略类，在基于线程池实现单机并发数限流时，当任务队列满，同时线程池中的线程个数达到最大线程数时，会触发拒绝策略，此时，我们使用自定义的ConcurrentRateLimiterPolicy拒绝策略类，抛出稍后重试的异常。

ConcurrentRateLimiterPolicy类的源码详见：seckill-ratelimiter工程下的[io.binghe.seckill.ratelimiter.concurrent.policy.ConcurrentRateLimiterPolicy](http://io.binghe.seckill.ratelimiter.concurrent.policy.ConcurrentRateLimiterPolicy)。

```go
public class ConcurrentRateLimiterPolicy implements RejectedExecutionHandler {
    @Override
    public void rejectedExecution(Runnable r, ThreadPoolExecutor executor) {
        throw new SeckillException(ErrorCode.RETRY_LATER);
    }
}
```

#### **4.3 新增BHConcurrentRateLimiter类**

BHConcurrentRateLimiter类是对自定义线程池的封装类，内部封装了自定义线程池，获取线程池任务返回结果的超时时间和时间单位。

BHConcurrentRateLimiter类的源码详见：seckill-ratelimiter工程下的[io.binghe.seckill.ratelimiter.concurrent.bean.BHConcurrentRateLimiter](http://io.binghe.seckill.ratelimiter.concurrent.bean.BHConcurrentRateLimiter)。

```go

    private long timeout;
    //超时时间单位
    private TimeUnit timeoutUnit;
​
    public BHConcurrentRateLimiter() {
    }
​
    public BHConcurrentRateLimiter(ThreadPoolExecutor executor, long timeout, TimeUnit timeoutUnit) {

    /**************省略setter/getter方法************/
​
    public <T> T submit(Callable<T> task){

            return executor.submit(task).get();
        } catch (Exception e) {
            if (e instanceof SeckillException){
```

#### **4.4 新增ConcurrentRateLimiterInterceptor类**

ConcurrentRateLimiterInterceptor类是实现单机并发数限流的核心类，实现了单机并发数限流的核心逻辑。

**（1）定义成员变量和常量**

在ConcurrentRateLimiterInterceptor类中，定义的成员变量和常量，如下所示。

```go
private static final Map<String, BHConcurrentRateLimiter> BH_CONCURRENT_RATE_LIMITER_MAP = new ConcurrentHashMap<>();
```

其中，每个成员变量和常量的含义如下所示。

1. BH _ CONCURRENT _ RATE _ LIMITER _ MAP：ConcurrentHashMap类型的集合，存储已经创建的线程池，将已经创建的线程池根据名称进行分类存储，只要名称相同，则使用同一个线程池进行并发数限流。

2. environment：Environment类型的Spring上下文环境，通过environment对象的resolvePlaceholders方法，对@ConcurrentRateLimiter注解中的name属性的值进行处理。

3. defaultCorePoolSize：int类型的成员变量，表示默认的线程池核心线程数量，这个值通过SpringBoot的配置文件指定，默认值为3。

4. defaultMaximumPoolSize：int类型的成员变量，表示默认的线程池最大线程数量，这个值通过SpringBoot的配置文件指定，默认值为5。

5. defaultQueueCapacity：int类型的成员变量，表示默认的任务队列大小，这个值通过SpringBoot的配置文件指定，默认值为10。

6. defaultKeepAliveTime：long类型的成员变量，表示默认的线程空闲时间，这个值通过SpringBoot的配置文件指定，默认值为30。

7. defaultTimeOut：long类型的成员变量，表示从线程池获取执行任务的结果的超时时间，这个值通过SpringBoot的配置文件指定，默认值为1。

**（3）定义环绕通知方法**

在ConcurrentRateLimiterInterceptor类中，创建around()环绕通知方法，如下所示。

```go
@Around(value = "pointCut(concurrentRateLimiter)")
public Object around(ProceedingJoinPoint pjp, ConcurrentRateLimiter concurrentRateLimiter) throws Throwable {
    MethodSignature signature = (MethodSignature) pjp.getSignature();
    String className = pjp.getTarget().getClass().getSimpleName();
    String methodName = signature.getName();
    String rateLimitName = environment.resolvePlaceholders(concurrentRateLimiter.name());
    if (StrUtil.isEmpty(rateLimitName) || rateLimitName.contains("${")) {
        rateLimitName = className + "-" + methodName;
    }
    BHConcurrentRateLimiter rateLimiter = this.getRateLimiter(rateLimitName, concurrentRateLimiter);
    Object[] args = pjp.getArgs();
    //基于自定义线程池实现并发数限流
    return rateLimiter.submit(() -> {
        try {
            return pjp.proceed(args);
        } catch (Throwable e) {
            if (e instanceof SeckillException){
                throw (SeckillException) e;
            }
            throw new RuntimeException(e);
        }
    });
}
```

可以看到，在around()环绕通知方法中，最主要的就是通过getRateLimiter()方法获取自定义的线程池封装类对象rateLimiter，然后调用rateLimiter对象的submit()方法向线程池提交任务，并获取任务的返回结果。

**（4）定义获取限流器的方法**

在ConcurrentRateLimiterInterceptor类中，创建getRateLimiter()方法，如下所示。

```go
private BHConcurrentRateLimiter getRateLimiter(String rateLimitName, ConcurrentRateLimiter concurrentRateLimiter) {
    //先从Map缓存中获取
    BHConcurrentRateLimiter bhRateLimiter = BH_CONCURRENT_RATE_LIMITER_MAP.get(rateLimitName);
    //如果获取的bhRateLimiter为空，则创建bhRateLimiter，注意并发，创建的时候需要加锁
    if (bhRateLimiter == null){
        final String finalRateLimitName = rateLimitName.intern();
        synchronized (finalRateLimitName){
            //double check
            bhRateLimiter = BH_CONCURRENT_RATE_LIMITER_MAP.get(rateLimitName);
            //获取的bhRateLimiter再次为空
            if (bhRateLimiter == null){
                int corePoolSize = concurrentRateLimiter.corePoolSize() <= 0 ? defaultCorePoolSize : concurrentRateLimiter.corePoolSize();
                int maximumPoolSize = concurrentRateLimiter.maximumPoolSize() <= 0 ? defaultMaximumPoolSize : concurrentRateLimiter.maximumPoolSize();
                int queueCapacity = concurrentRateLimiter.queueCapacity() <= 0 ? defaultQueueCapacity : concurrentRateLimiter.queueCapacity();
​
                long keepAliveTime = concurrentRateLimiter.keepAliveTime() <= 0 ? defaultKeepAliveTime : concurrentRateLimiter.keepAliveTime();
                TimeUnit keepAliveTimeUnit = concurrentRateLimiter.keepAliveTimeUnit();
​
                long timeout = concurrentRateLimiter.timeout() <= 0 ? defaultTimeOut : concurrentRateLimiter.timeout();
                TimeUnit timeoutUnit = concurrentRateLimiter.timeoutUnit();
​
                ThreadPoolExecutor executor = new ThreadPoolExecutor(corePoolSize, maximumPoolSize, keepAliveTime, keepAliveTimeUnit, new ArrayBlockingQueue<>(queueCapacity), (r) -> new Thread(r, "rate-limiter-threadPool-".concat(rateLimitName).concat("-")) , new ConcurrentRateLimiterPolicy());
                bhRateLimiter = new BHConcurrentRateLimiter(executor, timeout, timeoutUnit);
                BH_CONCURRENT_RATE_LIMITER_MAP.putIfAbsent(rateLimitName, bhRateLimiter);
            }
        }
    }
    return bhRateLimiter;
}
```

可以看到，在getRateLimiter()方法中，首先会从BH_CONCURRENT_RATE_LIMITER_MAP中获取限流器对象bhRateLimiter，如果获取的bhRateLimiter对象不为空，则直接返回bhRateLimiter对象。

如果获取的bhRateLimiter对象为空，则获取synchronized锁，如果获取锁成功，则再次从BH_CONCURRENT_RATE_LIMITER_MAP中获取bhRateLimiter对象。如果获取的bhRateLimiter对象不为空，则直接返回bhRateLimiter对象。

如果获取的bhRateLimiter对象为空，则解析@ConcurrentRateLimiter注解的属性，如果@ConcurrentRateLimiter注解的属性值大于0，则优先获取@ConcurrentRateLimiter注解的属性值，否则获取配置的默认值。

将解析出的参数和自定义的拒绝策略对象传入ThreadPoolExecutor的构造方法，创建自定义线程池，随后将自定义的线程池，以及超时时间和超时时间单位封装到bhRateLimiter限流器对象中。接下来，将bhRateLimiter限流器对象存储到BH_CONCURRENT_RATE_LIMITER_MAP中。最终返回bhRateLimiter限流器对象。

**（6）实现DisposableBean接口的方法**

由于ConcurrentRateLimiterInterceptor类实现了DisposableBean接口，所以，ConcurrentRateLimiterInterceptor类需要实现DisposableBean接口的destroy()方法。主要是在bean销毁之前执行关闭线程池和清理BH_CONCURRENT_RATE_LIMITER_MAP中数据的逻辑，如下所示。

```go
@Override
public void destroy() throws Exception {
    //关闭线程池
    logger.info("destroy|关闭线程池");
    Map<String, BHConcurrentRateLimiter> map = BH_CONCURRENT_RATE_LIMITER_MAP;
    if (map.size() > 0){
        for (Map.Entry<String, BHConcurrentRateLimiter> entry : map.entrySet()){
            BHConcurrentRateLimiter rateLimiter = entry.getValue();
            rateLimiter.shutdown();
        }
        map.clear();
        BH_CONCURRENT_RATE_LIMITER_MAP.clear();
    }
}
```
