### **一、前言**

随着互联网的不断发展和技术的更新迭代，系统的架构模式由最初的单体应用架构，一直发展到如今的微服务与云原生架构，而项目的部署结构也随着系统架构模式的不断演进而发生了翻天覆地的变化。

由最初在单台服务器上运维单个服务实例，到如今大规模集群运维和容器化部署，从最初一行行敲命令到如今可视化运维，都在预示着技术的进步和解放运维重复而繁琐的工作。

### **二、本章诉求**

对秒杀系统的容器化集群部署进行落地实现，在实际部署的过程中体验大规模容器化集群部署为企业带来的遍历，掌握大规模容器化集群部署的架构方案和落地实现，结合自身实际项目思考如何能够将容器化架构设计与落地方案运用到自身实际项目中。

### **四、部署秒杀系统**

我们实现的秒杀系统，总体上分为了七个微服务，分别为用户微服务、网关微服务、秒杀活动微服务、秒杀商品微服务、库存微服务、预约微服务、秒杀订单微服务，这些微服务都要通过容器化集群的方式进行部署。

#### **4.1 构建微服务镜像**

对于秒杀系统中的每个微服务来说，都需要将其构建成微服务镜像，最终在容器中运行。

**（1）修改配置IP并打包**

由于我们部署中间件集群和秒杀系统集群的宿主机IP地址为192.168.184.102，所以，在构建微服务镜像之前，我们需要将每个微服务下的bootstrap.properties文件中，连接Nacos的IP地址由127.0.0.1修改成192.168.184.102。随后，将各个微服务打包成Jar文件。

**（2）编写Dockerfile文件**

以用户微服务为例，编写用户微服务的Dockerfile文件，如下所示。

```go
FROM kdvolder/jdk8
VOLUME /tmp
ADD ./seckill-user-starter-1.0.0-SNAPSHOT.jar app.jar
RUN sh -c 'touch /app.jar'
ENV JAVA_OPTS=""
ENTRYPOINT [ "sh", "-c", "java $JAVA_OPTS -Djava.security.egd=file:/dev/./urandom -jar /app.jar" ]
```

其他微服务的Dockerfile文件与用户微服务基本相同，只是将用户微服务打出来的Jar包名称换成其他微服务打包成的Jar文件即可。

**（3）构建镜像**

将用户微服务打包出来的[seckill-user-starter-1.0.0-SNAPSHOT.jar](http://seckill-user-starter-1.0.0-SNAPSHOT.jar)文件和Dockerfile文件一起上传到服务器上，并执行如下命令构建用户微服务。

```go
docker build -t seckill-user .
```

构建其他微服务的镜像与构建用户微服务的镜像基本相同，只是构建其他微服务镜像时，命令中填写其他微服务的服务名称即可。
