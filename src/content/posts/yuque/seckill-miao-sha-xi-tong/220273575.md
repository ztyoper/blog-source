### **一、前言**

阅读过《[深入理解高并发编程：核心原理与案例实战](https://binghe.gitcode.host/md/knowledge/book/2022-06-17-%E6%B7%B1%E5%85%A5%E7%90%86%E8%A7%A3%E9%AB%98%E5%B9%B6%E5%8F%91%E7%BC%96%E7%A8%8B.html)》一书的小伙伴，肯定都知道，这本书里最后一章深度剖析了秒杀系统的架构设计，并且有一小节叫做缓存穿透技术，这里的缓存穿透技术只的并不是出现了缓存问题，而是流量网关将清求透传到分布式缓存查询数据。

如果缓存中存在要获取的数据，则直接返回，不再请求后端服务。同样的，在秒杀下单时，流量网关将请求透传到分布式缓存获取数据，在流量网关层校验各种下单条件，如果未通过下单校验，则直接返回对应的提示结果，不再请求后端服务。这样会极大的提升秒杀系统的性能。

### **二、本章诉求**

要知道，对于像OpenResty实现的流量网关和Redis实现的分布式缓存来说，其性能远远高于后端服务，如果请求到达OpenResty流量网关，由OpenResty流量网关读取Redis分布式缓存数据后，不再请求后端服务，会极大的提升秒杀系统的性能。

所以，本章从秒杀系统的流程进行优化，将到达OpenResty流量网关的请求透传到分布式缓存读取数据。如果是查询数据，分布式缓存中存在对应的数据，则不再请求后端服务。如果是秒杀下单，则从分布式缓存中获取到数据后，进行校验，校验不通过直接返回结果，不再请求后端服务。

重点掌握流量网关直接透传读取分布式缓存的架构设计和落地方案，并能够结合自身实际项目思考，将流量网关直接透传读取分布式缓存的架构设计和落地方案灵活应用到自身实际项目中。

### **三、秒杀系统流程**

OpenResty流量网关没有直接读取Redis分布式缓存之前，秒杀系统的执行流程如图124-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/564c63ed1d8d40b89aa6ae4850a6e704a5e922e654c2794341420baa9eb1e4a3.png)

可以看到，OpenResty流量网关没有直接读取Redis分布式缓存之前，秒杀系统的总体执行流程是：客户端（H5、小程序、APP）—&gt;DNS—&gt;OpenResty流量网关—&gt;系统网关—&gt;Web服务—&gt;基础服务—&gt;数据存储。

OpenResty透传读取Redis数据时，秒杀系统的执行流程如图124-2所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/f4bb687c366d6212fb508e614ef42b14fa8288d45d94bda1792bceb53d204a60.png)

可以看到，OpenResty流量网关将查询流量透传到Redis分布式缓存，如果是查询数据，分布式缓存中存在对应的数据，则不再请求后端服务。如果是秒杀下单，则从分布式缓存中获取到数据后，进行校验，校验不通过直接返回结果，不再请求后端服务。

这样就会将OpenResty流量网关—&gt;系统网关—&gt;Web服务—&gt;基础服务—&gt;数据存储的请求链路，直接缩短为：OpenResty流量网关—&gt;数据存储的请求链路，减少了请求链路中经过的服务数量和交易流程，并且OpenResty流量网关和Redis分布式缓存的性能都比后端服务高很多。

所以，将流量从OpenResty流量网关透传到Redis分布式缓存查询数据会极大的提升秒杀系统的性能。

### **四、网关透传缓存实现**

本节，我们以获取秒杀活动列表为例，实现将流量从OpenResty流量网关透传到Redis分布式缓存查询数据。其他接口流量从OpenResty流量网关透传到Redis分布式缓存查询数据的具体实现，大家获取到本章对应的源码分支后，自行查看源码即可。

实现的主要逻辑为：请求到达OpenResty流量网关时，如果用户登录校验通过，则首先从Redis分布式缓存读取数据，如果Redis分布式缓存存在对应的数据，则将数据解析成最终的结果数据并返回，不再请求后端服务。如果Redis分布式缓存不存在对应的数据，再请求后端服务获取数据。具体的实现步骤如下所示。

**注意：获取秒杀活动实现流量从OpenResty流量网关透传到Redis分布式缓存查询数据的源码详见：seckill-nginx工程下的lua/**[get_activity_list_access.lua](http://get_activity_list_access.lua)**，本节分析的源码均在lua/**[get_activity_list_access.lua](http://get_activity_list_access.lua)**文件中。**

**（1）校验用户登录状态**

从请求头中解析中access-token，如果access-token为空，则直接返回用户未登录的状态，如下所示。

```go
--校验用户是否登录
local accessToken = require("access_token")
local access_token = accessToken.get_access_token()
if not access_token then
    ngx.say("{\"code\": 2012, \"data\" : \"用户未登录\"}")
    return ngx.exit(200)
end
```

**（2）获取Redis数据**

首先，将seckill-nginx工程下的lua目录下的[redis_basic.lua](http://redis_basic.lua)文件、[seckill_redis.lua](http://seckill_redis.lua)文件和[number_util.lua](http://number_util.lua)文件复制到OpenResty的lua目录下，接下来，从Redis中获取秒杀活动列表数据，如下所示。

```go
--直接从Redis读取数据
local rredis = require("seckill_redis")
local json = require("cjson")
local number_util = require("number_util")
ngx. req.read_body()
local args = ngx.req.get_post_args()
local status = args["status"]
local version = args["version"]
local redisKey = "SECKILL_ACTIVITIES_CACHE_KEY_" .. status
local redisValue = rredis.get(redisKey)
```

**（3）解析获取到的数据**

由于存储到Redis中的数据不是要返回的最终数据，所以，如果从Redis中获取到的数据不为空，我们需要解析从Redis中获取到的数据，将其解析成最终要返回的数据，如下所示。

```go
if redisValue ~= nil and redisValue ~= ngx.null  then
    local jsonRedisObj = json.decode(redisValue)
    local dataResult = json.decode(jsonRedisObj)
    local dataVersion = dataResult.version
    local data = dataResult.data
    if data ~= nil and data ~= ngx.null then
        local transferData = {}
        for i, v in pairs(data) do
            v["version"] = dataVersion
            local startTime = v["startTime"]
            local endTime = v["endTime"]
            local startTimeStr = os.date("%Y-%m-%d %H:%M:%S",  startTime / 1000)
            local endTimeStr = os.date("%Y-%m-%d %H:%M:%S",  endTime / 1000)
            v["startTime"] = startTimeStr
            v["endTime"] = endTimeStr
            v["inSeckilling"] = nil
            v["online"] = nil
            v["id"] = number_util.LongNumber2String(v["id"])
            transferData[i] = v
        end
        local result = {}
        result["code"] = 1001
        result["data"] = transferData
        ngx.say(json.encode(result))
        return ngx.exit(200)
    end
end
```
