秒杀系统由单体项目拆分为微服务之后，对于秒杀商品异步事件后置处理器的实现同样不能仅仅局限于JVM进程内，也需要对这部分的实现升级为分布式架构，并且同样需要对原有的设计与实现做到零侵入，兼容原有的设计与实现，充分体现出秒杀系统在设计上的高度可扩展性。

### **一、前言**

目前，在秒杀系统的实现中，当秒杀商品信息变更后，基于Cola实现了JVM进程内的事件发布与接收，领域层会将事件发到到Cola，而应用层则监听并接收Cola中的事件，并更新分布式缓存中的秒杀商品信息。当秒杀系统由单体应用升级为微服务架构后，这种JVM进程内的事件发布与接收同样不能满足当前更新秒杀商品缓存的需求了。

### **二、本章诉求**

重构秒杀商品异步事件后置处理器，将JVM进程内的事件发布与接收方式，升级为支持分布式的事件发布与接收方式，并且要对原有的设计与实现做到零侵入，兼容原有的设计与实现，充分体现出秒杀系统在设计上的高度可扩展性。

### **四、编码实现**

零侵入重构秒杀商品异步事件后置处理器的核心实现步骤如下所示。

**（1）修改SeckillGoodsColaEventHandler类**

主要是将原有的SeckillGoodsEventHandler类更新成SeckillGoodsColaEventHandler类，不会修改具体的业务实现。

**（2）新增SeckillGoodsRocketMQEventHandler类**

SeckillGoodsRocketMQEventHandler类的源码详见：seckill-goods-application工程下的[io.binghe.seckill.application.event.SeckillGoodsRocketMQEventHandler](http://io.binghe.seckill.application.event.SeckillGoodsRocketMQEventHandler)。

```go
@Component
@ConditionalOnProperty(name = "event.publish.type", havingValue = "rocketmq")
@RocketMQMessageListener(consumerGroup = SeckillConstants.EVENT_GOODS_CONSUMER_GROUP, topic = SeckillConstants.TOPIC_EVENT_ROCKETMQ_GOODS)
public class SeckillGoodsRocketMQEventHandler implements RocketMQListener<String> {
    private final Logger logger = LoggerFactory.getLogger(SeckillGoodsRocketMQEventHandler.class);
    @Autowired
    private SeckillGoodsCacheService seckillGoodsCacheService;
    @Autowired
    private SeckillGoodsListCacheService seckillGoodsListCacheService;
    @Override
    public void onMessage(String message) {
        logger.info("rocketmq|goodsEvent|接收秒杀品事件|{}", message);
        if (StrUtil.isEmpty(message)){
            logger.info("rocketmq|goodsEvent|接收秒杀品事件参数错误" );
            return;
        }
        SeckillGoodsEvent seckillGoodsEvent = this.getEventMessage(message);
        seckillGoodsCacheService.tryUpdateSeckillGoodsCacheByLock(seckillGoodsEvent.getId(), false);
        seckillGoodsListCacheService.tryUpdateSeckillGoodsCacheByLock(seckillGoodsEvent.getActivityId(), false);
    }
​
    private SeckillGoodsEvent getEventMessage(String msg){
        JSONObject jsonObject = JSONObject.parseObject(msg);
        String eventStr = jsonObject.getString(SeckillConstants.EVENT_MSG_KEY);
        return JSONObject.parseObject(eventStr, SeckillGoodsEvent.class);
    }
}
```

可以看到，SeckillGoodsRocketMQEventHandler类主要是监听并接收RocketMQ中新增和修改秒杀商品的事件，并且在SeckillGoodsRocketMQEventHandler类上标注了@ConditionalOnProperty注解，当SpringBoot配置文件中的[event.publish.type](http://event.publish.type)属性的值为rocketmq时，就会加载并实例化SeckillGoodsRocketMQEventHandler类的实例对象。

**（3）修改application.properties配置**

主要是将application.properties文件中的[event.publish.type](http://event.publish.type)配置项的值修改成rocketmq。

application.properties文件的源码详见：seckill-goods-starter工程下的src/main/resources/application.properties。

```go
event.publish.type=rocketmq
```
