### **一、前言**

如果要将秒杀系统的性能优化到极致，单单优化秒杀系统源码的性能是远远不够的，还需要进一步优化服务器和操作系统的性能。将秒杀系统所在的服务器和操作系统性能再提升一个档次，会让秒杀系统的性能更高。

### **二、本章诉求**

对秒杀系统所在的服务器进行优化，了解秒杀场景下服务器物理机可以从哪些方面进行优化，重点掌握秒杀系统场景下服务器物理机极致优化的方式，并能够结合自身实际项目思考，将对服务器的极致优化灵活应用到自身实际项目中。

**注意：本章对服务器的优化都是基于CentOS服务器，如果是其他版本服务器的话，优化的参数或者优化的方式可能会有所不同。**

### **三、操作系统参数**

在CentOS 操作系统中，可以通过如下命令来查看所有的系统参数。

```go
/sbin/sysctl -a
```

使用此命令输出的参数太多了，大概有一千多个，在高并发场景下，不可能对操作系统的所有参数进行调优。更多的是关注与网络相关的参数。如果想获得与网络相关的参数，那么，首先需要获取操作系统参数的类型，如下命令可以获取操作系统参数的类型。

```go
/sbin/sysctl -a|awk -F "." '{print $1}'|sort -k1|uniq
```

运行上述命令，输出的结果信息如下所示。

```go
abi
crypto
debug
dev
fs
kernel
net
sunrpc
user
vm
```

其中的net类型就是要关注的与网络相关的操作系统参数。可以获取net类型下的子类型，如下所示。

```go
/sbin/sysctl -a|grep "^net."|awk -F "[.| ]" '{print $2}'|sort -k1|uniq
```

运行上述命令，输出的结果信息如下所示。

```go
bridge
core
ipv4
ipv6
netfilter
nf_conntrack_max
unix
```

在Linux操作系统中，这些与网络相关的参数都可以在/etc/[sysctl.conf](http://sysctl.conf)文件里修改，如果/etc/[sysctl.conf](http://sysctl.conf)文件中不存在这些参数，可以自行在/etc/[sysctl.conf](http://sysctl.conf)文件中添加这些参数。

**注意：在net类型的子类型中，需要重点关注的子类型有：core和ipv4。**

### **四、优化套接字缓冲区**

如果服务器的网络套接字缓冲区太小，就会导致应用程序读写多次才能将数据处理完，这会大大影响程序的性能。如果网络套接字缓冲区设置的足够大，在一定程度上能够提升程序的性能。

可以在服务器的命令行输入如下命令，来获取有关服务器套接字缓冲区的信息。

```go
/sbin/sysctl -a|grep "^net."|grep "[r|w|_]mem[_| ]"
```

运行上述命令，输出的结果信息如下所示。

```go
net.core.rmem_default = 212992
net.core.rmem_max = 212992
net.core.wmem_default = 212992
net.core.wmem_max = 212992
net.ipv4.tcp_mem = 43545        58062   87090
net.ipv4.tcp_rmem = 4096        87380   6291456
net.ipv4.tcp_wmem = 4096        16384   4194304
net.ipv4.udp_mem = 87093        116125  174186
net.ipv4.udp_rmem_min = 4096
net.ipv4.udp_wmem_min = 4096
```

其中，带有max、default、min关键字的参数分别代表：最大值、默认值和最小值；带有mem、rmem、wmem关键字的参数分别为：总内存、接收缓冲区内存、发送缓冲区内存。

**注意：带有rmem和wmem关键字的单位都是字节，而带有mem关键字的单位是页。页是操作系统管理内存的最小单位，在Linux系统里，默认一页的大小是4KB。**

### **五、优化频繁接收大文件**

在高并发、大流量的场景下，如果系统中存在频繁接收大文件的现象，则需要对服务器的性能进行优化。这里，可以修改的系统参数如下所示。

```go
net.core.rmem_default
net.core.rmem_max
net.core.wmem_default
net.core.wmem_max
net.ipv4.tcp_mem
net.ipv4.tcp_rmem
net.ipv4.tcp_wmem
```

假设系统最大可以给TCP分配 2GB 内存，最小值为 256MB，压力值为 1.5GB。按照一页为 4KB 来计算， tcp_mem 的最小值、压力值、最大值分别是 65536、393216、524288，单位是页。具体的计算方式如下所示。

1. 最小值：256 * 1024 / 4 = 65536。

2. 压力值：1.5 * 1024 * 1024 / 4 = 393216。

3. 最大值：2 * 1024 * 1024 / 4 = 524288。

假如平均每个文件数据包的大小为 512KB，每个套接字读写缓冲区最小可以各容纳2个数据包，默认可以各容纳4个数据包，最大可以各容纳10个数据包，则可以计算出tcp_rmem和tcp_wmem的最小值、默认值、最大值分别是 1048576、2097152、5242880，单位是字节。具体的计算方式如下所示。

1. 最小值：512 * 2 * 1024 = 1048576。

2. 默认值：512 * 4 * 1024 = 2097152。

3. 最大值：512 * 10 * 1024 = 5242880。

rmem_default 和 wmem_default 是 2097152，rmem_max和wmem_max 是5242880。

经过上面的分析和计算，可以得出如下的系统调优参数。

```go
net.core.rmem_default = 2097152
net.core.rmem_max = 5242880
net.core.wmem_default = 2097152
net.core.wmem_max = 5242880
net.ipv4.tcp_mem = 65536  393216  524288
net.ipv4.tcp_rmem = 1048576  2097152  5242880
net.ipv4.tcp_wmem = 1048576  2097152  5242880
```

**注意：如果缓冲区的大小超过了 65535，还需要将 net.ipv4.tcp_window_scaling 参数设置为 1。**

### **六、优化TCP链接**

TCP的连接需要经过“三次握手”和“四次挥手”，还要经过慢启动、滑动窗口、粘包算法等支持可靠性传输的一系列技术支持。虽然，这些技术能够保证TCP协议的可靠性，但有时会影响程序的性能。

所以，在高并发场景下，可以按照如下方式优化TCP连接。

**（1）关闭粘包算法**

如果用户对于请求的耗时很敏感，就需要在TCP套接字上添加tcp_nodelay参数来关闭粘包算法，以便使数据包能够立刻发送出去。此时，也可以设置net.ipv4.tcp_syncookies的参数值为1。

**（2）避免频繁创建和回收连接资源**

网络连接的创建和回收是非常消耗性能的，可以通过关闭空闲的连接、重复利用已经分配的连接资源来优化服务器的性能。例如，经常使用的线程池、数据库连接池就是复用了线程和数据库连接。

可以通过如下参数来关闭服务器的空闲连接和复用已分配的连接资源。

```go
net.ipv4.tcp_tw_reuse = 1
net.ipv4.tcp_tw_recycle = 1
net.ipv4.tcp_fin_timeout = 30
net.ipv4.tcp_keepalive_time=1800
```

**（3）避免重复发送数据包**

TCP支持超时重传机制。如果发送方将数据包已经发送给接收方，但发送方并未收到反馈，此时，如果达到设置的时间间隔，就会触发TCP的超时重传机制。为了避免发送成功的数据包再次发送，可以将服务器的net.ipv4.tcp_sack参数设置为1。

**（4）增大服务器文件描述符数量**

在Linux操作系统中，一个网络连接也会占用一个文件描述符，连接越多，占用的文件描述符也就越多。如果文件描述符设置的比较小，也会影响服务器的性能。此时，需要增大服务器文件描述符的数量。例如：[fs.file-max](http://fs.file-max)= 10240000，表示服务器最多可以打开10240000个文件。

### **七、优化CPU模式**

优化CPU的工作模式，主要就是优化CPU的工作频率，让CPU在不同的场景下表现出更优的性能。在CentOS这种Linux操作系统中，CPU可以有多种工作模式，如下所示。

1. performance：运行于最大频率。

2. powersave：运行于最小频率。

3. userspace： 运行于用户指定的频率。

4. ondemand：按需快速动态调整CPU频率， 一有cpu计算量的任务，就会立即达到最大频率运行，空闲时间增加就降低频率。

5. conservative：按需快速动态调整CPU频率， 比 ondemand 的调整更保守。

6. schedutil：基于调度程序调整 CPU 频率。

如果是秒杀场景，可以将CPU模式调整为performance，如果是平常的业务流量，可以将CPU模式调整为powersave模式。

可以使用cpupower命令修改CPU的工作模式，具体步骤如下所示。

1. 查看CPU当前的工作模式

```go
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
```

1. 安装cpupower命令

```go
yum install -y cpupowerutils
cpupower frequency-info
cat /proc/cpuinfo
```

1. 修改CPU当前工作模式为performance

```go
cpupower frequency-set -g performance
```

### **八、优化网卡中断**

服务器的机器硬件与CPU之间的交互是通过“中断”来完成的，也就是通过“中断”的方式来通知CPU进行处理。秒杀的瞬时流量非常高，瞬间会有非常多的请求进入系统，而网卡也是通过“中断”的方式来通知CPU进行处理。如果不对网卡的中断操作进行优化，很可能处理网卡中断的CPU都在一个核心上，如果此时这个CPU核心还要处理其他任务，就有可能出现性能问题。

所以，我们需要对网卡中断进行优化，让某个CPU核心专门处理网卡中断的任务。另外，对于运行了Redis和Nginx的服务器来说，也可以将Redis和Nginx的进程绑定到特定的CPU核心上，减少CPU切换带来的性能损失。

### **九、优化Nginx**

虽然Kong网关使用起来更加便捷，也是基于OpenResty的一个高性能网关，但是，本着空杯心态学习技术的原则，我们的秒杀系统流量网关使用的是OpenResty，而OpenResty是基于Nginx的，最终我们还是要对Nginx进行优化。

#### **9.1优化全局模块**

**（1）进程绑定 CPU核心**

配置worker_cpu_affinity将Nginx的工作进程绑定到特定的CPU核心上，以4核CPU为例，如下所示。

```go
worker_cpu_affinity   0001 0010 0100 1000;
```

以上配置具体含义为：

1. Nginx的第1个工作进程绑定CPU的设置为0001，表示绑定CPU3。

2. Nginx的第2个工作进程绑定CPU的设置为0010，表示绑定CPU2。

3. Nginx的第3个工作进程绑定CPU的设置为0100，表示绑定CPU1。

4. Nginx的第4个工作进程绑定CPU的设置为1000，表示绑定CPU0。

**（2）优化吞吐量**

优化吞吐量可以配置Nginx的worker_rlimit_nofile参数，worker_rlimit_nofile参数是Nginx能打开的最大文件描述符数量。一般可以配置成65535。

#### **9.2 优化events模块**

**（1）优化单个进程最大连接数**

单个进程最大连接数是由worker_connections配置决定，而worker_connections配置会受限于worker_rlimit_nofile配置，一般情况下，可以将这两个配置项都设置为65535。

**（2）优化新连接接入方式**

新连接的接入方式是由accept_mutex配置决定的，系统流量比较大时，建议关闭此配置，此时新任务进来，所有工作进程都会被唤醒，但最终有会有一个进程接受新连接并处理任务。其他未接受到新连接的进程过段时间就会继续等待。

系统流量比较小时，建议开启此配置，此时工作进程会用过互斥锁轮流依次接受新连接并处理。

如果开启此配置，建议还要配置accept_mutex_delay，主要是设置等待超时时间，避免获取互斥锁的进程长时间占用资源，而导致其他请求阻塞。

#### **9.3 HTTP模块优化**

**（1）优化零拷贝**

秒杀场景下可以开启sendfile配置，从而开始零拷贝。

**（2）优化TCP传输**

优化TCP传输可以使用tcp_nopush，不过tcp_nopush配置只有Nginx开启了sendfile配置的前提下才会生效。开始tcp_nopush配置后，Nginx会将多个小数据包进行合并发送，减少网络拥堵，并优化网路传输。

还一个是tcp_nodelay配置，这个配置与tcp_nopush的功能正好相反，在秒杀这种瞬时高并发、大流量的场景下，建议关闭tcp_nodelay配置。

**（3）优化长短链接配置**

将客户端与Nginx之间配置成短连接，Nginx与后端服务之间配置成长连接，如下所示。

```go
#与客户端使用短连接
keepalive_timeout  0;
#与下游服务使用长连接,指定HTTP协议版本，并清除Connection
proxy_http_version 1.1;
proxy_set_header Connection "";
```

**（4）优化其他配置**

在Nginx中，还可以对连接建立超时时间的proxy_connect_timeout配置、发送请求超时时间的proxy_send_timeout配置和获取响应数据超时时间的proxy_read_timeout配置进行优化。

在秒杀场景下，可以进行如下配置。

```go
proxy_connect_timeout 500ms;
proxy_send_timeout 500ms;
proxy_read_timeout 3000ms;
```

**注意：这里，我将优化后的Nginx配置放到了seckill-nginx工程下，详见：seckill-nginx工程下的conf/**[nginx-optimize.conf](http://nginx-optimize.conf)**。大家获取到本章对应的源码后，可以将**[nginx-optimize.conf](http://nginx-optimize.conf)**文件修改成**[nginx.conf](http://nginx.conf)**文件，并且修改下加载其他文件的路径，就可以将**[nginx.conf](http://nginx.conf)**放到OpenResty的conf目录下进行测试了。**
