### **一、前言**

运营人员对于秒杀系统中订单业务的需求与用户是不同的，用户可以在秒杀系统中抢购商品下单，查看自己下单的订单数据。而运营人员则是查看某种活动下的订单数据，以此来分析这场秒杀活动的收益。

### **二、本章诉求**

对于秒杀订单业务来说，用户端的业务会比运营端简单些，运营端会通过秒杀活动查看活动下的订单数据。本章，就从运营角度实现最简化的秒杀订单业务，并将前后端代码联调成功。

运营人员在登录秒杀系统后，在活动页面点击查看订单，就会跳转到查看订单页面，以此来分析当前秒杀活动下产生的订单收益等。简化后的流程如图24-1所示。

运营人员在查看订单数据时，会进行如下逻辑校验：

（1）如果未登录，则提示请登录后操作，并跳转到登录页面，否则进行下一步。

（2）如果获取订单信息失败，则提示获取订单失信息失败，否则进行下一步。

（3）如果遇到网络异常的情况，则提示获取订单失信息失败，否则进行下一步。

（4）如果抛出了其他异常，则提示获取订单失信息失败，否则进行下一步。

（5）后端返回活动维度的订单列表数据，前端填充查看订单页面的数据。

**（2）查看订单JS代码开发**

在加载查看订单的页面时，会调用获取活动维度的订单列表接口，如下所示。

```go
// 定义全局订单数组信息
var g_orderList = [];
jQuery(document).ready(function () {
    var activityId = getParameterByName("activityId");
    $.ajax({
        type:"GET",
        headers:{
            "access-token": get(common_localstorage_key)
        },
        url:"http://"+g_host+"/order/getSeckillOrderByActivityId?activityId=" + activityId,
        xhrFields: {withCredentials: true},
        success:function (data) {
            if (data.code == 1001) {
                g_orderList = data.data;
                reloadDom();
            }else if (data.code == 2012){
                alert("请登录后操作");
                window.location.href = "login.html";
            }
            else {
                alert("获取订单信息失败");
            }
        },
        error:function (data) {
            alert("获取订单信息失败");
        }
    })
})
```

可以看到，在加载页面时，就会调用获取用户维度的订单列表，将正确返回的结果信息赋值给g_orderList变量，并调用reloadDom()方法重载页面Dom元素。

reloadDom()方法的源码如下所示。

```go
function reloadDom() {
    for (var i = 0; i < g_orderList.length; i ++){
        var itemVO = g_orderList[i];
        var dom = "<tr id='goodsDetail"+ itemVO.id +"'>" +
            "<td>"+ itemVO.id +"</td>" +
            "<td>"+ itemVO.userId +"</td>" +
            "<td>"+ itemVO.activityId +"</td>" +
            "<td>"+ itemVO.goodsId +"</td>" +
            "<td>"+ itemVO.goodsName +"</td>" +
            "<td>"+ itemVO.activityPrice +"</td>" +
            "<td>"+ itemVO.quantity +"</td>" +
            "<td>"+ itemVO.orderPrice +"</td>" +
            "<td>"+ getStatus(itemVO.status) +"</td>" +
            "<td>"+ itemVO.createTime +"</td>" +
            "</tr>";
        $("#container").append($(dom));
    }
}
```

可以看到，在reloadDom()方法中，主要就是遍历g_orderList数组变量，获取商品信息来填充页面数据，在填充页面数据的过程中，会调动getStatus()方法处理状态信息。

getStatus()方法的源码如下所示。

```go
function getStatus(status){
    if (status == 1){
        return "待支付";
    }else if (status == 2){
        return "已支付";
    }else if (status == 0){
        return "已取消";
    }else if (status == -1){
        return "已删除"
    }
}
```

可以看到，在订单信息中状态为1表示待支付，状态为2表示已支付，状态为0表示已取消，状态为-1表示已删除。

innerHtml +=  "<input type='button' value='查看订单' onclick='getOrders(" + itemVO.id + ")'/>";
