### **三、可扩展流程设计**

在秒杀系统中，我们在业务网关中基于责任链模式实现了多重风控校验模块，预留了大量的风控扩展点。还是那句话，一上来就设计和实现一个非常完善的风控系统是不可能的。在设计和实现风控规则时，我们要做到高度可扩展、可编排和可配置，随时可以扩展其他的风控规则，也能够随时对这些风控规则进行编排，同时，能够随时配置风控的具体规则。

当请求进入业务网关时，会触发风控规则，此时会执行风控链中的校验规则，只有经过所有过滤器链的校验之后，请求才会被业务网关路由到正确的服务上执行后续业务逻辑，总体如图114-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/44ef27b4c01607b353c5d80d9c54eaf4e9b6cb1b111cf112939374c3ef65f556.png)

可以看到，用户在访问秒杀系统时，请求会首先到达流量网关，经过流量网关的流控、限流、防刷和黑白名单等校验，到达业务网关。在业务网关会经过多重风控校验和鉴权校验。而在多重风控校验设计中，会提供风控扩展点接口，后续要新增风控规则时，只需要新建一个扩展点实现类，实现风控扩展点接口即可，并且可以对这些具体的风控逻辑进行编排，使其按照自己想要的顺序执行，完全做到了高度可扩展、可配置和可编排。

实现了风控可扩展点接口的具体实现类，就是风控要执行的具体逻辑了，在执行风控逻辑时，会以责任链模式以此执行风控可扩展接口实现类中的逻辑，例如：账户风控、IP风控、设备风控、防攻击风控、自定义风控、其他风控等等。只有通过所有风控逻辑的校验之后，接下来就是对请求进行鉴权校验，通过鉴权校验的请求才会被业务网关路由到目标微服务执行具体业务逻辑。

### **四、风控模型设计**

在风控模型的设计上，总体上会以责任链模式来执行多重风控逻辑，并且具体的风控逻辑可扩展、可配置和可编排，为此我们需要对风控的模型进行精心的设计。

#### **4.2 模型可配置设计**

对于基础模型，我们设计了可扩展的配置模板，后续变更或者扩展风控规则时，只需要根据配置模板进行配置即可。配置模板是Json类型的字符串，如下所示。

```go
{
  "enabled": true,
  "ipRule": {
    "enabled": true,
    "windowPeriod": 1000,
    "windowSize": 5
  },
  "accountRule": {
    "enabled": true
  },
  "pathRule": {
    "enabled": true,
    "windowPeriod": 1000,
    "windowSize": 5,
    "urlPaths": [
      {
        "path": "/**"
      },
      {
        "enabled": true,
        "path": "/seckill-order/order/saveSeckillOrder",
        "windowPeriod": 1000,
        "windowSize": 3
      }
    ]
  }

```

可以看到，这里的风控配置模板中，我们配置了IP风控规则、账户风控规则和请求路径风控规则。这些配置不仅可以在项目中配置，更是能够在配置中心进行可视化配置，当配置中心的配置变更后，风控会立刻感知到配置的变化，并且会及时生效。

#### **4.3 可扩展接口设计**

对于风控来说，最重要的是要具备高度可扩展行，那如何做到高度可扩展呢？在设计时，只要实现一个可扩展点接口，就能自动将风控规则添加到现有风控中，不需要进行其他的改动，那这就是可扩展的代码设计。所以，在设计风控时，我们首先要设计一个扩展点接口，这个可扩展点接口就是各个风控规则实现类要实现的接口，如下所示。

```go
public interface SeckillGatewayRuleChainService {
    /**
    * 执行调用链服务
    */
    ErrorCode execute(ServerWebExchange exchange);
​
    /**
    * 调用链的顺序
    */
    int getOrder();
}
```

可以看到，在扩展点接口中，提供了一个执行调用链服务的方法execute()和一个标识当前风控规则执行顺序的方法getOrder()。在具体执行风控规则时，会按照责任链模式来执行所有的风控逻辑，只有通过所有风控逻辑的校验后，请求才会继续向下执行。

#### **4.4 风控规则链设计**

整个风控规则是按照责任链模式执行的，那具体是如何设计的呢？具体的设计方式就是基于SpringCloud Gateway的过滤器机制，获取到所有实现了可扩展点接口SeckillGatewayRuleChainService的实现类对象，按照getOrder()方法指定的顺序以此执行具体的风控规则逻辑，如下所示。

```go
@Override
public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
    List<SeckillGatewayRuleChainService> seckillGatewayBaseRuleChainServices = this.getSeckillGatewayBaseRuleChainServices();
    for (SeckillGatewayRuleChainService seckillGatewayRuleChainService : seckillGatewayBaseRuleChainServices){
        ErrorCode errorCode = seckillGatewayRuleChainService.execute(exchange);
        if (!ErrorCode.SUCCESS.getCode().equals(errorCode.getCode())){
            return fastFinish(exchange, errorCode);
        }
    }
    return chain.filter(exchange);
}
```
