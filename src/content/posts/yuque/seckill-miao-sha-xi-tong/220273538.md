#### **4.2 风控规则配置实现**

这里，我们以IP规则、路径规则和账户规则为例，实现风控规则的配置。在seckill-gateway工程下的[io.binghe.seckill.gateway.risk.rule.config](http://io.binghe.seckill.gateway.risk.rule.config)包下新增SeckillGatewayRulesConfig类，如下所示。

```go
public class SeckillGatewayRulesConfig {
    /**
    * 是否开启
    */
    private boolean enabled;
​
    /**
    * 基于ip的规则
    */
    private Rule ipRule;
​
    /**
    * 基于路径的规则
    */
    private PathRule pathRule;
​
    /**
    * 基于账户的规则
    */
    private Rule accountRule;
​
    public Rule getIpRule() {
        if (ipRule == null || !ipRule.isEnabled() || !this.isEnabled()){
            return new Rule().setEnabled(false);
        }
        return new Rule()
                .setEnabled(ipRule.isEnabled())
                .setWindowPeriod(ipRule.getWindowPeriod())
                .setWindowSize(ipRule.getWindowSize());
    }
​
    public Rule getAccountRule(){
        if (accountRule == null || !accountRule.isEnabled() || !this.isEnabled()){
            new Rule().setEnabled(false);
        }
        return new Rule().setEnabled(accountRule.isEnabled());
    }
​
    public Rule getPathRule(String path) {
        if (StrUtil.isEmpty(path) || pathRule == null || CollectionUtil.isEmpty(pathRule.getUrlPaths())){
            return new Rule().setEnabled(false);
        }
        if (!pathRule.isEnabled() || !this.isEnabled()){
            return new Rule().setEnabled(false);
        }
        for (Rule rule : pathRule.getUrlPaths()){
            if (StrUtil.isEmpty(rule.getPath())){
                continue;
            }
            if (this.isPathMatch(rule.getPath(), path)){
                return new Rule()
                        .setEnabled(rule.isEnabled())
                        .setPath(rule.getPath())
                        .setWindowPeriod(rule.getWindowPeriod() <= 0 ? pathRule.getWindowPeriod() : rule.getWindowPeriod())
                        .setWindowSize(rule.getWindowSize() <= 0 ? pathRule.getWindowSize() : rule.getWindowSize());
            }
        }
        return new Rule().setEnabled(false);
    }
​
​
    private boolean isPathMatch(String uriTemplate, String path) {
        PathPatternParser parser = new PathPatternParser();
        parser.setMatchOptionalTrailingSeparator(true);
        PathPattern pathPattern = parser.parse(uriTemplate);
        PathContainer pathContainer = toPathContainer(path);
        return pathPattern.matches(pathContainer);
    }
​
    private PathContainer toPathContainer(String path) {
        if (path == null) {
            return null;
        }
        return PathContainer.parsePath(path);
    }
​
    public boolean isEnabled() {
        return enabled;
    }
​
    public void setEnabled(boolean enabled) {
        this.enabled = enabled;
    }
​
    public void setAccountRule(Rule accountRule) {
        this.accountRule = accountRule;
    }
​
    public void setIpRule(Rule ipRule) {
        this.ipRule = ipRule;
    }
​
    public void setPathRule(PathRule pathRule) {
        this.pathRule = pathRule;
    }
}
```

可以看到，在SeckillGatewayRulesConfig类中提供的getter方法中，在返回数据时，会对相应的数据进行处理，如果对应的数据为空或者未开启配置，则返回未开启配置的规则对象。否则，返回对应的配置信息。

#### **4.3 动态感知配置中心**

秒杀系统的风控规则由配置中心统一管理，如果配置中心变更了配置规则，则需要动态感知到风控规则的变化。所以，在实现上，需要动态感知配置中心。

源码详见：seckill-gateway工程下的[io.binghe.seckill.gateway.risk.rule.factory.SeckillGatewayRulesConfigFactoty](http://io.binghe.seckill.gateway.risk.rule.factory.SeckillGatewayRulesConfigFactoty)。

```go
public interface SeckillGatewayRulesConfigFactoty {
    Rule getIpRule();
    Rule getAccountRule();
    Rule getPathRule(String path);
}
```

可以看到，在SeckillGatewayRulesConfigFactoty接口中分别定义了获取IP规则、获取账户规则和获取路径规则的方法。

**（2）新增SeckillGatewayRulesNacosConfigFactoty类**

源码详见：seckill-gateway工程下的[io.binghe.seckill.gateway.risk.rule.factory.impl.SeckillGatewayRulesNacosConfigFactoty](http://io.binghe.seckill.gateway.risk.rule.factory.impl.SeckillGatewayRulesNacosConfigFactoty)。

​

​
    private SeckillGatewayRulesConfig seckillGatewayRulesConfig;
​
    @Override
    public Rule getIpRule() {
        if (seckillGatewayRulesConfig == null){
            return new Rule().setEnabled(false);
        }

    }
​

            return new Rule().setEnabled(false);
        }
        return seckillGatewayRulesConfig.getAccountRule();
    }
​
    @Override

        if (seckillGatewayRulesConfig == null){

### **五、风控规则实现**

风控规则的实现要具备可扩展性，所以，在实现具体的风控规则之前，我们需要思考这些风控规则能否抽象成接口，将风控规则抽象成接口后，具体的规则实现类只要实现接口，并实现接口中的方法接口。

可以看到，在SeckillGatewayRuleChainService接口中定义了执行逻辑的execute()方法和当前规则的getOrder()执行顺序方法。

#### **5.2 风控规则具体实现**

这里，我们以IP规则为例进行说明，具体规则大家获取到本章对应的源码时，自行查看，这里不再赘述。

新增SeckillGatewayIPRuleChainService类，源码详见：seckill-gateway工程下的[io.binghe.seckill.gateway.risk.rule.service.impl.SeckillGatewayIPRuleChainService](http://io.binghe.seckill.gateway.risk.rule.service.impl.SeckillGatewayIPRuleChainService)。

```go
@Component
public class SeckillGatewayIPRuleChainService extends SeckillGatewayBaseRuleChainService implements SeckillGatewayRuleChainService {
    private final Logger logger = LoggerFactory.getLogger(SeckillGatewayIPRuleChainService.class);
    @Override
    public ErrorCode execute(ServerWebExchange exchange) {
        Rule rule = seckillGatewayRulesConfigFactoty.getIpRule();
        if (!rule.isEnabled()){
            return ErrorCode.SUCCESS;
        }
        try{
            String ip = this.getIp(exchange);
            boolean result = slidingWindowLimitService.passThough(ip, rule.getWindowPeriod(), rule.getWindowSize());
            return result ? ErrorCode.SUCCESS : ErrorCode.RISK_CONTROL_IP_INVALID;
        }catch (Exception e){
            logger.error("SeckillGatewayIPRuleChainService|IP限制异常|{}", e.getMessage());
            return ErrorCode.RISK_CONTROL_IP_INVALID;
        }
    }
    @Override
    public int getOrder() {
        return SeckillGatewayRuleEnum.IP.getCode();
    }
    @Override
    public String getServiceName() {
        return SeckillGatewayRuleEnum.IP.getMesaage();
    }
}
```

可以看到，在IP规则的实现中，会首先获取IP规则对象，如果获取到的规则对象为空，表示未配置风控或者配置的风控未开启，则直接返回成功。随后获取ip地址，对ip地址进行滑动窗口限流，如果通过检验，则返回成功，否则返回失败。

其他的具体规则实现，大家获取到本章对应的源码分支，自行查看，也可以基于现有的规则扩展其他规则。

### **六、风控调用链实现**

风控规则最终会在业务网关的过滤器中执行，新增SeckillGatewayRiskControlFilter类。

源码详见：seckill-gateway工程下的[io.binghe.seckill.gateway.filter.impl.SeckillGatewayRiskControlFilter](http://io.binghe.seckill.gateway.filter.impl.SeckillGatewayRiskControlFilter)。

```go
@Component
public class SeckillGatewayRiskControlFilter extends SeckillGatewayGlobalFilter {
​
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        List<SeckillGatewayRuleChainService> seckillGatewayBaseRuleChainServices = this.getSeckillGatewayBaseRuleChainServices();
        for (SeckillGatewayRuleChainService seckillGatewayRuleChainService : seckillGatewayBaseRuleChainServices){
            ErrorCode errorCode = seckillGatewayRuleChainService.execute(exchange);
            if (!ErrorCode.SUCCESS.getCode().equals(errorCode.getCode())){
                return fastFinish(exchange, errorCode);
            }
        }
        return chain.filter(exchange);
    }
    @Override
    public int getOrder() {
        return SeckillGatewayFilterEnum.RISKCONTROL.getCode();
    }
}
```

可以看到，在业务网关的SeckillGatewayRiskControlFilter过滤器的filter()方法中，会获取排好序的风控规则列表，获取到排好序的风控规则列表后，遍历列表，执行每一个风控规则中的execute()方法，只要有一个风控规则校验不通过，则直接返回，不再向下执行后续逻辑。只有所有的风控规则校验都通过后，才会继续执行后续逻辑。
