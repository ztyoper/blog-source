### **一、前言**

对于一个系统来说，无论设计的多么优雅，也或是功能多么强大，性能和并发多么高，可靠性多么稳固，最终都是要落地到代码上的。代码健壮，在一定程度上系统稳定性就高。代码优雅，在一定程度上维护性就高。代码性能高，在一定程度上系统整体并发度就高，性能就高。

### **二、本章诉求**

本地缓存+分布式缓存的混合型缓存架构设计，不仅能够提升秒杀系统读写数据的性能，还能在代码层面抗住秒杀系统的大部分流量，不至于让流量直接打入数据库。那么，如果要将本地缓存+分布式缓存的混合型缓存落地到代码，该怎么实现呢？

本章，就从代码层面对秒杀系统混合型缓存进行代码设计与实现。

### **三、代码设计**

在设计混合型通用代码时，将会从流量缓存防线设计、代码扩展性设计和代码类结构设计等方面进行详细的说明。

#### **3.1 流量缓存防线设计**

在正式设计代码之前，先来回顾一张图，如图29-1所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/204e02f7f5b4b2b1f142aad4f060762af1b14934c08f9eb94b5700be774bfb2e.png)

可以看到，在秒杀系统中本地缓存和分布式缓存相结合，能够抗住进入秒杀系统内部的大部分流量。并且在技术选型上，本地缓存默认基于Guava Cache实现，分布式缓存则默认基于Redis实现。并且本地缓存不仅仅只是支持Guava Cache，分布式缓存不仅仅只是支持Redis，在代码层面，都是面向接口编程，而非面向具体实现类编程，不管是本地缓存还是分布式缓存，都可以根据简单的配置切换具体的实现方式。

#### **3.2 代码扩展性设计**

代码具备良好的扩展性，后续维护和升级的成本就比较低。相反，如果代码写的杂乱无章，犹如“屎山”，那后期维护起来是相当痛苦的，谁也不想天天面对着一堆“屎山”，哪来有问题改哪里。所以，从一开始写的代码就要有良好的扩展性，方便后期的维护和升级。

秒杀系统整体是基于SpringBoot实现呢？那如何写代码具备良好的扩展性呢？**总体的原则就是面向接口编程，而非面向具体的实现类编程，具体业务逻辑里依赖的是接口，而非实现类，在接口不变的前提下，可以随时切换具体的实现类，也可以随时新增接口的实现类。业务中可以根据配置加载接口的某个具体实现类。**

本地缓存的扩展示意图如图29-2所示。

可以看到，具体秒杀业务中会依赖本地缓存的接口，而非具体的实现类。本地缓存的接口可以有多个实现类，在秒杀业务中可以根据具体的配置项指定要加载并使用哪个实现类，也可以根据具体的需求和业务场景随时新增本地接口的实现类，大大提高了程序的扩展性。

分布式缓存的扩展示意图如图29-3所示。

可以看到，分布式缓存在扩展性方面的设计与本地缓存类似，同样是秒杀系统在具体业务中依赖分布式缓存的接口，而非分布式缓存的具体实现类。分布式缓存的接口可以有多个实现类，在秒杀业务中可以根据具体的配置项加载并实例化具体的实现类，也可以根据具体的需求和业务场景新增分布式缓存接口的实现类，提高了实现分布式缓存程序的扩展性。

#### **3.3 代码类结构设计**

关于混合型缓存通用代码的类结构设计，同样会从本地缓存和分布式缓存两个方面进行代码的类结构设计。

本地缓存的代码类结构设计如图29-4所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/ce926eae029f5b368d4d5d104adc04addd551b8708ff0b5e1a1a58bfd8ce4cea.png)

可以看到，秒杀系统在实现本地缓存时，默认是基于Guava Cache实现，并且主要包含一个接口和两个类，分别如下所示。

1. LocalCacheService：本地缓存的接口，提供了向缓存中添加数据的put()方法和从缓存中获取数据的getIfPresent()方法，秒杀系统的具体业务中会依赖LocalCacheService接口。

2. LocalCacheFactory：本地缓存工厂类，提供了创建本地缓存Cache对象的方法。

3. GuavaLocalCacheService：基于Guava Cache实现的本地缓存实现类，实现了LocalCacheService接口，并依赖LocalCacheFactory类，通过LocalCacheFactory类创建Guava Cache对象，并通过Guava Cache对象实现LocalCacheService接口中的方法。

分布式缓存的代码类结构设计如图29-5所示。

![](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/24755995667e410be03828cbc0dd56f3d97191c7819464acac40468f86c491ce.png)

可以看到，秒杀系统在实现分布式缓存时，默认是基于Redis实现的，主要包含一个接口和一个实现类，分别如下所示。

1. DistributedCacheService：分布式缓存的接口，提供了常用的操作缓存的方法，秒杀系统具体业务中会依赖DistributedCacheService接口，DistributedCacheService接口默认的实现类为RedisCacheService，也可以根据具体的需求和业务场景新增其他的实现类。

2. RedisCacheService：基于Redis实现的分布式缓存接口的默认实现类，基于Redis实现了DistributedCacheService接口中定义的常用的操作缓存的方法。

### **四、代码实现**

在代码实现上，会将混合型缓存通用的代码放到seckill-infrastructure工程下，这里，同样会从本地缓存的代码实现与分布式缓存的代码实现两个方面进行完善。

#### **4.1 本地缓存的通用代码实现**

本地缓存通用代码实现的步骤如下所示。

**（1）新增LocalCacheService接口**

LocalCacheService接口的源码详见：seckill-infrastructure工程下的[io.binghe.seckill.infrastructure.cache.local.LocalCacheService](http://io.binghe.seckill.infrastructure.cache.local.LocalCacheService)。

```go
public interface LocalCacheService<K, V> {
    void put(K key, V value);
    V getIfPresent(Object key);
}
```

可以看到，LocalCacheService接口是一个泛型接口，定义了缓存中的Key的泛型类型K和Value的泛型类型V，并在LocalCacheService接口中定义了向缓存中添加数据的put()方法和从缓存中获取数据的getIfPresent()方法。

**（2）新增LocalCacheFactory类**

LocalCacheFactory类的源码详见：seckill-infrastructure工程下的[io.binghe.seckill.infrastructure.cache.local.guava.LocalCacheFactory](http://io.binghe.seckill.infrastructure.cache.local.guava.LocalCacheFactory)。

```go
public class LocalCacheFactory {
    public static <K, V> Cache<K, V> getLocalCache(){
        return CacheBuilder.newBuilder().initialCapacity(15).concurrencyLevel(5).expireAfterWrite(5, TimeUnit.SECONDS).build();
    }
}
```

可以看到，在LocalCacheFactory类中提供了一个创建Guava Cache的getLocalCache()方法，并且会将缓存的初始容量设置为15，并发度设置为5，过期时间为5秒。

**（3）新增GuavaLocalCacheService类**

GuavaLocalCacheService类的源码详见：seckill-infrastructure工程下的[io.binghe.seckill.infrastructure.cache.local.guava.GuavaLocalCacheService](http://io.binghe.seckill.infrastructure.cache.local.guava.GuavaLocalCacheService)。

```go
@Service
@ConditionalOnProperty(name = "local.cache.type", havingValue = "guava")
public class GuavaLocalCacheService<K, V> implements LocalCacheService<K, V> {
    //本地缓存，基于Guava实现
    private final Cache<K, V> cache = LocalCacheFactory.getLocalCache();
​
    @Override
    public void put(K key, V value) {
        cache.put(key, value);
    }
​
    @Override
    public V getIfPresent(Object key) {
        return cache.getIfPresent(key);
    }
}
```

可以看到，本地缓存的扩展性是基于SpringBoot的@ConditionalOnProperty注解实现的，当配置文件中的[local.cache.type](http://local.cache.type)配置项的值为guava时，就会加载并实例化GuavaLocalCacheService类的对象。并且GuavaLocalCacheService类实现了LocalCacheService方法，在GuavaLocalCacheService类中基于Guava Cache实现了LocalCacheService接口中的方法，通过Guava Cache实现了本地缓存。

至此，本地缓存的通用代码实现完毕。

#### **4.2 分布式缓存的通用代码实现**

分布式缓存通用代码的实现步骤如下所示。

**（1）新增DistributedCacheService接口**

DistributedCacheService接口的源码详见：seckill-infrastructure工程下的[io.binghe.seckill.infrastructure.cache.distribute.DistributedCacheService](http://io.binghe.seckill.infrastructure.cache.distribute.DistributedCacheService)。

```go
public interface DistributedCacheService {
    void put(String key, String value);
    void put(String key, Object value);
    void put(String key, Object value, long timeout, TimeUnit unit);
    void put(String key, Object value, long expireTime);
    <T> T getObject(String key, Class<T> targetClass);
    String getString(String key);
    <T> List<T> getList(String key, Class<T> targetClass);
    Boolean delete(String key);
    Boolean hasKey(String key);
}
```

可以看到，在DistributedCacheService接口中，定义了操作分布式缓存常用的方法。

**（2）新增RedisCacheService类**

RedisCacheService类的源码详见：seckill-infrastructure工程下的[io.binghe.seckill.infrastructure.cache.distribute.redis.RedisCacheService](http://io.binghe.seckill.infrastructure.cache.distribute.redis.RedisCacheService)。

```go
@Service
@ConditionalOnProperty(name = "distributed.cache.type", havingValue = "redis")
public class RedisCacheService implements DistributedCacheService {
​
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
​
    @Override
    public void put(String key, String value) {
        if (StringUtils.isEmpty(key) || value == null) {
            return;
        }
        redisTemplate.opsForValue().set(key, value);
    }
​
    @Override
    public void put(String key, Object value) {
        if (StringUtils.isEmpty(key) || value == null) {
            return;
        }
        redisTemplate.opsForValue().set(key, value);
    }
​
    @Override
    public void put(String key, Object value, long timeout, TimeUnit unit) {
        if (StringUtils.isEmpty(key) || value == null) {
            return;
        }
        redisTemplate.opsForValue().set(key, value, timeout, unit);
    }
​
    @Override
    public void put(String key, Object value, long expireTime) {
        if (StringUtils.isEmpty(key) || value == null) {
            return;
        }
        redisTemplate.opsForValue().set(key, value, expireTime, TimeUnit.SECONDS);
    }
​
    @Override
    public <T> T getObject(String key, Class<T> targetClass) {
        Object result = redisTemplate.opsForValue().get(key);
        if (result == null) {
            return null;
        }
        try {
            return JSON.parseObject((String) result, targetClass);
        } catch (Exception e) {
            return null;
        }
    }
​
    @Override
    public String getString(String key) {
        Object result = redisTemplate.opsForValue().get(key);
        if (result == null) {
            return null;
        }
        return String.valueOf(result);
    }
​
    @Override
    public <T> List<T> getList(String key, Class<T> targetClass) {
        Object result = redisTemplate.execute((RedisCallback<Object>) connection ->
                connection.get(key.getBytes()));
        if (result == null) {
            return null;
        }
        return ProtoStuffSerializerUtils.deserializeList(String.valueOf(result).getBytes(), targetClass);
    }
​
    @Override
    public Boolean delete(String key) {
        if (StringUtils.isEmpty(key)) {
            return false;
        }
        return redisTemplate.delete(key);
    }
​
    @Override
    public Boolean hasKey(String key) {
        return redisTemplate.hasKey(key);
    }
​
    public RedisTemplate<String, Object> getRedisTemplate() {
        return redisTemplate;
    }
}
```

可以看到，分布式缓存的扩展性也是基于SpringBoot的@ConditionalOnProperty注解实现的，当配置文件中的[distributed.cache.type](http://distributed.cache.type)配置项的值为redis时，会加载并实例化RedisCacheService类的对象。并且RedisCacheService类实现了DistributedCacheService接口，在RedisCacheService类中会基于Redis实现DistributedCacheService接口中定义的方法。

#### **4.3 新增配置项**

在seckill-starter工程下的src/main/resources目录下的application.properties文件中新增Redis相关的配置项，本地缓存的扩展配置项和分布式缓存的扩展配置项，如下所示。

```go
#Redis配置
spring.redis.host=127.0.0.1
#Redis服务器连接端口
spring.redis.port=6379
#Redis服务器连接密码（默认为空）
spring.redis.password=
#连接池最大连接数（使用负值表示没有限制）
spring.redis.pool.max-active=8
#连接池最大阻塞等待时间（使用负值表示没有限制）
spring.redis.pool.max-wait=-1
#连接池中的最大空闲连接
spring.redis.pool.max-idle=8
#连接池中的最小空闲连接
spring.redis.pool.min-idle=0
#连接超时时间（毫秒）
spring.redis.timeout=30000
spring.redis.address=redis://127.0.0.1:6379
# redis
distributed.cache.type=redis
# guava
local.cache.type=guava
```
