## 2、代码开发

这里接口设计的参数传入`较少`，因此不使用使用DTO封装传入的参数。

#### 1、Controller

```java
/**
 * 启用或者禁用员工
 * @param status
 * @param id
 * @return
 */
@PostMapping("/status/{status}")
@ApiOperation("启用或者禁用员工")
public Result startOrStopEmp(@PathVariable  Integer status, Long id){
    log.info("启用或者禁用员工：{}，{}", status, id);
    employeeService.startOrStopEmp(status, id);
    return Result.success();

    }
```

#### 2、Service

```java
/**
     * 启用或者禁用员工
     *
     * @param status
     * @param id
     * @return
     */
    @Override
    public void startOrStopEmp(Integer status, Long id) {
        //sql语句应该是 update employee status = ? where id = ?
        Employee employee = Employee.builder()
                .status(status)
                .id(id)
                .build();//Employee添加了@Buildr注解,就可以实现链式编程。

        employeeMapper.update(employee);
    }
```

#### 3、Mapper

```java
    <update id="update">
        update employee
        <set>
            <if test="name != null">name = #{name},</if>

            <if test="updateTime != null">update_time = #{updateTime},</if>
            <if test="updateUser != null">update_user = #{updateUser},</if>
        </set>
        where id = #{id}
    </update>
```

> 写一个可以复用的update的Mapper实现。
> `parameterType="Employee"`事实证明，这句话要不要都没问题。

## 3、功能测试

> 功能测试方式：
> 1. 通过接口文档测试（推荐 `Swagger` ，因为这个接口我们是直接生成的，以后还可以将 `Swagger` 导入到 `Apifox` 中供前段使用。）
> 2. 通过前后端联调测试(前端还没有写好接口时，该种测试无法执行)
> 3. 注意：由于开发阶段前端和后端是并行开发的，后端完成某个功能后，此时前端对应的功能可能还没有开发完成，导致无法进行前后端联调测试。所以在开发阶段，后端测试主要以接口文档测试为主。
