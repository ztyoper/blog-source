# Spring Cache

![tmp49C6.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/d167e1a783de1957df6c46212820ea10db749323cd548dd8d5ada3926eb83e4b.png)

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-cache</artifactId>
  <version>2.7.3</version>
</dependency>
```

1. 导入这个依赖后，就可以使用注解了。
2. 如何选择缓存的实现方法呢？导入 `spring-boot-redis-starter` 依赖就会选择使用 `redis` 的缓存实现方式。导入哪个依赖就用哪种方式。同时导入我也不知道。可能有优先级吧。

![tmpFBAE.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/b9e3a5337a3c77d845b214b44645a8247f8711e947ebe89f02d601132776e3a2.png)

1. @CachePut只能写，@Cacheable能读能写。
2. @CacheEvict: eviction：收回

> 我们测试使用的项目是springcache-demo项目。测试前先运行sql脚本。生成对应的mysql数据库。然后在knife4j里面进行测试。

```java
@Slf4j
@SpringBootApplication
@EnableCaching //不能忘记这一句，开启缓存注解
public class CacheDemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(CacheDemoApplication.class,args);
        log.info("项目启动成功...");
    }
}
```

```java
@RestController
@RequestMapping("/user")
@Slf4j
public class UserController {

    @Autowired
    private UserMapper userMapper;

    @PostMapping
    //下面这些语法："#user.id" 叫做SqEL语法，Spring expression language
    @CachePut(cacheNames ="userCache",key ="#user.id")//如果使用Spring Cache缓存数据，key的生成：userCache::2
    //user是“形参” 的 user , id属性添加了回显的。所以看得到  @Options(useGeneratedKeys = true,keyProperty = "id")
    //@CachePut(cacheNames = "userCache", key = "#result.id")//对象导航
    //@CachePut(cacheNames "userCache",key "#p0.id")
    //@CachePut(cacheNames "userCache",key "#a0.id")
    //@Cacheput(cacheNames "userCache",key "#root.args[0].id")
    //存入redis缓存中就是：key:userCache:(Empty):形参user的id,  value就是返回对象user
    public User save(@RequestBody User user) {
        userMapper.insert(user);
        return user;
    }

    @DeleteMapping
    @CacheEvict(cacheNames = "userCache", key = "#id")// key生成： userCache::id,也就是删除对应key的value
    public void deleteById(Long id) {
        userMapper.deleteById(id);
    }

    @DeleteMapping("/delAll")
    @CacheEvict(cacheNames = "userCache", allEntries = true) // 删除userCache全部键值对
    public void deleteAll() {
        userMapper.deleteAll();
    }

    @GetMapping
    @Cacheable(cacheNames = "userCache", key = "#id")//key生成： userCache::10
    public User getById(Long id) {
        User user = userMapper.getById(id);
        return user;
    }

}
```

```java
package com.itheima.mapper;

import com.itheima.entity.User;
import org.apache.ibatis.annotations.*;

@Mapper
public interface UserMapper{

    @Insert("insert into user(name,age) values (#{name},#{age})")
    @Options(useGeneratedKeys = true,keyProperty = "id")
    void insert(User user);

    @Delete("delete from user where id = #{id}")
    void deleteById(Long id);

    @Delete("delete from user")
    void deleteAll();

    @Select("select * from user where id = #{id}")
    User getById(Long id);
}
```

1. 原理是生成controller的代理对象来实现对缓存的增删读操作。
2. 生成的key就是这么来的。记住，不管是删除缓存、添加缓存还是访问缓存。都只用关注生成key的策略。因为key是我们查询到value的唯一标识。
3. 生成key的策略可以查看源码的注释，例如查看@CachePut的key的生成策略。
