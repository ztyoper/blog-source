# 9、JVM篇

## 1、JVM是什么

### 1、JVM定义

Java Virtual Machine是Java程序的运行环境，准确说是Java二进制**字节码**的运行环境

### 2、学习JVM的好处

1. 一次编写，到处运行
2. 自动内存管理，垃圾回收机制。-&gt;防止内存移除
3. 更好地调试bug，修复内存溢出问题、cpu飙高问题。

## 2、JVM组成

![tmp443.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/393f8ac0b8d1af0baf4695bb6557fb731b4c972830cec9550b38ecc5b8bce4ff.png)

总共4个组成部分。

1. **类加载子系统** ：将字节码文件加载到内存中
2. **运行时数据区（内存）：** 用于分配存储空间

1. 方法区/元空间；方法区就是元空间
2. 堆
3. 程序计数器
4. 虚拟机栈、本地方法栈

3. **C、C++实现的本地接口**
4. **执行引擎：执行字节码文件或本地方法**

1. 即时编译器
2. 解释器
3. 垃圾回收器

### 1、什么是程序计数器

程序计数器：线程私有的，内部保存的字节码的行号。用于记录正在执行的字节码指令的地址。

```java
public class Application{
    public static void main(String[] agrs){
        System.out.println("hello world");
    }
}
```

`javap -v target/classes/Application.class`打印堆栈大小，局部变量的数量和方法的参数。

0行：获取静态对象：这里获取到了System的静态对象out，类型为PrintStream

3行：获取常量 ： String的hello world

5行：执行打印方法

8行：返回空，结束

![tmpAE36.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/4284c4b3edc03dd070c642761415b77281c53f9ad2e99c2adfe61ee46df54663.png)

当线程1从0行执行到10行后，被线程2夺走cpu。线程2从0行执行到9行，又被线程1夺走cpu，线程1不是从0行开始执行，而是从13行开始执行。

这就是程序计数器的作用，每个线程私有一份，用于保存字节码的行号。用于记录正在被执行的字节码指令的地址。

### 2、你能给我详细的介绍下堆吗？

堆就是线程共享的区域：主要用来保存对象实例，数组等，当堆中没有内存空间可以分配给实例或者数组，也无法在扩展时，则会抛出OutOfMemoryError异常。OOM异常。

![tmpCA51.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/b5b64edca4c843e0313f8a69deed3d30d51c322548187da3fb59330dc24e699f.png)

1. 先不用管本地空间，直接空间。
2. 元空间就是方法区。 **用于保存类的信息、静态变量、常量、JIT即时编译后的代码**
3. 堆中存在年轻代和老年代

- 年轻代被 **划分为三部分** ：分配的实例对象会放在Eden部分，根据JVM的策略，一次垃圾回收后仍然存在的实例对象会被放到幸存区S0/S1中。几次垃圾回收后，仍然存活在Survivor区的对象将会被移动到老年代区间中。
- 老年代：主要保存生命周期长的对象，一般是一些老的对象。

![tmpF71E.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/c76d4b439f6207680a01afd5099c8825e66aa9cb3f22d73e9a4fdf3e7209cad8.png)

jdk8之前，没有元空间，它是将**方法区**放到**堆**中，称之为**永久代。**因为随着**动态类**加载的情况会越来越多，永久代空间会越来越不可控。如果永久代**小了**，会报OOM异常。如果永久代**大了**，会浪费空间。因此我们将永久代取消。换成了本地内存中的元空间。主要就是**避免OOM**异常。

![tmpD71C.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/170123a609785a3cffc02349e78379dd990faab55f7cd0f964b419beb6e72319.png)

### 3、什么是虚拟机栈

Java Virtual Machine Stack 就是虚拟机栈。

1. 每一个线程运行时所需要的内存，就称之为虚拟机栈（每个线程 **私有** ），先进后出。
2. 每一个栈可以存放多个栈帧（frame），对应着每次方法调用时所占用的内存。需要存放 **参数** 、 **局部变量** 、 **返回地址** 。
3. 每一个线程只能有一个活动栈帧，对应着当前正在执行的那个方法。就是栈顶的那个方法。
4. 默认的栈内存通常是1024k 也就是 1M。也就是每一个虚拟机栈分配1024K的内存大小。

### 4、垃圾回收是否涉及栈内存

垃圾会后主要指就是**堆内存，**当栈帧弹栈以后，内存就会释放，不需要垃圾回收器。

### 5、栈内存分配越大越好吗？

未必，默认的栈内存通常为1024k

栈内存过大会导致线程数变少，例如，机器总内存为512m，目前能活动的线程数则为 512 个，如果把栈内存改为2048k,那么能活动的栈帧就会减半

### 6、方法内的局部变量是否线程安全？

![tmp950E.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/d9001ce63a79a236fc48944ca0541a9538edd1d0cc494346d349512996c9eb5e.png)

1. 如果方法内局部变量没有逃离方法的作用范围，它是线程安全的

1. 就像 **m1()** 方法的调用

2. 如果是局部变量引用了对象，并逃离方法的作用范围，需要考虑线程安全

1. 引入对象： **m2()** 方法在main方法中调用。如果main方法在 **new Thread()** 后面又对 **对象sb** 进行操作。那么就同时有 **两个线程** 对 **对象sb** 进行操作。
2. 逃离方法的作用范围： **m3()** 方法返回一个实例对象，并且这个对象在多个线程中被共享和修改，那么这个方法可能是线程不安全的。线程不安全意味着多个线程同时访问共享的数据时可能会导致意外的结果，比如数据损坏、不一致性等问题。

### 7、什么情况下会导致栈内存溢出？

**栈帧过多**导致栈内存溢出，典型问题：递归调用 java.lang.**StackOverflowError**

**栈帧过大**导致栈内存溢出。栈帧大小超过分配的1024K的大小。不过一般不会。

### 8、堆栈的区别是什么？

1. 栈内存一般会用来存储方法调用栈帧（包含方法参数，局部变量（实例引用），返回地址），但堆内存是用来存储实例对象和数组的。
2. 堆会GC垃圾回收，而栈不会。
3. 栈内存是线程私有的，而堆内存是线程共有的。
4. 两者异常错误不同，但如果栈内存或者堆内存不足都会抛出异常。

1. 栈空间不足：java.lang.StackOverflowError。
2. 堆空间不足：java.lang.OutOfMemoryError。

### 9、能不能解释一下方法区

1. 方法区(Method Area)是 **各个线程共享** 的 **内存区域** 。和堆一样都是共享的。方法区jdk8后从永久代变为了元空间。
2. 本地内存就是操作系统的内存。元空间的大小一般是无上限的。当然操作系统的内存有上限。如果如果方法区域中的内存无法满足分配请求，则会抛出OutOfMemoryError:Metaspace
3. 主要存储 **类的信息** 、 **运行时常量池。** 还会存储 **类加载器**
4. 虚拟机启动的时候创建，关闭虚拟机时释放

### 10、介绍一下运行时常量池

常量池：可以看作是一张表，虚拟机指令根据这张常量表找到要执行的**类名、方法名、参数类型、字面量**等信息。**常量池（常量表）的信息是存储在类的信息中的。**

当**类被加载**，它的常量池信息就会**放入运行时常量池**，并把里面的**符号地址**变为**真实地址**

### 11、你听说过直接内存吗？

1. 并不属于JVM中的内存结构，不由JVM进行管理。是虚拟机的系统内存（就是操作系统的内存）。但是方法区/元空间属于JVM的内存结构
2. 常见于NIO操作时，用于 **数据缓冲区** ，分配回收成本较高，但 **读写性能高** ，不受JVM内存回收管理。

![tmpDFAF.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/b4fce5b313d5de3061ab9f380504294d514e1c58d7bcbc5c869f148f1b863709.png)

```java
/**
 * 演示 ByteBuffer 作用
 */
public class DirectMemoryDemo {
    static final String FROM = "E:\\bak1\\01-java成神之路.mp4";
    static final String TO = "E:\\bak2\\abc.mp4";
    static final int _1Mb = 1024 * 1024;

    public static void main(String[] args) {
        io();  //256.8563   常规IO
        directBuffer();//63.2449   NIO
     }

    private static void directBuffer() {
        long start = System.nanoTime();
        try (FileChannel from = new FileInputStream(FROM).getChannel();
             FileChannel to = new FileOutputStream(TO).getChannel();
        ) {
            ByteBuffer bb = ByteBuffer.allocateDirect(_1Mb);
            while (true) {
                int len = from.read(bb);
                if (len == -1) {
                    break;
                }
                bb.flip();
                to.write(bb);
                bb.clear();
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
        long end = System.nanoTime();
        System.out.println("directBuffer 用时：" + (end - start) / 1000_000.0);
    }

    private static void io() {
        long start = System.nanoTime();
        try (FileInputStream from = new FileInputStream(FROM);
             FileOutputStream to = new FileOutputStream(TO);
        ) {
            byte[] buf = new byte[_1Mb];
            while (true) {
                int len = from.read(buf);
                if (len == -1) {
                    break;
                }
                to.write(buf, 0, len);
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
        long end = System.nanoTime();
        System.out.println("io 用时：" + (end - start) / 1000_000.0);
    }
}
```

常规IO会先调用native的**本地接口**将磁盘文件保存到**系统缓冲区**。但是Java**访问不到**系统缓冲区，所以需要使用InputStream is进行**is.read(byte[])**读取到我们定义的java缓冲区byte[]，然后**才能被java访问和操作**。这个过程中发生了同一个数据进行了**两次缓冲。**

NIO会先调用native的**本地接口**将磁盘文件保存到**直接内存（让操作系统内存指定一个内存），java和系统都能访问和操作。**这个过程中发生了同一个数据进行了**一次缓冲。**

## 3、类加载器

### 1、什么是类加载器，类加载器有哪些？

JVM只会运行**二进制文件**，类加载器的作用就是将**字节码文件的二进制**加载到JVM中，从而让Java程序能够启动起来。

类加载器有哪些:

1. 启动类加载器(BootStrap ClassLoader) 由C++编写实现 ，内嵌在JVM中:加载JAVA HOME/jre/ib目录下的库
2. 扩展类加载器(ExtClassLoader):主要加载JAVA HOME/jre/Iib/ext目录中的类
3. 应用类加载器(AppClassLoader):用于加载classPath下的类
4. 自定义类加载器(CustomizeClassLoader):自定义类继承ClassLoader,实现自定义类加载规则。

### 2、什么是双亲委派模型？

加载某一个类，先委托上一级的加载器进行加载，如果上级加载器也有上级，则会继续向上委托，如果该类委托上级没有被加载，子加载器尝试加载该类。

### 3、说一下JVM的分代回收

#### 1、堆的区域划分

![tmpDB89.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/b94220dcc2d55a4724c79b7813907fdb0d1ab6bcf98e848fd14a6fd710041265.png)

#### 2、对象回收分代回收策略

1.新创建的对像，都会先分配到eden区

2.当伊甸园内存不足，标记伊甸园与from（现阶段没有）的存活对象

3.将存活对像采用复制算法复制到o中，复制完毕后，伊甸园和from内存都得到释放

4.经过一段时间后伊甸园的内存又出现不足，标记eden区域to区存活的对象，将其复制到from区

5.当幸存区对象熬过几次回收(最多15次)，晋升到老年代（幸存区内存不足或大对像会提前晋升）

### 4、MinorGC、MixedGC、FullGC的区别分别是什么

这三种GC是**特定垃圾回收器**使用的三种**回收的范围**策略：

- MinorGC(young GC)：发生在 **新生代** 的垃圾回收，暂停时间短(STW)
- Mixed GC： **新生代** + **老年代部分区域** 的垃圾回收，G1收集器特有
- FullGC： **新生代** + **老年代完整垃圾** 回收，暂停时间长(STW),应尽力避免。因为真的会停很久。

**STW**(Stop-The-World):暂停所有应用程序线程，等待垃圾回收的完成

### 5、说一下JVM有哪些垃圾回收器

在jvm中，实现了多种垃圾收集器，包括：

1. 串行垃圾收集器：Serial GC、Serial Old GC
2. 并行垃圾收集器：Parallel New GC、Parallel Old GC
3. CMS（并发）垃圾收集器：作用在老年代
4. G1垃圾收集器，作用在新生代和老年代

### 7、强引用、软引用、弱引用、虚引用的区别

1. 强引用：只要所有GC Roots能找到，就不会被回收
2. 软引用：需要配合SoftReference使用，当垃圾多次回收，内存依然不够的时候会回收软引用对象
3. 弱引用：需要配合WeakReference使用，只要进行了垃圾回收，就会把弱引用对象回收
4. 虚引用：必须配合引用队列使用，被引用对象回收时，会将虚引用入队，由Reference Handler线程调用虚引用相关方法释放直接内存

#### 1、强软引用

![tmp7D03.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/093c24e012840393b798b618569d9a7b3f5941635c8d28b9083daec3642fe28a.png)

#### 2、弱引用

![tmp8AEE.png](https://pub-ccd5622eabb54b4a81678003778ddce1.r2.dev/PicGo/923ff7d1a61e16e730978b44603c061b2dcc81208b6d968add581423dffa773d.png)

因为Entry继承WeakReference，ThreadLocal的赋值是调用super(k)，也就相当于调用WeakReference的构造器来赋值。因此k对象是弱引用。

> 为什么不将key设置为强引用：如果设置为强引用，当线程结束后，线程回归线程池，ThreadLocalMap又是Thread中的静态变量，这存在静态的引用GC root 因此，ThreadLocal不会被释放掉，会造成内存泄露。**线程执行结束 ≠ 线程对象被 GC**，尤其是在线程池中，**线程是被复用的，不会立即销毁！**只要线程对象还在，`Thread.threadLocals`也还在，它是一个强引用，**不会被 GC**。
> 如果将value设置为弱引用，可能会随时被GC当成垃圾回收掉，这不符合ThreadLocal的保存线程信息的初衷。因此需要程序员手动使用remove方法进行value的释放。否则会造成内泄露问题。
