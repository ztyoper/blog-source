# 1、Java基础

## 1、基础总结上

### 1、基本概念

#### 1、Java语言的特点

1. 简单易学：Java设计简单，具有清晰的语法规则，相比于c++，更容易学习和使用。比如：垃圾自动回收机制，类的单一继承。
2. 面向对象：

1. Java是一门面向对象的编程语言，支持类、对象、继承、封装以及多态等面向对象的概念。
2. 面向对象：OOP（Object-Oriented Programming）； 面向过程：POP（Procedure-Oriented Programming）

3. 跨平台性：Java程序可以在不同的操作系统上运行，只需要在不同平台上安装对应JVM虚拟机即可。这是因为Java程序在编译时生成的是字节码文件，不是机器码文件，然后由JVM在运行时转化为特定平台的机器码执行。
4. 多线程：Java提供了多线程编程，方便开发并发程序。
5. 高性能：Java是 `半编译半解释型语言` ，相比于Python等纯解释型语言，Java通过即时编译器JIT可以实现更高的性能。是Java应用运行地越来越快。
6. 安全性：提供了各种权限修饰符，具备异常处理和自动内存管理机制。

#### 2、JavaSE vs JavaEE

1. Java SE （Standard Edition）是Java平台标准版。它包含了支持Java应用开发和运行的核心类库以及虚拟机等核心组件。
2. Java EE （Enterprise Edition）是Java平台企业版。它多了：

1. 更多企业级组件：提供了开发和部署企业级应用程序的组件。如EJB（Enterprise JavaBeans）、JSP(JavaServer Pages) 、JMS（Java Message Service）、JTA（Java Transaction API）、JPA（Java Persistence API）
2. 事务管理：使用JTA和EJB来实现事务控制，确保数据操作的一致性和可靠性。
3. Java Persistence API（JPA），一种Java ORM框架。用于进行数据库操作。实现数据的持久化操作。

3. 除了 Java SE 和 Java EE，还有一个 Java ME（Java Platform，Micro Edition）。Java ME 是 Java 的微型版本，主要用于开发嵌入式消费电子设备的应用程序，例如手机、PDA、机顶盒、冰箱、空调等。Java ME 无需重点关注，知道有这个东西就行。

#### 3、JVM vs JDK vs JRE

1. JVM（Java Virtual Machine）：是Java虚拟机，不同操作系统的平台有对应不同的虚拟机。作用是让同一个字节码文件，运行出同一种结果。也是实现一次编译，多处运行的原因。JVM并不是只有一种。每个企业、组织、个人都可以开发自己的虚拟机。平时接触到的HotSpot VM只是JVM规范的一种实现。
2. JDK（Java Development Kit）：即Java开发工具包，JRE + 开发工具集（例如Javac编译工具，javadoc文档注释工具、javap反编译工具等）
3. JRE (Java Runtime Environment) ：是Java程序的运行时环境，包含JVM 和运行时所需要的核心类库。JVM + Java SE标准类库。
4. JDK 9以后不区分JDK和JRE了。而是使用模块系统和jlink工具(随 Java 9 一起发布的新命令行工具，用于生成自定义 Java 运行时映像，该映像仅包含给定应用程序所需的模块) 。并且，从 JDK 11 开始，Oracle 不再提供单独的 JRE 下载。

#### 4、什么是字节码？采用字节码的好处是什么？

1. 在Java中，JVM可以理解的代码就叫做字节码。扩展名是.class的文件。它不面向任何特定的处理器，只面向虚拟机。Java通过字节码的方式，在一定程度上解决了传统解释型语言执行效率低的问题（ 与传统的解释型语言（如Python或JavaScript）不同，这些语言通常在运行时逐行或逐块解释执行，而Java的字节码则在JVM上执行。JVM可以对字节码进行优化，例如通过即时编译（JIT）技术将热点代码（经常执行的代码）编译成机器码，从而提高执行效率。 ）。同时又保留了解释型语言可移植的特点。最终就是：效率上：c++ rust go &gt; java &gt; python 。一次编译，多处运行。无需重新编译。
2. 具体过程：java文件 -&gt;javac编译-&gt;class文件-&gt;解释器&即时编译器JIT-&gt;机器码
3. 判断热点代码？即使编译器JIT ：解释器

#### 5、Java vs C++

1. Java有自动内存管理机制，而C++使用指针来对内存进行操作
2. Java类没有多继承，而C++有类的多继承。Java有接口的多继承
3. Java有自动垃圾回收机制，而C++只能手动回收
4. Java有方法重载，而C++有方法重载和操作符重载。

### 2、语法知识

#### 1、标识符 vs 关键字

1. 标识符就是起的名字
2. 关键字就是赋予了特殊含义的标识符
3. true false null 是字面量不是关键字

#### 2、基本数据类型

1. 6个数字类型（字节数）：byte(1) short(2) int(4) long(8) float(4) double(8)
2. 1个字符类型：char(2)
3. 一个布尔类型：boolean(1)

#### 3、包装类型 vs 基本类型

1. 用途

1. 基本类型：一般用在局部变量、常量
2. 包装类型：一般用在方法参数、对象属性

2. 存储方式

1. 基本类型：一般存储在JVM栈中的局部变量表中
2. 包装类型：(无static) 在JVM堆中。(有static)在JVM方法区中

3. 占用空间

1. 基本类型：小
2. 包装类型：大

4. 默认值

1. 基本类型： 基本类型有默认值且不是 null 。
2. 包装类型：成员变量包装类型不赋值就是 null

5. 比较方式

1. 基本类型：==
2. 包装类型：重写equal（）方法

#### 4、为什么说是几乎所有对象实例都存在于堆中呢？

这是因为 HotSpot 虚拟机引入了 JIT 优化之后，会对对象进行逃逸分析，如果发现某一个对象并没有逃逸到方法外部（例如没有被其他方法引用），那么就可能通过标量替换来实现栈上分配，而避免堆上分配内存。

#### 5、包装类型的缓存机制

1. 8种类型：

1. Byte,Short,Integer,Long 这 4 种包装类默认创建了数值 **[-128，127]** 的相应类型的缓存数据，创建好了Integer[]
2. Character 创建了数值在 **[0,127]** 范围的缓存数据
3. Boolean 直接返回 True or False。
4. 两种浮点数类型的包装类 Float,Double 并没有实现缓存机制。

2. 在常量池中创建。目的就是提升性能。
3. 在上述区间可以使用==，但是出了区间就只能使用equal，因此推荐使用equal

#### 6、自动装箱与拆箱了解吗？原理是什么？

1. 是什么

- 装箱：将基本类型用它们对应的引用类型包装起来；
- 拆箱：将包装类型转换为基本数据类型；

2. 字节码中

- Integer i = 10 等价于 Integer i = Integer.valueOf(10)
- int n = i 等价于 int n = i.intValue();

3. 为了性能考虑，避免多次大量的装箱拆箱

#### 7、精度丢失

1. 小数的二进制是无限循环。而float、double的精度又只有32、64。所以多余部分被截断，也就出现了精度缺失。比如0.2的二进制0.00110011.....
2. 我们使用BigDecimal来做精确的浮点运算，避免精度缺失。

#### 8、超过long整型的数据

使用BigInteger来存储。底层使用int[]

#### 9、为什么要有默认值

1. 程序的可靠性：如果没有默认值，可能会包含任意垃圾值，取决于它们所在内存位置的初始内容。运行时如果忘记了赋值，使用垃圾值，会导致程序出错。
2. 程序的一致性：成员变量都有相同的默认值，默认值确保了对象的可预测性和一致性。免去了手动赋值。
3. 对于编译器（javac）来说，局部变量使用时有没有赋值很好判断，可以直接报错。而成员变量可能是运行时赋值，无法判断，误报“没默认值”又会影响用户体验，所以采用自动赋默认值。

#### 10、静态变量的作用

1. 多个该类的实例对象共用该静态属性，该静态变量只会分配一次内存空间，这样可以节省内存，而且也更符合某些业务场景。

#### 11、字符型常量与字符串常量

1. 形式上：

1. 字符型常量：一个被单引号引起来的字符。不能0个
2. 字符型常量：一串被双引号引起来0个或若干字符

2. 含义：

1. 字符型常量：一相当于一个整数值（ASCll值），可以参加表达式运算
2. 字符型常量：代表一个地址值（该字符串在常量池中存放的位置）

3. 内存分配：

1. 字符型常量：分配在JVM的栈中局部变量表中，占2个字符
2. 字符型常量：分配在JVM的常量池中，占若干字符，底层使用byte[]

#### 12、静态方法与实例方法

1. 调用方式上：

1. 静态方法：类.静态方法 或者 对象.静态方法
2. 实例方法：只能 对象.实例方法

2. 访问权限上：

1. 静态方法：只能访问静态成员（静态方法和静态变量），不能访问实例成员
2. 实例方法：都能访问

#### 13、重载 vs 重写

1. 重载：重载就是同一个类中多个同名方法根据不同的传参来执行不同的逻辑处理。

1. 发生在同一个类中（或者父类与子类之间），要求是方法名相同，但是形参列表不同（参数个数不同，顺序不同）。方法返回值和访问修饰符对是否构成重载不影响。
2. 构造方法和普通方法都存在重载。编译器是在运行时，所有重载的方法中根据方法名和形参列表进行匹配。如果不存在指定方法，则匹配失败。会报编译错误。

2. 重写：重写就是子类对父类方法的重新改造，外部样子不能改变，内部逻辑可以改变。

1. 如果父类方法访问修饰符为 private/final/static 则子类就不能重写该方法，但是被 static 修饰的方法能够被再次声明。
2. 构造方法不能被重写
3. “两同”即方法名相同、形参列表相同；
4. “两小”指的是子类方法返回值类型应比父类方法返回值类型更小或相等，子类方法声明抛出的异常类应比父类方法声明抛出的异常类更小或相等；
5. “一大”指的是子类方法的访问权限应比父类方法的访问权限更大或相等。
6. 关于 重写的返回值类型 这里需要额外多说明一下，上面的表述不太清晰准确：如果方法的返回类型是 void 和基本数据类型，则返回值重写时不可修改。但是如果方法的返回值是引用类型，重写时是可以返回该引用类型的子类的。

#### 14、什么是可变长形参

1. 从 Java5 开始，Java 支持定义可变长参数，所谓可变长参数就是允许在调用方法时传入不定长度的参数。就比如下面的这个 printVariable 方法就可以接受 0 个或者多个参数。
